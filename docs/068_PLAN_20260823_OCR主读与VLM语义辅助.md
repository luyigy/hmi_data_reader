# 068 OCR 主读与 VLM 语义辅助计划

## 1. 决策与目标链路

对外契约和端口保持不变：

```text
Web / 其他调用方
        |
        v
8765 /api/v1/recognize（唯一对外接口）
        |
        +-- 质量门禁、矫正
        +-- PaddleOCR：文本、数字、坐标、置信度
        +-- 现有分类/模板指纹：只确定 family / page_type
        +-- OCR 证据整理
        |     +-- 证据明确：确定性规则直接映射 field_catalog
        |     +-- 证据歧义：只把文本证据发给 8003 做语义归位
        |     `-- 仍失败：现有模板/专用旁车兜底
        `-- 契约校验：ok / review / reject

8003：仅内部文本推理，实际模型 Qwen3.8-27B-AWQ-INT4
8000：硬隔离，不访问、不配置、不重启
```

VLM 只允许回答“哪些 OCR token 属于哪个字段、屏幕顺序、启用段数和是否存在歧义”。它不得返回新的业务数值；最终值必须由 8765 按 VLM 返回的 token ID 从原始 OCR 证据中组装。这样即使模型误判语义，也不能凭空改写数字。

## 2. 当前基线与不可覆盖项

### 2.1 已核实运行与代码事实

- `8765/ready` 正常；生产入口是 `hmi_service.py::recognize_image`，当前单 Worker、单信号量，并发占用时返回 429。
- 当前顺序是质量门禁 → 矫正 → PaddleOCR → 后处理/分类 → OCR 旁车 → `extract_one` → `attach_contract` → 原响应契约。
- `scripts/extract_fields.py::extract_one` 的模板同时承担家族/页面路由、行列结构、段序、禁用段和专用提取器选择，不能一次性删除。
- `scripts/vlm_qwen.py` 目前只被离线 `scripts/vlm_eval.py` 调用，接口是“原图 + 已知 page_type”；它不是本计划最终要接的文本语义接口。
- VLM 默认 URL 已是 `8003`，但默认模型名仍为旧 `Qwen3-VL-32B-Instruct`；任何评测和接线都必须显式设置 `HMI_VLM_MODEL=Qwen3.8-27B-AWQ-INT4`。
- GitNexus 能识别离线 VLM 调用链，但当前索引没有识别出异步生产入口 `recognize_image` 和 `extract_one`。因此不能把离线客户端的 LOW 风险结论套到生产主链。

### 2.2 当前工作区已有用户修改

- `scripts/extract_generic.py`、`tests/test_generic_extraction.py` 以及 `extract_fields.py` 的 `GENERIC_FALLBACK` 已构成“无模板时通用 OCR 提取”草稿。先验证、复用和收口，禁止另写一套并行实现。

## 3. 目标数据契约

### 3.1 OCR 证据

最小证据对象只保留现有 OCR 已有信息，不引入新依赖：

```json
{
  "page_type": "injection_metering",
  "rows": [
    {
      "label_token_ids": ["t12"],
      "value_token_ids": ["t13", "t14", "t15"],
      "text": "射出速度 30 25 20",
      "order": "screen_left_to_right"
    }
  ],
  "tokens": {
    "t12": {"text": "射出速度", "conf": 0.98, "bbox": [0.10, 0.20, 0.25, 0.24]},
    "t13": {"text": "30", "conf": 0.96, "bbox": [0.40, 0.20, 0.44, 0.24]}
  }
}
```

证据生成规则应复用现有 `norm_tokens`、OCR 合并和 `field_catalog`，不再复制归一化、数值解析或容差逻辑。

### 3.2 VLM 文本响应

VLM 只返回引用，不返回数值：

```json
{
  "mappings": [
    {
      "field": "stage_velocity_mms",
      "value_token_ids": ["t13", "t14", "t15"],
      "screen_order": "reverse_physical",
      "active_count": 3
    }
  ],
  "unresolved": [],
  "notes": []
}
```

8765 必须拒绝未登记字段、未知 token ID、重复占用、越界 active_count 和模型直接返回的数值。所有数组反转、禁用段裁剪和单位换算仍由确定性代码完成。

## 4. 实施切片

### S0：冻结脏工作区并建立可复现基线

目标：知道当前代码和草稿实际能做什么，避免在不明基线上接主链。

1. 保存 `git status`、相关定向 diff、当前 commit、Python/依赖版本；不清理、不 reset、不覆盖用户文件。
2. 运行现有最小测试，优先验证 `tests/test_generic_extraction.py`、`tests/test_contract.py`、路由/温度/注射相关测试；再运行全量测试并区分既有失败与新增失败。
3. 枚举可配对的真值和图片，按 `page_type`、家族、正样本/拒识样本生成固定清单；不把缺图真值混入准确率分母。
4. 对当前模板链和现有 generic 草稿分别回放，输出字段准确率、完整率、状态和每图耗时基线。

交付物：一份基线 JSON/REPORT，包含可复现命令、样本清单 hash、测试结果和现有失败。

停止条件：现有草稿无法独立辨认、测试基线不可复现，或发现用户修改互相冲突；先报告，不进入 S1。

### S1：收口通用 OCR 证据层

目标：把已有 generic 草稿从“直接猜字段”收口成可审计的 OCR 证据，不接 VLM、不改线上返回。

1. 在修改每个函数前按 `AGENTS.md` 对目标符号做 upstream impact；`recognize_image`/`extract_one` 若仍无法被索引，明确记录图谱缺口并用源码调用者、路由契约和测试补充评估。HIGH/CRITICAL 必须先告知用户。
2. 优先复用 `scripts/extract_generic.py`、`norm_tokens`、`merge_variant_lines` 和 catalog；只补缺少的 token ID、行聚类和证据输出。
3. 明确证据直接映射条件：唯一标签、空间邻接明确、类型/范围合法、数组列无错位、字段属于当前 `page_type`。不满足即 unresolved，禁止猜测。
4. 保留最小单测：标量邻接、温度行列、缺格不左移、歧义不直出。

验收：证据中的每个数值都能追溯到 OCR token；无 token 来源的值数量严格为 0；现有已验收模板路径输出零 diff。

### S2：新增文本语义映射器并离线评测

目标：让 8003 只处理 OCR 文本歧义，不接生产入口。

1. 不改造现有图像客户端为万能接口；增加一个最小文本调用函数，复用其 stdlib HTTP、JSON 解析和错误类型。
2. 请求只发送当前页相关的 OCR 证据和 catalog 字段子集，不发送原图，不发送其他页面字段，不允许模型生成数值。
3. 显式配置：`HMI_VLM_BASE_URL=http://localhost:8003/v1`、`HMI_VLM_MODEL=Qwen3.8-27B-AWQ-INT4`。评测前核对 `/v1/models`，不得依赖旧默认模型名。
4. 先用小批覆盖标量、数组、反序段、禁用段和 OCR 歧义；通过后再跑 S0 固定清单。
5. 记录字段映射准确率、结构准确率、非法引用率、解析失败率、调用延迟 p50/p95/max、token 用量；与图像 VLM 和纯模板基线分开报告。

验收：

- 非 OCR 来源数值 = 0；未知 token/字段和非法结构均被拒绝。
- 真值门禁沿用 `verify_accuracy.py`：numeric accuracy ≥ 0.95、error auto-import rate = 0、rejection accuracy = 1 或按既有口径 N/A。
- 段数、段序和数组长度必须逐项报告；任一系统性错位不得进入 S3。
- 8003 不可用、超时或返回坏 JSON 时，本地流程可控失败且不污染字段。

### S3：8765 影子接线

目标：真实请求旁路比较，但不改变响应、状态和模板主链。

1. 在 `recognize_image` 的 OCR/分类之后、响应组装之前，以默认关闭的环境开关启用影子语义链；不开新 API，不改 Web 地址。
2. 只对 S1 判为 unresolved 的请求调用 8003；明确字段不调用。VLM 故障立即跳过，原模板链照常完成。
3. 影子记录只包含请求关联 ID、路由、字段/token 引用、耗时和差异；不长期保存原图或完整敏感 OCR 文本。
4. 固定模型调用上限和短超时；具体值由 S2 p95 决定，不先拍脑袋写死。不得让共享 8003 的拥塞拖死 OCR 主链。

验收：影子开关关闭时行为零 diff；开启时 HTTP 响应零 diff；8003 停止/超时/坏响应时 8765 仍按旧链返回；完成足量真实样本后输出调用率、差异和容量报告。

### S4：先切无模板/低风险路径

目标：让当前必拒或 generic-review 的路径先受益，不动已稳定模板的自动导入结果。

1. 路由和 `page_type` 继续由现有 record/machine/classifier/template fingerprint 体系提供。
2. 无模板页面按“确定性 generic → 文本 VLM → 原拒识”运行；VLM 辅助结果初期强制 `review`，不得直接 `ok`。
3. 模板已稳定页面继续旧链，同时运行新链对照；发现任何已验收路径回归立即关闭开关。
4. 按页面/profile 分批启用，不做全局一次性切换。

验收：全量旧路径零错误放行；新增可用 review 数量和人工采纳率有数据；关闭开关可立即回到旧行为，无数据迁移和回滚脚本。

### S5：OCR 通用链升主、模板降兜底

前置条件：S3/S4 在固定 holdout 和真实影子数据上同时通过，且用户确认切换。

最终顺序调整为：确定性 generic → 歧义文本 VLM → 模板/专用旁车兜底。切换仍按 page/profile 逐个进行；只有已有契约门禁通过的确定性路径可返回 `ok`，VLM 参与的 profile 是否可自动导入须单独有 holdout 证据。

本切片只降级模板职责，不删除模板代码。记录每个模板的兜底命中次数、成功率和不可替代职责，为未来删除提供证据。

### S6：容量验证与独立扩容决策

目标：回答“多人同时填报是否够用”，但不把并发改造混进识别正确性切换。

1. 对三类请求分别压测：纯 OCR 直出、OCR + 文本 VLM、模板兜底；报告吞吐、429、p50/p95 和 GPU/8003 占用。
2. 把飞书 Bot 对 8003 的共享负载纳入测试窗口；Reader 不得假设独占模型。
3. 先用降低 VLM 调用率、短超时和限流解决；只有数据证明 `8765` 单并发是主瓶颈，再另立容量变更计划选择排队、多实例或并发模型。

本 PLAN 不预先实现队列或多 Worker，因为 PaddleOCR GPU 单例、临时文件和共享 8003 的安全并发上限尚无数据。

## 5. 总体验收与停止规则

### 必过门禁

- 公共入口仍为 `8765/api/v1/recognize`，现有响应键保持兼容；Web 无需改调用地址。
- 任何 VLM 辅助值都可回溯到 OCR token，模型生成数值严格为 0。
- numeric accuracy ≥ 0.95；error auto-import rate = 0；负样本 rejection accuracy = 1（空分母按既有 N/A 口径，不冒充通过）。
- 段序、启用段数、数组长度单独验收；不能用总体字段准确率掩盖结构错位。
- 8003 异常不造成 8765 500、不覆盖模板结果、不延长纯 OCR 明确路径。
- `HMI_VLM_MODEL` 的运行值和报告值均为 `Qwen3.8-27B-AWQ-INT4`。
- 全程不访问、不配置、不停止、不重启 `8000`。

### 立即停止并报告

- GitNexus impact 为 HIGH/CRITICAL 且用户尚未确认。
- 发现新链产生非 OCR 来源数值、错误自动导入或数组静默错位。
- 8003 共享负载使飞书 Bot 或 Reader 出现明显退化。
- 需要改 Web 契约、生产配置、服务状态、数据回填或扩大授权范围。
- 为通过单张图而准备新增机台专用规则；该样本应进入失败分类，而不是继续补丁。
