# 073 OCR 证据混合链落地计划

## 决策

068 的 S2 把整页字段重新交给 VLM，并把一个非法映射升级成整页失败，实际全量门禁因此停在原地。本计划取代该阶段顺序，固定为：

```text
主 OCR + 现有旁车 OCR
        -> 统一 token / 行证据
        -> 确定性 generic 保留明确字段
        -> 现有模板/专用提取器只补剩余字段
        -> VLM 只处理仍 unresolved 的字段和相关 token
        -> 本地逐字段校验、字段级合并
        -> ok / review / reject
```

模板不匹配只表示布局未知，不直接判异常。`reject` 只用于 OCR/图像不可用或关键字段硬冲突；部分证据和歧义进入 `review`。

## 切片

### S0：修正离线混合编排

- 保留 `extract_generic` 已解决字段和 token mappings。
- 仅从 `detail.unresolved` 选 catalog 合法字段，并裁出相关 token/行交给文本 VLM；无 unresolved 时不调用 8003。
- VLM 返回逐 mapping 校验；某项非法只拒绝该项，已解决字段和其他合法项不清空。
- 合并时禁止 VLM 覆盖确定性字段，报告 deterministic / VLM / unresolved 各自贡献。
- 只改 LOW 风险离线链及最小测试，不改 `extract_one`、`hmi_service.py` 或服务状态。

验收：已有字段不被覆盖；请求不含已解决字段和无关 token；单字段非法仍保留合法字段；8003 失败仍输出确定性结果。

### S1：补齐证据候选并重跑 89 例

- 复用现有 CLAHE、zoom、cell、stage、rate、moire、delay、setrow、hot-runner、mold-temp 旁车，不新增 OCR 引擎。
- 让 evidence 层把“识别到标签但不能确定值”的 catalog 字段稳定写入 unresolved；不为单图增加机台专用规则。
- 跑固定 89 例和负样本，分别报告确定性、模板、VLM 的新增正确字段、错误字段、调用率和延迟。

验收：非 OCR 来源数值为 0；numeric accuracy >= 0.95；error auto-import rate = 0；rejection accuracy = 1；数组段序和长度单独通过。

### S2：8765 影子接线

- 在修改 `extract_one` / `run_attempt` 前重新执行 upstream impact；HIGH/CRITICAL 先向用户报告。
- 默认关闭，仅对最终 unresolved 调 8003；HTTP 响应和现有模板结果保持不变。
- 8003 超时、坏 JSON、非法引用时立即降级，记录差异但不影响 8765 返回。

验收：开关关闭与当前生产零 diff；开启仍响应零 diff；8003 故障不产生 500。

### S3：按页面小范围切换

- 先切当前必拒或 generic-review 的低风险路径，VLM 参与结果初期固定 `review`。
- 稳定模板路径继续对照；只有 holdout 门禁通过且用户确认后，才允许按 profile 切主。

## 停止条件

- 出现非 OCR 来源数值、确定性字段被覆盖、数组静默错位或错误自动导入。
- 需要改公共契约、生产配置、服务状态或访问 8000。
- 代码目标 impact 为 HIGH/CRITICAL 且尚未向用户报告风险。
