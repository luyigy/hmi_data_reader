# 109_HANDOVER_20260717_Agy本地集成

## 任务类型
feature / test

## 所属主线
支线任务：本地 harness 扩展

## 为什么做
本机已从 Gemini CLI 迁移到 Antigravity CLI，需要让 Agent Platform 将已安装的 `agy` 作为 platform-local harness 发现、展示和执行。

## 修改内容
- 新增 Antigravity agent runner 和 harness adapter，通过 `agy -p <prompt>` 执行一次性任务并转发 stdout/stderr。
- 普通权限配置映射到 `--sandbox`；full access 映射到 `--dangerously-skip-permissions`。
- 新建 ACPX 任务表单增加 Safe Local / Dev Local / Full Access 选择，并在创建任务时写入现有 `acpxPermissionConfig`，避免 Antigravity 首次 headless run 固定落到 Safe Local。
- 接入 harness registry、本地 agent 初始化、ACPX catalog、进程存活识别、Feishu 状态和旧版 local-agent executor。
- 注册 API 改用共享 harness availability registry，避免重复且 PATH 不一致的 shell 检查。
- 增加 `ANTIGRAVITY_CLI_PATH` 可选配置、README 说明和最小参数测试。

## 验证结果
- `agy --version`：通过，版本 `1.1.3`。
- 参数测试：通过，确认 safe/full-access 分别生成 `-p ... --sandbox` 和 `-p ... --dangerously-skip-permissions`。
- 真实 sandbox smoke test：通过，输出 `AGY_SANDBOX_OK`。
- 真实 full-access smoke test：通过，输出 `AGY_FULL_ACCESS_OK`。
- `npx --offline tsc --noEmit --pretty false`：通过。
- 相关文件 targeted lint：通过。
- `git diff --check`：通过。
- ACPX 权限表单：`npx --offline tsc --noEmit --pretty false` 通过，目标组件 lint 通过。

## 对主线的影响
Antigravity CLI 现在可作为本机 agent 被平台发现并执行。Gemini CLI adapter 保留，未影响仍安装 Gemini CLI 的其他环境。

## 下一步建议
当前只支持一次性 print execution。`agy` 能使用 `--continue` 和 `--conversation`，但 print 输出没有提供可靠的 conversation ID；需要先确定并发房间安全的会话 ID 获取方式，再接入 continuation。

### Live Room 按成员权限计划

当前 Live Room 只从 source task 读取一份共享权限，Web 成员卡片只能显示，飞书授权也没有统一持久化为成员配置。按以下最小闭环实施：

1. 在 `LiveRoomMember` 保存可空的成员权限配置；旧成员为空时继续继承 source task，避免破坏现有 workspace。
2. 提供共享的成员权限解析/更新入口，Web API 与飞书授权复用同一套校验和持久化。
3. Web workspace 创建时可为每个 agent 选择权限；创建后可在成员卡片修改，变更只影响该成员下一次 run / continuation。
4. Live Room delivery 启动成员时优先使用成员权限，未设置则回退 source task 权限。
5. 飞书 `/ap grant` 同步写入目标成员权限，并继续沿用现有 continuation 行为。
6. 增加最小解析测试，执行 Prisma generate、TypeScript、targeted lint 和 diff check。
