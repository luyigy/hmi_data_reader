## 任务类型
feature / test

## 所属主线

## 为什么做
本机已从 Gemini CLI 迁移到 Antigravity CLI，需要让 Agent Platform 将已安装的 `agy` 作为 platform-local harness 发现、展示和执行。

## 修改内容
- 新增 Antigravity agent runner 和 harness adapter，通过 `agy -p <prompt>` 执行一次性任务并转发 stdout/stderr。
- 普通权限配置映射到 `--sandbox`；full access 映射到 `--dangerously-skip-permissions`。
- 新建 ACPX 任务表单增加 Safe Local / Dev Local / Full Access 选择，并在创建任务时写入现有 `acpxPermissionConfig`，避免 Antigravity 首次 headless run 固定落到 Safe Local。
- 接入 harness registry、本地 agent 初始化、ACPX catalog、进程存活识别、Feishu 状态和旧版 local-agent executor。
- 注册 API 改用共享 harness availability registry，避免重复且 PATH 不一致的 shell 检查。
- 增加 `ANTIGRAVITY_CLI_PATH` 可选配置、README 说明和最小参数测试。

### Live Room 按成员权限计划

当前 Live Room 只从 source task 读取一份共享权限，Web 成员卡片只能显示，飞书授权也没有统一持久化为成员配置。按以下最小闭环实施：

1. [完成] 在 `LiveRoomMember` 保存可空的成员权限配置；旧成员为空时继续继承 source task，避免破坏现有 workspace。
2. [完成] 提供共享的成员权限解析/更新入口，Web API 与飞书授权复用同一套校验和持久化。
3. [完成] Web workspace 创建时可为每个 agent 选择权限；创建后可在成员卡片修改，变更只影响该成员下一次 run / continuation。
4. [完成] Live Room delivery 启动成员时优先使用成员权限，未设置则回退 source task 权限。
5. [完成] 飞书 `/ap grant` 同步写入目标成员权限，并继续沿用现有 continuation 行为。
6. [完成] 增加最小解析测试，执行 Prisma generate、TypeScript、targeted lint 和 diff check。

### Live Room 定向与 mode 调度修复

- 修复 workspace 后台刷新可能清空 composer 目标成员的问题；后台刷新现在保留 dropdown 和 mention 状态。
- Web dropdown 定向消息写入 `targetLocked`，delivery 不再回退到 current speaker。
- 新增独立 `live-room-scheduling.ts`，避免继续扩展已超过 1000 行的 delivery 文件。
- `discussion`：显式目标优先；无目标时仅 current speaker 回复。
- `execution`：无显式目标时按 `planner → researcher → implementer → reviewer → tester → custom` 顺序执行。
- `hybrid`：普通消息沿用 discussion；以 `/run` 开头的消息启动角色队列。
- role queue 禁用 agent 回复产生的额外链式触发，避免重复执行和抢话。
- Workspace 设置页补充三种 mode 的真实行为说明。

### Feishu mode 控制

- `/ap room --agents=... --mode=discussion|execution|hybrid` 在创建或复用绑定房间时设置 mode。
- `/ap mode discussion|execution|hybrid` 修改当前 Feishu 会话绑定的 Live Room。
- 命令回执会说明实际模式行为；Web 与 Feishu 随后共用同一 delivery scheduler。
- Feishu 帮助文本已加入两个入口；非法 mode 不写库并返回可选值。
