## 为什么做

## 关键发现（决定项目规模的根因）

### 归类状态：真实 UI 家族数量尚未定型

当前 15 个附件中已观察到 **TACT、FANUC ROBOSHOT、ZizES、TRD6/SPT** 四类 UI，但这不等于“5 个品牌固定对应 4 套模板”。文件哈希复核发现 3 组附件完全重复，其中两组跨“伯乐/日精”记录复用。因此，品牌与 UI 家族的对应关系以及最终模板数量均须在替换错挂/重复样本后重新评估。

| 飞书记录品牌（不作为真值） | 图片中观察到的 UI | 当前状态 |
|---|---|---|
| 伯乐 | TACT | 样本可用，但仅能证明这些图片是 TACT |
| 日精 | FANUC + 两张与伯乐完全相同的 TACT 图片 | 存在错挂/重复，不能归类为 TACT |
| 发那科 | FANUC ROBOSHOT | t1 与 t3 完全重复，页面覆盖不完整 |
| 佳明 | ZizES | 三张独立样本，当前质量最好 |
| 沙迪克 | TRD6 + SPT | 三张独立样本，但图片质量较差 |

**当前可靠结论**：
- 路由必须依据图片像素识别 UI 家族，不能依据品牌、机台类型或附件字段名。
- 模板按 `UI家族.页面` 组织，例如 `TACT.temperature`，禁止按品牌组织。
- 沙迪克/TRD6 样本屏幕小、发白且小字难辨，应先触发质量报警并要求重拍，不勉强抽取数字。
- 完整证据、逐图真值表和质量门禁见 `docs/002_RESEARCH_20260725_HMI图片真值与质量门禁.md`。

### 数据陷阱：飞书附件字段命名 vs 实际屏内容不一致

用户/填报人员把图片填到飞书字段时，**「成型条件-炮筒温度设定」字段里实际塞的是"射出·计量"Tab 的照片**——这在以下 3 台机台确认：

| 字段 | 飞书记录的"含义" | 下载到的实际 Tab |
|---|---|---|
| 成型条件-炮筒温度设定（伯乐 Z001 t1）| 温度 | ✅ **温度**（6 段温度） |
| 成型条件-炮筒温度设定（日精 Z022 t1）| 温度 | ❓ 待 OCR 验证，文件名只看了 t2 |
| 成型条件-炮筒温度设定（发那科 Z036 t1）| 温度 | ❌ **射出·计量**（条件：TX22049A） |
| 成型条件-射出/保压（发那科 Z036 t2）| 射出 | ❓ 待 OCR 验证 |
| 成型条件-射出/保压（伯乐 Z001 t2）| 射出 | ✅ **射出·计量** |
| 成型条件-射出/保压（日精 Z022 t2）| 射出 | ✅ **射出·计量**（日精也是 TACT）|

**含义**：**OCR 不能信任飞书字段名**，必须先 **"识别当前 Tab 标题/内容"** 来决定走哪个解析模板。否则会把"射出·计量"的照片当成"温度"页解析，全部数据错位。

## 验证结果

### 已下载样本（15 张 = 5 品牌 × 3 张）

路径：`/data1/code/hmi_data_reader/docs/samples/`

| 品牌 | 机台 | 文件名 |
|---|---|---|
| 伯乐 | Z001 | `boletuo_Z001_t1_炮筒.jpeg` 等 3 张 |
| 日精 | Z022 | `rijing_Z022_t1_炮筒.jpeg` 等 3 张 |
| 发那科 | Z036 | `fanake_Z036_t1_炮筒.jpeg` 等 3 张 |
| 佳明 | Z052 | `jiaming_Z052_t1_炮筒.jpeg` 等 3 张 |
| 沙迪克 | Z020 | `shadike_Z020_t1_炮筒.jpeg` 等 3 张 |

### Vision 人工识别结论（每张图都过了一遍 vision_analyze）

- **TACT（伯乐/日精）**：温度 Tab = 6 段温度 × 4 行（设定/现在/控制%/保温），数字字体清晰
- **FANUC ROBOSHOT**：彩色 UI，"温度" Tab 命名带"·计量"后缀，9 个加热器命名特殊（M1-M4+N+B1-B3+H）
- **ZizES（佳明）**：Tab 是"监视/温度/设定/预热/曲线/返回"，温度 7 段+油温
- **TRD6+SPT（沙迪克）**：屏幕占图 ~30%，物理按键包围，**屏外干扰最大的品牌**

### 待 OCR 验证（不能光靠 vision）

1. **沙迪克** 屏小且反光，**实际能不能稳定 OCR** 是个未知数 → 必须装环境跑实测
2. **伯乐拍摄角度歪斜**（~10° 透视），OCR 模型对透视畸变的鲁棒性需要验证
3. **15 张样本是否覆盖每个品牌的全 Tab** —— 可能还有其他 Tab 没采到

### 关键上下文（给下一个 agent）

- **飞书拉附件流程**：`lark-cli base +field-list` 拿 attachment 字段 ID → `+record-list --format json --sort-json` 拿 `record_id_list` + 行数据 → `cd <目录> && +record-download-attachment --file-token ... --output ./ --overwrite` 下载。**必须 `--output ./` 相对路径**，绝对路径会被 CLI 拒绝。
- **Vision 看图限制**：每次 vision_analyze 自动截断上下文，所以一次性看太多图会丢后续分析结果。这次 9 张图后被截断了日精/发那科/佳明/沙迪克的 t2/t3 详情。**下一轮每张图单独 vision_analyze**，不要批量发。
- **字段值陷阱**：飞书记录的"成型条件-炮筒温度设定"字段里**实际可能是"射出·计量"Tab 照片**，OCR 必须先识别 Tab 内容。
- **数据规模**：最近 100 条记录里"工艺参数图片"全空，"成型条件-模温机行位"只 4 条有值，"成型条件-热流道温控箱温度"只 19 条。**真正能用的字段主要是"炮筒温度设定""射出/保压""储料/冷却""成型监控一/二""波形图"**，每天每台约 3-5 张。
