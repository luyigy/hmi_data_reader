## 实现

- `acpx/room-admission.ts`：仅当双方都有可信普通聊天室绑定、且都在本机时，
  不再因基础工作目录或权限 writableRoots 重叠而互斥。保留同一 member 防重入、
  同一原生 Session 防重入、可信绑定及权限验证。
- 保留普通会话与非普通/Graph 运行之间的目录重叠检查，保留
  `assertWorkspaceWriterAvailable()` 对 Graph claim / 未释放 Writer 的保护。
  普通会话先启动与 Graph 先占用两个方向都检查，未整体删除 overlap。
- 已批准补充资源的 writableRoots 继续独占；兼容 Run 和 Participant 两处元数据。
  后续资源准入与实际进程退出证明逻辑不变。远端主机的保守互斥策略不变。
- `live-room-delivery-execution.ts`：启动前抛错只清理进度，不提前发布泛化失败终态；
  真实错误交给外层 Delivery 现有错误处理。已有 TaskRun 结果仍负责正常完成、失败、停止终态。
  清理范围包含进度对象创建之后的权限、Session 与 Task 准备步骤；清理异常不覆盖原始异常。
- `feishu-progress.ts` 增加只停止更新的 `stop()`；普通输出与 Antigravity 结构化输出均支持
  不终结卡片的 dispose，清理心跳、待发进度和延迟更新。
  `feishu-turn-card.ts` 的 terminal 保护和外层 processing 错误处理均无需修改。

允许共享基础工作区是协作准入政策，并非文件系统隔离；需要隔离的任务继续使用 Worktree。
未修改 Agent 身份、原生 Session 续接、数据库结构、历史会话或生产任务记录。

## 验证

先在旧代码上取得两项红灯：

- `local-room-concurrency`：相同工作区第二个普通会话收到 Workspace write conflict。
- `room-startup-card`：持久化卡片丢失实际原因，只有泛化执行失败。

使用一次性 PostgreSQL 和真实 Bubblewrap；并发测试通过独立 Node 进程执行实际
Delivery / Runner / 数据库准入事务。仅模型适配器和飞书传输使用 fixture，不发送生产消息。

通过的回归：

- `local-room-concurrency`：同一 Codex 跨房间、同目录、父子目录、符号链接、权限附加目录并发；
  独立完成与原生续聊；Graph 前后两种启动顺序的保护；旧元数据补充资源仍互斥。
  其中普通会话先启动的反向 Graph 检查直接调用持锁准入 API，未启动真实 Graph 模型。
- `room-member-admission`：同房间 Kimi 与 Codex 可写协作；同成员/同原生 Session 仍拦截，
  请求防重、可信绑定、重试与其他成员运行状态保持。
- `room-startup-card`：实际 Delivery 失败处理、持久化卡片和发送卡片保留真实错误，
  覆盖 Codex / Antigravity；stop 后延迟更新不会覆盖结果或提前发布终态。
- `graph-writer-scope`、`thin-room-entry`、`task-resource-writers`：Graph 归属、
  claim/live Writer、补充资源冲突及真实退出证明。
- `feishu-turn-card`：单卡持久化、重放及终态后禁止迟到覆盖。
- `tests/live-room-progress.test.ts`、`tests/live-room-raw-output.test.ts`：普通与结构化进度、
  正常结束、失败、发送异常和一轮一张卡。
- 全量 TypeScript 检查、改动 TS 文件定向 ESLint、长文件守卫、diff 空白检查。
  `room-member-admission.test.ts` 保留仓库原有测试 mock 写法，不做无关 lint 重构。
- 隔离数据库下 Next.js 完整构建通过，退出码 0。构建有 Browserslist 数据陈旧提醒，
  以及 harness-options 使用 request.headers 而转为动态路由的日志；该路由最终标记为动态且构建成功。
