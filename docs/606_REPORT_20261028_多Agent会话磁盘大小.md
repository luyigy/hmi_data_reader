# 多 Agent 会话磁盘大小

## 本次结果

在 `1727aa3`（603/604 已部署回执）上创建隔离分支 `feat/session-size-606`、工作区 `output/worktrees/session-size-606`。本次完成代码和自测，不更改当前服务工作区或运行中的原生会话。无数据库迁移。

脚注继续展示会话总字节数、本轮增量、采样时间，明确“磁盘历史，非上下文占用”。沿用现有 10 MiB 提醒、20 MiB 强提醒以及 AP_SESSION_SIZE_WARN_MIB / AP_SESSION_SIZE_STRONG_MIB 配置，不自动重置 Agent。

- Codex：原有 rollout JSONL 及 session_meta 身份验证不变，把周期/最终采样逻辑提取为公共模块，仍缓存已定位文件。
- Kimi Code：按原生 Session ID 唯一定位 sessions/<workspace>/session_<id>，统计该会话目录中的普通文件（包括主 Agent、子 Agent 的原生记录）。运行时绑定 session.resume_hint，失败也能完成最后采样。使用真实 runtimeHome 的 .kimi-code 路径，不统计整个用户配置目录。
- 本机 Pi：统计绑定的 --session-dir 内原生 JSONL；只读有合法 session header 的记录，其他日志不计入。目录必须位于配置的 PI_AGENT_SESSION_ROOT（默认 ~/.acpx/pi-agent-sessions）内。
- Antigravity CLI：按原生 conversation_id 统计 ~/.gemini/antigravity-cli/conversations/<id>.db 及存在的 -wal；验证 SQLite 文件头。不包含共享内存 -shm、brain 产物或整个 CLI home。
- 远端 Pi：新增已登记 Remote Runner 的完成帧 sessionSize 数据；Runner 在本机读取自己的原生记录，平台只接收数字，不按远端路径读本机文件。Remote Node WebSocket 仍按认证节点和 pending runId 绑定帧；平台生成 executionId，再用 CAS 同时绑定原生 Session 和采样，旧执行晚到不能改写新会话。采集失败不导致业务执行失败。

本机周期仍为 30 秒，并在退出时补采；远端 Runner 此版本在运行完成时回传总量和增量。旧 Runner 或纯 SSH（非 Remote Runner）通路没有新增采样，显示“未采集”，不会伪造零值。远端 WPI 需更新并重连对应 Runner 才会提供该字段；本次没有访问或替换远端机器上的安装。Gateway OpenClaw 的远端存储不在本次覆盖范围。

## 防误算与边界

新执行清除前一轮采样，读取脚注仍校验 participant、execution、原生 session 和时间。已存在但无法读取的 Pi 目录不是零基线；文件替换、截断、消失或 WAL checkpoint 会令本轮增量变为未知。Kimi 多个相同 ID 不猜测，拒绝越界路径和会话记录 symlink。采样使用 stat 和有界文件头，不读取不断增长的历史正文；会话目录遍历限制深度及条目数。大记录仍可统计，不因文件大于上下文分析上限而漏报。
