# 全机台工艺页面夜间自治计划

## 1. 目标与完成定义

本计划把现有逐家族、逐页面试验收敛为一个可恢复的夜间队列。调度最小单元固定为“控制器家族 × 页面类型”；不为单张异常图片创建机台专用模板，只有证据确认页面结构不同才增加变体。

计划完成必须同时满足：

1. `ground_truth/machine_labels.json` 中全部 53 台机台完成控制器家族和页面存在性盘点。
2. 每个已盘点的“家族 × 页面”单元只有四种终态：`PASS`、`SAFE_REJECT`、`NOT_APPLICABLE`、`BLOCKED_EXTERNAL`，不存在“等待用户裁决”或第五种状态。
3. 53 台覆盖审计报告中四类终态计数之和等于已盘点页面单元总数。
4. 每个终态可追溯到样本 SHA-256、真值来源、模板/代码版本、验证报告和提交哈希。
5. runner 能从 checkpoint 幂等恢复，不重复下载、预标注、验收或处理已终态单元，并能在窗口结束时产出日报。

本计划完成只代表离线提取能力矩阵收敛，不代表生产准入。

## 2. 全局队列与推进波次

业务优先级复用 027 ROADMAP，不再维护重复 Backlog：

1. 射出／保压：接受 038 的 DEMAG `SAFE_REJECT`，从 035 的下一未完成家族继续。
2. 炮筒温度：先补 B_AND_R、TACT、FANUC/DEMAG 泛化缺口，再覆盖 EST、TRD6、ARBURG 等剩余家族。
3. 储料／冷却。
4. 成型监控一／二。
5. 波形图。
6. 热流道温控。
7. 模温机前／后／行位。
8. 全机台一图覆盖审计与矩阵收口。

每个“家族 × 页面”单元按三波推进：

- 第一波：单机 6 图跑通页面结构。
- 第二波：同家族另外 2 台各 6 图验证泛化；家族不足 3 台时明确标记单机 PoC。
- 第三波：其余同家族机台每台抽 1 图做覆盖审计。

同一波最多一轮定向整改，禁止开放式调参。样本不足、附件不可访问或真值证据不足时写明 `BLOCKED_EXTERNAL`，继续处理不依赖该阻塞的其他单元。

## 3. 自动裁决

### 3.1 PASS

必须同时满足：

- controller 分类准确率 = 1.0；
- page 分类准确率 = 1.0；
- numeric_accuracy >= 0.95，数值匹配容差沿用 `scripts/verify_accuracy.py` 的已提交口径；
- error_auto_import_rate = 0；
- rejection_accuracy = 1.0；无负样本时只标 PoC，不宣称完整安全验收；
- 已冻结回归集零退化。

满足后冻结该单元并领取下一项。

### 3.2 SAFE_REJECT

未达到 PASS、但通过置 null/review 能保证 `error_auto_import_rate = 0` 时，保留已证实可靠字段，其余风险字段或整页拒识，记录 `SAFE_REJECT` 后继续队列。numeric_accuracy 不设人为下限；拒识造成的低完整率必须如实报告，不得伪装成 PASS。

若初次验证出现错误自动导入，只允许一轮有明确根因、影响范围可验证的定向修复。复验仍有错误时，风险字段或整页必须拒识，直至错误自动导入率归零；不能安全归零则记 `BLOCKED_EXTERNAL`，不得让风险值进入 ok。

### 3.3 NOT_APPLICABLE 与 BLOCKED_EXTERNAL

- `NOT_APPLICABLE`：有可审计证据证明该机台或家族不存在对应页面。
- `BLOCKED_EXTERNAL`：缺附件、缺权限、基础设施持续失败、真值不可判或工作区冲突；必须记录恢复条件，不等待用户逐项裁决，且不阻塞独立单元。

只有安全风险影响全局、权威输入未提交、工作区写冲突、生产写入边界或数据完整性无法保证时，runner 才停止全局任务。

## 4. 夜间执行契约

- 时区与窗口：Asia/Shanghai，每日 23:00 启动，06:30 停止领取新切片；在跑切片最多宽限到 07:00，随后安全 checkpoint 并退出。
- 首个通过 S1–S3 门禁的运行夜最多执行 3 个切片；日报正常且无重复派发、锁冲突或 checkpoint 损坏后，下一夜自动取消该配额。
- 单写：仓库级 `flock` 只允许一个写任务。下载、OCR、VLM 可作为可恢复后台批次运行，但同一输出键不得并发写。
- 幂等：去重键优先使用输入内容 SHA-256；checkpoint 原子替换，包含单元、波次、状态、输入哈希、开始/结束时间、心跳、产物路径和提交哈希。
- 超时：单切片墙钟上限 60 分钟，10 分钟无 progress 心跳视为卡死；合法长任务必须拆为可 checkpoint 的小批，禁止靠延长无限等待解决。
- 基础设施失败：最多重试 2 次，随后记 `BLOCKED_EXTERNAL` 并继续独立单元。
- Git：自动化只读取已提交权威内容；每个完成切片形成边界清楚的本地提交，禁止 `git add -A`。本地分支领先远端不构成阻塞；不自动 push、merge、rebase、reset 或强推。
- 日报：每夜记录完成项、四类终态计数、失败与恢复条件、回归结果、提交哈希、下一夜队首；队列为空时幂等退出。

## 5. 实施切片

### S1：P0 状态对账与可追溯基线

按 workflow prompt 完成 027、035、038、checkpoint 和 Git 状态对账；统一 53 台口径，接受 038 `SAFE_REJECT`，消除重复派发，并把后续自动化输入固化为提交。

停止条件：下一切片所需权威输入已提交，且工作区不存在与 S2 重叠的未提交改动。

### S2：最小 runner 与状态模型

新增一个标准库 runner，复用 027 队列和 workflow contract，不建立数据库、服务或重复配置层。只实现：启动门禁、队列领取、四态裁决、单写锁、子进程/心跳监控、原子 checkpoint、重试和日报。

停止条件：只读 `--dry-run` 能确定唯一下一单元，重复运行结果一致且不写业务产物。

### S3：定时环境演练与启用

使用与定时任务完全相同的工作目录、解释器和环境做 dry-run；验证 PATH、虚拟环境、锁、窗口边界、信号退出和日报。通过后安装每日 23:00 的本机定时触发，首夜保留 3 切片配额。

停止条件：定时入口可审计，dry-run 不修改业务产物；未通过时不得开启真跑。

### S4：射出／保压线收敛

从 035 的下一未完成家族继续，按三波规则推进；038 DEMAG 段表维持整体拒识，不再投入段格 CV，除非未来出现新的高质量证据并另立整改计划。

停止条件：所有已盘点射出／保压单元取得四态终态，且既有 Z022 PASS 和 DEMAG 安全态零退化。

### S5：炮筒温度线收敛

先完成已存在候选和泛化缺口，再覆盖剩余家族；复用已有温度页脚本、模板、真值和验证口径，不重造链路。

停止条件：所有已盘点炮筒温度单元取得四态终态，既有家族回归零退化。

### S6：其余页面线矩阵化推进

依次处理储料／冷却、成型监控一／二、波形图、热流道温控、模温机页面。页面结构确证同构时复用实现；确证不同才增加最小变体。

停止条件：每个已盘点单元取得四态终态，无待用户裁决项。

### S7：53 台覆盖审计与计划收口

对全部机台和页面矩阵做一图覆盖审计，核对终态计数、证据链、回归和未解外部阻塞；生成最终 REPORT 与 HANDOVER，将本 PLAN 更新为 completed/none 并移除 workflow prompt。

停止条件：四态计数闭合，所有终态可追溯；`BLOCKED_EXTERNAL` 可保留，但必须有恢复条件且不被误报为完成能力。

## 6. 风险与控制

| 风险 | 控制 |
|---|---|
| 现有未提交产物与 035/038 状态失配导致重复执行 | S1 先对账；只消费提交；PLAN/HANDOVER/checkpoint 一致性作为启动门禁 |
| 自动裁决把错值放入 ok | `error_auto_import_rate = 0` 为不可降级红线；一轮修复后强制字段或整页拒识 |
| 回归破坏既有家族 | 每个变更前后运行冻结回归集；非零 diff 不进入 PASS |
| 夜间任务死锁或无限调参 | 单写锁、60 分钟墙钟、10 分钟心跳、最多一轮定向整改、两次基础设施重试 |
| cron 环境与交互环境不同 | S3 用同一工作目录和解释器 dry-run 后才启用 |
| checkpoint 损坏或重复领取 | 原子替换、输入哈希、终态幂等、启动时交叉校验提交哈希 |
| 自动真值污染验收 | VLM 仅生成草稿；自动接受必须标注降级证据层，不用于生产级准确率宣称 |
| 页面矩阵规模膨胀 | 以家族×页面为单元，三波固定取样；仅确证结构不同才新增变体 |

## 7. 验证

S2–S3 至少验证：

1. `--dry-run` 连续两次选择相同唯一单元，且业务目录零 diff。
2. 第二 runner 无法取得锁并安全退出。
3. 模拟成功、`SAFE_REJECT`、`NOT_APPLICABLE`、两次基础设施失败和无心跳超时，均写出正确终态或恢复状态。
4. 中断后从最后一个完整 checkpoint 恢复，不重复已完成动作。
5. 06:30 停领、07:00 强制 checkpoint、空队列退出和日报计数闭合。

业务切片至少验证：分类双 1.0、numeric_accuracy、error_auto_import_rate、rejection_accuracy、自动导入完整率、既有回归 diff，并保留实际命令和报告路径。无负样本、自动接受真值或单机 PoC 必须在结论中明确降级，不得扩大宣称。

## 8. 待确认项与默认裁决

本计划不把以下事项退回用户逐项裁决，按默认值执行并保留事后修订能力：

| 事项 | 默认裁决 |
|---|---|
| 机台总数 | 读取 `machine_labels.json`，当前为 53，不复制维护常量 |
| 队列权威来源 | 027 §4 管业务优先级，本 PLAN 管自治规则；checkpoint 只记状态 |
| runner 形态 | 一个标准库脚本 + 本机定时触发，不引入新服务或依赖 |
| 038 DEMAG | `SAFE_REJECT` 收口，stage 整体 null/review，停止继续攻段格 CV |
| 普通验收 FAIL | 最多一轮根因明确的整改；仍失败则安全拒识并继续队列 |
| 首次真跑 | S1–S3 全部通过后的下一个 23:00，限 3 切片；不绑定已经错过的日期 |
| 远端同步 | 本地提交用于可追溯；不自动 push，ahead 数不阻塞本地 runner |

任何未来变更若涉及生产真实写入、数据删除覆盖、服务重启或远端发布，仍需新的明确授权，不能由本计划推导。
