# ZizES 温度页扩样盲测验证计划

## 1. 背景与目标

008 HANDOVER 已确认 007 的端到端 PoC 在 5 张、3 台机台上通过六项指标，但这 5 张图片参与过模板 0.2.0 校准，只能证明链路可运行，不能证明对新机台、新日期、报警态或低质量图片的泛化能力。

本计划只验证 ZizES 温度页冻结基线。验收样本必须是未用于模板、分类器、矫正或阈值调整的全新 holdout；原 5 张作为 legacy 回归集单列，不进入扩样门槛分母。无论结果如何，本计划都不允许生产真实自动入库。

## 2. 范围与硬约束

### 2.1 包含

- 从飞书大表佳明 394 条记录中盘点并筛选 ZizES 温度页候选。
- 目标建立不少于 20 张 SHA-256 去重图片、覆盖至少 5 台机台的 holdout。
- 覆盖不同日期、正常态、报警态和图片质量；单机台目标占比不超过 30%。
- 沿用“VLM 预标注草稿 + 人工逐字段核验”；VLM 不进入被测提取链路。
- 冻结现有 OCR、模板、分类、矫正、提取和校验链路，盲测只运行一次。
- 输出总体、机台、状态和质量分组结果以及明确决策。

### 2.2 不包含

- 其他 HMI 家族模板、residual unknown 治理或设备厂商正名。
- 根据 holdout 结果直接修代码、调模板、调阈值或补规则。
- 飞书自动回填、生产自动入库、服务重启或共享环境变更。
- 将 20 张零错误解释为生产可靠性证明。

### 2.3 先选后拉

S1 只能读取大表记录字段、附件元数据及已有本地证据。候选清单必须经用户明确批准，S2 才能下载所选附件；禁止批量下载 394 条记录的附件。批准同时覆盖候选范围，不代表允许降低样本门槛、修改基线或启动生产写入。

## 3. 盲测定义与数据隔离

盲测同时满足三层约束：

1. **数据独立**：holdout 图片从未参与 007 模板校准，也未被任何后续会话用于调参；legacy 5 张只做回归。
2. **链路冻结**：S1 固化 commit、模板、OCR 和关键脚本哈希；S3 前校验无漂移。
3. **口径预注册**：样本门槛、指标公式、报警态定义、停止规则和分组口径在 S1/S2 定稿后锁定，看到 S3 结果后不得修改。

任一层失守，当前盲测结论作废。若需要整改，必须另划校准集、另立后续 PLAN；当前 holdout 不得再次作为验收集。

## 4. 方案与薄切片

### S1：扩样池盘点、冻结快照与候选清单

**输入**：飞书大表 `tbl5KKYuANqGpycE` 的佳明记录、仓库已有 OCR/图片证据、当前 HEAD。

**工作**：

1. 只读盘点记录和附件元数据，按已有可见证据预筛 `ZIZES / KAIMING / UNKNOWN`。大表没有可靠 record 级家族标签，禁止直接把佳明等同于 ZIZES。
2. 输出 `output/expansion_pool_inventory.json`，列出记录、机台、日期、状态、质量及重复证据；内容去重只能在有文件字节后用 SHA-256 确认。
3. 输出 `output/baseline_snapshot.json`，记录 commit、版本和关键文件 SHA-256。
4. 以固定 seed 分层排列至多 30 条候选，输出 `output/zizes_expansion_candidates.json`；目标 20 条，其余为按序候补。
5. 提交候选清单给用户批准。若 ZIZES 证据池少于 20 张、少于 5 台或无报警态，S1 直接停止，由用户决定是否降级、补采或终止。

**停止条件**：三份产物和 S1 HANDOVER 可审计；等待用户批准。不得下载附件或启动 S2。

### S2：获批样本下载与独立真值生产

**前置条件**：用户批准 S1 候选清单及任何门槛调整，且确认核验人窗口。

**工作**：

1. 只下载获批候选，计算 SHA-256；重复、非 ZIZES、非温度页或无法建立真值的图片按 S1 固定顺序用候补替换，不临时人工挑图。
2. 将原 5 张标为 legacy；全新图片标为 holdout。任何曾用于调参的图片不得进入 holdout。
3. 对 holdout 做 VLM 草稿和人工逐字段核验，记录草稿字段数、改动数、人工新增数、核验人、时间和来源。
4. 预注册报警态：满足数值越限标红、可见报警字符/图标或屏幕报警条任一项即为报警态；歧义项进入人工裁定，不由提取结果反推标签。
5. 若任一草稿字段被修改，恢复至少 30% 数值字段的第二人独立抽检；第二人默认使用不共享草稿的独立 Agent 会话，用户指定业务人员时改为外部阻塞。发现系统性误读则整批退回重核。

**停止条件**：达到用户批准的样本结构；holdout 100% 完成人工逐字段核验，必要抽检通过；样本清单、真值和预注册口径锁定。不得修改冻结基线。

### S3：冻结基线一次性盲测

**前置条件**：S2 真值锁定，且 `baseline_snapshot.json` 哈希复核无漂移。

**工作**：

1. 使用冻结的 OCR + 模板链路对 holdout 运行一次。
2. legacy 5 张单列回归，不计入门槛分母。
3. 输出总体指标，并按机台、状态、质量分组；机台组 `n >= 3` 才报告准确率，否则只列样本数和混淆项。
4. 同时报告 `status=ok` 的图片数、字段数、review/reject 数，防止 reject-all 形成假零错误。
5. 计算错误率的单侧 95% 精确置信上界。若 20 张图片零错误，图片级上界约为 `1 - 0.05^(1/20) = 13.9%`；该结果不得表述为已具备生产统计意义。

**停止条件**：报告完整并按预注册规则给出 PASS/FAIL；不得针对结果 hotfix 或重跑调参版。

### S4：决策与交接

按 S3 结果只允许三种结论：

- **保持冻结基线**：全部门槛通过，但仍不开放生产自动入库。
- **另立整改计划**：门槛未通过或需调参；另建校准集和新 PLAN，当前 holdout 作废为后续验收集。
- **停止该路线**：数据池不可行、安全门槛失败或收益不足。

S4 只形成决策和 HANDOVER，不实施整改。

## 5. 验证与验收

### 5.1 样本门槛

| 项目 | 目标 |
|---|---:|
| holdout 内容去重图片 | ≥ 20 |
| holdout 机台覆盖 | ≥ 5 |
| 单机台占比 | ≤ 30% |
| 真值人工逐字段核验完成率 | 100% |
| 报警态 | 尽池覆盖；若为 0，必须在 S1 由用户裁定，不得自行降级 |

若池规模无法达到目标，S1 停止并报告真实分布。任何降级必须写入批准记录，且 S4 结论同步降低，不得沿用“20 张、5 台”的统计表述。

### 5.2 指标公式与门槛

| 指标 | 公式 | 门槛 |
|---|---|---:|
| 控制器分类准确率 | 正确控制器图片数 / holdout 图片数 | ≥ 95% |
| 页面分类准确率 | 正确温度页图片数 / holdout 图片数 | ≥ 95% |
| 字段完整率 | 已提取真值非空字段数 / 真值非空字段数 | ≥ 95% |
| 数值准确率 | 误差在 ±0.5 内的数值字段数 / 真值非空数值字段数 | ≥ 95% |
| 错误自动入库率 | 误识别但 `status=ok` 的字段数 / `status=ok` 字段数 | 严格 = 0 |
| 正常样本自动放行率 | 正常态且 `status=ok` 图片数 / 正常态图片数 | ≥ 80% |
| 报警态错误放行 | 报警态但 `status=ok` 图片数 | 严格 = 0 |

当 `status=ok` 字段数为 0 时，错误自动入库率不得记为 0 或 PASS；整体门槛判 FAIL。所有指标同时报告图片分母与字段分母。

### 5.3 预注册硬停止规则

S3 出现以下任一项即停止并判 FAIL：

- holdout 中至少 1 个误识别字段仍为 `status=ok`。
- 至少 1 张报警态图片被 `status=ok` 放行。
- 任一机台子组在 `n >= 3` 时数值准确率低于 80%。
- 正常态与报警态子组准确率相差超过 15 个百分点。
- 冻结快照漂移、holdout 被用于调参或验收口径在看结果后改变。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 佳明记录混有 KAIMING 或未知家族 | S1 先做有证据的家族预筛；UNKNOWN 单列，禁止按品牌猜测 |
| 20 张、5 台或报警态在真实池中不可达 | S1 先盘点并停止，由用户决定补采、降级或终止 |
| 相似附件使有效样本量虚高 | S2 下载获批样本后以内容 SHA-256 去重，候补按固定顺序顺延 |
| 挑选清晰图造成选择偏差 | 固定 seed、分层和候补顺序；保留质量分布与排除原因 |
| legacy 校准样本污染验收 | legacy 与 holdout 分栏，门槛只使用 holdout |
| 盲测结果诱发边测边调 | 基线哈希冻结；失败后另立校准集和新 PLAN |
| review/reject 过多制造假零错 | 错误率与正常样本自动放行率绑定，并强制报告 `status=ok` 分母 |
| VLM 草稿锚定人工判断 | 逐字段核验、记录 draft diff；发生修改即恢复 30% 独立抽检 |
| 核验工作量约为 007 的四倍 | S2 前确认核验人窗口；未确认则停在 S1 完成态 |
| 小样本被误解为生产可靠 | 报告精确置信上界；正文和 HANDOVER 明示不授予生产准入 |
| raw API 权限失效 | S1 只读访问失败即记录阻塞；不在本计划扩大权限治理范围 |

## 7. 待确认项

以下事项都由 S1 产物支持后再由用户确认，实施者不得预先代决：

1. 候选清单及获准下载的附件范围。
2. 若少于 20 张、少于 5 台或无报警态，是补采、降低目标还是终止。
3. S2 的业务核验人及可用时间窗口；第二人抽检是否改由业务人员承担。
4. UNKNOWN 候选是否允许在获批范围内下载后人工判族。
5. 若候选池不足，是否接受“全量可用 ZIZES 机台”的降级报告；降级结果仍不得作为生产准入依据。
