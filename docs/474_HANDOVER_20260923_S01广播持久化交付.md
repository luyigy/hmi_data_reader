## 存储设计（范围与去重约定）

- `FeishuGroupBroadcast`：`appId + chatId` 定位群；`@@unique([appId, chatId, sourceMessageId])` 使同一来源消息幂等（重放返回原记录，禁止改写内容/发送者）；`@@unique([appId, chatId, sequence])` 保证群内稳定顺序，序号在事务内 `MAX+1` 分配。
- `FeishuGroupBroadcastTarget`：发布事务内对当时 `threadId/rootMessageId` 非空且 `liveRoom.status = active` 的任务绑定做不可变身份快照（appId/chatId/bindingId/liveRoomId/threadId/rootMessageId）。快照无指向绑定/房间的活外键（仅 broadcastId 级联），绑定行事后删除也不改历史范围。
- 发布与隔离开关、任务确认共用 `FeishuGroupTaskSettings` 行锁（`lockEnabledGroup`，自 feishu-task-binding 导出复用）：模式关闭（含无设置行）拒绝新发布；同群发布串行化，序号无竞态；已入库广播不受开关影响、保持可读。
- 归档任务在发布时被排除；发布后新建的任务不进入已发布范围；跨群、跨应用绝不混入。广播只存原文、来源与顺序，不复制任务私有讨论。
