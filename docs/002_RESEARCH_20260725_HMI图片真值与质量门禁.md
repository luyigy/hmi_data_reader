## 1. 已确认的数据问题

对 15 张样本计算 SHA-256，发现 3 组完全重复文件：

| 重复组 | 文件 | 结论 |

| A | `boletuo_Z001_t2_射出保压.jpeg` = `rijing_Z022_t2_射出保压.jpeg` | 跨机台/品牌字段挂载同一原图，至少一条映射错误 |
| B | `boletuo_Z001_t3_储料冷却.jpeg` = `rijing_Z022_t3_储料冷却.jpeg` | 跨机台/品牌字段挂载同一原图，至少一条映射错误 |
| C | `fanake_Z036_t1_炮筒.jpeg` = `fanake_Z036_t3_储料冷却.jpeg` | 同一记录不同业务字段重复挂图，至少一个页面字段错误 |

因此：

1. 不能按飞书中的品牌或机台类型选择解析模板。
2. 不能按附件字段名决定页面类型。
3. OCR 前必须做文件哈希；同一记录跨字段重复、跨机台重复均需报警。
4. 原交接文档中“日精=TACT”“5品牌固定为4套模板”“节省40%”均降级为待核验假设。

## 3. 质量门禁（先保守运行，再用实测数据校准阈值）

### 3.1 硬拒绝：不进入数字OCR

满足任一项即拒识：

- `DUPLICATE_ATTACHMENT`：同一记录不同字段挂载相同文件。
- `CROSS_RECORD_DUPLICATE`：不同机台/记录挂载相同文件，且业务上不应复用。
- `SCREEN_NOT_FOUND`：检测不到完整屏幕四边或主要显示区域。
- `SCREEN_TOO_SMALL`：透视矫正后的屏幕有效宽度小于 700 px，或关键数字字符高度小于约 14 px。
- `SEVERE_GLARE`：高亮/反光区域覆盖关键字段，造成字符笔画丢失。
- `SEVERE_BLUR`：关键数字区域无法稳定分辨小数点或相邻字符。
- `SEVERE_PERSPECTIVE`：屏幕边缘缺失，或矫正后局部拉伸导致数字不可辨。
- `PAGE_UNKNOWN`：UI家族或页面类型置信度低于门槛，不允许送入某个固定模板硬解析。

### 3.2 可处理但需告警

- `NEEDS_RECTIFICATION`：屏幕完整但存在中度斜拍，可透视矫正。
- `LOW_TEXT_SIZE`：文字偏小，OCR结果必须进行字段范围和单位校验。
- `MINOR_GLARE`：反光未覆盖关键数字。
- `LOW_CLASS_CONFIDENCE`：UI家族/Tab置信度不足，只输出候选，不输出结构化生产参数。

### 3.3 三色处置

- **绿灯**：UI家族和页面均明确；图片质量合格；OCR字段通过格式、范围、行列一致性校验。自动入库。
- **黄灯**：可矫正或部分字段可读；保留OCR候选和置信度，暂不自动覆盖正式数据，进入人工复核。
- **红灯**：重复、严重反光/模糊/斜拍、屏幕过小、页面未知。拒识并要求重拍。

## 4. 正确流水线

```text
图片
→ SHA-256/感知哈希去重
→ 屏幕检测与完整性检查
→ 质量评分（尺寸、模糊、反光、透视）
→ 不合格：输出原因码 + 重拍要求
→ 合格：透视矫正、裁切
→ 基于像素识别 UI 家族
→ 基于标题和布局识别页面/Tab
→ 对应页面解析器 OCR
→ 字段格式、单位、范围、行列一致性校验
→ 绿灯自动入库 / 黄灯人工复核 / 红灯拒识
```

模板按图片内容命名，例如：

- `TACT.temperature`
- `TACT.injection_metering`
- `FANUC.<page>`
- `ZizES.temperature`
- `TRD6.<page>`

禁止使用“伯乐模板”“日精模板”作为路由键。

## 5. 给现场用户的重拍提示

不要只说“OCR失败”，必须给明确动作：

- **角度不合格**：请正对屏幕拍摄，四个屏幕边角全部入镜，不要从侧面斜拍。
- **反光严重**：请调整站位或关闭闪光灯，确保反光不覆盖数字区域。
- **画面模糊**：请擦净镜头、保持手机稳定，点击屏幕区域对焦后重拍。
- **屏幕太小**：请靠近拍摄，让显示屏主体占照片大部分，同时保留完整四边。
- **页面错误/未知**：请打开指定页面，并确保页面标题和全部参数区域同时入镜。
- **重复图片**：当前多个字段使用了同一张照片，请分别拍摄并上传对应页面。

## 6. 当前优先级

1. 优先用 ZizES 三张绿灯样本建立“质量检测 + 页面路由 + OCR”最小闭环。
2. TACT/FANUC 样本先做透视矫正，再决定是否进入精确数字OCR。
3. TRD6 三张当前不勉强抽取数字；先报警要求更近、更正、更清晰地重拍。
4. 从飞书重新抽取独立样本，替换已确认的重复附件，之后才能评估真实UI家族数量和模板工作量。
