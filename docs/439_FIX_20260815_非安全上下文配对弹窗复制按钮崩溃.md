# FIX · 非安全上下文下配对弹窗复制按钮崩溃

## 问题描述

用户通过局域网 `http://192.168.31.109:3010`（非 HTTPS）访问 Web UI，点击
「+ 接入我的本地电脑」后弹窗正常展示 curl 命令，但点「复制命令」抛出：

```
Unhandled Runtime Error
TypeError: Cannot read properties of undefined (reading 'writeText')
src/components/common/PairComputerButton.tsx (43:65)
```

## 根因分析

异步 Clipboard API（`navigator.clipboard`）**只在安全上下文（HTTPS 或
localhost）存在**。平台当前以 HTTP 服务于局域网 IP，`navigator.clipboard` 为
`undefined`，`navigator.clipboard.writeText(...)` 直接同步抛 TypeError，且按钮
回调没有 try/catch，由 Next.js 冒泡为整页 Unhandled Runtime Error。

（`RemoteGatewayForm.tsx` 的复制有 try/catch + execCommand 回退，不受影响。）

## 修复方案

`src/components/common/PairComputerButton.tsx`：

1. 新增 `copyText()`：优先 `navigator.clipboard?.writeText`（安全上下文），
   失败或不可用时回退到隐藏 textarea + `document.execCommand('copy')`（HTTP 下
   可用）；两者都失败返回 false，不抛异常。
2. 按钮增加状态反馈：成功显示「已复制 ✓」2.5s；回退失败显示
   「浏览器禁止了自动复制，请手动选中上方命令复制」，同时命令区块显式
   `select-text` 保证可手动选中。

## 验证情况

- `npx tsc --noEmit` 通过；`npm run build` 通过（`/runner.js`、
  `/api/pairing-tickets` 等路由齐全，Middleware 正常编译）。
- 平台 dev server 重启后 `/login` 200、未登录 `/rooms` 307、LAN 地址可达。

## 事故记录（与本次修复无直接因果，需避免复发）

构建验证期间在 dev server 运行时执行了 `next build`，二者共享 `.next` 导致
`Cannot find module './8948.js'`、`/login` 500——即 `docs/437_FIX…` 记录过的同一
损坏模式。已按既定处置恢复（stop → `rm -rf .next` → start）。**结论：dev server
在线期间禁止在仓库根执行 `next build`/第二个 `next dev`；验证构建需先停服或使用
独立 `distDir`。**
