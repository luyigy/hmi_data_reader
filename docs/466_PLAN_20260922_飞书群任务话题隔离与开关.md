# PLAN · 飞书群任务话题隔离与开关

## 总体目标

用户在同一个飞书群里用不同任务卡片的话题持续推进各自任务，各任务只使用自己的历史；群管理员可明确开启或关闭任务隔离。公共广播由后续 PLAN 提供。

## 当前障碍与核验依据

- `src/lib/feishu-live-room.ts` 的 `FeishuConversationContext` 没有话题字段，`getBoundLiveRoomId` 与绑定创建按 `feishu:group:<chatId>` 定位。
- `prisma/schema.prisma` 的 `FeishuConversationBinding` 只有群、最近消息和房间绑定，没有稳定话题/入口卡片映射。
- `src/lib/feishu-long-connection.ts` 解析 `parent_id`，当前消息类型未承接 `thread_id` / `root_id`；不能直接把父消息 ID 当成话题 ID。
- `src/lib/feishu-live-room-relay.ts` 存在按群选择绑定的回退；`src/lib/live-room-progress.ts` 仅用 chatId 创建进度跟踪器。因此仅修输入不足以保证输出归属。
- 上述为当前源码核验；真实群话题事件、卡片回复及 SDK 行为尚未实测。此前提到的群 ID 未确认绑定，不能作为测试目标。

## 固定规则与范围

1. 同一接入身份范围内，`chat_id + thread_id` 唯一定位任务房间。若当前系统支持多个应用，键须包含已有应用身份，不能跨应用混用。群级入口继续存在，不构建复杂父子房间系统。
2. 保存稳定话题 ID、根消息/入口卡片 ID 和房间映射；普通父消息只用于经验证的映射查询。未知、冲突或伪造归属不得回退到群级房间或最近任务执行。
3. 创建必须是明确的任务创建动作；群里普通消息不自动创建任务。任务只继承允许的目录、默认成员等配置，不复制群聊天历史或其他房间 Agent 会话。
4. 开关默认关闭，仅经服务端验证的群管理员或现有平台授权管理员可修改；不能只凭卡片按钮可见性授权。关闭后禁止创建新隔离任务，已有任务仍可续聊且保持隔离；重新开启复用原绑定。显示“隔离模式已关闭，已有任务仍保持隔离”。
5. 任务卡片为入口和状态面板，实际连续对话发生在其话题。归档任务不隐式恢复执行，给出明确提示。
6. 不新增 worktree 自动隔离、不迁移旧群历史、不做广播、不新增复杂网页管理界面。共享工作目录不等于文件修改隔离；并发编辑同一目录仍可能冲突。
7. 新增字段采用兼容迁移；回退功能开关不删除任务数据。若旧版本不认识新绑定，须证明其不会误路由才可回滚二进制。

## S01：建立可持久恢复的任务归属

- **目的**：消除同群多任务共用绑定，以及重启、重复事件导致重复建房的风险。
- **完成后结果**：数据库与绑定服务可独立证明同群 A/B 映射不同房间，重复创建返回同一结果；尚不开放用户入口。
- **实现方法**：沿用现有绑定表、唯一约束与 Live Room 创建逻辑；增加最少的话题/根消息映射和群开关状态。将共享定位收口到一个明确的解析入口，区分群入口、已绑定任务和未知话题。创建并发由数据库约束及事务处理；飞书创建卡片和本地事务不能原子提交，定义可恢复的待绑定状态及失败补偿，避免产生可执行的孤立房间。先核验真实事件样例或官方 SDK 契约，固定根消息与话题的转换规则。
- **修改边界**：`prisma/schema.prisma`、新增 migration、`src/lib/feishu-live-room.ts` 与必要的独立绑定模块，直接绑定测试；不接 UI、不开放开关、不改消息投递。超过两个生产文件是同一持久化能力的 schema/服务配套，不引入第二个业务能力。
- **验收**：测试群旧绑定兼容、同群双话题、不同群、重复/并发创建、映射冲突、进程重启后恢复、建卡失败补偿；在隔离测试数据库验证迁移与旧记录读取。未知话题不得命中群房间。保留可运行测试命令于 HANDOVER。
- **前置与停止条件**：实施前运行长文件检查、读取当前 Git 状态，按 AGENTS 要求用 GitNexus 辅助共享绑定及 schema 影响分析，并核对真实调用者。事件身份无法可靠确认或迁移需破坏旧数据时停止，不猜测 thread_id。此层独立验收可先发现归属数据错误，避免与外部发送混合后难以定位，因此不与 S02 合并。
- **交付物**：本 Slice 实现与测试提交、记录迁移和映射约定的 HANDOVER；仅交接 S02 后停止。

## S02：打通任务话题的输入、输出与控制

- **目的**：让正确的归属贯穿整个运行过程，避免输入隔离但结果、进度或取消操作串到其他任务。
- **完成后结果**：对预置隔离绑定的 A/B 任务可做端到端契约测试，A 的指令、执行与反馈只到 A。
- **实现方法**：事件解析传递 thread/root/message 信息，普通消息与命令统一使用 S01 解析结果；沿 Live Room 成员会话及执行链路保留任务范围。绑定信息贯穿文字、图片、进度卡、最终卡及失败重试；经核验的飞书回复接口在原话题发送，失败不得降级为群广播。卡片操作从服务端映射校验操作者、chat、room、message，覆盖停止、新会话、加成员，不能信任客户端 roomId。检查同一 Agent 在两个房间的历史与会话恢复路径。
- **修改边界**：`src/lib/feishu-long-connection.ts`、`feishu-live-room.ts`、`feishu-live-room-relay.ts`、`live-room-progress.ts`、`feishu-progress.ts`、`feishu-api.ts` 及实际控制入口 `feishu-card-action.ts` / `feishu-interaction-card-action.ts` / `feishu-live-room-commands.ts`；优先复用共享解析器，只修改需要传递归属的调用处。直接测试复用 `tests/feishu-live-room-relay.test.ts`、`tests/feishu-room-controls.test.ts` 等。文件数超过预警线，原因是同一消息归属必须原子贯穿所有反馈通道；不加入数据库设计、广播或新 UI。若发现需重构执行调度架构，另立计划，不在此新增 Slice。
- **验收**：模拟双话题同时执行，检查实际发送参数及 Agent 输入；覆盖文字/图片/进度/最终反馈、事件重放、投递重试、未知话题、伪造跨房卡片、停止 A 不影响 B、新会话后仍归 A、加成员不影响 B；回归旧群及 DM。测试中断言 A 的私有标记绝不出现在 B 上下文。
- **前置与停止条件**：S01 通过；仍不向普通用户开放创建。话题回复能力不足、权限无法可靠验证、或任一输出通道无法保持归属时停止，禁止群级兜底。真实飞书调用前须有确认的测试群与授权。
- **交付物**：消息闭环实现与测试提交、包含通道覆盖证据的 HANDOVER；交接 S03 后停止。

## S03：开放管理员开关与任务入口并验收

- **目的**：让用户明确启停任务隔离，且切换不改变已有任务的历史归属。
- **完成后结果**：管理员可查询/开启/关闭模式，创建任务入口卡片；同群双任务持续对话可演示。
- **实现方法**：复用现有 `/ap` 命令、房间创建卡片和服务端权限检查，补最少的模式状态及任务创建操作。具体命令名在实施时按 parser 现有约定确定并写入帮助，不把本计划中的描述当作已经存在的命令。开启后先完成稳定绑定再允许执行；关闭后仍优先查已有话题绑定。没有任务归属的群普通消息只进入群入口。
- **修改边界**：`src/lib/feishu-command-parser.ts`、`feishu-live-room-commands.ts`、`feishu-room-create-card.ts` 及必要的卡片 handler 与对应测试；不增加网页设置系统。多个文件为同一管理操作入口的适配，无独立新架构。
- **验收**：自动测试默认关闭、管理员与非管理员、连续启停、创建失败恢复、已有话题在关闭后续聊、归档拒绝执行；回归 `npm run test:feishu-room-create-card` 及实际触达的控制测试。获授权后在同一真实测试群创建 A/B，验证双向续聊、准确停止、重启恢复和关闭后不混历史，记录脱敏的 chat/thread/message/room 关联与结果。
- **前置与停止条件**：S02 所有通道测试通过。缺真实测试群、权限或账号时保持默认关闭，交接标记验收受阻，不声称已上线或整体验收完成。
- **交付物**：管理入口与测试提交、终止式 HANDOVER（验收通过才标记完成）；本 PLAN 完成后等待验收，不自动启动广播 PLAN。
