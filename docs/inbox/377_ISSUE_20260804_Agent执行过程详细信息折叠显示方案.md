# ISSUE · Agent 执行过程详细信息折叠显示与按需查看方案

## 优先级与状态

- 优先级：P1，显著改善飞书群聊/私聊及网页端 Agent 执行过程中的信息轰炸与界面混乱问题。
- 状态：draft，记录于 Git Inbox，等待排期实施。
- 提出时间：2026-08-04。

## 问题背景

在 Agent 执行任务（如代码修改、故障排查、工作流调度）的过程中，Agent 会持续输出大量的中间过程信息（包括思考过程、工具调用参数、终端命令标准输出/错误日志、文件 Diff 等）。

- **痛点**：这些信息如果不加限制地直接平铺输出到聊天界面（飞书群/DM、网页对话框），会导致聊天界面迅速被长日志和密集卡片淹没，界面极为混乱，用户很难一眼识别出“当前 Agent 在干啥”以及“最终结果是什么”。
- **需求**：这些详细执行信息对于问题追溯和透明度又是**必不可少**的。因此需要提供**折叠显示 + 按需展开查看**的交互机制，在保障聊天界面清爽高效的同时，允许用户在需要时一键展开查看完整的执行上下文。

## 总体设计与信息分级

将 Agent 输出信息划分为两个层级：**摘要/状态层（默认外露）** 与 **详细执行层（默认折叠）**。

```
+-----------------------------------------------------------------------+
|  [Agent 图标] Agent 名称                                  [状态: 运行中]  |
|                                                                       |
|  📌 当前阶段：正在运行单元测试并验证修复方案...                          |
|                                                                       |
|  +-----------------------------------------------------------------+  |
|  | ▶ 详细执行过程 (已完成 3 个步骤 / 4 次工具调用) [点击展开]         |  |
|  +-----------------------------------------------------------------+  |
|  | (折叠区内容 - 默认隐藏)                                          |  |
|  |  - Step 1: Read file src/lib/feishu-api.ts (耗时 120ms)           |  |
|  |  - Step 2: Run command `npm test` (stdout: 45 lines)              |  |
|  |  - Step 3: Edit file src/lib/feishu-api.ts (+5, -2)              |  |
|  +-----------------------------------------------------------------+  |
|                                                                       |
|  ✅ 结论/回答：修复已完成，单元测试全数通过。                           |
+-----------------------------------------------------------------------+
```

### 1. 摘要/状态层（默认外露，界面主体）
- **核心结论与回答**：Agent 针对用户提问的最终回复、解释说明、确认提问。
- **高阶状态与进度指示**：当前正在执行的核心动作（如“正在读取配置文件...”、“正在运行单元测试...”）。
- **关键告警与错误提醒**：若出现中断、报错或需要人工审批（如卡片审批），保持突出显眼展示。

### 2. 详细执行层（默认折叠，按需展开）
- **工具调用详情**：如 `read_file`, `write_to_file`, `grep_search` 等调用的入参、文件路径及行号。
- **命令行与终端输出**：`run_command` 的完整 `stdout` / `stderr` 日志。
- **代码 Diff 预览**：文件修改的具体增删行。
- **模型中间思考过程**：Agent 内部推理链（Reasoning / Thinking blocks）。

## 跨端实现方案

### 方案一：飞书交互卡片 (Feishu Interactive Cards)

在飞书消息场景中，利用飞书卡片的新特性（折叠面板 `collapsible_panel` / 展开隐藏组件 / 动态卡片更新）：

1. **实时流式更新模式 (Streaming Mode)**：
   - 任务执行期间，推送一张动态更新的卡片（使用 `message_id` 原位更新）。
   - 卡片页眉展示全局状态指示（`运行中...` / `已完成` / `执行失败`）。
   - 主体区使用折叠容器（`collapsible_panel`），标题显示如 `▶ 详细执行步骤 (4)`，展开后为 Markdown 格式的日志与工具明细。
2. **执行完成收纳**：
   - 当轮次结束时，卡片自动收缩详细日志折叠块，只留下一行摘要及终态回答，界面极大简化。
   - 用户如需对历史推理过筛，点击卡片中的折叠面板按钮即可就地展开。

### 方案二：网页端对话界面 (Web Platform Chat UI)

在 `src/app/tasks/[id]/chat` 及相关组件中：

1. **新建 `<CollapsibleExecutionBlock>` 组件**：
   - 将连续的 `tool_call` / `tool_response` / `thinking` 节点收纳进一个可折叠的手风琴（Accordion）组件中。
   - 折叠头部展示：图标 + 动作概括（如 `🔧 运行了 3 个工具命令`）+ 运行耗时。
   - 点击可流畅展开/收起完整日志；单条输出超过 10 行时，内部另提供“展开完整输出 (120 行)”的二次折叠。
2. **全局切换开关与偏好设置**：
   - 界面右上角增加“折叠执行过程 / 展开全部”切换按钮（Toggle）。
   - 支持记忆用户偏好（如默认全部折叠或默认展开错误日志）。

## 协议与服务端调整

1. **事件流（StreamEvent）打标**：
   - 服务端在发送 ACPX / Runner 事件流时，为 event 标记级别 `tier: 'summary' | 'detail'`。
   - `detail` 级别的事件由前端 / 飞书卡片渲染器自动路由至折叠组件中。
2. **文本片段长内容截断预览**：
   - 超长终端输出在前置合成卡片/消息时提取前 2 行与后 2 行作为预览，避免单张飞书卡片超出 JSON 长度限制。

## 验收目标

1. 飞书群聊与私聊中，Agent 密集执行过程不再产生多条刷屏消息，统一收纳于单张卡片的折叠面板中。
2. 网页端对话界面中，所有中间工具调用与终端输出默认合并折叠，聊天主视图只保留用户提问与 Agent 最终答复。
3. 用户点击“展开”按钮后，能完整查阅工具入参、命令行输出及日志信息。
