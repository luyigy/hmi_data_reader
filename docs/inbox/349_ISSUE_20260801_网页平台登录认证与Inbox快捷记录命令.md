## 问题与背景

1. 当前网页平台（Web Dashboard）缺乏登录认证与权限鉴权系统，任何可以直接访问 HTTP 端口的客户端均可操作平台 API 和房间控制台，存在严重的安全隐患。
2. 目前缺乏快捷记录灵感与需求的命令行/AP命令机制，导致用户或 Agent 在协同对话中提出的需求、议题无法随时随地一键登记入 Git Inbox (`docs/inbox/`)。

## 需求与设计规范

### 1. 网页平台登录认证系统 (Authentication & Auth System)
- 引入用户身份认证机制（支持 Username/Password、Session Cookie、JWT Token 或与飞书/OAuth 身份集成）。
- 实施路由与 API 中间件保护（Auth Middleware），未登录未授权请求统一被重定向至登录页或返回 `401 Unauthorized`。
- 建立角色权限模型（RBAC），支持管理员与普通用户权限隔离。

### 2. Inbox 快捷记录命令 (`ap inbox add` / `/ap inbox`)
- 提供独立的 CLI 命令（如 `ap inbox add "需求标题" --body "详细说明"`）或平台指令（如 `/ap inbox`）。
- 执行命令时，自动在 `docs/inbox/` 目录下按照规范格式生成 Markdown 规范议题（包含 YAML frontmatter、自动递增编号 `3xx_ISSUE_YYYYMMDD_...md`）。
- 校验文件格式符合 `docs/workflow/workflow-contract.yaml` 的 `allowed_types: ISSUE` 规范，并完成 Git 跟踪。

### 3. 定期轮询与排期消费
- 平台 Cron / Watcher 定期扫描 `docs/inbox/` 目录中的待处理 ISSUE。
- 支持由用户或主控 Agent 选定议题并一键转化为 Workflow PLAN 进行排期实施。

## 验收标准

1. 未通过身份认证的请求无法访问网页控制台敏感操作及后台 API。
2. 通过命令行或平台指令触发记录后，`docs/inbox/` 下能自动生成符合 YAML 合同规范的 ISSUE 文件。
3. `npm run workflow:validate` 能正确校验新生成的 Inbox 议题文件。
