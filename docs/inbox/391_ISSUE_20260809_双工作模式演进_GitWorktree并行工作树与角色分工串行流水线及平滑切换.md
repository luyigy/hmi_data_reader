## 问题背景与现状反思

随着 Agent Platform 在复杂工程任务与飞书 Live Room 中的深入使用，未来的工作方式已明确收敛为两大主线：**“并行的工作树”** 与 **“串行的角色分工流水线”**。然而当前系统在两种模式的实现与协同上存在显著痛点：

### 1. 现状痛点一：串行角色分工落地机械、流于形式，默认 Speaker 单点包揽

- **现象**：虽然系统定义了 `planner` / `researcher` / `implementer` / `reviewer` / `tester` 等角色枚举，但在真实执行中（特别是在飞书 Live Room 房间内执行计划时），往往仍然是**默认的 Speaker（或触发计划的单一 Agent）从头到尾承担了所有工作**。
- **根因**：
  1. 当前串行执行机制缺少强约束的阶段流转（Stage Handover）门禁与权限移交，未能在阶段结束时强制将控制权移交给下一个专业角色。
  2. 飞书 Live Room 缺少“严格工序守护者”，当计划执行时，默认 Speaker 习惯性在同一上下文里继续执行代码修改、测试与评审，导致多 Agent 协作沦为摆设。
  3. 缺乏细粒度职责与意图路由（如 [382](file:///data1/code/agent-platform-v2/docs/inbox/382_ISSUE_20260804_Agent%E8%81%8C%E8%B4%A3%E5%88%86%E5%B7%A5%E4%B8%8E%E6%8C%89%E6%84%8F%E5%9B%BE%E8%B7%AF%E7%94%B1.md) 所述），平台未从机制上保障“各司其职”。

### 2. 现状痛点二：缺乏工程级并行工作树（Git Worktree）隔离与防冲突体系

- **现象**：当面对多个并发 Bug 修复或正交子任务时，多个 Agent 若在同一个工作区或主分支上并发执行，极易发生文件写覆盖、锁争用、构建端口抢占、Git 历史污染等破坏性冲突。
- **诉求**：必须有一套完整的物理工作区隔离（Git Worktree）、影响范围预判（Overlap Detection）、合并队列（Merge Queue）以及冲突自动化自愈闭环。

### 3. 现状痛点三：缺少双模式之间的统一抽象与平滑切换机制

- **现象**：用户在飞书房间或 Web 控制台中，无法根据任务性质（独立多 Bug vs 复杂系统演进）在“并行工作树模式”与“串行角色分工模式”之间自由且低门槛地切换，也缺乏组合使用的混编支持（如：先串行规划 -> 拆解子任务并行执行 -> 合并后串行评审与测试）。

---

## 核心方案设计

针对上述痛点，设计**“双工作模式统一治理与自由切换”**架构体系：

```
                      ┌─────────────────────────────────────────┐
                      │    用户意图 / 飞书 Live Room / Web 控制台    │
                      └────────────────────┬────────────────────┘
                                           │
                        ┌──────────────────┴──────────────────┐
                        │   工作模式调度器 (Mode Orchestrator)   │
                        │   - 支持命令 / 卡片动态平滑切换        │
                        │   - 支持模式混编 (Hybrid Pipeline)   │
                        └──────────┬───────────────────┬──────┘
                                   │                   │
                ┌──────────────────┴──┐             ┌──┴──────────────────┐
                ▼                     ▼             ▼                     ▼
┌─────────────────────────────────────────┐     ┌─────────────────────────────────────────┐
│     模式一：Git Worktree 并行工作树      │     │      模式二：串行角色分工流水线         │
│   (Parallel Git Worktree Mode)          │     │    (Sequential Role-Based Pipeline)     │
├─────────────────────────────────────────┤     ├─────────────────────────────────────────┤
│ 1. 物理隔离：动态 Worktree + 临时分支   │     │ 1. 告别单点代劳：严禁默认 Speaker 包揽   │
│ 2. 调度预判：文件重叠检测 (Overlap Det) │     │ 2. 工序流转：Planner→Researcher→Impl... │
│ 3. 契约守卫：受限改动半径 + 长文件门禁  │     │ 3. 阶段交接：Handoff 契约 + 自动接力唤醒│
│ 4. 集成自愈：Merge Queue + Agent 自动修复│    │ 4. 交付检查：各阶段产物完整性刚性校验    │
└─────────────────────────────────────────┘     └─────────────────────────────────────────┘
```

### 一、 模式一：Git Worktree 并行工作树模式（深入设计）

主要面向**多 Bug 并发修复、多独立模块并行开发、探索性方案验证**等场景。

#### 1. 物理层：工作区与运行时环境强隔离
- **动态 Git Worktree 分配**：
  - 调度平台为每个并发任务动态创建独立的 `git worktree`（如 `.worktrees/task-<task_id>-<agent>`），绑定独立的临时分支（如 `agent/fix-<task_id>`）。
  - 各 Agent 拥有完全隔离的文件系统视图，共享底层 `.git` 对象库，磁盘与初始化开销极低。
- **环境与端口沙箱**：
  - 构建缓存、Dev Server 端口、测试数据库实例各自使用动态端口与隔离临时目录，杜绝并行测试相互踩踏。

#### 2. 调度层：任务切分与重叠检测（Overlap Detection）
- **改动范围预估**：
  - 通过静态代码依赖分析、调用链或代码图谱预估任务涉及的文件集合。
- **正交任务完全并行**：
  - 无文件重叠的任务（如 Agent A 改动文档，Agent B 改动支付模块）全速并行。
- **重叠任务排队或锁定（Module Lease）**：
  - 改动同一核心文件的任务，调度器自动识别强依赖关系，降级为局部串行队列，或引入轻量级模块租约（Lease），防止并发代码撕裂。

#### 3. 契约层：受限修改半径与安全守卫
- **受限变更半径（Blast Radius 约束）**：
  - 约束并发修复任务非必要不得改动公共 API、全局配置、数据库 Schema 等核心契约。
- **门禁守卫（Long-File Guard & Contract Test）**：
  - 在各 Worktree 独立运行长文件守卫与契约测试，阻断单任务大范围膨胀共享文件。

#### 4. 集成层：合并队列与自动化冲突自愈（Merge Queue & Self-Healing）
- **Merge Queue 机制**：
  - 各 Agent 分支在 Worktree 内跑通验证后，提交 PR 进入合并队列。
  - 队列按序自动 `git rebase main`（或 merge main）。
- **Agent 自动化冲突自愈（Self-Healing Loop）**：
  - 若 Rebase 出现代码冲突或测试失败，平台将 Git 冲突标记、Diff 和错误日志自动回传给该 Agent。
  - 唤醒 Agent 在其独立 Worktree 中重新理解冲突并自动解决，跑通验证后重新入队合入。

### 二、 模式二：角色分工串行流水线模式（深入设计）

主要面向**大型功能研发、核心架构重构、高复杂度系统演进**等需要步步为营、各工种深度协作的场景。

#### 1. 根治“默认 Speaker 包揽所有工作”的顽疾
- **硬性阶段流转门禁（Stage Gate Enforcement）**：
  - 系统严禁默认 Speaker 在未移交控制权的情况下直接越权完成下一角色的职责。
  - 每一个工序完成后，平台自动将上下文与执行令牌移交给房间内对应角色的 Agent。

#### 2. 标准工序与角色分工职责契约
| 阶段 | 责任角色 (Role) | 核心职责与产出物 | 阶段交接门禁 (Gate) |
| :--- | :--- | :--- | :--- |
| **阶段 1：规划** | `planner` | 需求分析、架构考量、产出标准化 `PLAN.md`（含任务拆解与分工） | 人工审批通过，且 PLAN 格式合规 |
| **阶段 2：调研** | `researcher` | 探索代码依赖、技术可行性分析、输出关键设计与调研结论 | 调研报告已输出，技术路径明确 |
| **阶段 3：实现** | `implementer` | 按 PLAN 逐项编写代码、补齐单元测试、确保本地验证通过 | 单测通过、长文件守卫通过 |
| **阶段 4：评审** | `reviewer` | 多维度代码评审（正确性、安全性、长文件、性能、复杂度） | 审查结论通过（无 P0/P1 阻塞项） |
| **阶段 5：测试** | `tester` | 端到端测试、边界用例验证、集成门禁检查 | 集成测试全部通过、产出最终验收报告 |

#### 3. 自动化接力唤醒（Automated Turn Handoff）
- 阶段完成后，平台自动在任务房间内发起标准的 `$member` 异步接力。
- 飞书消息与 Web 卡片中明确更新当前责任人标签（如 `[当前阶段: 代码评审] 责任人: reviewer · Platform Local / codex`），提供透明的可视化流转轨迹。

### 三、 双模式统一抽象与平滑切换机制（Switching & Hybrid）

#### 1. 切换维度与交互控制入口
- **飞书 Live Room 快捷命令**：
  - `/mode parallel` 或 `/run parallel`：切换到 Worktree 并行模式（支持指定多个子任务/Agent）。
  - `/mode pipeline` 或 `/run feature`：切换到角色分工串行流水线模式。
  - `/mode hybrid`：启用混合编排模式。
- **AP 命令中心与 Dashboard 卡片**：
  - 在飞书交互卡片中提供直观的单选按钮组：`[ 并行工作树 ]` | `[ 角色串行流水线 ]` | `[ 智能混编 ]`，支持一键切换并实时调整当前房间成员的编排策略。

#### 2. 混合编排工作流（Hybrid Orchestration）
支持将两种模式进行组合嵌套：
```
[1. 串行规划阶段 (Planner)]
           │ 产出拆解后的正交子任务列表
           ▼
[2. 并行工作树开发阶段 (Worktrees)]
   ├── Task A -> Agent 1 (Worktree 1) ──┐
   ├── Task B -> Agent 2 (Worktree 2) ──┼──> [Merge Queue 自动合入]
   └── Task C -> Agent 3 (Worktree 3) ──┘
           │
           ▼
[3. 串行评审与验收阶段 (Reviewer + Tester)]
   ├── Reviewer 统一代码审查
   └── Tester 全链路端到端验收
```

#### 3. 会话状态与工作区资产平滑继承
- 切换模式时，统一的工作区管理器（Workspace Manager）自动维护主工作区与各 Worktree 之间的同步映射。
- 阶段产物（PLAN、HANDOVER、代码变更、测试报告）在会话中完整沉淀，确保无论如何切换，历史上下文与执行状态均不丢失。

## 分阶段演进路线 (Roadmap)

1. **Phase 1 (串行角色治理与防单点代劳 - Quick Win)**：
   - 修复飞书 Live Room 计划执行时默认 Speaker 包揽全部工作的缺陷。
   - 强化阶段流转门禁与自动 `$member` 异步接力，实现真正的 `planner -> implementer -> reviewer -> tester` 角色分工流转。
2. **Phase 2 (Git Worktree 隔离与并行执行原型)**：
   - 落地基于 `git worktree` 的多 Agent 独立工作区生命周期管理（创建、端口分配、销毁）。
   - 实现初步的分支合并队列（Merge Queue）与静态冲突告警。
3. **Phase 3 (双模式切换与混编工作流)**：
   - 在飞书卡片、Live Room 命令与 Web 端提供双模式一键切换。
   - 支持“规划串行 -> 执行并行 -> 评审验收串行”的混编执行能力。
4. **Phase 4 (智能重叠调度与冲突自动化自愈闭环)**：
   - 引入基于代码图谱的冲突重叠检测（Overlap Detection）。
   - 实现 Rebase 冲突与测试失败的 Agent 自动唤醒与自愈重提机制。

---

## 验收标准

1. **角色串行模式**：在飞书 Live Room 启动计划执行后，工序严格在对应的各个专业 Agent（Planner/Implementer/Reviewer/Tester）之间自动交接流转，默认 Speaker 不得擅自越权包揽其他角色的工作。
2. **并行工作树模式**：平台能够同时为多个 Agent 分配独立的 `git worktree` 并发执行任务，各 Agent 间无写冲突、无端口冲突，且能通过 Merge Queue 安全合入。
3. **平滑切换与混编**：用户能够通过飞书命令或卡片在两种模式间无缝切换，且支持“串行规划 + 并行执行 + 串行评审”的混合编排链路。
