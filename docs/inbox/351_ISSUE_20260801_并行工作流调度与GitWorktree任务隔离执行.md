# ISSUE · 并行工作流调度引擎与 Git Worktree 多 Agent 任务隔离执行

## 状态

- 优先级：P1，提高多 Agent 并发协同效率与安全隔离的核心能力。
- 当前处理：仅记录到 Git Inbox，待后续 Workflow 排期评估。
- 提出时间：2026-08-01。

## 问题与背景

1. 当前工作流主要针对单任务/单 Agent 顺序执行，缺乏任务拆分后的多 Agent 并行 Spawn 与并发调度机制。
2. Web 界面与飞书界面缺乏针对多个并发工作流的直观状态可视化能力。
3. 多个 Agent 在同一代码库并发写入时极易造成工作区冲突与文件覆盖。

## 需求与设计规范

### 1. 任务拆分与并行 Spawn 机制
- 支持主控 Agent 将大型任务分解为独立子任务。
- 支持并发 spawn 多个 Agent 并行执行各自领取的子任务。

### 2. 多端界面并发工作流可视化展示
- 在 Web 控制台与飞书 Live Room/审批卡片中，提供多工作流并发状态面板。
- 明确划分并实时展示“工作流一”、“工作流二”等多条并发流水线的进度、当前执行步骤与日志输出。

### 3. 基于 Git Worktree 的多 Agent 并行任务隔离
- 为每个被分配任务的注册 Agent 创建独立的 Git Worktree 隔离目录/临时分支。
- 保证各 Agent 在各自独立的 Worktree 中并行编写代码、运行测试与校验，避免对主工作区和其他 Agent 产生文件冲突。
- 所有子任务在 Worktree 中完成后，由主控 Agent 或平台统一进行代码审查与分支合并。

## 验收标准

1. 平台支持拆分任务并同时 spawn 多个 Agent 并行执行。
2. Web 界面和飞书界面均能清晰展示各并发工作流（工作流一、工作流二）的实时运行状态与进度。
3. 各 Agent 在各自独立的 Git Worktree 环境中并行工作，无代码与工作区冲突，并在完成后成功合并。
