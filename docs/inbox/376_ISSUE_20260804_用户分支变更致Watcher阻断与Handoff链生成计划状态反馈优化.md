# ISSUE · 用户分支变更致 Watcher 阻断与 Handoff 链生成计划状态反馈优化

## 优先级与状态

- 优先级：P1，提升用户在使用工作流/命令卡片/Handoff 链提升时的排障体验与透明度。
- 状态：draft，记录于 Git Inbox，等待后续排期实施。
- 提出时间：2026-08-04。

## 问题背景

在多分支并行开发或用户切换 Git 分支的场景中，经常出现因为用户分支改变导致 Watcher Cursor 错位，从而触发 Git 历史安全门阻断 Watcher 的现象。
当用户在飞书群/网页平台中打开命令卡片，或在运行过程中点击“将本轮 handoff 链生成计划”时，系统可能提示“已接收，正在生成审批 PLAN”，但随后因为以下原因导致流程卡死或静默停止，用户无法得到明确反馈：

1. **PLAN 未生成**：解析或提升 handoff 链生成 PLAN 文件过程中发生异常。
2. **PLAN 校验失败**：生成的 PLAN 未通过 Workflow Validator（如 schema/action 不合规或依赖路径失效）。
3. **Watcher 阻断**：项目 Git 监控分支被切换，数据库 Cursor 仍留在旧分支提交，系统触发安全门挂起 Watcher，导致生成的 PLAN 无法被自动扫描并转换为飞书审批卡片发送。
4. **审批卡发送失败**：Validator 通过且 Watcher 扫描到 PLAN，但由于飞书 API 报错、Token 过期或网络问题导致卡片未能成功弹出。

上述情况会导致用户困惑（不清楚是还在处理中、生成失败还是发送失败），需要人工介入追踪日志才能定位原因。

## 处理思路与优化方案

### 1. 明确的阶段性状态反馈机制
在提升 Handoff 链为计划或运行命令的全生命周期中，提供分阶段、清晰可读的状态与原因提示：
- **生成阶段提示**：若 PLAN 文件未成功生成，明确提示 `PLAN 生成失败：[具体原因/缺失模板/解析错误]`。
- **校验阶段提示**：若 Validator 报错，明确提示 `PLAN 校验未通过：[详细校验错误信息]`。
- **Watcher 状态/阻断提示**：若 Watcher 被挂起或无法处理该 PLAN，检测 Watcher 阻断原因并提示 `PLAN 已生成，但 Watcher 监控暂停：[原因：如分支改变造成 Cursor 错位 (configured ref mismatch)]`，并附带修复引导。
- **卡片发送结果提示**：若推送 API 失败，提示 `PLAN 校验通过但审批卡发送失败：[Feishu API 报错及错误码]`；若发送成功，返回对应消息 ID 和审批截止时间。

### 2. 命令卡片与交互入口优化
- **打开命令卡片时自动诊断**：当用户打开 AP 命令卡片或查看工作流状态时，主动展示当前 Watcher 健康度。如检测到 Cursor 错位或 Watcher 暂停，在卡片顶部给出警示卡片及“一键同步 Cursor / 修复监控配置”的操作按钮。
- **点击“生成计划”实时更新状态**：将原本静态的“已接收，请稍候”提示升级为带状态跟踪的提示块或更新卡片（`接收中` -> `生成 PLAN` -> `Validator 校验` -> `Watcher 扫描与发卡`），任何环节出错即时显示具体原因和处理方案。

## 验收目标

1. 用户打开命令卡片时，能直观看到 Watcher 是否受分支变更阻断。
2. 用户点击“将本轮 handoff 链生成计划”后，不论是 PLAN 未生成、校验失败、Watcher 阻断还是发送失败，均能获得包含具体原因和处理指引的明确提示。
3. 提供修复或恢复引导（例如引导运行 `ap workflow reset-cursor` 或在卡片中提供修复触发点）。
