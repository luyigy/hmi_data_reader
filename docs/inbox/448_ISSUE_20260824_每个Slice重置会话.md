# ISSUE · 每个 Slice 重置会话

## 背景

当前 workflow 的连续 slice 可能复用同一 TaskSession。随着 slice 推进，前序讨论、运行事件和工具输出会持续累积，导致后续 slice 上下文膨胀，也让不同职责之间的上下文边界不清晰。

## 待办

- [ ] 明确语义：每个新 slice 派发前，为可轮换的参与成员创建 fresh session；同一 slice 内的重试和纠错默认继续当前 session。
- [ ] 新 session 只注入当前 PLAN、上一 slice 的结构化 HANDOVER、当前 slice Prompt 和必要的房间稳定背景，不回灌完整历史 transcript。
- [ ] 保留成员权限档位、工作目录、模型与 harness 配置；不得因换代退回默认权限或错误工作区。
- [ ] 定义不可轮换 harness、运行中任务、dirty workspace、换代失败和 watcher 恢复的处理规则，避免中断或重复派发。
- [ ] 评估手工、半自动、自动 workflow 是否统一启用，以及是否需要按 PLAN 提供显式开关；默认值在实现前确认。
- [ ] 补充覆盖“slice 边界换代、slice 内续聊、权限继承、失败恢复、无 provider 遥测”的最小自动化测试。

## 验收目标

1. 相邻两个 slice 使用不同的可续聊 session，后一个 slice 能通过结构化交接正确继续任务。
2. 同一 slice 内的正常追问、重试和 completion gate 纠错不发生无意换代。
3. 换代后权限、工作目录与执行配置保持一致，且不会重复执行已完成 slice。
4. Live Room 能明确展示 slice 边界的 session 换代结果；失败时给出可恢复状态，而不是静默退化。
