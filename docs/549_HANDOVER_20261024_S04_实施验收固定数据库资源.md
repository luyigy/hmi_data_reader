## 实现与删减

`RuntimeDeclaration` 新增可选字段：

```json
{
  "version": 1,
  "postgres": {
    "resource": {
      "kind": "path",
      "path": "/explicitly-approved/postgres-bundle",
      "sha256": "88173c650921e15528294eccd26e6f53d5cc37eb4f8e8035bfe4700c7a98d21d"
    }
  }
}
```

以上只是合同示例，不会自动登记或授权该路径。资源必须是已规范化、无链接的完整 bin/lib/share 目录。
复用原路径授权、摘要计算、RuntimeDeclarationSource、claim pin 和后续复验，不增加平行配置。
宿主登记必须使用绝对路径；图 JSON 的 services 仍只接受原 Node/Python 合同，不能直接自授宿主数据库路径。
旧 pin（包括固定的缺省声明）保持原状，不主动扩充授权。

`withGraphTaskServices` 从已准备且复验的 PostgreSQL 资源构造 S03 服务，实施和检查均传入同一个
PreparedRuntime 合同；执行前资源复验也集中到该公共边界。资源按整包摘要去重，连接 key 包含摘要前缀；
调用方从 `TASK_GRAPH_SERVICES_JSON` 选择 `runtime === 'postgres'`，可核对其中的 resource.sha256。
每次阶段调用仍由 `withAttemptServices` 建立独立数据、密码、监听与清理回执。
无任务图执行归属的 PostgreSQL 声明拒绝执行，不静默忽略数据库要求。

`runner-harness.ts` 与 `check-environment.ts` 仅传递准备结果，保留各自写权限、模型访问和输出绑定。
未改全局 DATABASE_URL 白名单，连接只存在阶段上下文；未改授权配置或已有业务票快照。

S02 的沙箱测试入口已删除自己的 initdb/pg_ctl 启停流程和随机端口选择，改用 S03 的同一生命周期。
测试夹具仍负责展开固定发行包内部链接并比对独立固定摘要；不会把当前缓存摘要当作新批准。
测试 schema 残留或服务清理失败现在会令入口退出失败，不能被套件成功掩盖。
