## 实现与自测结果

1. **归属与授权。** `graphResourceJobs` 从 childTaskId 或已登记 graphReview 运行解析图归属。正常 Harness 的项目工具、输出、服务、材料与补充目录装配使用该关系，普通 Task ID 也可执行；伪装 Task 名称不能获得别人的资源。验收者按真实任务、用户、参与者与批准范围继承资源，不再按“实施回合”拒绝写授权。只读配置会把继承的补充写授权限制为读取；跨任务 worktree 写入仍被拒绝。
2. **人工 runtime。** 新 `conversation-runtime.ts` 复用项目工具、宿主登记、Python 和 runtime declaration 合同，逐 execution 核验实际 Git 源码与当前授权，不借旧调度 claim。多仓保留分别的工具环境；生成 `room_runtime_prepared` 源码提交/目录/资源身份回执。项目能力同时核验所属任务与当前消息作者。实际沙箱验证了可写运行目录、额外写目录、显式源码写授权、工具只读和未授权目录不可见。
3. **输出与服务。** 正常聊天也取得隔离输出、验证 argv、已声明临时服务；新增测试实际启动 HTTP 服务、检查响应并确认两次运行后端口均关闭。真实测试脚本产物写在本次 `AP_GRAPH_OUTPUT_DIR`，原候选及预检身份留有记录。
4. **权限覆盖与隔离。** 精确的显式写授权不会被继承的同路径只读覆盖；嵌套只读目录、固定输入、旧输出和 Git 保护仍保留。授权的上游源码继续映射私有 checkout；同一目录对应多个固定版本时报告歧义，不任选第一个候选。撤销、目录身份、并发 Writer 和退出证明检查保持有效。
5. **新旧成员。** 新成员继承实际目标任务权限，并记录平台生成来源；成员权限设置在事务中记录变更。验收成员修改权限时从自己的已登记 Task 继承目录，不误用实施者目录。迁移只处理完整相等的平台旧默认，须同时有房间/任务归属、创建来源、未变更行证据、无后续权限修改记录和可核验的任务授权。缺少任一证据保留并报告 `ambiguous`，不把缺审计视为用户未修改。

本片的 `room_runtime_prepared` 是执行前资源/源码身份回执，不是验收通过证据；源码在执行中变化后的正式提交、证据绑定及依赖推进由 S03 处理。
