# HMI 拍照验证台

用户已在本会话以“do it”批准独立验证台方案，本任务手动执行，不启动 inbox 架构 PLAN 或自动派发。

目标：手机连续拍照，查看分段识别、纠错并下载拟写入当前 Web 参数结构的结果，快速形成回归案例。
当前障碍：Reader 有识别 HTTP，但缺跨图核对入口；部分 canonical 字段尚无 Web 映射。

| 阶段 | 结果 | 本次 |
| --- | --- | --- |
| 验证台 | 上传→识别→分段核对→拟写入→纠错留存 | 是 |
| 识别扩展 | 根据真实失败案例补充 profile/语义 | 否 |
| 真实 Web 写入 | 权限、并发、事务与审计验收 | 否 |

## S01 可操作的独立拍照验证台

- 目的：让用户直接发现读错、段序不明、单位与目标不匹配的问题。
- 结果：独立页面与服务，连续上传，原图/原始响应保留，分模块展示，可修改验证副本与纠错，下载快照。
- 实现：调用既有 recognize HTTP；原生 HTML/JS；本地文件批次；冻结 Web 源码依据的脱敏目标样例；保守映射仅作用于验证副本。
- 边界：新增 validation_lab 模块、页面、fixture、直接测试；不修改已有识别符号、不改 Web 仓、不连数据库、不重启生产服务。超过两文件是同一独立验证工具的 UI/服务/纯函数职责分离，没有数据库或识别算法改造，可在单会话收口。
- 验收：聚焦映射测试（段数、单位、冲突、缺值、纠错隔离）、HTTP 上传/恢复/下载测试、浏览器移动端与桌面检查；实际 OCR 能力与模拟接口验证分别记录。
- 前置与停止：固定当前 Web 来源与 Reader 合同版本；缺少语义只展示/复核，禁止猜测。不因不支持字段扩大识别算法任务；验证台可用并记录限制后停止。
- 交付物：独立工具提交、测试与使用记录、HANDOVER。原始图片与纠错存 output/，不入 Git。
