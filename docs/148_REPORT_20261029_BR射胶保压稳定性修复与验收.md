## 根因分层

| 层次 | 实测事实与旧假设 | 本轮处理 |
|---|---|---|
| 物理布局 | 段号条有 5 个段号，实际输入格并非每行都有 5 个。当前图射胶速度/压力/位置为 5/4/4 格，保压速度/压力/时间为 3/2/2 格。位置格错开半列。 | 按闭合输入框定位物理格，三行分别建立列序，不套固定坐标。 |
| OCR | 当前图 20 个分段显示值及两个切换标量均读对。射胶段号 OCR 全漏，保压只识别段号 2。历史图也有段号漏检与菜单/图表噪声。 | 数值 OCR 绑定到物理格。缺读保留 null，重复识别拒绝该格；至少一张同页表的段号须能核实，再核对两表列位。冲突时拒绝猜段号。 |
| 行列归属 | 旧提取器把每行 OCR 压紧后按数组下标编号，又直接 zip OCR 行到字段名。缺中间格或整行会错位。 | 独立从边框找到三行，漏整行 OCR 仍保留该行物理格；各行中缺格不移动其他段位。 |
| 视觉启用 | `fea9117` 要至少 4 个速度 token，`b39272d` 改成至少 3 个。两者仍把 OCR 框当完整物理段位。 | `_visual_active_count()` 从物理格内定位字形并测对比度，不依赖 OCR 数量或速度 OCR 置信度。原有 25 与 1.2 判据保持不变。 |
| 段数与原值 | 旧段数由可能已错位的非零数组推断，再裁掉残值；漏保压时间会把段数从 3 变成 2。 | 保留原始物理格数组与数值候选段数；只有布局、段号和视觉证据共同支持时才确认图像段数。缺值有效数组仍返回 null，不补零。 |
| 旧契约兼容 | Model v1 把列表中最大段号当末段。直接往旧列表加灰显第 5 段，会使第 4 段末位置丢失业务映射。 | 完整原屏事实保存在 `detail.raw_page_observations`、`raw_rows`、`physical_rows`；`page_observations` 继续保留既有有效段范围。没有增加另一套注册体系或修改 Model。 |
| 自动预选 | Model 的段规则与单字段置信度是不同门禁。单个低置信保压速度仅写 unknown，仍可能被其他有效压力/时间带入已启用段。 | Reader 同时写既有 `low_confidence` 原因，Model 原有单字段门禁即可拒绝自动选择。 |

在同一版本 15 原图和 OCR 上重放历史代码：`fea9117` 射胶 12 个分段字段 enabled、保压 0 个 enabled；`b39272d` 射胶 12、保压 6。本轮同样保留这 18 个有效字段，并增加对 OCR 缺读、物理格与段号的可靠核实。完整对比在 `artifacts/br_stability/v15-version-comparison.json`。

## Model 自动预选验证与限制

只读运行实际部署 Model 的 `import_observations()`，复用现有 0.1.2 页面候选及已审 overlay。七张图分别测试原输出、全部段状态强制 unknown、单个保压速度置低置信 unknown，共 21 个场景。

已核实的有效分段字段继续自动预选；原有 unknown 分段字段不自动预选；全部分段状态强制 unknown 后没有分段字段被自动预选；单个低置信保压速度也不会因同段压力/时间有效而被自动选择。版本 15 的 18 个有效分段字段及原有末段位置映射均通过。非分段 V/P 标量沿用其原有规则，不能把“段状态未知”测试表述成所有标量都禁止预选。

证据在 `model-import-results.json`，可重复脚本为 `model_import_probe.py`，输入为 `model-inputs.json`。脚本记录 Model 源码与候选文件 hash，没有修改 Model 源码或调用确认保存接口。

这属于导入模块验证，不是完整 HTTP、模板接纳或 UI 保存重开验收。实际调用完整模板加载器时遇到既有 `pinned Reader page package content hash mismatch`，已如实保留此限制；本轮不绕过该校验发布，也不扩张范围修 Model 模板包。该模块探针明确直接使用现有候选与 overlay，不宣称模板包校验通过。
