# 撤销补充候选分支合并门槛

用户在 Feishu DM 08a216 明确要求撤销补充候选必须合入独立分支的限制。

## 修改

- input-candidates 不再从原执行 gitRef 推导 integrationRefs；历史登记中的该字段不再约束发布。
- candidate-integration/store 只核对本轮固定输入与真实登记来源，不再执行“候选是旧基线祖先”的分支检查。
- upstream-inputs/delivered-inputs 复用前置执行的固定输入清单，把实际消费的补充候选带给后继，包含同主仓的后继和再下一跳。
  遵守 consumeUpstream 选择；无关消费者的历史输入不变。若多个前置提供真正分叉的版本，不擅自选一个冒充共同交付。
