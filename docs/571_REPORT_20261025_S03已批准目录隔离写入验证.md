## 改动

- 将进程退出观察移出资源认领事务；锁内重查重叠范围和完整退出身份。观察后新写作者和身份变化仍拒绝。
  `full_access` 是能力，不再作为 `/` 的写占用；按任务 cwd、声明根和补充资源根认领，重叠写入继续串行。
  图实施通过实际沙箱挂载限制到隔离源码；此修改没有削减普通主对话已有 full_access 能力，也不宣称阻止宿主管理员越过平台直接操作文件。
- 以现有固定输入 manifest 的 Reader SHA 建立独立 checkout，登记资源工作区事件与目录身份；重放保留未提交修改。
  原批准路径保持原义，运行证据保存批准版本、旧/当前 claim、原 Session、checkout 与最终挂载；审批人和旧申请不改写。
- 组装完固定输入、依赖和项目能力后核对挂载；原生协议启动前在相同 namespace 实际创建、写入、读回并删除临时探针文件。
  此探针是权限应用预检，不是业务验证。不可写时以退出 73 终止，原生 Agent 不启动。
- 每轮保存 prepared/effective 挂载与 Native Session 关联，接续返回不同 Native Session 时拒绝。
  实际应用失败按 `resource_application_failed` 留下平台阻塞，条件轮询不重复启动同一失败尝试；修复后由原话题明确接续。
- 旧资源申请 application=failed 是旧 claim 接续失败的历史记录，本轮没有把它篡改成 effective。
  后续实施通过任务范围授权继承，在新 TaskRun 保存核对记录与真实应用结果，无需重复批准 Reader 目录。
