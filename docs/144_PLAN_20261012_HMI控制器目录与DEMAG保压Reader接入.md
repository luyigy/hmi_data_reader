# HMI 控制器目录与 DEMAG 保压 Reader 接入计划

## 总体目标

后续接入其他 HMI 控制器时，开发者能在 Reader 仓按控制器找到页面规则和提取入口；同一张机台照片通过 HTTP、CLI、飞书入口得到一致、可追溯的原屏事实。本计划以 DEMAG 保压屏证明这条 Reader 路线，供主仓随后审核业务字段并完成保存重开。

## 当前障碍

- `templates/` 仍平铺 DEMAG 与 TACT5 模板；新建控制器目录不会自动进入现有页面路由。
- `scripts/extract_families/` 的 DEMAG 与 TACT5 文件按不同粒度平铺，共享分派和 HTTP 补读仍直接知道家族细节。
- DEMAG 已有注射、保压与背压等 profile，但不能把 profile 数量当作已确认的实屏数量；计量屏须以实图再确认。
- 本仓 TACT5 生效模板和归档存在既有未提交改动，不能混入结构迁移提交。

## 已核对的现场事实与不确定项

- `contracts/profiles.json` 已登记 `demag.injection_metering.multi_stage_holding` 为 verified，说明保压识别并非从零开始；注册表也披露 Z002/Z005 的 17 份样本全部参与过迭代修复，没有独立留出图。
- `scripts/page_template_registry.py` 已可按 `contracts/profiles.json` 的相对路径读取控制器子目录，无需新增一套目录扫描器；此前锚点未命中时会回退误选唯一的注册模板。`26ee50a` 加入模板可选择的 `require_anchor_match` 守卫，`b595562` 让历史别名回退也传入 OCR 行；实测 5 张保压 OCR 命中子目录、6 张射胶 OCR 仍使用平铺模板。真实 DEMAG 目录和模板尚未建立。
- 本机 5 份 Z002 保压矫正产物当前均输出 `demag.injection_metering.multi_stage_holding`，结果摘要已在 `26ee50a` 前后保持一致。另 3 份 Z005 历史矫正产物以 `holding_Z005...` 裸文件名运行时家族为 unknown 并拒识；它们不能直接代表带机台上下文的现网请求，S01 要补证据。
- `scripts/extract_fields.py` 已统一调用 `resolve_page_template()`，但 `extract_page_fields()` 直接知道 DEMAG 与 TACT5 的提取函数。`hmi_service.py` 还直接调用 TACT5 的局部补读函数。
- TACT5 页面事实和三入口补读已有本仓 143 PLAN；本计划不重开那条路线。DEMAG 目录名只能根据图像或控制器资料确认，不能把品牌名直接当成型号。

## 总体路线与归属

| 阶段 | 先解决什么 | 结束时可验证的结果 | 归属 |
| --- | --- | --- | --- |
| S01 冻结 DEMAG 基线 | 避免把既有正确结果当作新改进 | 已核对图、当前输出、页面身份和未知项有可回放对照 | 本 PLAN |
| S02 目录选页 | 注册子目录模板须避免误选 | 唯一匹配、歧义拒识和旧平铺回退均可验证 | 本 PLAN |
| S03 接入真实保压屏 | 目录机制只在夹具上成立 | Z002/Z005 保压图经目录产出独立页面规则和版本 | 本 PLAN |
| S04 收拢 DEMAG 提取入口 | 新页仍依赖平铺的家族函数 | DEMAG 的温度与工艺页有一个家族入口，输出与 S01/S03 基线一致 | 本 PLAN |
| TACT5 提取与补读 | 同图三入口一致性 | 按现有 143 PLAN 独立处理，不阻断 DEMAG | 既有计划 |
| 主仓落表 | Reader 原屏事实还须审核业务去向 | 人工确认、保存、读回、重开 | 主仓后续独立 PLAN |

本 PLAN 完成后，Reader 可用真实 DEMAG 保压照片交付独立版本的原屏事实包，旧结果可回放，DEMAG 家族提取入口也清楚。它不宣称主仓字段已写入，更不宣称未经实图确认的计量屏已存在。

## 架构与验收约束

`extract_one()` 仍是 HTTP、CLI、飞书共用入口。`contracts/profiles.json` 保持唯一生效页面注册表，模板路径可指向控制器目录；`controller.json` 仅记录控制器证据与共享说明，不再复制一份路由表。每张真实页面有独立规则和版本。先由路由唯一选页，再交给现有提取器；完成实页验证后，收拢 DEMAG 家族提取代码。通用 OCR 与网格原语继续复用。Reader 交付原屏值、单位、段序、启用态、坐标、来源及待核对状态；主仓拥有业务映射、权限、人工确认与写入权。

每片只改 Reader 仓，并在本仓独立提交和交接。修改符号前按 `AGENTS.md` 运行 GitNexus impact，提交前运行 detect_changes。历史超限文件不得增长，新文件不得达到 1000 行。所有回归先固定旧输出再改动；比对页面身份、字段、数值、单位、段序、启用态、警告和拒识，不只比较测试是否通过。

## 1. S01：冻结 DEMAG 保压的可回放基线

- **目的**：分清既有保压能力、待核实的控制器身份和真正缺口，避免后续目录迁移用不确定事实做路由。
- **完成后结果**：Z002/Z005 已确认照片的哈希、旧 profile/页面身份、当前 Reader 响应、字段真值范围、禁用段和拒识结果有一份可回放对照；样本是否参与过调参明确标注。
- **实现方法**：从现有 `contracts/profiles.json`、DEMAG 模板和样本中取证，运行当前共享提取入口，记录响应及最小回放命令；建立“控制器证据—真实页面—稳定 profile ID—模板文件名”对应表，不凭品牌推断型号。分别记录带机台上下文与裸文件名的家族路由；缺独立留出图时如实标为未验证。
- **修改边界**：Reader 短证据文档和必要的固定响应夹具；不改提取算法、路由或生效模板，不提交未经确认的原图。
- **验收**：一张已确认保压图可从原始输入重放到完整响应，输出与记录一致；至少一张不同布局或非保压图用于观察误路由，若没有可用样本则记录缺口并停止路由设计。哈希、版本和真值来源能复查。
- **前置与停止条件**：先确认本机样本路径和工作树归属。若 Z002/Z005 图或领域确认记录不可取得，停止，不用模板描述代替实图。
- **交付物**：基线对照、样本/版本清单、验证命令、Reader 提交及 S01 HANDOVER。此片独立固定参照系，避免后续路由与提取改动同时发生时无法定位差异。

## 2. S02：让 Reader 从控制器目录唯一选页

- **目的**：使新页面能按控制器归档并被现有共用入口发现，同时守住旧平铺模板行为。
- **完成后结果**：控制器目录中的测试页面能被唯一选中；无匹配或多匹配有明确状态，现有 DEMAG 和 TACT5 平铺页面结果与 S01 及原有样本一致。
- **实现方法**：沿用 `page_template_registry.py` 已支持的注册路径，让 `contracts/profiles.json` 指向目录内页面 JSON。复用 `26ee50a` 的 `require_anchor_match`，补齐缺模板、歧义和旧别名验证；不新增第二套路由表或目录扫描器。目录内容只声明页面证据，不引入可执行逻辑。
- **修改边界**：Reader 模板注册/路由文件、直接测试和最小目录夹具；不搬现网模板、不修改 `extract_fields.py` 或业务字段。多个入口已经共用 `resolve_page_template()`，不为 HTTP、CLI、飞书各写一套路由。
- **验收**：唯一匹配、歧义、缺文件和旧平铺回退有直接测试；用 S01 固定输入对比页面身份、来源、拒识和字段输出；`git diff --check`、GitNexus 影响与改动检测通过。
- **前置与停止条件**：S01 的控制器与页面对应表已确认。若目录名或锚点不能从实图区分保压与射胶，先保留旧路径，不能静默选一个页面。
- **交付物**：Reader 提交、目录格式说明、路由前后对照及 S02 HANDOVER。此片只建立加载能力，暂不移动现网 DEMAG 模板，降低路由和模板误差相互掩盖的风险。

## 3. S03：用 DEMAG 保压实图验证目录页面

- **目的**：证明目录机制能承载真实保压屏和独立版本，而非只在测试夹具成立。
- **完成后结果**：S01 中已确认的保压图由控制器目录定位到保压页面规则，输出原屏字段、单位、物理段序、启用态、坐标和来源；原 `injection_metering` profile 仍可回放。
- **实现方法**：按 S01 的证据命名控制器目录，添加控制器说明与 `holding.json`，在现有 `contracts/profiles.json` 注册其路径。文件名可叫 `holding.json`，内部仍保留 `page: injection_metering` 与稳定的 `demag.injection_metering.multi_stage_holding` profile ID，并声明 `require_anchor_match`；这样沿用现有 DEMAG 工艺提取和旁车逻辑，不重新定义对外页型。仅当实图证明页面规则不足时调整局部提取，不能顺手改数值语义或猜计量屏。
- **修改边界**：Reader 的控制器目录页面文件、注册项和直接测试；如需动提取算法，先单独说明原因与影响并保持同一可验收结果。不改主仓 YAML、准入表或保存链路。
- **验收**：Z002/Z005 逐字段同图对照 S01 基线与新路径；区分页面身份、数值、单位、段序、启用态和警告；用非保压图验证不会误入保压。旧版本回放及 HTTP/CLI 共用入口一致；真实飞书入口未跑时只报告模拟结论。无独立留出图则明确保留这一限制。
- **前置与停止条件**：S02 已提交；实图能确认控制器身份和保压页锚点。若不能唯一选页、缺单位或段序证据，保持候选待核对，不自动导入。
- **交付物**：Reader 页面包及固定版本、同图对照、版本与样本哈希、Reader 提交及 S03 HANDOVER；主仓业务目标待审清单。

## 4. S04：收拢 DEMAG 家族提取入口

- **目的**：让下一张 DEMAG 实屏有明确的提取入口，避免维护者在平铺文件和共享分派中重复找逻辑。
- **完成后结果**：DEMAG 温度及工艺页由一个家族入口接收模板与 OCR 事实并完成分派；S01/S03 的输出、错误与拒识保持一致。下一页可先按目录加页面规则，再判断是否需要家族专属解析。
- **实现方法**：先列出 `demag.py`、`demag_injection.py`、`extract_fields.py` 的调用和导入，再把 DEMAG 温度与工艺实现归入一个家族目录，由单一入口接到现有共享分派；迁移真实调用方和测试导入后删除旧路径。保留图像启用态、OCR 变体与错误处理。
- **修改边界**：Reader DEMAG 两个提取文件、一个家族入口、共享分派及直接测试；多文件移动是同一导入链的原子修改，不碰 TACT5 或其他家族，不修改模板/字段契约。
- **验收**：用 S01/S03 固定输入逐字段比较旧新输出，另检查温度、注射、保压、候选背压、歧义及失败结果；相关测试通过且无旧导入；GitNexus detect_changes 和长文件检查通过。
- **前置与停止条件**：S03 页面包与回归对照可重放；修改符号前做 GitNexus impact。若家族入口需要调用方知道额外内部规则，或结果语义变化，停止并重画接口，不用兼容包装隐藏两套实现。
- **交付物**：Reader 精准提交、导入链前后图、回归对照及 S04 HANDOVER。此片在实页已成立后只整理家族入口，使结构变动的失败能单独定位。

## 后续与验收退出

Reader 每片完成后单独提交、验证和交接。S04 结束时交付 DEMAG 保压固定页面包版本、样本哈希、字段证据、旧路径回放和家族入口清单。TACT5 继续依 143 PLAN 处理，不以其进度阻断 DEMAG；主仓在 Reader 包可验收后，另立 PLAN 审核字段映射、人工确认与保存重开。DEMAG 射胶按实图另接，计量先确认实际页面，不以工艺优化或背压候选冒充。
