# HMI 控制器目录与 DEMAG 保压 Reader 接入计划

## 总体目标

后续接入其他 HMI 控制器时，开发者能在 Reader 仓按控制器找到页面规则和提取入口；同一张机台照片通过 HTTP、CLI、飞书入口得到一致、可追溯的原屏事实。本计划以 DEMAG 保压屏证明这条 Reader 路线，供主仓随后审核业务字段并完成保存重开。

## 当前障碍

- `templates/` 仍平铺 DEMAG 与 TACT5 模板；新建控制器目录不会自动进入现有页面路由。
- `scripts/extract_families/` 的 DEMAG 与 TACT5 文件按不同粒度平铺，共享分派和 HTTP 补读仍直接知道家族细节。
- DEMAG 已有注射、保压与背压等 profile，但不能把 profile 数量当作已确认的实屏数量；计量屏须以实图再确认。
- 本仓 TACT5 生效模板和归档存在既有未提交改动，不能混入结构迁移提交。

## 总体路线与归属

| 阶段 | 解决的问题 | 可检查的结果 | 归属 |
| --- | --- | --- | --- |
| S01 控制器目录入口 | 新目录无法被路由读取 | Reader 能选唯一页面，旧平铺模板结果不变 | 本 PLAN |
| S02 DEMAG 家族入口 | DEMAG 提取职责分散 | 温度及工艺页经同一家族入口，输出不变 | 本 PLAN |
| S03 TACT5 家族入口 | 组合页提取和补读散开 | 三入口共用清楚入口，输出不变 | 本 PLAN |
| S04 DEMAG 保压实页 | 新目录尚未用实图证明 | 保压页版本包及原图证据可交付主仓 | 本 PLAN |
| 主仓落表 | 页面事实须审核业务目标 | 人工确认、保存、读回、重开 | 主仓后续独立 PLAN |
| 射胶、计量及其他控制器 | 其他实屏须逐页核定 | 每页独立证据与验收 | 后续 PLAN |

本 PLAN 完成后，Reader 可以用真实 DEMAG 保压照片产出独立版本的页面事实包，旧记录和旧入口仍可回放；它不宣称业务字段已经写入。TACT5 射胶、保压、计量在一张组合屏上，仍只用一个页面身份。目录以已核实的控制器身份命名，不凭品牌臆测型号。

## 架构边界

`extract_one()` 仍是 HTTP、CLI、飞书共用入口。统一路由根据控制器与页面证据选择规则，通用 OCR 与网格原语复用，段序、灰显和单位等专属解析留在对应家族模块。Reader 只交付原屏事实、证据、版本和待核对状态；主仓拥有业务映射、权限、人工确认和写入权。

每个 Slice 只改本 Reader 仓并在本仓交接。修改符号前依 `AGENTS.md` 做 GitNexus 影响分析，提交前做改动检测。已超 1000 行的历史文件不得增长，新文件不得达到 1000 行。

## 1. S01：让 Reader 能从控制器目录正确选页

- **目的**：消除新目录无法被现有平铺文件路由发现的障碍，同时守住旧机台识别行为。
- **完成后结果**：在固定测试目录中，Reader 按控制器证据和页面锚点选出唯一页面规则；歧义时明确拒绝；现有平铺 DEMAG、TACT5 样本输出不变。它先建立加载能力，避免在同一 Session 中同时移动现网模板而无法定位回归差异。
- **实现方法**：沿用 `page_template_registry.py` 的注册、路由、模板加载接口，增加对控制器目录及内部页面索引的读取；保留原有注册模板、平铺文件和 DEMAG 历史别名路径。目录索引只描述页面候选与共同证据，不执行 Python 代码。Reader 三入口仍由 `extract_one()` 使用同一选择结果。在 Reader 文档中说明目标目录与“逐页版本”关系。
- **修改边界**：Reader `scripts/page_template_registry.py` 与直接测试、最小目录夹具。不移动生产模板、不改业务映射或保存，不增长历史超限测试文件。本仓独立提交并记录 SHA。
- **验收**：Reader 单测覆盖目录内唯一匹配、歧义、缺模板、旧平铺回退；固定 DEMAG、TACT5 图片经 HTTP/CLI/飞书共享入口的页面身份和来源证据与基线一致；`git diff --check`、Reader GitNexus 影响与改动检测通过。
- **前置与停止条件**：先核对 Reader 的实际工作树与 AGENTS 规则、现有模板版本和入口调用方。若目录身份无法与实图/注册信息关联，或旧平铺页面出现静默改路由，停止并保留旧路径。
- **交付物**：Reader 精准提交、一份 Reader HANDOVER；按 Reader 模板/提取器/路由、主仓映射模板列实际文件与提交号，同图 OCR、字段映射和保存重开未测项明确标后续。

## 2. S02：让 DEMAG 提取代码按家族找到入口

- **目的**：解决 `demag.py` 与 `demag_injection.py` 平铺且名称不能直接说明职责的问题，给后续 DEMAG 新页一个固定接入点。
- **完成后结果**：DEMAG 温度与注射/保压现有样本通过同一 DEMAG 家族入口分派，识别字段、单位、段序、警告和拒识状态与改动前一致。此步只整理代码，是为 S04 隔离页面规则风险，不能与模板迁移混在一个 Session 判断失败原因。
- **实现方法**：在 `extract_families/demag/` 建小的显式入口；把现有温度和工艺提取实现按职责归位，复用共同段表算法。`extract_page_fields()` 只需知道 DEMAG 入口，不复制逐页算法。迁移真实调用方和测试导入后删除旧模块；代码移动保留错误处理、OCR 变体和图像启用态逻辑。
- **修改边界**：Reader 的两个 DEMAG 提取文件、家族入口、`extract_fields.py` 及其直接测试。文件数量超过通常两文件预警，是因为旧模块移动与所有调用方更新必须原子完成；不改模板、字段契约、HTTP 协议或主仓。
- **验收**：固定 DEMAG 温度、注射、保压、候选背压样本前后逐字段对照；专测禁用段、单位冲突和拒识；Reader 相关测试与三入口回归通过，旧导入不存在；GitNexus detect_changes 与长文件守卫通过。
- **前置与停止条件**：S01 已提交且旧路由可回放；移动前对每个被改符号做 Reader GitNexus impact。若结果结构或失败语义变化，停止代码整理，先查差异而非顺手改识别算法。
- **交付物**：Reader 提交和 Reader HANDOVER；列明 Reader 提取器、模板、路由及主仓沿用映射版本，同图 OCR 与字段映射分别报告，保存重开仍标待办。

## 3. S03：让 TACT5 组合页提取有清楚入口

- **目的**：清除另一处明显的平铺/直接调用模式，使“控制器目录 + 家族入口”不是 DEMAG 专属例外。
- **完成后结果**：TACT5 组合屏仍被识别为同一页，HTTP 补读、CLI 和飞书输出不变；后续增加另一张 TACT5 实屏时可以在家族内部定位。此步独立于 DEMAG 保压迁移，能用现有 TACT5 固定图片充分验证。
- **实现方法**：将 `tact5_process.py` 的提取与补读函数归入 TACT5 家族模块，通过一个明确入口供共享分派和 HTTP 使用；不改变实际 OCR 补读步骤或模板内容。更新全部调用与测试后删除旧文件。
- **修改边界**：Reader TACT5 提取文件、`extract_fields.py`、HTTP 入口和直接测试；不碰 TACT5 生效 JSON、归档或主仓固定包。多个相邻入口需要同时迁移，因为留下旧路径会造成两套实现。
- **验收**：同一 TACT5 固定照片比较字段、选项、单位、框、段数、补读状态及警告；HTTP/CLI/飞书回归通过，相关直接测试通过；确认未暂存现场未提交模板与归档，GitNexus 与长文件检查通过。
- **前置与停止条件**：S02 完成；先核对 Reader 未提交 TACT5 模板及测试夹具来源。若补读调用不能保持原行为或被误与脏模板一起提交，停止并恢复本 Slice 范围内的方案，不改现场内容。
- **交付物**：Reader 精准提交和 Reader HANDOVER；附两仓模板/映射/路由清单及同图 OCR 对照，映射与保存重开未测明确记待办。

## 4. S04：把 DEMAG 保压屏作为目录中的第一张真实页面

- **目的**：证明新组织方式能承载真实机台屏幕，而不是只在测试夹具里成立。
- **完成后结果**：已确认的 DEMAG 保压屏从控制器目录读取独立页面规则，Reader 输出完整页面 ID、版本、数值、单位、物理段序、启用态及原图证据，并可导出供主仓审核的页面包；原 DEMAG 平铺模板和历史识别可回放。主仓写入留给主仓后续独立 PLAN，因为 Reader 不拥有业务目标。
- **实现方法**：先建立实图页面标题、Z002/Z005 控制器证据、布局、旧 profile、模板和提取入口对应表；确认目录名与保压页面名。把保压所需稳定规则纳入目录内页面 JSON 与注册表，复用 S02 的提取算法；只在页面确有差异时调整局部解析，不猜计量语义。版本独立于其他 DEMAG 屏。
- **修改边界**：Reader DEMAG 目录的控制器索引/保压页 JSON、注册项、必要的家族提取局部与短测试；主仓旧 YAML、页面包接受表及表单暂不改。原图和真值保留原件，不把现场敏感照片无意提交。
- **验收**：用已核对的 Z002/Z005 照片逐字段比较新版与旧版 Reader 结果，另用未参与调参的图片或明确披露无独立留出；检查 HTTP/CLI/飞书一致、歧义拒识、旧版本回放和版本包内容。主仓映射目标逐项列待审，不把 OCR 通过算作落表通过。
- **前置与停止条件**：S01、S02 已完成；实图与控制器身份有证据。若保压与射胶锚点无法可靠区分，或新包缺少必要单位/段序证据，停止并保持候选待核对，不把不确定值自动导入。
- **交付物**：Reader 提交和 Reader HANDOVER；列出页面模板、提取器、注册与主仓旧映射的路径和提交号，附同图 OCR 结果和主仓待完成映射清单。

## 后续与验收退出

Reader 每个 Slice 单独提交、验证并创建本仓 HANDOVER。S04 结束时，交付固定页面包版本、样本哈希、字段与证据清单、旧路径回放结果；由主仓另立 PLAN 审核字段映射与保存重开。DEMAG 射胶按相同路径后续接入；计量先核实实际屏幕，不以工艺优化或背压候选冒充。其他控制器逐页扩展，不批量改名。

本计划处于草案状态，等待人工审批；审批后才改为 `ready / start_first_slice` 并写入可执行 Prompt。关联主仓已废止的跨仓计划：`docs/dev/545_PLAN_20261012_HMI控制器目录与DEMAG首屏接入.md`。现有工作树的 TACT5 模板及归档不属于本计划提交。
