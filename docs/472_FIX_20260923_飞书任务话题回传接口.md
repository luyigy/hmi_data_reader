# 飞书任务话题回传接口修复

## 问题与根因

471 HANDOVER 实群验收发现 create-message API 不接受 `receive_id_type=thread_id`。此前 relay、progress 和 session continuity 都使用该参数，mock 又错误接受它，导致本地测试通过、真实输出失败。

按本地官方 SDK `im.message.reply` 契约，复用 `POST /im/v1/messages/{message_id}/reply`，在 body 设置 `reply_in_thread=true`；`uuid` 同样属于 body。官方接口说明：https://open.feishu.cn/document/server-docs/im-v1/message/reply。

## 修复

- 统一从持久绑定解析 chat 与根消息。话题缺少根消息时拒绝发送，禁止退回群根。
- 文字、卡片和图片发送支持 `threadRootMessageId`，进入现有 reply API；移除 create 发送类型中的 thread_id。
- 最终结果、文字降级、进度首卡/重发、图片、会话失效提示均传递对应任务根消息。普通群与私聊保留 create 路径。
- 进度最终卡 PATCH 同时检查 HTTP 状态和飞书业务码，失败后在同一话题重发。

## 验证

- `feishu-thread-output`：真实 HTTP 形状断言，文字/卡片/图片、UUID body、进度 PATCH 失败重发、reply 失败不降级、旧群发送。
- `feishu-live-room-relay`：正确根消息、卡片失败的文字降级、缺根消息拒绝发送。

- `feishu-task-thread-loop`：隔离 PostgreSQL schema，双话题输出、进度与最终卡重发、会话失效提示、控制作用域和旧群回归。出站请求 mock，不发送真实测试消息。
