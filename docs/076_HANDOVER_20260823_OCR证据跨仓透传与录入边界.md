# OCR 证据跨仓透传与录入边界交接

## 本次完成

- `hmi_service.py` 在每次 OCR 成功后返回 `ocr_evidence`：模型名、画面尺寸，以及每行文字、置信度和坐标。
- OCR 证据独立于模板与字段提取结果返回。模板不匹配、字段不完整或状态为 `review/reject`，都不能抹掉已经读到的 OCR 证据。
- Web 开发仓和 deploy worktree 已同步接收该可选字段；旧 Reader 不返回时兼容为 `null`。
- 未把离线 VLM 接入 8765 同步请求，未允许 VLM 直接生成数值或修改 Web 字段。

## 核心原则

```text
图片 -> OCR 原始证据 -> 候选字段映射 -> Web 契约校验 -> 人工确认 -> 工艺参数
         必须保留          可以失败          必须通过       必须审计
```

字段映射是 OCR 的下游消费者，不能成为 OCR 结果返回和保存的前置条件。必须分别表达：

- `ocr_evidence` 为空或置信度低：OCR 没读到或读得不可靠；
- 有 `ocr_evidence`、没有候选字段：映射失败；
- 有候选字段、契约不通过：单位、结构、段序、Profile 或目标字段不安全；
- 候选通过门禁：只进入待确认预填，不等于正式工艺参数。

这样新增机台、页面或字段目录时，映射覆盖率可以逐步提高，但不能阻塞、覆盖或丢失已经取得的 OCR 证据。

## 正确录入的职责边界

Reader 只负责视觉事实和 Reader 字段候选：

1. 保存 OCR token/行、坐标、置信度和使用的模型；
2. 确定性规则或模板只能引用这些证据构造候选值；
3. 无法确定的字段保留为 `unresolved`，不得猜值；
4. `status/profile/contract/warnings` 明确候选是否可进入下游。

Web 是业务字段和写入规则的唯一所有者：

1. Web 提供允许的字段、类型、单位、数组/段结构和目标路径目录；
2. Reader 字段必须通过显式映射进入 Web 目录，不接受任意键；
3. OCR 原值、候选值、确认值和最终写入值分层保存，保留来源与修订记录；
4. 未映射证据仍随采集快照保存，允许以后用新目录重新映射；
5. 正式工艺参数仍经过 Web Schema、工艺护栏、人工确认、审批和变更审计。

跨仓合同宜以稳定字段 ID 为主键，并记录 `value_type`、单位、`source_pages`、`web_target`、段序、允许范围和合同版本。合同应由 Web 发布，Reader 消费；Reader 不复制或发明第三套业务 Schema。

## VLM 的位置与接入条件

VLM 只适合做“证据到目录字段的候选映射”：

- 输入只含当前页尚未解决的合法字段子集和相关 OCR token；
- 输出只能选择字段 ID、引用 token、段序和有效段数；
- 数值必须由程序从被引用 token 解析，VLM 不得直接生成业务数值；
- 单字段失败只保留该字段 `unresolved`，不能清空兄弟字段或覆盖确定性结果；
- 首次生产接入只能是默认关闭的异步/shadow 对照，不改变 8765 响应和 Web 写入。

当前不接生产。固定 89 例最近结果为 numeric accuracy `0.8295`、error auto-import rate `0.0321`、rejection accuracy `0.8387`，均未达到 `>=0.95 / 0 / 1` 门禁，数组长度和段序也未通过。只有重新达到全部门禁、确认延迟预算并由用户批准后，才可进入 shadow；shadow 证明持续稳定后，仍应先限定在 `review` 候选，不得直接写正式工艺参数。
