## 实现与边界

- 界面直接消费 `candidates`，不从最后一次 attempts 或旧 preview 反推候选。按原文相同的参数分组，设定/实际等角色分列，以段/温区标签及同标签出现次序对齐，不猜同义参数或屏幕段序。不同角色缺少该段时明确显示缺项；目录外参数可见，完整原响应和所有层次的额外元数据可展开。
- 原图按钮保留整图与完整历史响应；参数名、单位、角色、数值、段/温区可修改。原值和原始元数据取自不可变 `candidate.result`，编辑在完整深拷贝上进行。UI 不增删/重排字段，原值按对应数组位置对照；外部 API 若已重排确认副本，须以完整原始响应核实对应关系，不能仅依赖行位置。
- 新识别没有 review 时强制逐项待确认，不接受 Reader 自带标记为人工确认。逐项核对写入副本的 `needs_confirmation`；数值/段修改撤回本项确认，参数名/单位/角色修改撤回整字段各项确认，同时撤回图片整体确认。整体确认必须由用户显式操作，逐项完成不自动确认图片；缺值、非法值及空候选不能整体确认。问题/画面不完整提示持续显示；不把确认转换为业务 safe。
- 保存按图片提交 `drafts[image_id]={attempt,result,confirmed}`，沿用 revision 和用户隔离。每次成功更新本地 revision；后续保存失败时不 adopt、不丢本地编辑，可继续重试。多图保存不是跨请求事务，前面已成功的图片可能已落盘；完整成功后 adopt 服务返回，刷新/下载继续使用 S04 结构。未确认编辑也可保存。
- 首次失败/未识别在照片卡片提示，重试失败同时展示错误和当前有效候选；新的成功结果（包括空候选）依服务返回重建编辑状态，不沿用旧确认。纯候选批次隐藏旧标准字段预览；混合或旧批次有旧 rows 时仍可展开原有映射表。
- 默认收起业务目标结构。照片的模温 select 仅在候选标签/目录 ID 有明确模温线索、已有用户选择或用户主动展开“手动选择业务目标”时可见，不用页面类型/Profile 判断。词汇提示只控制可见性，不进行业务映射；未涵盖词汇可主动展开。
- 编辑控件用文本节点、原生 label/input/checkbox/details，复用现有窄屏样式。字段角色/单位控件放在表格外，避免移动端隐藏表头时一起隐藏。桌面、移动端和键盘可用性均尚待浏览器确认。
