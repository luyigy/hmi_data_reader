# 60 飞书 Session 连续性方案文档

## 日期
2026-04-04

## 背景

飞书里 agent 长时间运行后上下文会打满，目前没有标准的"交棒"机制。
目标是做到：提醒 → 交接文档 → 新 session 拿文档继续干活。

---

## 三阶段计划

### 阶段 1：`/ap handover`（先做）

目标：让当前 agent 一键产出交接材料。

**飞书命令：**
```
/ap handover
/ap handover --title="feishu session continuity"
```

**最小输出：**
- `docs/NN_..._HANDOVER.md`（固定模板）
- 飞书里一条简短摘要消息

**交接文档固定模板：**
- 当前目标
- 已完成
- 未完成
- 风险/阻塞
- 下一步
- 相关文件
- 验证状态

---

### 阶段 2：上下文水位提醒

目标：在"快该交棒时"提醒，不等彻底爆掉。

**启发式判断（不追求精确 token 计数）：**
- 对话轮次超过阈值
- 最近 N 条消息总长度超过阈值
- TaskRun / TaskRunEvent 累积过大
- 同一 agent 连续运行时间过长

**提醒方式：** 系统消息，不自动切
```
系统提示：当前 session 上下文已接近阈值，建议执行 /ap handover 后切换新 session。
```

---

### 阶段 3：`/ap new-session`

目标：让新 session 拿到交接材料并继续。

**命令：**
```
/ap new-session --from-handover=docs/60_xxx.md
```

**新 session 启动只做三件事：**
1. 先读文档
2. 复述当前状态
3. 继续执行"下一步"

---

## 实现边界（第一版不做）

- 不做自动迁移消息历史
- 不做多 agent 并行 session 编排
- 不做复杂 token 统计
- 不做强制切换（只提醒）
