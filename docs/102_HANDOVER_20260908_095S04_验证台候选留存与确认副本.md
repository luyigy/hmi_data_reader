- 旧 review 请求继续可用。仅保存 drafts 时可省略业务 target；未传 edits/note 保留旧值。drafts 为按图片更新，未传图片保持原副本；用 confirmed=false 保存未确认修改。既有用户命名空间、鉴权、revision、锁与原子文件替换沿用，不批量迁移旧数据。

## S05 接口示例

`PUT /api/sessions/{sid}/review` 的 JSON 示意（未执行请求）：

```json
{
  "expected_revision": 2,
  "drafts": {
    "<image-id>": {
      "attempt": 1,
      "result": {"sections": [], "questions": ["原图需补拍"]},
      "confirmed": false
    }
  }
}
```

实际 result 应为完整人工核对副本，包括未改动字段及证据；逐项纠错可使用原 items/needs_confirmation 结构，confirmed 表示用户对该图片副本的整体确认，不能用它推导业务安全。用户要撤回确认时写 false。S05 必须消费 candidates，而非从 attempts 最后一项或旧 preview 推断候选；显示 last_error、空结果及暂不可映射，刷新和下载使用同一返回结构。当前前端尚未接线，因此不能声称用户界面已完成闭环。
