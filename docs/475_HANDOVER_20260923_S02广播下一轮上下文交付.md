## 接入与确认语义

- 实际路径：`executeLiveRoomReplyViaAcpx` → `runLiveRoomAcpxAttempt` → `executeAcpxTaskRun` → `executeParticipant` → local / SSH / Gateway harness。`live-room-members.ts` 的 transcript 使用也已检查；水位视图不是实际输入的唯一来源。
- 首次执行追加到 `taskRoomContext.transcript`；续聊同时追加到 `participant.continuationMessage`。保留广播 ID、序号、发送者、来源消息 ID、发布时间、原文及分段范围，标明是用户内容。
- 未采用普通聊天历史追加：现有历史有 12 条/4000 字符裁剪且会把最后一个 `task-room-user` 当作最高优先级任务指令；原生续聊还会绕过完整历史。这些机制不能可靠确认广播，故直接复用 S01 不可变记录重建公共输入，只新增一张成员消费表。
- `FeishuGroupBroadcastMemberDelivery` 唯一键为 target/member/session；保存已送达 UTF-16 offset 和是否完整。session 包含任务会话、适用成员/全房 reset 标记及执行后端/harness；有原生续聊时增加 provider session ID，并用成功返回的 session ID 确认。Local Codex 每轮重建 CLI 输入，沿用逻辑会话消费进度；明确 new-session 会重放适用广播。新成员独立从未消费记录开始。
- 准备输入只读；成功执行且本轮收尾通过后，确认准备时冻结的 receipt。失败、启动失败、被中断均不确认；运行途中新发布不在 receipt 内，留待下一轮。确认写库失败会记录错误、保留重试，不能把已完成模型运行改成失败。
- 事务内唯一键去重，offset 只单调前进。并发重试允许再次发送同一稳定 ID，不承诺外部模型恰好执行一次，也不把确认解释为模型理解或采纳。
- 每轮最多 8 条、4000 个原文 UTF-16 单元（来源元数据及 JSON 转义开销另计）；长广播按顺序分段，不拆代理对。未送部分不确认，不因短历史窗口截断而丢失。已消费内容仍存于 S01，显式会话重置可重放；消费确认不是永久记忆承诺。
- 不读取当前活跃绑定来扩大目标范围：关闭模式后原目标仍可读，发布后新任务/其他群/其他 app 不误收。
