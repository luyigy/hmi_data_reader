## 4. 审阅裁定与最小代码结构

### 4.1 一个执行入口，图只补上下文

复用现有 LiveRoom 目标选择、队列、Steering、TaskRun、回复生命周期和原生会话接续。
引入或提取一个小的图上下文解析函数：按实际目标成员/被回复卡片找到 Task、Session、工作区、
授权与图归属，不判断“这句话能不能实施”，不添加关键词恢复识别器、项目黑白名单或第三套调度器。

实施者对应 childTaskId 与自己的 worktree；验收/架构角色对应其历史 Task、Session 与运行目录。
回复特定卡片优先使用 relay 绑定的参与方；普通消息使用已选目标成员的有效会话。
保留显式新会话和失效会话处理；不悄悄改送其他角色，不把用户已有明确要求变成新的权限确认。
多 execution 节点必须准确映射各仓与候选，不用第一个 execution 代表整个验收。

### 4.2 权限与目录由实际授权决定

权限沿用成员显式设置、任务授权及已批准补充资源；图阶段、任务 ID 前缀和有无调度 claim 不得增减权限。
成员创建和请求装配中不再注入通用只读覆盖；resource grants 按真实用户、任务、运行身份及有效范围核验。
**不采纳“只有 implementer 才能获得写授权”作为新规则**；任何目标 Agent 都可使用其已获批的写目录。

验收者默认接回自己的隔离可写运行目录；候选源码沿用明确的任务授权或既有独立验收约定。
**不能仅因角色叫 tester 就再次全局只读**；用户明确授予的源码或额外目录写权限须保留。
证据绑定实际受测提交；若 Agent 改变源码，应形成新版本并重新测试，不能把旧候选结论套到新版本。
固定提交与历史证据可保留不可变引用，不需要把 Agent 的整个会话冻结。

### 4.3 任务关联与自动调度 claim 分开

在 AcpxRunRequest 中提取 GraphAssociation，仅提供任务归属（实际 run/node 与参与 execution 集合）、
角色及消息身份，由平台根据已登记任务关系生成，不信任 Agent 自报归属。
GraphAssociation 不负责阶段判断、业务重试或恢复决策；具体类型复用现有领域类型，不另造平行状态机。
Task Graph 只负责依赖编排，不限制正常对话；安全执行与结果记录复用现有机制，不增加额外控制层。
graphExecution / graphReview 的 claim 继续用于自动调度幂等与重试预算，不再作为普通聊天运行许可。
graphConversation 独立运行类型最终退出；历史 metadata 可只读解码，不能借兼容重新启动旧问答。

### 4.4 一个工作区同一时刻只有一个写入者

复用现有事务锁和 Writer 退出证明，但 TaskSession 行锁单独不足以保护不同 Session 共用的 worktree。
聊天室与自动调度必须使用相同的任务/工作区占用边界、锁顺序和原子占用操作；
禁止“先查无运行，稍后再启动”的竞态。验收固定输入另绑定其受测版本，不允许证据覆盖新候选。
已运行时复用 Steering 或排队；自动调度 defer。旧进程状态未知不能仅凭数据库 completed 当成退出。
不保留 conversation_followup_reserved 的第二套预约流，也不新增房间级状态机。

### 4.5 结果只收一次，普通聊天不被自动提交

抽取现有 TASK_GRAPH_IMPLEMENTATION、TASK_GRAPH_REVIEW、ticketVerification 的结果解析与入账，
由自动执行和聊天室执行共享。角色/验收方式来自用户真实选择；调整以追加授权记录表达，不改历史快照。
没有正式结果的普通对话，只记录对话及运行，不推断完成/失败，**不因发现工作区有改动就自动 git commit 或更新候选**。
工作现场保留；Agent 按项目约定提交交付后再走现有集成与证据记录。复用已有 checkpoint 合同的情况须明确来源。

结果事务核验任务归属、实际角色/授权、提交与证据身份及当前候选版本；使用 TaskRun/结果标识幂等，
重复回调、服务重启和并发提交不重复推进。旧候选的结论保存为历史，不能自动通过当前新版本。
普通回答不强制补结果口令；有正式交付意图但结果格式错误则说明实际缺项，不冒充通过。
平台检查证据归属和格式，不重新代跑项目测试，也不再按业务错误分类自动重做实施。

exhausted / conditions_unchanged 仅限制后台自动重试；显式用户运行不必清空旧次数、伪造条件变化或先恢复旧 claim。
普通聊天也不自动把旧节点 exhausted 改为 passed。只有实际结果按合同推进。

工作流归属从已登记的图执行关系/工作流绑定解析；同时读取到冲突归属时报告真实配置错误，不能同时唤醒两边。
不通过存在 HANDOVER 文件、tickets、taskId 前缀或 graphConversation 字段猜归属。
graph 的完成只通知图；handover 的完成只通知 watcher；普通聊天只保存结果。
