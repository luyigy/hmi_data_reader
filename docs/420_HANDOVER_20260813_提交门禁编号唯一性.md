# HANDOVER · 提交门禁编号唯一性

已完成 S02：提交门禁做分支级编号唯一性校验（对应 408 B02）。钩子侧无需改动（已走
`--hook-batch`），全部改动在 validator 与其 Reader 抽象内。

**实现**（`src/lib/scheduled-jobs/workflow-validator.ts`）：`validateWorkflowDocuments` 在
`contract.numbering.unique` 且 Reader 支持 `list` 时，对目标 ref 执行一次
`git ls-tree -r --name-only <ref> -- <branch_spaces.root>`，与本次 filePaths 合并去重后按
候选文档所在分支空间目录（`dirname(filePath)`，与 watcher 的 `watchRoot` 口径一致）做同号
碰撞检查。同号两份即抛 `WorkflowDocumentValidationError`（code
`DOCUMENT_NUMBER_DUPLICATE`，error 级），报出新增与现存两份路径，钩子按
`WORKFLOW_DOCUMENT_VALIDATION_FAILED` 拒绝提交。作用域严格限定**同一分支空间目录**（合同
`numbering.scope: branch_space`；`scripts/new-workflow-document.ts` 的取号同样按单目录自增），
跨分支空间（如 `docs/branch` 与 `docs/branch/main`）允许重号——初版按 root 递归判重被
`tests/workflow-watcher.test.ts` 的 root/main 双空间 000 夹具拦下后修正。仅当本次提交改动
PLAN/HANDOVER 时触发（钩子只对这些文件调 validator）；`Reader.list` 失败抛普通 Error，按
现状降级为告警放行，不冻结提交。

**Reader 扩展**（`src/lib/scheduled-jobs/workflow-reader.ts`）：`Reader` 新增可选
`list(dirPath)`；`GitRefReader` 用 `ls-tree -r --name-only <ref>` 实现，`WorkingTreeReader`
委托 fallback（HEAD）——preflight 场景由 filePaths 并集覆盖未提交新文档。

**测试**（`tests/workflow-validator.test.ts`）：ref 已有 001 PLAN 时再交同目录第二份 001
HANDOVER 被拒，报错同时列出新增与现存路径；跨分支空间（`docs/021_branch/`）同号放行；不同
编号（022）放行。重建 `src/lib/scheduled-jobs/generated/workflow-validator.cjs` 并同步部署到
`.git/agent-platform/workflow-validator.cjs`（与 `ensureAppendOnlyGitRef` 安装口径一致）。
