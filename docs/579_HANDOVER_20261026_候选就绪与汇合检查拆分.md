## 实现

candidate-integration.ts 导出 assertCandidateInputsReady：保留当前 claim 的固定清单摘要检查、缺失清单保护、候选登记事件、节点/执行/仓库/SHA 对应关系及 integrationRefs 校验，返回已验证的候选引用。
此函数不检查 Git 祖先关系，也不代表业务验收通过。登记证据仍由既有 registerInputCandidate 校验，本轮没有增加业务证据认证能力。
assertCandidateInputsIntegrated 复用上述检查后，继续检查每个候选是否已进入全部已登记目标 Ref。

store.ts 的 completeUnverifiedNode、submitNodeVerification、approveHumanNode 三处调用保持不变。
既有 Graph 在候选未汇合时仍不能发布通过或释放后继。新增 Ready 接口尚未被这些完成入口单独使用。
