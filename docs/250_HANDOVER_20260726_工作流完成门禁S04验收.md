# HANDOVER · 工作流完成门禁 S04 验收

## 完成内容

- `/ap job stop <job-id>` 通过运行记录传递跨进程停止请求，并取消匹配的当前执行。
- `/ap job disable` 仍只阻止后续运行；stop 不修改 enabled 状态。
- 人工停止记录为 `failed + job cancelled by operator`，与 `timed_out` 明确区分。
- PLAN 正文从待审批 commit 读取并导入飞书文档；审批卡包含文档链接。
- 文档 URL 先写入 pending cursor，再在下一次 watcher 执行中复用并发卡；发卡重试不重复导入。
- 修订 PLAN 使用新 commit 内容生成新文档和新卡片。

## 边界

- stop 依赖 handler 遵守 `AbortSignal`；已发出的不可取消外部请求不会被强杀。
- runner 以 100ms 周期读取本次运行的停止请求，因此跨进程取消存在一个轮询周期的延迟。
- 未增加数据库 schema、队列、依赖或新的文档转换服务。

## 验证

- 隔离 scheduled job：人工停止、重复停止、跨进程停止、其他 job 不受影响、超时区分。
- 假飞书导入/发卡：commit 正文、链接、重试复用、导入失败、修订新文档。
- Feishu job command、workflow watcher、validator、completion gate 聚焦测试。
- TypeScript `--noEmit`、`git diff --check`、workflow validator 和 GitNexus `detect_changes`。
