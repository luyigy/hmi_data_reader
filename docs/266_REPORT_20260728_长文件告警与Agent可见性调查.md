# REPORT · 长文件告警与 Agent 可见性调查

## 结论

现有 `long-file-detector` 每十分钟扫描 `config/projects.yaml` 中配置 ref 的已提交树；命中
文件保存在 `ScheduledJobState.cursorJson`，仅在首次命中、内容变化或行数增加时发飞书消息。
它不会把命中列表传入 Coding Agent 的启动 Prompt。

`src/lib/acpx/runner.ts` 当前为 1963 行，已超过合同 `blocking_lines: 1000`；近期提交中从
1909 行增长到 1963 行。仓库 `AGENTS.md` 已规定历史超限文件不得继续增长，但未要求 Agent
在开工时计算当前命中列表，也没有一个完成门禁阻止其继续增长。

## 建议

不要在 `AGENTS.md` 静态维护名单。新增一个从
`docs/workflow/workflow-contract.yaml` 读取阈值的单一检查命令：开工时输出当前超限文件，完成时
与任务 baseline 对比并拒绝“已有超限文件增长”或“新文件跨过阻断阈值”。将它接入平台 TaskRun
完成门禁和 CI/提交检查；定时飞书告警保留为观测，不作为防线。

本报告仅记录调查，未修改检查器、Agent Prompt、完成门禁或任何业务代码。
