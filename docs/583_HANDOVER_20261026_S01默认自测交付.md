## 遇到的问题与处理

- GitNexus `list_repos` 返回空列表，`impact(configureGraphRoles)` 和 `detect_changes` 均报
  `No indexed repositories`。没有冒称分析成功，也未扩大本票去重建索引。
  源码核对 configureGraphRoles 的两个入口（新提议、待确认卡配置），以及 proposal/card → snapshot →
  implementationQuality → submitNodeVerification → releaseReadyNodes；用上述隔离回归补证。
- 原命令 `node scripts/sandbox-postgres-session.mjs run ...` 在此会话缺少 `/etc/passwd`，initdb 无法识别 UID 1000。
  外层嵌套 bwrap 尝试又得到 `spawn /usr/bin/bwrap EACCES`。最终复用仓库 renderer 生成的原沙箱命令，
  在同一测试沙箱只读挂入 fixture passwd/nsswitch/machine-id 和空项目注册表；宿主文件、真实 projects.yaml
  及权限策略未修改。空注册表避免 fixture 启动去校验未挂载的无关业务仓库。
- 测试初次通过新提议入口时，临时仓不在默认授权根目录；仅在 fixture 提议创建阶段设置临时根，随后还原。
- Python 输入测试初次受到父测试会话的 AP_PROJECT_REPOSITORY 和 Anaconda PATH 影响而失败。
  测试启动器不继承父项目指向，并明确使用系统 Python PATH 后，同一套 runtime-inputs 回归通过。
  未修改平台环境白名单或业务环境选择逻辑。
- 原始 `npx tsc --noEmit --incremental false` 内存不足；提高堆到 8 GiB 后发现 7 个错误，
  全部来自历史 `output/manual-chat-s03-baseline/tests/task-resource-workspace.fixture.ts` 的旧接口副本。
  保留 `types-initial.log` / `types-with-output.log`。临时 tsconfig 继承仓库配置，只额外排除 output，
  当前源码最终检查通过；未删除旧输出、未修改仓库 tsconfig 或掩盖实际源码错误。

- 文档预检曾发现 581 设为 none 后仍保留首票 Prompt，触发 PROMPT_FORBIDDEN；
  已移除该自动块，原文保留在 Git 历史中。583 的唯一可执行 Prompt 只接续 S02。
