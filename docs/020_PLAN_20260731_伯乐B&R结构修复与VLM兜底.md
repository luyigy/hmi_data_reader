# 伯乐 B&R 结构修复与局部 VLM 兜底计划

## 1. 决策摘要

采用分层兜底，但不立即引入 VLM：PaddleOCR + 模板继续作为零 API 成本、低延迟、确定性的主链路；先修正已确认的真值问题，再给 B_AND_R 一次结构提取修复机会。只有 B_AND_R 家族门禁仍失败，才启动异常温度表 ROI 的局部 VLM PoC。

本 PLAN 是 013 PLAN 的伯乐 S3 后续专项，不回写已经履行过的 015 PLAN。015 针对 TACT，历史约束和执行事实保持不变。

## 2. 已知基线与问题定位

现有 `output/bole_calib/accuracy_report_bole_calib.json` 汇总 20 张图、528 个数值元素：

| 范围 | 图片数 | 不匹配 | numeric_accuracy | 主要现象 |
|---|---:|---:|---:|---|
| 全部 | 20 | 61 | 0.8845 | 双门禁当前 FAIL |
| B_AND_R | 7 | 40 | 约 0.8148 | 39 个真实问题集中在 4 张图，主要为整组行列错配 |
| KEBA | 13 | 21 | 约 0.9327 | 18 个错误集中在一张已 reject 的报警态图 |

B_AND_R 的主要根因不是普通 `0/O/8` 字符混淆，而是列头 `#3/#4/#5` 被吸入实际温度、实际温度被推入偏差行等结构对应关系丢失。继续泛调 CLAHE 的收益低且容易单图过拟合。

报告中唯一 `status=ok` 不匹配为 rank09 第 6 列：真值 260.1、基础 OCR/CLAHE/提取均为 250.1；原图复核也支持 250.1。该项是真值假阳性，不是 Validation Guard 漏网。修正后预期整体为 468/528（约 0.8864），错误自动入库率为 0。

## 3. 方案与切片

### S1：真值修正与可信基线

1. 按 workflow prompt 对 rank09 做可追溯复核，只修正有原图与两路 OCR 一致证据的单个真值。
2. 不重跑 OCR，仅用现有提取产物重建报告，避免把真值修正与提取改动混在同一基线。
3. 报告增加整体、KEBA、B_AND_R 分家族口径；后续 B_AND_R 止损决策不得再由 KEBA+B_AND_R 汇总值替代。

**停止条件**：真值审计可追溯；修正后计数与预期一致；分家族基线完整；HANDOVER 已落盘。若证据或计数不一致，停止且不进入 S2。

### S2：一次 B_AND_R 行列结构修复

只允许一个实现迭代，目标限定为：

- 阻止 `#N` 列头进入数值单元格；
- 保持实际/设定/高偏差/低偏差/输出行的对应关系；
- 用列数、行标签和目标单元格完整性识别整组错位；
- 复用现有模板、提取器与 warning，不新增插件、工厂或通用框架；
- 不再泛调 CLAHE、灰度或二值化参数。

实现后仅运行一次伯乐 20 图链路并生成整体及分家族六指标报告，同时确认 ZizES、TACT 既有聚焦检查不退化。

**B_AND_R 止损门禁**：

| 指标 | 门槛 |
|---|---:|
| numeric_accuracy | >= 0.95 |
| error_auto_import_rate | 严格 = 0，且 `status=ok` 分母不得为空 |

KEBA 必须单独报告且不得因本次 B_AND_R 改动回退；KEBA 是否达到 013 PLAN 的独立家族门禁仍由 013 S3 收口，不用 KEBA 汇总值掩盖或阻塞本 PLAN 的 B_AND_R 止损判断。

- 两项均通过：停止，不建设 VLM fallback；回到 013 S3 处理 KEBA 与伯乐阶段收口。
- 任一失败：立即停止 Paddle 调参，HANDOVER 指向 S3；不得追加“再试一轮”。

### S3：条件式局部 VLM fallback PoC

本切片仅在 S2 明确 FAIL 后执行。

1. 先建立独立盲核真值集。核验者不得看到 VLM fallback 输出，也不得直接复用本批由 VLM 草稿加整批概览确认形成的 `ground_truth/bole_temperature/` 作为 VLM 验收真值。若需下载新样本，先走 013 PLAN 批准门。
2. PaddleOCR + 模板保持主链路。只对目标温度表的提取完整性异常触发 fallback：
   - `ROW_LABELS_NOT_FOUND`
   - `CELL_MISSING`
   - `COLUMN_CLUSTER_COUNT`
   - `TEMPLATE_COLUMNS_FALLBACK`
   - `VALUE_OUT_OF_RANGE`
   - 目标字段的 `LOW_CONF`
3. 不因正常工况或非目标字段问题触发：
   - `CURRENT_SET_INCONSISTENT`
   - `OIL_LABEL_FALLBACK`
   - 非目标字段缺失
   - 泛化的 `status=review`
4. B_AND_R 成组错位时提交完整温度表 ROI，保留行列上下文；不拆成逐字段碎片。
5. VLM 返回值必须经过 schema、字段数量、数值范围校验，并与 Paddle 结果比对。冲突、缺失、越界或结构不完整一律进入人工复核，不得标记为可自动入库。
6. 固化模型/版本、提示词版本、触发原因、ROI、原始响应、结构化结果、耗时与 token 用量，支持成本审计；不得宣称 VLM 保证 100% 精度或完全可复现。

**PoC 验收条件**：

- 在独立盲核真值集上，B_AND_R numeric_accuracy >= 0.95；
- error_auto_import_rate 严格 = 0，且 `status=ok` 分母不得为空；
- 所有 Paddle/VLM 冲突均进入人工复核；
- 报告 fallback 图片调用率、字段调用率、延迟和 token 成本；若当前 20 图回放的图片调用率超过 25%（即超过约 5/20），不得将其描述为“少量边缘兜底”，须重新提交成本与架构审批；
- 结论仅为 PoC，不授权生产自动入库。

## 4. 验证口径

1. 数值准确率沿用现有定义：匹配真值（容差 ±0.5）的非空数值元素数 / 真值非空数值元素数。
2. 错误自动入库率沿用现有定义：误识别但仍 `status=ok` 的数值元素数 / 所有 `status=ok` 图片的数值元素数；空分母不得记为 0 或 PASS。
3. 所有报告必须同时保留整体与家族级分母、分子、逐图错误明细，避免汇总指标掩盖家族差异。
4. S2 使用现有 20 图既做定向修复又验收，只能证明当前样本 PoC，不构成盲测或泛化证据；S3 必须以独立盲核真值消除 VLM 同源循环论证。

## 5. 风险与控制

| 风险 | 控制 |
|---|---|
| rank09 真值再次被无证据改写 | 原图、基础 OCR、CLAHE OCR 三方一致才修正，并保留审计备注 |
| 单轮结构修复对 20 图过拟合 | 限定结构不变量，不调图像参数；结果只声明 PoC，后续仍需独立扩样 |
| 合法但错误的 OCR 数值绕过范围规则 | 不承诺仅靠数值范围发现所有错误；S3 使用独立盲核集与 Paddle/VLM 冲突复核 |
| 所有 review 均触发导致 VLM 调用率达约 75% | 使用明确的完整性 warning 白名单，并报告/限制图片调用率 |
| VLM 与真值同源造成虚假高分 | 原真值不得验收 fallback；盲核者不可见 VLM 输出 |
| VLM 幻觉或非确定性造成错误入库 | schema/范围/数量校验；冲突转人工；不授权生产入库 |
| 修改公共提取逻辑影响 ZizES/TACT | S2 做既有家族聚焦回归检查，B_AND_R 逻辑保持家族边界 |
| 现有工作区含未提交伯乐产物与代码 | 每个 Slice 开工先核对并保留现状，只提交本 Slice 明确范围 |

## 6. 交付与停止规则

- S1：审计后的 rank09 真值、修正后整体/分家族报告、HANDOVER。
- S2：最小结构修复、一次性 20 图分家族报告、聚焦回归证据、PASS/FAIL HANDOVER。
- S3（仅条件触发）：独立盲核真值、局部 fallback PoC、成本/延迟/精度报告、HANDOVER。
- 任一 Slice 完成即停止，不自动启动下一 Slice；S2 PASS 时不得创建未使用的 VLM 框架。
- 不修改 015 PLAN，不重启服务，不执行飞书回填或任何生产写入。
