## 已确定的架构方向

Kimi 专用模块负责原生协议、进程或服务、会话生命周期、事件转换和追加消息。
平台通过统一适配接口调用它，负责房间消息、派发、权限、展示和执行记录。
Kimi 协议细节留在专用模块内部，平台公共流程按接口和能力工作。

优先沿用现有 `HarnessAdapter`、注册表、流式事件和 steering 回执接口。

## 逐项实施记录

1. 原生路径：先探测本机 2.3.1 的实时 OpenAPI/AsyncAPI，再用本地模型桩验证 Server + WebSocket；ACP 缺失的方法不作为全局能力判断。
2. 专用模块：选择每次执行一个私有 Server，桥接进程与 Kimi 同处 Bubblewrap，平台经标准输入/输出控制；先验证首轮及冷会话续用。
3. 事件接入：按原生 transcript seq 消重，过滤旧历史及其他 Agent；思考仅转换为状态，正文保留完整长度，工具/子代理转换为统一事件；原生 wire 继续提供遥测。
4. Steering：复用平台回执，先 enqueue 再 steer，消息 ID 防重；丢失回执不重投，结束边界先核对队列；真实 CLI 验证两条插话各消费一次。
5. 兼容和集成：验证新旧通路双向续聊、沙箱、停止及断线等失败；平台按适配器能力派发。完整构建与针对性回归通过，保留显式 print 回退。重载前不声称目标飞书群已在线验证。
