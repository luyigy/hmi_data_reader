## 实际定位与修改

1. `waiting_for_user` 的普通输入此前由 `reconcileConversationWaits` 送入业务 admission，且只读 followup 明确排除它。移除此自动入口，普通输入进入原会话只读 followup；显式模型恢复动作仍走原有身份、候选和 Writer 核验。
2. 生产 M06 最新 TaskRun 是启动失败，只有 `resumeSessionId`。对话续接现在必须在同任务、TaskSession、角色、harness、gateway、agent 的历史中找到该原生 ID 的真实回执；不创建替身会话。
3. 已批准的实施 write 目录只在 `graphConversation + read-only` 中投影为 read，原审批不变。没有源码写集合时不认领 Writer。对话不执行声明的业务运行环境预检，也不启动任务图业务服务；源码和 Reader 的只读约束用真实 Bubblewrap 探针验证。
4. 对话卡身份在输入绑定事务内保存，键由原始输入及回答者身份构成。恢复输入沿用 rootInputId，重试 TaskRun 共用消息 ID；最新尝试独占原卡更新。旧失败晚到不会覆盖成功答复或下一轮。每次只领取一个源输入；耗尽的旧输入不阻塞下一条新消息。
5. 单输入最多四次尝试，间隔至少 15 秒。已经绑定 TaskRun 的失败不再额外发送阶段进度卡；尚未建立 TaskRun 的失败保留稳定通知键（仍见下方未完成项）。对话卡区分“启动前失败”和“会话执行失败”。
6. Agent 明确报告 missing_capability，而平台自己的检查通过时，保留 `agent_capability_missing` 阻塞和原说明。普通 conditions 检查不能自动消除此阻塞；实际已知资源缺失/恢复、暂时故障及原有工程继续路径仍保留。

## 遇到的问题与限制

测试启动器原来会用父项目的只读挂载覆盖嵌套 worktree，并且没有挂载资源审批使用的 `/etc/machine-id`。
本轮仅修复隔离测试入口：过滤覆盖测试工作区的父只读项目，补只读机器身份文件；不修改生产沙箱策略。
包含卡片投递的 target 套件需与既有 relay 套件一样使用 3 个连接，避免独立回执事务等待自己的单连接。
投递/输入旧夹具还缺少原生会话身份，本轮补成真实目标合同要求的 taskSession/participant/native 字段。

额外 `task-graph-conversation` 套件在“Coordinator must rerun the actual acceptance flow with the supplied material”失败。
已经在 `output/manual-chat-s02-baseline` 的原始 a98630f 产品源码重跑，同一断言失败（仅复制上述测试沙箱入口修正）。
这是本轮发现的基线失败，未修改产品恢复逻辑来绕过它；日志 `baseline-conversation.log` 与 `extra-conversation.log` 保留。不能宣称全仓测试全绿。

GitNexus MCP impact/detect_changes 返回 Transport closed；索引刷新长时间停留在增量导入，已终止本轮启动的刷新进程。
CLI impact 返回 Target not found / risk UNKNOWN。没有删除数据库或 WAL，也没有把结果当成低风险证明。
人工追踪的影响链为 Coordinator → followup → 原身份续接 → ACPX/resource scope → 输入回执 → graph relay/progress delivery；
环境结果 → admission 条件检查另有回归。共享权限和工作流变更应按中等风险复核，后续恢复索引后再补检查。
