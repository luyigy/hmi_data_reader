# PLAN · Live Room 通用原生包装层：Antigravity 首个试点

## 总体目标与决定

保留现在的消息展示和执行方式，让用户通过同一套 header（成员状态与操作包装层）使用不同 harness 的原生 CLI；网页提供原生终端选择，飞书继续聊天，并按成员实际能力设置模型和思考强度。

本次是 Phase PLAN，优先在 Platform Local 用 Antigravity 验证完整路径，但通用包装层与跨 harness 可复用性属于本 PLAN 的交付范围。2026-10-01 复审明确：Antigravity 是首个适配器，不是产品边界；不要求本轮完整上线所有 harness。遵循最新讨论：

- 网页原生菜单按 CLI 自身语义生效，不拦截所有设置强制延后。
- 飞书提交的设置只在下一轮任务开始时应用；当前运行中的追加指令不算下一轮。
- 保留现有默认路径，新路径默认关闭、按房间成员显式选择。
- 切换“显示视图”不启动任务；切换执行模式先等待当前轮结束，不双开进程、不重复提交提示词。
- 复用 CLI 原生追加、排队和中断能力；平台保留路由、权限、去重、回执和最终回复提交职责。

## 包装层边界与复用要求

- **平台包装层**：header 展示成员身份、运行状态、当前视图及可用操作；房间鉴权、唯一进程所有权、连接回放、设置待生效状态、路由去重与最终回复提交由平台负责。这些逻辑不能绑定 `agy` 命令、Antigravity 事件格式或型号名称。
- **原生 CLI**：终端内容、快捷键和原生菜单仍由 CLI 决定；包装层不通过解析屏幕文字猜测忙闲、设置值或每轮完成。
- **Harness 适配器**：CLI 启动参数、恢复方式、输入/中断、结构化事件到平台状态的映射、模型/强度查询与应用留在各自 adapter。复用现有 `src/lib/harness/types.ts`、`registry.ts` 和 `getCapabilities`，只按实测缺口扩展，不另建插件框架。
- **按能力显示**：header、网页连接和飞书卡片读取适配器能力；原生终端、运行中追加、恢复、模型选择与思考强度分别判定。缺失/未验证能力默认不可用，明确原因并保留现有消息模式；不得以 `harnessType === 'antigravity'` 作为公共入口的功能判断。
- **复用验收**：S01 选择本机可用的第二种 harness（Codex 或 pi，依据环境），记录差异；S02 用两个不同协议的适配器测试共同生命周期；S07 至少以第二种真实 harness 验证 header 能力展示和降级。若其原生能力可用，验证最小启动、输入、完成、停止路径，差异仅落在 adapter/注册与测试；若不支持，明确缺口，不能宣称已支持其原生终端。第二种真实验证未完成时，不得宣称跨 harness 验收完成。

文件名保留原路径，避免既有任务引用失效；文档标题与正文以本次通用包装层范围为准。

## 当前障碍与已核实证据

2026-10-01 在 Platform Local 实际执行 `agy --version`、`agy --help`、`agy models`、`agy changelog`：

- 本机版本为 1.2.14，模型列表查询成功；列表必须动态获取，不能将这次账户可见的型号写死。
- 帮助提供 `--model`、`--effort low|medium|high|max`、`--conversation`、`--continue`、`--prompt-interactive`。帮助列出档位不代表所有模型都支持全部档位。
- `--input-format stream-json` 配合 `--output-format stream-json` 可逐条读取输入并运行多轮；这不能证明运行中输入具有 steer 语义。
- 更新日志提到 Esc 中断、排队输入及 `/model`、`/effort`。这里只是 CLI 自述证据，尚未完成真实生成中的操作实验。
- `src/lib/real-agents/antigravity-agent.ts` 用 `-p` 启动单轮，stdin 为 ignore；最终结果在子进程 close 后提取。原生常驻进程不能继续把进程退出当作每轮完成。
- `src/lib/harness/adapters/antigravity.ts` 未宣告排队消息、恢复或实时会话控制；不能直接启用能力标记。
- `src/lib/live-room-steering.ts` 已有投递认领、回执与未知状态不自动重放机制，应复用。
- 直接调用者包括 Harness adapter 与 `src/lib/real-agents/index.ts`，新增配置需保持旧调用默认行为。
- package.json 已有 ws，未声明 node-pty/xterm；只在验证确有需要时引入终端必需依赖，不自制终端模拟器。

本轮没有对用户正在运行的 Antigravity 会话输入或中断，也未验证原生终端端到端。开工长文件检查通过，无达到 1000 行阻断阈值的文件。

## 总体路线与本 PLAN 结果

| B：通用包装层与本机试点 | 同一进程安全连接网页 | 通用 header/连接层，Antigravity 首先可打开终端、续聊和切回消息视图 | S02–S04 |

## S01：隔离验证原生能力与跨 Harness 边界

- **目的**：先确定 CLI 能否同时满足真实终端交互、飞书输入、可靠完成事件，避免先搭 UI 再发现协议不可用。
- **完成后结果**：提供版本、命令、脱敏事件样本和通过/不支持/未验证矩阵；明确 TUI 与 stream-json 是否能控制同一会话，不能把两个进程当成同一进程。
- **实现方法**：在临时工作目录创建独立项目与会话，使用无文件副作用的小任务测试启动、两轮对话、会话 ID 恢复、模型/强度切换、运行中追加、排队、Esc/停止、错误及完成通知。区分 TUI、JSON 两种模式；确认是否存在原生事件或控制通道，不假设二者可组合。确认权限询问与登录失效可见；禁止 attach 用户当前会话、修改全局默认设置。保留最小可重跑探针。再选择一个本机可用的第二种 harness，以同一检查表核对启动、输入、完成与能力缺省行为，形成共享操作与 CLI 差异清单；此步不实现完整第二适配器。
- **修改边界**：新增最小探针（CLI 专属部分分别隔离）与两种 harness 实验记录（可放 HANDOVER）；不改生产执行链路。探针设总超时，仅清理自身启动的进程。
- **验收**：实际运行探针，逐项记录输入、可观察结果和退出状态；同名工具连续调用仍可辨别，最终事件一轮一个；没有证据的能力不可标为通过。启动/恢复参数携带设置是否真的生效须回读确认。
- **前置与停止条件**：需要可用登录和测试额度；若同进程输入或可靠完成信号缺失，记录具体缺口，停止后续并提出限定试点范围；不承诺用屏幕文本解析补齐。若需重构共享协议，先按 AGENTS 做 GitNexus 影响分析。
- **交付物**：探针、实测结果、单独提交及 S01 HANDOVER；通过后下一步 S02，否则 HANDOVER 标记 blocked，不派发后续。

## S02：一个成员拥有一个原生执行进程

- **目的**：建立可管理的本机 CLI 生命周期，为终端与飞书提供唯一执行对象。
- **完成后结果**：可通过本地测试启动、输入、调整尺寸、停止一个隔离的原生会话，并获得每轮完成/失败结果。
- **实现方法**：沿用 Harness adapter 与 process registry 的所有权模型，按 S01 差异清单提取最小通用原生会话生命周期，Antigravity 的命令与事件转换放入其 adapter；公共运行模块只依赖适配器提供的操作、能力和规范化轮次事件。保留默认 print 路径；执行模式由调用方显式选择。绑定 room/member/session/generation，复用权限沙箱、工作目录和停止链路。每轮结果按唯一轮次提交，等待输入不算完成，退出为未完成轮次产生失败。追加接收未知时禁止自动重发。
- **修改边界**：通用原生运行模块、既有 Harness 类型的必要扩展、Antigravity adapter、process registry 必要接点及直接测试；超过两处生产文件是单一进程所有权必须原子接通的例外，不顺带重构其他 Harness。
- **验收**：单一成员并发启动只产生一个进程；错房间/过期 generation 拒绝；连续两轮、错误、停止、重复完成事件不重复结算；旧 print 测试通过；终端断开不终止任务。使用两个协议不同的适配器测试同一生命周期与缺省能力，不得让共用模块解析 Antigravity 原始事件；测试替身不计为第二种真实 CLI 验收。
- **前置与停止条件**：S01 通过且关键协议有证据；如果无法保留权限边界或可靠完成结算，停止，不以 full access 绕过。
- **交付物**：运行模块与针对生命周期的测试、提交、S02 HANDOVER。

## S03：经过房间鉴权的终端连接

- **目的**：将已验证的进程安全连接到浏览器，避免连接动作隐式重复启动任务。
- **完成后结果**：已授权用户可订阅输出、发送输入和尺寸；其他房间用户与失效连接被拒绝。
- **实现方法**：复用现有 WebSocket 服务与房间权限校验，接入 S02 的通用进程句柄，不感知具体 CLI 参数或事件；连接附带成员和会话归属，不接受任意 shell 命令或客户端指定 cwd。只允许一个写入控制者，其他连接只读。保留有容量上限的终端输出回放，截断时明确标识；完成回复沿用房间消息持久化。
- **修改边界**：现有 WS 入口、新终端路由模块和直接测试；实现前定位实际服务文件，不另起旁路无鉴权端口。
- **验收**：未登录、无权限、跨房间、旧会话、超大输入拒绝；刷新重连无新进程，无重复提示词；断线重连可回看容量内输出；停止后连接有明确状态。
- **前置与停止条件**：S02 可本地运行；若当前运行服务无法承载连接，记录部署边界并缩小/重新划分本 Slice，禁止顺带重构服务器。
- **交付物**：终端连接及测试、提交、S03 HANDOVER。

## S04：网页通用 Header 与原生终端选择

- **目的**：让正在使用 Antigravity 的用户最早实际试用。
- **完成后结果**：当前消息视图继续可用，目标成员出现原生终端入口；可输入、操作原生菜单、调整大小与刷新回看。
- **实现方法**：在 `src/components/live-room/LiveRoomDetailsPanel.tsx` 复用成员展示，接入通用 header 与独立终端组件，采用成熟终端渲染库；header 根据 S02 能力和规范化状态显示入口，不包含 Antigravity 专属判断；实验开关关闭时不加载终端。视图切换仅 attach/detach；执行模式切换在任务空闲时确认并沿用 S01 验证的会话恢复，无可靠恢复时明确新会话，不能暗中丢失上下文。网页设置按 CLI 原生语义处理；平台不拦截全部按键以强制下一轮。
- **修改边界**：成员面板、终端组件及必要 package/lockfile、组件检查；不重做聊天消息布局。
- **验收**：键盘输入、中文粘贴、尺寸变化、断线状态、刷新回放、消息/终端来回切换；运行中切换视图不会再发任务；开关关闭后旧界面正常。控制者状态、可访问标签和键盘焦点可用；以两种 harness 能力数据验证同一 header 的入口及不支持提示。
- **前置与停止条件**：S03 通过；未支持的成员不给可用入口，不显示假终端。
- **交付物**：可供用户试用的网页入口、检查记录、提交、S04 HANDOVER。

## S05：飞书待生效设置与下一轮应用

- **目的**：在不修改当前运行的前提下，为房间成员保存模型和强度。
- **完成后结果**：服务接口能保存待生效值；下一轮准确应用，失败不会伪称已生效。
- **实现方法**：先阅读 `src/lib/live-room-codex-settings.ts` 及成员 metadata 现有模式，复用待生效设置的存储与版本规则，模型列表、字段校验和实际应用委托目标 harness adapter；不把 Codex 或 Antigravity 的档位直接推广为通用枚举；写入时校验房间权限、模型和适用档位；不写机器全局配置。任务开始时固定本轮设置版本；经 S01 验证的配置/启动恢复方式应用到唯一会话，确认后记录生效版本。网页原生修改若不能回读，显示“上次确认值”，不冒充实时状态。飞书待应用值在下一轮覆盖其涉及字段，并显示来源；无待应用值时不反复覆盖网页选择。
- **修改边界**：新成员设置模块、S02 原生运行模块、目标 adapter 的设置接点及直接测试；多文件仅用于连通保存到应用的单一链路；必要的元数据接点应复用现有字段，非必要不迁移数据库。
- **验收**：运行中保存不改变本轮；当前轮追加不提前应用；多次保存只应用下一轮启动前最后版本；启动后新保存留待再下一轮；无效模型/档位拒绝；应用失败和无法确认分别显示失败/待确认，原运行不受影响。
- **前置与停止条件**：S01 已证实配置与恢复机制；若原生进程不支持安全应用，只支持空闲时经验证的恢复启动，否则标记不支持并停止该功能，不另开并行会话。
- **交付物**：设置服务、配置时序测试、提交、S05 HANDOVER。

## S06：飞书模型与强度卡片

- **目的**：让用户不记命令也能修改指定成员设置。
- **完成后结果**：飞书卡片可选择房间成员、模型、支持的强度，提交后显示“已保存，下一轮生效”；可查看确认状态并打开网页终端。
- **实现方法**：复用现有成员选择、表单和卡片回调入口，连接 S05；回调校验操作者、绑定房间和成员，使用版本避免旧卡片覆盖新设置。模型列表失败时禁用提交并保留已确认值；按成员能力展示模型/强度字段，不硬编码全部模型都支持四档；缺少某项能力时隐藏或禁用该项并说明原因。飞书追加消息仅在 S01/S02 证明原生能力后接入既有 steering；不支持时沿用现有队列，不声称已中途接收。
- **修改边界**：新设置卡片模块、`src/lib/feishu-card-action.ts` 或其现有分发模块的最小入口及直接测试；共用卡片与回调不得依赖 Antigravity 专属字段，不扩张为通用动态表单框架。
- **验收**：合法提交、重复回调、过期卡片、权限不足、成员删除、列表失败、待生效/已确认/失败提示；卡片显示与 S05 状态一致。实际群聊验证使用测试房间，只有用户指定并授权的发送目标才发消息。
- **前置与停止条件**：S05 通过；无法从回调验证房间归属时停止，不信任卡片传入的任意成员 ID。
- **交付物**：设置卡片、回调测试、提交、S06 HANDOVER。

## S07：两端联合验收、跨 Harness 复用与回退

- **目的**：证明试点解决实际使用问题并可关闭。
- **完成后结果**：用户可在测试房间确认网页原生使用、飞书设置延后生效、单次最终回复和模式回退。
- **实现方法**：组合前六步，以隔离房间执行验收矩阵；记录实际版本与会话归属，复用各 Slice 的检查，不另建测试平台。对 S01 选定的第二种真实 harness 验证同一 header 与能力降级；具备原生能力时，通过最小适配完成启动、输入、每轮完成与停止。记录新增接入修改的文件，若必须改 header、WS 或飞书公共流程中的 CLI 分支，说明通用边界尚未通过，应先修正对应 Slice。服务重启不自动恢复，展示会话失联/已停止，用户显式新开或恢复；默认关闭开关，已运行轮次正常收尾后切回旧路径。
- **修改边界**：验收记录、第二种 harness adapter/注册的最小接点与直接集成检查；若该适配超过单个 Session 或需要新协议，先拆分 Slice 修订 PLAN，不以替身通过代替真实验证；发现生产问题回到明确对应边界修复，不在验收阶段集中重构。
- **验收**：同名工具连续执行、等待/权限询问/错误可见、运行中追加或明确排队、停止续聊、网页刷新回看、飞书设置下一轮生效、网页原生菜单、双端同时输入不双开进程、一轮最终回复一次、关闭开关旧模式正常。测试不支持的行为必须如实列出。
- **前置与停止条件**：S01–S06 通过，真实飞书测试房间由用户指定；无目标时完成本地验证并把真实联调标为未完成，不能宣称全量上线。
- **交付物**：验收结果、提交、完成 HANDOVER（await_acceptance）；第二种 harness 的最小适配与验证属于交付，不自动扩展其全部功能。

## 范围、风险与退出

不做远端 SSH 终端、多用户同时写入、服务重启自动恢复、所有 Harness 的完整原生功能上线、完整终端历史永久归档。刷新可回看有界终端输出及持久化最终消息，不承诺永久保存整个屏幕历史。

通用包装层不意味着所有 CLI 都有相同能力，也不要求零适配；新增 harness 的预期成本限定在 CLI 适配、注册及针对性测试，不复制平台包装层。

现有行为无预期 breaking change：默认仍是原消息模式。真实风险是 Antigravity 原生模式缺少可靠的输入/完成控制通道；因此 S01 必须先独立交付，不与网页建设混成一个 Session。后续遇到文件数过多或跨数据库/服务/UI 边界，应拆分 Slice 并修订 PLAN，不能扩大单个 Session。

每个 Slice 开工运行长文件守卫；共享模块或权限变更按 AGENTS 使用 GitNexus 支持影响判断。仅运行相关测试与合同门禁；HANDOVER 必须用 workflow:new 创建，暂存后 preflight。每个 Slice 提交并交接后停止；不改写已提交历史，不夹带其他工作区改动。

本 PLAN 为 ready / await_approval 候选：当前请求为先写计划，未明确要求发送审批卡，不操作 watcher/cursor 或启动下一 Session。本轮已完成 CLI 能力预检；真实任务实测属于 S01。
