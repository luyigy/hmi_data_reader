## 关键机制发现（S03 起直接复用）

1. 隔离 netns 中 lo 未拉起时 TCP loopback 仍可用（内核本地路由直接投递）；bwrap 默认丢弃
   capabilities，`ip link set lo up` 会被拒，但 postgres 绑 127.0.0.1 不需要它。
2. `renderBubblewrap` 默认不挂 `/etc/passwd`；initdb 需 getpwuid 解析运行用户，沙箱入口必须把
   `/etc/passwd`（及 `/etc/nsswitch.conf`）加入只读挂载。
3. linked worktree 的 gitdir 在检出目录之外，必须按 `linkedWorktreeGitDirectories` 把
   worktree gitdir 与 common dir 一并只读挂入，否则沙箱内 `executionConditionsVersion` 的
   `git rev-parse` 静默失败，节点永远无法 requeue（生产 `runSandboxedGraphCheck` 已这样做）。
4. `loadProjectsConfig` 会校验 `config/projects.yaml` 里**全部**项目路径存在；沙箱入口需把这些
   项目目录作为只读根挂入（本入口从 yaml 自动派生）。挂多项目目录会触发“多个项目 Python 环境”
   保护，需设 `AP_PROJECT_REPOSITORY` 指定本仓库。缺这两项时派发以
   `AcpxRunStartupError` 静默转 `decision_required`，无任何控制台报错。
5. 生产 `withSandbox` 用 `env: plan.env` 启动 bwrap；本地入口若漏传，沙箱会继承宿主 shell 的
   全量环境（含潜在敏感变量），破坏受控通道假设。
6. 套件适配器桩在 `executeAcpxTaskRun` 内执行；宿主只读复用父仓库 `node_modules`（本 worktree
   与父仓库 HEAD 同源、package-lock 一致）经 ro-bind + 软链解析可用，Prisma/ts-node 全程只读。
7. zonky 包仅含 initdb/pg_ctl/postgres；就绪等待用 `pg_ctl -w`，探活用 TCP 连接 + Prisma 查询。
