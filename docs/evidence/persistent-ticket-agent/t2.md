# T2 独立验收反馈与受控集成

测试入口：`node scripts/test-task-graph-postgres.mjs persistent-ticket-agent-t2`。

固定旧 repair.ts 的反向运行已经失败：原 Agent 被固定回修次数阻断，未达到第四个候选的通过条件。模型服务是 Adapter 夹具；真实 Coordinator、候选提交、Git 集成、检查和独立 Review 账本参与执行。

修改后四个候选分别验收，三个不同的范围内缺陷交回同一原生实施会话。验收固定源码位于 readonly 挂载，独立验收运行目录可写；测试不把 writable test runtime 错判为源码可写。最终 repairAttempts 保留为 3，后继只放行一次。

相同 Git tree 与输入反复产生相同缺陷时，利用现有历史 outcome 证据停止空转，保留原资格与现场。新的代码或实际输入可以再次正常推进，不通过清空旧分类计数获取资格。平台故障和协议补收的安全上限保留，硬编码平台上限改为读取唯一配置。

冲突恢复不再把 requiresUserDecision=false 当作不能自动准备的格式。旧合并父、候选、Writer、批准文件范围与结果 CAS 都保留。

巨型 diff 的处理改为流式生成原有 JSON 指纹，没有增加 maxBuffer 或指纹格式版本。实际 >4MiB、中文/emoji 字节边界、转义、空输出和末尾空白测试与旧摘要完全一致。原冲突修复和已完成但 blocked 的续接场景通过。

兼容回归包括受影响仓内任务单独回修、保留成功兄弟成果、平台验收重试/耗尽、验收准备、归属失败和启动网络故障。新回修预读实际 Git tree，因此原仅使用虚构仓库与提交的状态测试改为真实临时 Git 仓库，未放宽其身份和兄弟成果断言。

本阶段没有恢复生产 Reader/Mold。历史 exhausted 的验收仍须 S04 核验真实运行条件与合法保存点，不能直接改成 ready。
