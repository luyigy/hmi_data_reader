# T1 正常连续实施

基线反例：`node scripts/test-task-graph-postgres.mjs persistent-ticket-agent-t1` 在修改前返回 answered 而非 working，普通进度被当成结束后等待。日志 t1-red.log 保留该断言。

修改后同命令通过。真实 Coordinator、事务账本、任务 Worktree 和平台检查运行；仅外部模型 Adapter 用确定性响应，spawn/退出回调真实执行。原 Agent 连续两轮保存不同进度，第三轮明确等待，用户重复投递同一答复只消费一次，第四轮沿相同 Session/目录交付，检查通过并放行后继。普通轮次不消耗 format/platform/repair 计数。

未交付的普通文本回到工作路径；正式交付仍需证据合同。历史 blocked/answered 协议继续读取。未改变验收中和已交付的只读会话权限。删除了输入消息中“回复不代表批准解除阻塞”的通用 Prompt 束缚，权限与身份仍由代码校验。

空转保护只看实际保存的 Git tree、已授权资料回执和实际用户输入，不把模型换个说法、Turn ID 或无内容新提交视为进展。连续三轮没有新工作事实则保留原会话等待干预，不宣称 Ticket 已失去批准，也不清空旧计数。用户输入可通过原有幂等 inbox 正常接回。

已授权表格查询回执补记请求 cursor 与返回 nextCursor，原 Session 输入附最近四条查询回执，40 次/轮限制及原来源授权不变。查询/下载仍重新校验来源和权限。
