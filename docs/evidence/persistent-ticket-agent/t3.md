# T3 父话题总览与原 Agent 定向回复

机器入口：`node scripts/test-task-graph-postgres.mjs persistent-ticket-agent-t3`。已经注册到现有 PostgreSQL 必跑套件。

复用现有飞书 relay 循环、通知回执、子话题 outbox 和 conversation inbox。每条路线保留一张总览卡，分页展示节点、实施输出、等待问题和独立验收状态；回复绑定具体 execution，进入原房间与原 Agent 输入队列。运行中输入仍走原 steering/续接入口。暂停时只存输入，不启动模型。

回调核验 SDK 事件外壳以外的原卡片 messageId、父聊天、原绑定、路线 snapshotHash、真实操作员权限、execution 归属；重放同一回调不得重复写消息或启动任务。原 Topic 同步使用现有幂等 outbox。用户暂停/继续共享既有运维操作；旧继续按钮不能覆盖后来的暂停。

测试使用真实数据库事务与 inbox，只有外部飞书发送/更新 API 为夹具。覆盖八个节点分页、重复发送抑制、伪造执行、错用户/聊天/快照、同一聊天内重绑 Topic、重复/篡改回调、暂停存储、显式继续和输入不串到其他 Ticket。测试没有调用真实生产飞书卡片，不能据此宣称客户端端到端验收完成。

反向验证曾临时移除实际源码的操作员权限检查，同一测试以 `Missing expected rejection` 失败。源码恢复后通过；t3-auth-mutant-red.log 与 t3-green.log 保存结果。该反例验证本入口拒绝越权，不冒充历史旧版本已经存在同一个总览功能。

仍需真实飞书验收：卡片渲染、移动端输入与分页、原 Topic 回显、实际模型消费回复及完成通知。原 Topic 的一键深链尚未提供，现阶段可在总览定向答复，详细交流仍进入已有 Topic。界面发布与旧业务恢复均未执行。
