# 远端 Pi 空结果误报完成修复

## 根因与修复

Pi 可能在模型报错后仍以退出码 0 结束。Runner 的成功信号不足以代表有效回复；原解析器又未保留 Pi 错误事件，导致平台接受空结果并报告成功。

- 共用 `processPiJsonLine` 解析器识别 assistant 的 `error` / `aborted` 状态，以及 `auto_retry_end` 重试失败；缺少错误文本时提供默认原因。
- Runner 与 SSH 路径保存解析出的错误，在完成时抛出，避免进程正常退出掩盖模型失败。后续正常 assistant 完成或成功重试事件会清除先前错误，允许恢复成功。
- Runner 优先使用非空 `complete.output`，缺失时回退到已解析的 assistant 正文；两者都为空则报告失败。Runner 错误沿用既有脱敏处理。
- SSH 本次增加模型错误识别；空响应拒绝逻辑只新增于 Runner，未宣称 SSH 已增加相同限制。
