# PLAN · 群初始化与房间讨论计划命令

## 目标

让未绑定的飞书群不会因第一条普通消息被静默创建或绑定到默认工作目录；新增仅在当前
Live Room 内讨论并产出计划的 `/ap plan` 命令。同步以真实 PLAN/HANDOVER 流程验证飞书卡片
明确展示所属 PLAN、Slice、阶段和下一动作。

## 边界

- 新群初始化必须由用户明确确认；不推测或回退工作目录，不复用其他群的 Room。
- `/ap plan <需求>` 只使用当前 Room 中可回复成员，按成员顺序各回复一次；主持人缺省选
  `planner` 角色成员，`--host=<成员>` 可显式覆盖。没有唯一主持人时要求用户指定，不猜测。
- 首版不修改代码、不跑测试、不自动实施；不创建通用工作流 DSL、回合配置或数据库模型。
- 复用 Room 消息、已有 Task Run、成员顺序和现有 Agent 路由；不自动写入 `docs/*PLAN*.md`。
- `/run feature` 保持原语义，不复用为讨论命令。

## S01：阶段卡片真人验收与基线

以本 PLAN 的审批、启动 S01 及后续 HANDOVER 为真实样本，在飞书中逐项确认卡片/提示显示：
PLAN 文件、当前或下一 Slice、文档状态、进度和下一动作。记录缺失字段、显示歧义和触发时机；
只修复可复现的卡片问题，不改变 workflow 审批或 cursor 语义。

## S02：未绑定群的显式初始化

追踪首条普通群消息、绑定查询、Room 创建、默认 agent 与工作目录解析路径。将未绑定群的处理
收窄为初始化提示/交互卡：用户确认后才创建以群名命名的专属 Room 并加入默认本机 Codex；
工作目录要求显式设置。补充最小回归测试，覆盖未确认不绑定、确认后独立绑定及不回退默认项目目录。

## S03：只讨论的 `/ap plan` 命令

实现 `/ap plan [--host=<成员>] <需求>`：主持人先定义问题与约束，随后其他可回复成员依房间
顺序各给一次建议并可读取前文，最后主持人输出唯一的 PLAN（范围、方案、风险、验证、待确认项）
后停止。复用现有消息与 Task Run，确保不触发代码执行、测试、Session 接续或仓库文档写入。补充
顺序、主持人选择、一次回复和停止边界的聚焦测试。

## S04：验证与交接

运行命令解析、Live Room/飞书路由和新增聚焦测试、TypeScript、相关 ESLint、long-file guard、
`git diff --check` 与 GitNexus `detect_changes`。创建终态 HANDOVER，列出飞书真人验收：未绑定群
初始化卡、显式工作目录、`/ap plan` 轮次顺序与卡片阶段显示；不重启服务。
