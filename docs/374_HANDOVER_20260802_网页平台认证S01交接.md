# HANDOVER · 网页平台认证 S01 交接

## 完成内容

- 新增最小 `AuthContext`，明确区分 `operator:admin`、绑定 gateway id 的 `machine:gateway` 与保留
  sender Open ID 的 `machine:feishu`，未引入用户表、RBAC、OAuth 或新依赖。
- 集中读取并校验管理员账号、密码、Session HMAC 密钥与 5 分钟至 24 小时生命周期；生产环境拒绝缺失、
  弱配置及本地兼容开关，非生产弱配置也必须显式开启 `AUTH_ALLOW_INSECURE_LOCAL=true`。
- 使用 Node.js 原生 HMAC-SHA256、base64url 与恒定时间比较实现管理员凭证校验、Session 签发、验签、用途
  隔离和过期判断。
- 建立页面、API、Feishu Webhook、Gateway 机器入口与 Socket.IO 的显式路由策略；健康检查和未来登录页公开，
  Feishu 授权链接继续自行验签，既有 Gateway/Feishu 入口继续入口自验，其余现有入口要求 operator，未知路径
  或未声明方法默认拒绝。
- 测试会动态扫描 `src/app` 的全部 `page.tsx` 与 `route.ts`，新增入口若未加入策略即失败。

## 配置

- `AUTH_ADMIN_USERNAME`
- `AUTH_ADMIN_PASSWORD`：默认至少 12 字符。
- `AUTH_SESSION_SECRET`：默认至少 32 字节。
- `AUTH_SESSION_TTL_SECONDS`：整数，范围 `300..86400`。
- `AUTH_ALLOW_INSECURE_LOCAL=true`：仅非生产可用，将密码/密钥下限降为 8 字符/16 字节；仍不提供默认凭证。
