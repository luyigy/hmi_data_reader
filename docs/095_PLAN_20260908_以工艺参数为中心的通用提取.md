## 3. 总体路线图与本 PLAN 结果

```text
原图 + OCR 文字／位置证据
  → 通用参数候选（理解标签、值、单位、表头和段／温区关系）
  → 程序校验 + 具体歧义
  → 验证台按参数展示、逐项纠错、保存确认副本
  → 后续：标准 Observation → Web ApplyPlan → 校验提交
```

## 4. 提取与校验约束

### 4.1 以参数关系为单位

| 参数类别 | 主要内容 | 必须保留的关系 |
| --- | --- | --- |
| 温度 | 料筒、喷嘴温度 | 温区身份，设定／实际 |
| 熔胶 | 转速、背压、位置 | 段标签，rpm/bar/mm，压力侧别未明时保留歧义 |
| 射胶 | 速度、压力、位置及切换参数 | 段对应，设定／限制／实际，单位 |
| 保压 | 压力、时间等 | 段对应，单段／累计时间含义 |
| 冷却时间 | 画面明确显示的时间 | 设定／经过／剩余时间不混用 |
| 模温 | 模具温度 | 温区与模具对象，设定／实际 |
| 热流道 | 各通道温度等 | 通道编号、启用状态有无证据，设定／实际 |

这是提取范围，不是每图必填清单。分区用于组织候选，不是先对整图分类；一图有多个类别时分别提取。

复用 082 结构，至少保存屏幕原文、数值、原始单位、角色、段／温区标签、来源和可回查原图的证据。目录外字段保留 canonical_id=null。证据关联优先用已有图像标识与 OCR bbox；模型自写的解释不能单独证明图上存在该值。

图片与 OCR 不一致时保留冲突，不投票自动确认。段标签不清时保留原行列顺序与待确认问题，不把屏幕左右顺序当物理段序；缺值不补零。合理范围用于报警，不能把数字改成“更合理”的猜测。

模型负责关系理解；程序负责结构、数值类型、证据可定位性、角色、重复冲突及单位约束。程序通过不代表事实已确认，所有模型候选仍待人工确认。现有协议不能无损表示的压力侧别、时间含义、启用状态等，先保留原文和问题并阻止标准化，不借角色 actual 混装经过／剩余时间。

### 4.2 主入口与最小实现

- 优先复用原图 + OCR + draft_from_ocr 和既有模型客户端，先测当前能力再修公共缺口；不默认换 OCR 或新增模型供应商。
- 页面类别、机型、Profile、目标字段目录都不能成为候选提取门禁；已知机型仅可作为有来源的语义提示。
- current_structure、target、canonical hints 用于后续对照和映射，不能裁掉其他参数或迫使模型生成指定段数；不新增通用框架或第二份字段目录。
- 先用现有 sections/questions 表达候选和具体疑问；若证据或语义确实无法无损承载，在对应 Slice 记录实例并评审最小合同变化，不能偷偷改严格 schema。
- 不以非空候选表示完整：已见表格缺单元格须指出缺项；图外不可见部分不能当已提全，也不能把七类中未出现的类别当漏提。

## 5. Slice 实施路线

以下边界为预计范围，每个 Slice 开工时先核对真实调用链和 upstream impact。HIGH/CRITICAL 必须先报告影响与风险；不得跳过分析直接改符号。每个 Slice 只完成一个主要结果，默认至多 2 个生产文件和 2 个直接测试文件，超过时先解释原子性或拆分。

### S01：冻结参数基线与留出样本

- **目的**：使“改进”有可比较的证据，防止只围绕 094 调试。
- **完成后结果**：七类参数覆盖表、逐项真值、按独立布局分组的开发／留出清单、旧链与现有 draft 的初始结果。
- **实现方法**：复用 ground_truth、已有原图和 OCR 快照，核对 scripts/vlm_text_eval.py、scripts/verify_accuracy.py 的评分能力；现有评分不能覆盖关系时只补最小评分入口。按“参数含义、值、单位、角色、段／温区”匹配；不确定真值标 unresolved，单独计数。记录原图哈希、提交及未提交差异、模型和提示版本。094 只入开发集。
- **修改边界**：评测脚本择一复用或最小新增、一个直接评分测试、脱敏真值与清单；原始用户图及身份信息留服务数据目录，不提交。无识别生产代码修改。
- **验收**：评分检查能捕获漏项、假项、角色错配和段号错配；每类至少有开发样本及独立布局留出样本，整体至少覆盖两个机型、混合参数画面、残缺画面；同图裁剪、缩放和同布局近重复必须同组。输出实际样本数与缺口。留出标签不得用于提示或算法调试。
- **前置与停止条件**：原图可访问且人工标注可核实；缺类别或独立布局时可交付开发基线，但对应覆盖与 S06 完整验收保持阻塞，不编造真值。评测前固定阈值和匹配规则；只有快照回放时不得声称完成端到端基线。
- **交付物**：基线报告、清单、可复跑命令及输出、聚焦提交和 HANDOVER。独立成片是为了先冻结评分与留出边界，避免边改算法边改答案。

### S02：验证并改进通用参数候选核心

- **目的**：使不同布局中的参数通过同一提取逻辑返回。
- **完成后结果**：开发集可得到含证据的参数候选，语义不明时返回具体问题，零候选不会被包装成成功提全。
- **实现方法**：复用 scripts/vlm_qwen.py 的 draft_from_ocr，依据 S01 分层错误修改通用提示和必要的确定性校验；同时使用图像及可用 OCR，不依赖页面模板。先运行现有实现；无证据需要改代码时不强造重构。
- **修改边界**：scripts/vlm_qwen.py、tests/test_vlm_text_mapping.py；不写页面专用分支，不修改模板、HTTP 或 Web。复用 082 合同；必须改 schema 才能表达证据时，停止并补出兼容方案后再执行。
- **验收**：同一逻辑处理七类、混合类别、无机型、无页面类别、空 hints、目录外字段；角色、段标签、缺值、冲突和证据缺失有测试。开发集原图实测与固定 OCR 回放分别报告，不能以 mock 测试替代模型效果。
- **前置与停止条件**：依赖 S01 开发基线。若需要某页面坐标、样本 ID 或模板分支才能通过，停止该方案，回到关系错误的共同原因；留出集不可参与调试。
- **交付物**：核心改动或无需改动的测量结论、聚焦回归、开发集对比、提交和 HANDOVER。核心先独立验收，避免把模型错误与 HTTP 接线错误混在一起。

### S03：让 draft 成为无页面前提的真实入口

- **目的**：保证实际请求也走参数主链，不让旧分类／提取拒绝阻断候选。
- **完成后结果**：仅上传图片也能请求候选；页面、机型和业务目标均非必需提取条件。
- **实现方法**：核对 hmi_service.py 的 draft_image，复用现有 OCR 证据获取函数；无 evidence 时直接获取文字／位置，而非必须先成功执行页面路由。将 target/current_structure/allowed_fields 改为可省略的中性上下文，保留旧显式请求的兼容解析；目标与 hints 改变不能隐藏画面其他候选。有合法 evidence 时不重复 OCR；保留认证、并发和输入上限。
- **修改边界**：hmi_service.py、tests/test_generic_extraction.py；必要时只抽取一处已有 OCR helper，若触及更多生产文件先重新切片。不修改旧 recognize 响应合同。
- **验收**：图片单独请求、空 hints、无 OCR、OCR 失败但图像可用、模型失败、401/422/429/502、坏图片及超限；用调用断言证明参数入口不调用页面分类或模板匹配；旧请求及 recognize 合同回归通过。无 OCR 时图像候选必须说明来源，不能伪造 OCR。
- **前置与停止条件**：依赖 S02 可复跑核心；必须打破旧调用方响应结构时先给出合同与迁移方案，禁止顺带切换生产服务。
- **交付物**：HTTP 变更、请求／响应例子、测试、提交和 HANDOVER。此片独立证明入口不再依赖页面成功。

### S04：验证台完整保存候选与确认副本

- **目的**：避免通用候选进入验证台后被 fields 映射丢掉。
- **完成后结果**：上传、恢复、纠错、重新预览及下载可以保留同一份候选结构与原始证据。
- **实现方法**：在 validation_lab/app.py 复用批次和 review 存储，调用 S03 draft；分开保存不可变原始响应与人工修改／确认副本。旧批次仍可读取；识别失败保留上次结果并标记此次失败。候选不能直接送入旧 fields 写入预览；未建立语义映射时明确暂不可映射。
- **修改边界**：validation_lab/app.py、tests/test_validation_lab.py；预计不动 mapping.py，必须改时限于阻止误送候选的边界判断并说明文件数量。无正式 Trial 写入。
- **验收**：上传→恢复→纠错→下载往返不丢目录外字段、角色、标签或证据；纠错不覆盖原始响应；失败不覆盖有效结果；既有用户隔离与旧批次回归通过，重新识别的旧确认不得自动套用到新结果。
- **前置与停止条件**：依赖 S03；需不可逆迁移或涉及其他用户批次时停止并另列迁移，不批量重写历史数据。
- **交付物**：服务及存储兼容变更、往返测试、提交和 HANDOVER。服务往返先验收，避免界面能显示但刷新就丢的假闭环。

### S05：按参数展示和逐项确认

- **目的**：用户能核对提取事实，清楚哪些是歧义、哪些仅缺业务映射。
- **完成后结果**：七类及其他参数均可展示，设定／实际并列、段／温区对齐，可查看证据、纠错与保存确认；unknown 不再被显示成模温。
- **实现方法**：validation_lab/lab.js 消费 S04 候选，复用现有交互；仅在有模温相关候选或用户主动选目标时显示相关目标操作，不能依赖页面分类。未识别、待确认、已确认和暂不可映射分别表达；显示问题及不完整提示。人工确认不等于业务 safe。
- **修改边界**：validation_lab/lab.js，必要时 validation_lab/index.html；一个相应浏览器检查。样式优先复用，不做 UI 重设计。
- **验收**：温度／熔胶／混合／零候选／目录外参数／真实模温样例；确认后刷新及下载仍一致；只有候选的批次不触发旧标准字段预览。桌面、移动端与键盘操作可用，原图与候选值可对照。
- **前置与停止条件**：依赖 S04；缺业务映射显示“暂不可映射”，不猜目标，不扩成正式 Web 写入。
- **交付物**：界面改动、浏览器验证记录、可复核样例、提交和 HANDOVER。

### S06：冻结版本并验收跨布局能力

- **目的**：证明改善来自公共参数能力，发现残余问题而不继续针对测试图打补丁。
- **完成后结果**：逐类别的新旧对比、失败归因及通过／未通过结论，明确已验证的机型和布局范围。
- **实现方法**：固定代码、模型、提示、OCR 配置和数据清单，运行 S01 评分和完整原图链；开发集与留出集分报。重复运行同一冻结版本三次，报告波动和最差结果；记录耗时、请求数、失败率及可得的调用成本。
- **修改边界**：评测结果与 REPORT/HANDOVER，不改生产代码或真值来追分；发现算法缺陷另开有共同原因的修复 Slice。
- **验收**：按第 6 节冻结门槛判定；提供完整命令、版本和逐项失败列表，不只展示成功截图。检查新增相似布局是否仍需页面专用分支；需要即未达到目标。
- **前置与停止条件**：依赖 S01–S05 和完整留出覆盖。打开留出结果后不得用它继续调参并称盲测；修复后需新的独立留出组。缺真实模型或原图时标未完成，不用 mock 补结论。
- **交付物**：验收报告、提交和终态或阻塞 HANDOVER；通过后才形成后续 Web Observation/ApplyPlan 计划的输入。此片的独立结果是冻结版本的准入结论。

## 6. 验收口径与退出

以人工核实、在画面可见的参数项为分母，每类分别统计：

- 提取精确率：候选中正确的参数项占比，虚构参数为假阳性；
- 完整关系召回率：真值项中含义、数值、单位、角色、段／温区全部正确的占比；
- 数字错误、漏提、语义关联错、单位错、角色错、段／温区错分别列数；
- 真值 unresolved、图像不可读、请求失败、空结果单独列出，失败与空结果不得从可读样本分母剔除；
- 确认前误标安全、无证据值被接受为已确认的数量；候选实际错误不能因都标待确认而不计错。
