# HMI 拍照验证台交付

## 用户如何使用

本次交付独立验证工具，目标是连续拍照、查看分段识别、人工纠错、查看拟填入字段并留存回归案例。没有修改 mold-data-webpage-tool，也没有改变 Reader 识别算法或 API。

在 Reader 仓根目录启动（复用现有 .venv 的 FastAPI / Uvicorn / HTTPX / Pillow / multipart）：

```bash
.venv/bin/python -m validation_lab.app
```

本机访问 http://127.0.0.1:8766 。默认调用 http://127.0.0.1:8765/api/v1/recognize；若识别服务有鉴权，将 HMI_API_KEY 设置在验证服务进程环境，密钥不发送给浏览器、不写入批次。

手机局域网访问：在可信局域网中给独立验证进程设置访问密码，然后绑定网卡。用户名固定 lab，密码从交互输入，不写命令历史：

```bash
read -rs -p '验证台访问密码: ' HMI_LAB_PASSWORD
export HMI_LAB_PASSWORD
.venv/bin/python -m validation_lab.app --host 0.0.0.0 --port 8766
```

手机访问 `http://服务器局域网IP:8766`。这是 HTTP Basic，跨公网应使用已有 HTTPS 代理；本次未更改反向代理、开放端口或部署 systemd。未配置访问密码时只允许本机访问。选择器调用手机原生相机，不依赖 getUserMedia。

可选环境变量：HMI_READER_URL（Reader 基础地址）、HMI_API_KEY（上游鉴权）、HMI_LAB_PASSWORD（验证台登录）、HMI_LAB_DATA_DIR（本地批次目录，默认 output/validation_lab）。不使用 dotenv 自动扫描，不读取 Web 凭据。

步骤：

1. 新建批次；连续拍照或多选图片。失败照片保留，可重新识别。重复文件按 SHA-256 去重，每批最多 30 张、单张最多 20 MiB / 4000 万像素。
2. 模温照片指定定模、动模或行位等目标；不属于本次工艺的图可排除。
3. 调整验证副本段数/温区数，或导入 parameter_data JSON。结构修改清除旧逐项确认，减少数量先提示；也可编辑区名、原值、单位和压力侧别。
4. 按模块核对原值、拟填值、目标及原因。原图按钮展示整图及原始 OCR 证据，不伪造字段 bbox。
5. 修改数值或目标后选“已核对值、段序及语义”，填写纠错说明并保存。不同来源写同一目标且值不同会阻断，需排除/修正冲突来源。
6. 下载 JSON 或 ZIP。ZIP 包含原图和 result.json，刷新或选择旧批次可继续。重新识别追加 attempt，旧响应和已保存的纠错历史保留，新结果重新确认。

## 文件及实现边界

- validation_lab/app.py：独立 FastAPI 服务，调用 Reader，原图和响应本地留存，批次恢复、乐观版本检查、原子 JSON 保存、下载 ZIP；不导入 OCR 模型，不调用 Web。
- validation_lab/mapping.py：纯函数识别整理、合同核对、既有目标枚举、冲突检查、自动/人工两份拟写入投影。
- validation_lab/index.html、lab.js、lab.css：原生 UI，手机卡片 / 桌面表格，连续上传、核对、纠错和下载。
- validation_lab/target.fixture.json：按 Web 已提交源码结构整理的空值投影，记录 Web commit 与源文件 SHA-256；不是完整 Trial 保存请求，不含机台/用户数据。
- tests/test_validation_lab.py：离线映射与 HTTP 行为检查，模拟 Reader，只使用临时目录。
- 089 PLAN 与本文：已获用户“do it”授权的单切片手动任务，不派发 inbox 大型架构计划。

本工具的映射代码仅属离线适配器；Reader 正式 recognize/draft 响应仍然不生成 Web 模型。

## 哪些检查已实现

自动可映射需要：匹配本批次冻结 Reader 合同、verified profile、对应控制器/页面、置信度达到 registry 门槛、green 质量且无警告、字段来源页面及元数据一致、单位相同、正确温区身份/段数/段序。保压时间检查 segment_duration；压力检查来源和目标侧别。温度验证范围 -273.15～500°C，其余数值不得为负、NaN、Infinity 或布尔值。此范围是验证台保守约束，不代替材料护栏或生产安全上下限。

料筒按列名匹配目标区名（例如屏幕喷嘴/区3/区2/区1 对应目标喷嘴/区1/区2/区3），不按下标照抄；模温由人指定唯一 zone_id；单位不一致不自动换算；无值不清空目标；目标冲突不采用“最后一张覆盖”。

原始响应不可编辑；session.edits 单独记录纠错。automatic_parameter_data 由没有逐项纠正的识别结果生成；corrected_parameter_data 可含明确人工核对项，raw_mapping_counts 不因人工改值/重定向提升。排除照片和设置模温目标是用户输入的上下文，不应将本工具的数量统计当作完整模型准确率。

## 当前限制，后续迭代按案例补充

- 目前只调用确定性 recognize，不新增模型或自动调用 /draft。未知页面可能只留下 OCR 证据；不能声称已识别用户全参数清单。
- 自动规则覆盖料筒设定/实际、符合条件的射出速度/压力、保压压力/时间、V/P 位置、冷却时间、指定目标模温。目录字段无规则（包括若干熔胶字段）保留展示，允许人工验证；不伪造新 canonical 字段。
- 热流道需要人工逐通道指定目标；黑屏槽位原样保留。段起点→终点、压力侧别转换、累计保压时间换算及 Web 联动尚未自动实现。模温 candidate 不自动晋级。
- 人工核对项是验证假设，可用于形成真值；不是生产安全放行。截图质量 red/yellow、语义不明等情况也不能因这里可人工核对而绕过未来 Web 保存门禁。
- 目标是 raw_value/raw_unit 投影，未执行 Web 完整 schema、材料护栏、权限或数据库保存检查。字符串参数（冷却介质等）可在目标 JSON 中保留，不提供自动映射。
- 单进程本地工具，进程内锁；禁止多个 worker 共享目录。没有账户体系、配额清理、自动回归批跑或跨机同步。
- 保存本地源码 commit/文件哈希与响应合同；Reader 当前响应没有构建版本，不能证明运行服务与本地源码完全一致。
- 未提交纠错离开页面会提醒，仍需点击保存；不做自动本地备份。
