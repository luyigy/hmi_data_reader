# PLAN · 科学试模群串台与意图路由排查

## 1. 总体目标

彻底排查并治理飞书群 / Live Room 多 Agent 协作场景下的“串台、抢话、回复错位与上下文污染”问题，使群内 `@` 提及、意图分发以及跨 Agent 讨论上下文保持精准隔离与稳定路由。

## 2. 当前障碍与已知事实

在“科学试模助手”群（Feishu 绑定 Live Room `cmrp0vqmz000014f2f12alk32`）的实际协作中，已定位到两类典型的串台问题：

1. **Speaker 漂移与意图截胡**：
   - 默认 Speaker 为 `antigravity`，但用户使用飞书客户端 `@本地AI助手` 发送长指令时，因群内成员别名均未包含 `"本地AI助手"`，导致未锁定目标成员；
   - 指令正文中随口提及“...还有上次更改没有写文档的先写文档”，命中了 `resolveDocumentationTarget` 的简单正则，被文档专员（`pi-agent`）强行截胡接单。
2. **跨 Agent 共享上下文污染与代词消歧混乱**：
   - 用户在群内分别与 `$lkc`（讨论多段只读与顶退从 2 开始计数）和 `$codex`（讨论轮次继承增压比审计）交替沟通后，向 Codex 发出泛指指令“$codex ... 明确列出我反馈的问题写个计划”；
   - `buildTaskRoomPromptContext` 将群内全部最近历史平铺注入 `Recent task-room transcript`，Codex 误将发给 lkc 的结构化 Bug 描述当成自身规划目标，生成了错误的 `210_PLAN`。
