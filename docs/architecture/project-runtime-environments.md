# 项目运行环境复用

任务图的实施、平台检查和验收默认复用源项目的既有 Python 环境。worktree 隔离代码，不创建或安装另一套任务虚拟环境。

## 选择规则

- 未配置时使用源仓库的 `.venv`，通过共享 Git 元数据定位源仓库。执行 worktree 不能用自己的配置覆盖源项目配置。
- 使用其他已有环境时，在源仓库 `.agent-platform/project-environment.json` 指定路径：

```json
{"pythonEnvironment": "/data1/code/ocr-training/.venv-ocr3"}
```

路径可以相对源仓库；必须是已有 venv 或 Conda 环境的真实目录。无效配置直接报错，不静默回退、不自动创建或安装。没有配置且没有 `.venv` 的项目保持原有工具链，不假设它是 Python 项目。

- 在任务图沙箱启动入口统一提供 PATH、VIRTUAL_ENV 和禁用用户包的 Python 设置。保留虚拟环境 Python 的调用路径，不将其符号链接解析为系统 Python 后执行。
- 任务图通过服务端输入清单显式提供主仓身份。验收目录没有 Git 元数据时，也只选择主仓环境作为默认 PATH / VIRTUAL_ENV；主仓没有环境时不借用上游环境。
- 所有需要消费的前置项目环境均只读挂载，通过清单中的 pythonExecutable 调用。多仓环境可同时可读，不能拼接 PYTHONPATH 或任选一个作为默认。历史非任务图调用未提供主仓身份时，仍保留单环境推断，多环境歧义时拒绝。
- 环境默认只读；实施、检查、验收均不能改共享依赖。Node 项目沿用已有源仓库 node_modules 只读挂载。

## 职责与生命周期

模型认证和会话状态继续按 Harness 隔离，不作为项目依赖来源。删除从私有 HOME 扫描 site-packages 的过渡方案，也不要求验收 Agent 手写 PYTHONPATH。

可写测试数据、缓存和报告留在任务运行目录或临时目录。任务清理不删除源项目环境。缺依赖或需要变更版本应明确报告，再单独安排项目环境变更，不能由并行 Agent 各自安装。

只读挂载限制沙箱写入，不阻止宿主项目所有者从外部更新环境。本轮不承诺依赖字节级冻结或完整可重建；发布依赖变更仍需版本记录和协调。
