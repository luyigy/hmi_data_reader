## 结构与唯一权威

```text
获批 Issue 依赖图
        ↓
ExecutionProgress / Node 聚合状态
        ↓
Reconciler：在现有协调器中决定唯一下一动作
        ↓
阶段适配器：准备、实施、检查、集成、架构、验收、冲突
        ↓
现有事务状态转移 + TaskGraphEvent
        ↓
投影消费者：节点状态、当前 TaskRun 流、飞书原卡、Issue 标签
```

Reconciler 是现有协调器的推进决策入口，不是第二个守护进程、全局串行队列或无阶段语义的总开关。无依赖执行继续并行；共享可写原目录的互斥和逐仓集成约束保留。

`ExecutionProgress.phase/state/review` 及其 revision、claim、候选、预算、writer 继续是当前执行事实。先定义从现有事实导出下一动作的完整表；确需保存下一阶段信息时，在同一版本化进度中增加类型化字段并校验一致性。不得另设独立 `pendingTransition` 表或 JSON 成为第二状态源。

## 固定运行资源贯穿阶段

共享 Python 环境继续按主仓解析已有 `.venv`。现有机制不是依赖字节冻结，不能将其宣传为完全可重建环境。

浏览器/OCR使用批准代码提交的 `.agent-platform/runtime.json`。在本次 claim 的输入清单中固定解析快照，至少关联声明提交、内容哈希、资源种类、来源、SHA-256、资源身份、批准只读根及预检回执。避免在后续阶段再次查询可变源仓当前配置。

- 实施、平台检查、架构及独立验收通过固定快照解析能力。非 Git 验收目录也从该清单获取声明，不借工作目录猜仓库。
- 后继 worktree 按其声明与批准来源消费资源。相同声明和资源保持同一身份；跨仓需要不同声明时分别绑定，不能无条件继承前置权限或任意合并环境。
- 归档迁移可改变物理路径，不改变资源身份；重新验证字节和权限，保留原事件引用。过期路径不能指向任意宿主目录。
- 配置无效、资源哈希不符或 Snap 包装无法启动时明确失败。显式配置不能被宿主自动发现结果覆盖。宿主兜底须有独立批准来源。
- 未声明资源不自动安装或扩大权限。票据要求浏览器而资源不可用时，在进入昂贵实施之前报告缺失能力。
- attempt 期间资源改变时拒绝继续；只有经受控准备、重新校验和记录的新 attempt 才能换资源。不得清空失败预算冒充新环境。
- 源码、原图和共享环境只读；缓存与报告写阶段输出目录。OCR能力不等同于本地 VLM，也不证明识读准确率。

## 统一推进，保留阶段安全约束

适配器负责执行阶段操作、读取该阶段证据并产生分类结果；Reconciler 负责选择下一动作。已有 `applyExecutionOutcome` 和原节点锁负责合法状态写入及幂等，不新增绕过它们的 ready/attention 更新。

每个动作绑定当前 revision、claim、候选、阶段和 writer 身份。锁内重读并校验，旧结果不能覆盖新进度。进程状态 completed 不等于实际写入者退出；未知或存活 writer 均不得接管。

| 当前结果 | 下一动作及预算 |
| --- | --- |
| 依赖未完成 | 等待该依赖，继续处理独立就绪支线 |
| 平台暂时故障 | 原阶段按现有预算退避，不重做成功阶段 |
| 缺运行能力 | 平台准备并证明能力变化后接续，不原样空转 |
| 范围内代码缺陷 | 只回修明确受影响 execution，成功兄弟提交与证据保留 |
| 架构或独立验收失败 | 同一分类规则，回修后重验受影响合同和合并结果 |
| 合流过期或冲突 | 调用冲突适配器，保留双边提交及现场；不自动 reset 或盲目 abort |
| 缺结构化结果 | 有限补收；无有效结论不能合成完成 |
| 必要业务材料、范围或权限决定 | 列出材料、批准来源、责任方及具体决定，仅影响相关分支 |
| 无进展或预算耗尽 | 持久化明确升级结果，由平台提出新措施；普通继续不能重置预算 |

一次分支读取或暂时基础设施错误不得中止整 Run 扫描。领取公平性、并发上限和原先就绪队列继续生效。

## 旧记录的兼容与删除条件

当前专用恢复模块同时承载准备绑定、旧 TaskRun 分类、冲突双方证据等职责，不能按文件数量直接删除。

1. 列出每个恢复入口、读取的旧事件、合法写入口、预算与幂等键，建立旧状态到当前阶段的显式映射。无法确定者保留现场并输出证据。
2. 旧模块先成为兼容适配器，由统一推进入口调用。旧事件只在有绑定的迁移过程中解释一次，不能每周期按历史文字猜阶段。
3. 在原锁下绑定旧事件 ID、当前 claim/revision、候选和退出证明，写入统一进度及追加迁移回执。崩溃重放只对账，不重复派发、不重复扣预算。
4. 新 attempt 全部走统一决策，迁移后不再由旧轮询入口推进。不得让新旧消费者同时领取同一执行。
5. 只有盘点显示没有未迁移引用、相关旧 Run 回放通过且无旧写入调用者，才删除对应适配器。保留事件和历史审计，不改写 Git。

不允许用“一键迁移全部”覆盖 M03A 当前现场。迁移前后候选、未提交更正、预算和证据必须逐项可比较。

## 飞书与 Issue 的同源投影

业务状态变化在现有事务边界产生带 revision 的 `TaskGraphEvent`，作为持久投影请求。复用已存在的 outbox 和回执；网络发送在业务提交之后执行。

卡片输入合并节点/执行状态、当前 TaskRun 摘要及最近可执行失败动作。保留 `run-reply-relay` 的消息 ID、stdout 游标及流式内容，使用当前执行绑定、状态 revision 和内容哈希去重。节点变化但没有新 TaskRun 时仍能更新原卡；旧流式输出不得把最新失败或完成状态覆盖回运行中。

投递超时只重试/对账投影，不重启 Agent、不扣业务回修预算、不写 dispatch_failed。发送结果不确定时先回读，不能重复建卡或重复发评论。原审批明确要求的审计通道仍在启动前验证。

Issue 标签按可理解的状态映射为 ready-for-agent、in-progress、in-review、blocked、done，保留无关标签与依赖正文。等待前置与自身失败在说明中区分。内部阶段不逐个生成评论；完成回执继续幂等发送，关单及标签由回读确认。远端关闭或标签不能反向越过本地验收与授权。

## 实施拆分与并行关系

以下为待写入真实 Issues 的工作单元，不是已创建的 Ticket 编号。先回读 WR07、W5 和相关父 Spec，区分原验收补充与新增范围，避免双份任务来源。

| 单元 | 交付 | 依赖 |
| --- | --- | --- |
| 契约基线 | Matt 对齐结论、固定资源快照、下一动作表、迁移表、投影事件契约及测试入口 | 本方案复核 |
| 运行资源 | 跨阶段固定资源及预检；非 Git 验收消费；后继一致性 | 契约基线 |
| 推进收敛 | Reconciler、阶段适配器及旧记录迁移 | 契约基线 |
| 外部投影 | 原卡流式输出兼容、全生命周期 Issue 标签 | 契约基线 |
| 联合验收 | 故障注入、真实跨仓并行、M03A 无损续跑及后继放行 | 上述三个实施单元 |

契约基线定稿后，运行资源、推进收敛、外部投影可用独立 worktree 并行。共享契约由基线单元维护，预先划定写入文件和接口；合流后重跑联合验收。原路线确认不能自动批准新增平台路线。

每张票记录适用的 pstack playbook、实际执行步骤和证据。Gardening 使用现有事件与 Git 证据复用或验证防线，只有反例失败且正确实现通过才称已验证。Gardening 后处理不成为业务后继门禁，不强制每票新增 Wire。
