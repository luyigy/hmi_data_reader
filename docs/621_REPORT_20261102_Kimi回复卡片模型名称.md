# Kimi 回复卡片显示模型名称

用户要求回复卡片展示 K2.8 Preview，而不只显示 kimi-for-coding。本次基于 d8fc158，在隔离工作区 kimi-model-display-20261102 实施。

## 实现

- 保留运行器实际报告的模型 ID，附加本机 CLI 模型目录的 displayName，例如 K2.8 Preview（kimi-for-coding）。不改变模型选择、思考强度或执行遥测证据。
- 只对通过会话/执行校验的 kimi_wire.llm.request 记录查询名称；其他运行器不查询。按完整别名或唯一匹配的实际模型 ID 查找，不用请求模型替代实际模型。
- 查询最长 2 秒。名称缺失、含控制字符、模型匹配歧义、CLI 失败时保留原 ID；不阻止回复。
- 此次作用于新回复卡片的 footnotes。已发送的历史卡片不回写，成员状态面板沿用原显示。

## 验证

- 新增端到端展示测试：模拟 CLI → collectLiveRoomFootnotes → 实际回复卡片，包括 K2.8/K3.1、别名、请求与实际模型不同、其他运行器、会话不匹配及失败回退。
- live-room-footnotes、kimi-code-runtime-state、kimi-code-model-catalog 回归通过。
- TypeScript、修改文件 ESLint、长文件守卫、git diff --check 通过。真实本机 CLI 名称查询通过，没有提交模型 prompt。
- 扩展测试 harness-runtime-state 报 Prisma P2025 / No Task found；在未包含此次修改的 d8fc158 工作区复测同样失败，未为测试创建生产数据。
- GitNexus 定向分析与源码确认共用 formatter 的两个调用者为回复脚注和成员状态面板。新增参数可选，原调用保持行为。

## 集成与运行

采用追加提交、fast-forward 合入运行目录；飞书常驻进程需重载才能读取新代码。使用 output/621-reload-feishu.mjs 等待运行任务、定时任务和 delivery 均空闲后重载，状态记录为 output/621-reload-feishu.json；waiting 不等于重载完成。
