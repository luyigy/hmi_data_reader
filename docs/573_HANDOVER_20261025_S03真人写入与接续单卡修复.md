## 原因与修复

同一条用户继续指令被分配 conversation 回复身份和 phase 回复身份；展示又直接把内部只读 TaskRun 完成当成用户请求完成。
控制 JSON 的 note 也被重复追加进正常答复正文。

修复让已获准的 conversation-material-handoff 在绑定实施 TaskRun 时继承原回复身份；核对原 task、TaskSession、实施者角色、执行后端及 Agent 身份。
权限判定和 admission 不在展示层执行。后续启动重试继续更新同卡；旧答复晚到不能覆盖当前实施。
只读 turn 已结束但交接尚未结束，或已安排实施尚未绑定时，卡片显示“正在继续”。接续被拒绝不会假显示正在执行。
有正常答复时不再追加控制 note；只有协议 note 的结果仍保留可见说明。下一条独立追问继续保留独立回答。
底层只读/可写环境交接仍存在，此次修正其用户回复生命周期，不承诺消除全部接续时延。
