## 实现与兼容

1. 原 `.agent-platform/runtime.json` 增加 v2 声明：有限的命名资源清单、每项既有 path/output 来源与 SHA256，
   validation 引用清单内的解释器和脚本，并给出有限 argv。禁止声明权限、混入旧业务字段、重复身份或未绑定脚本。
   仓内声明仍须提交；宿主登记仍须使用独立批准的绝对路径。没有新的环境调度器、数据库迁移或授权入口。
2. `prepareDeclaredRuntime` 复用路径授权、规范路径、内容摘要及产物事件绑定，生成资源回执和 Agent 指令，
   通过 `AP_GRAPH_RUNTIME_RESOURCES_JSON` 和 `AP_GRAPH_RUNTIME_VALIDATION_JSON` 提供精确路径及命令。
   新路径不执行项目脚本，也不写入旧版业务探测成功事件。准备完成只表示资源核验完成，不等于业务环境通过。
3. Agent 在现有任务沙箱、Writer 与预算内执行验证；指令要求把固定候选、实际解释器、依赖版本、运行资源身份、
   日志及 environmentFingerprint 纳入自测证据，缺依赖如实返回 environment_failed。
   复用现有自测/验收结果合同，平台不因一份资源声明推断业务成功。
4. 原生启动、非 Git 复核和恢复准入继续使用同一 claim pin；资源存在但源码候选错误仍拒绝。
   多项目入口保留各项目验证指令，不丢失个别项目的资源环境。沙箱仅增加两个通用环境变量，不增加读写授权。
5. v1 OCR 必需文件、浏览器启动和技能检查移入 `runtime-preflight-legacy.ts`，实际调用者按声明版本选择入口。
   原有成功探测复用、探测内外资源重验、PostgreSQL 服务识别和旧快照行为保持兼容；没有批量迁移旧声明。

最小 v2 形状如下，SHA256 必须替换为实际内容摘要，路径须先有现有权限；示例不是已批准的资源申请：

```json
{
  "version": 2,
  "resources": [
    { "id": "interpreter", "resource": { "path": "/approved/runtime/bin/node", "sha256": "<实际摘要>" } },
    { "id": "script", "resource": { "path": "scripts/verify-environment.cjs", "sha256": "<实际摘要>" } },
    { "id": "dependencies", "resource": { "path": "/approved/dependencies", "sha256": "<实际摘要>" } }
  ],
  "validation": { "interpreter": "interpreter", "script": "script", "args": [] }
}
```
