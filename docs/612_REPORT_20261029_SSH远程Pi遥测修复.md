# SSH 远程 Pi 遥测修复

本次针对实际出现问题的 `pi-206`，不启动任务图或自动交接。

## 根因与修复

`pi-206` 已安装 Node，但 Pi 启动器只给自身进程添加
`${XDG_DATA_HOME:-$HOME/.local/share}/pi-node/current/bin`。
平台原采样命令只添加 `$HOME/.local/node/bin`，实际执行返回 127，提示 node 未找到。
采样命令现在复用 Pi 管理的 Node 路径，保留旧路径和系统 PATH 作为回退。
远端未安装新软件，也未修改 Pi 设置。

SSH 执行原先只回传正文、工具事件、错误和会话目录，未返回或持久化模型与用量。
现在结束采样时使用本轮 JSON 输出中的原生 session ID，读取唯一匹配的 JSONL 文件。
只传输分支 ID、时间、模型、思考设置及用量字段，排除提示词、回复正文和工具结果。
沿用已有 `parsePiSessionTelemetry`，核验本轮用户消息、有效 assistant 消息、时间范围与分支链。
模型、思考和用量都来自原生证据，不使用请求参数冒充实际值。

采样结果返回 SSH 执行器后，平台依次写入会话绑定、上下文用量和执行状态，卡片可读取同一
execution/session 的数据。仍保留未知、身份歧义、文件损坏及遥测失败时的降级行为。
文件超过既有解析上限 64 MiB 时只采大小，不读取完整内容生成模型用量。

改动仅接入登记 SSH 主机的执行分支。`remote-node:` 网关 Runner 的传输协议未改变。
上下文窗口上限尚未由该链路确认，显示沿用明确标注的默认 1M 估算；token 数是实际用量。
卡片的输入/输出指标表示最近一次模型调用，不是整轮多次工具调用的累计花费。
