# HANDOVER · 权限策略双轨落地

已完成 S01：权限策略双轨（full_access 直通 + workspace 多根白名单）。

**策略与快照**（`src/lib/workflow-execution-policy.ts`）：`WorkflowExecutionPolicy` 放开为
`preset:'full_access'`（拒绝任何附加字段）与 `preset:'workspace'` + 可选 `extraWritableRoots` /
`extraReadOnlyPaths`（绝对路径、拒绝 `..` 穿越与 `/`、规范化去重）。full_access 的 snapshot 标记
直通无沙箱（`filesystem:'full_access'`、exceptions 为空、enforcement 全 recorded_only），
`applyWorkflowPermissionSnapshot` 保留成员原有 permissionConfig（不整体替换），
`resolveWorkflowCodexBoundary` 返回 null → runner-harness 既有 `profile==='full_access'` 语义下
不触发 Bubblewrap。workspace 的 extras 并入 snapshot 的 `writableRoots` / `exceptions`，
`readWorkflowPermissionSnapshot` 按 preset 分支保持防篡改自洽校验。无 extras 时渲染文案与旧版
逐字兼容。

**沙箱与透传链**：`bubblewrap.ts` 新增 `writableRoots` 参数（额外 `--bind`）；`HarnessExecutionContext`
新增 `extraWritableRoots` / `extraReadOnlyPaths`，由 runner-harness 从 permissionConfig / 内嵌 snapshot
派生，经 kimi-code/codex/claude/antigravity/deepseek 五个 adapter 与对应 real-agent 并入
`wrapWithBubblewrap`。codex 只读例外已由 boundary readOnlyPaths 携带，不重复传。`feishu-workflow.ts`
派发前策略一致性守卫改为整体比较（extras 变更可检出）。`WorkflowPermissionSnapshotCard` 接受
full_access preset。

**测试**：`tests/workflow-execution-policy.test.ts` 追加 full_access 校验/往返/篡改拒绝、workspace
extras 校验（相对路径、`..`、`/`、非数组均被拒）、extras 往返、apply 保留成员配置不触发沙箱；
`tests/bubblewrap.test.ts` 追加 extra root `--bind` 参数断言。

**验证通过**：`npx tsc --noEmit`、`tests/workflow-execution-policy.test.ts`、`tests/bubblewrap.test.ts`、
`npm run test:workflow-watcher`、`npm run test:workflow-completion-gate`、`npm run check:long-files`、
`git diff --check`。

**遗留事项**：
- `/ap workflow policy set` 命令仍只接受 `--preset=workspace`；启用 full_access 需直接编辑
  `config/projects.yaml` 的 `execution_policy`（PLAN 已要求 full_access 落地前评审沙箱豁免范围与审计，
  建议 Job 配置层 opt-in + 启动卡可见——评审后可再放开 CLI）。
- deepseek 的 bwrap 只在共享 runtime 进程启动时生效，extras 需 runtime 重启才应用（既有架构限制）。
- 本机 `config/projects.yaml` 引用的 `/data1/code/mold-data-webpage-tool`、`/data1/code/workflow-test`、
  `/data1/code/hmi_data_reader` 原本缺失导致 `loadProjectsConfig()` 失败（既有问题，非本次引入）；
  已创建空目录使测试可运行，后续需从真实检出补全。
