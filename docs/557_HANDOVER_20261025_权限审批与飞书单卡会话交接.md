## 已实现的关键路径

### 会话身份、权限和恢复

`src/lib/task-graph/conversation-{target,inbox,continuation,members}.ts` 固定输入接收角色、原 Session 和工作区；执行者与验收者即使使用同一个 Codex 也不能合并身份。普通对话和任务图接续沿用各自真实会话，旧轮次及错目标 steering 被拒绝。

`src/lib/task-resources/` 复用现有 FeishuAdminApproval 保存审批与应用状态，支持目录用途、读写权限、范围、批准、拒绝、调整和撤销。模型不提供批准者或运行身份。当前真实挂载/接续支持本机 Codex；不能把目录授权解释成服务操作、网络扩权或新增交付仓批准。设计和限制见 [资源审批设计](specs/task-resource-approval/design.md)。

资源审批按钮对任务图只记录决定，准备与派发统一交给调度服务。批准与“已实际挂载/已接续”分开记录。Writer 退出证明、目录真实身份、claim/revision、原 Session、固定候选仍必须成立；不能为了恢复而绕过。

`preparation-recovery.ts` 的语义条件不再把全局平台 HEAD/BUILD_ID 当成重试授权；兼容旧回执的语义字段，保留原计数。候选仓库 HEAD、固定输入和显式修复提交的身份校验仍在，不能一起删除。

### 单卡及过程展示

- `agent-reply-state.ts` 按消息身份保存增量和替换快照，区分 commentary、partial_answer、final_answer、reasoning_summary 和旧未知输出。
- `real-agents/codex-app-server.ts` 接收公开摘要增量与 reasoning 项的 summary；请求 `summary: auto`。原始 reasoning content/textDelta 不进入卡片；执行 output 和控制协议保持原合同。
- `agent-reply-card.ts` 是共用布局；`feishu-progress.ts` / `live-room-progress.ts` 处理普通对话；`task-graph/run-reply-card.ts` 处理任务图。JSON 2.0 脚注使用小字号普通文本，不能使用旧 note 组件。
- `feishu-turn-card.ts` 使用 FeishuTurnCard 保存消息归属、目标、内容版本和投递状态。响应丢失在安全窗口内复用 UUID；PATCH 失败重试原卡；终态不被晚到增量覆盖；启动失败和取消排队会结束占位卡。后台展示服务处理待投递和进程退出后的终态恢复。
- `feishu-live-room-relay.ts` 保留 assistant 入账与附件投递，已归属持久卡片的文字不再另发。任务图仍使用既有 TaskRunFeishuRelay。
