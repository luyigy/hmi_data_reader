# 交接 · 工作流沙箱"看不到兄弟仓/权限降级"修复 + 额外挂载飞书卡片配置

- 适用项目：`mold-data-webpage-tool`（科学试模助手 / machine-converter-release），Reader 仓 `/data1/code/hmi_data_reader`

## 1. 背景（原始问题）

用户反复反馈：工作流模式下 **kimi-code 在沙箱里看不到第二个仓库（Reader 仓）**，且成员权限"本来是 full access，后面被降级"。此前声称"修复"，实际未生效。

## 2. 根因（已定位，代码级证据）

详见 `docs/RCA_20260813_工作流沙箱兄弟仓库不可见与权限降级.md`。要点：

1. **平台早有能力，缺的是配置**：`config/projects.yaml` 里 `mold-data-webpage-tool` 的 `execution_policy: { preset: workspace }` **从未把 Reader 仓登记进 `extraReadOnlyPaths`/`extraWritableRoots`**。
2. **降级是设计行为**：`workflow-execution-policy.ts` 的 `detectWorkflowPermissionDowngrade`（:344）在 `preset: workspace` 下，凡 `profile === 'full_access'` 的成员都会被**强制收敛为单目录 Bubblewrap 沙箱**。full_access 阶段无沙箱、Reader 仓可见；一旦收敛、又未登记 → Reader 仓消失。
3. **数据流贯通**：`config` → `buildWorkflowPermissionSnapshot` → `applyWorkflowPermissionSnapshot` → `runner-harness.ts:123-129` → 各 harness adapter → `wrapWithBubblewrap({ readOnlyPaths/writableRoots })` → bubblewrap `--ro-bind`/`--bind`。底层链路一直可用。
