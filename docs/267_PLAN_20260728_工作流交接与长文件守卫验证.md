# PLAN · 工作流交接与长文件守卫验证

## 目标

用完全本地、确定性的测试验证新行为：workflow watcher 不会中断仍在完成中的
上一 Session；workflow completion gate 会拒绝已超阻断阈值文件的增长。

## 边界

- 只修改相关测试及必要的最小实现缺口。
- 不重启服务、不调用真实飞书、不执行真实 Agent Session、不修改共享数据库数据。
- 不处理新的业务功能或重构既有超长文件。

## S01：等待旧 Session 的 watcher 回归测试

在 `tests/workflow-watcher.test.ts` 增加一个 runner 返回“等待”的场景，断言 watcher 保留
原 cursor/event，未把下一 Slice 标记为已启动；随后 runner 可启动时断言复用同一 event key
并正常推进。

## S02：长文件 completion gate 回归测试

在 `tests/workflow-completion-gate.test.ts` 的临时仓库中构造一个已达阻断阈值的源文件；记录
baseline 后增长该文件，断言 completion gate 失败并包含文件与行数变化。保留无合同仓库的
兼容行为。

## S03：本地验证与交接

运行两项聚焦测试、现有 long-file detector、TypeScript、`git diff --check`；执行
`npm run check:long-files` 确认输出仍由合同驱动。提交后创建终态 HANDOVER，
`plan_progress: complete`、`next_action: await_acceptance`，列出未执行的真实飞书/服务验收。
