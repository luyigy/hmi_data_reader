## 当前体验问题

1. `/ap menu` 一次发送四张卡，信息密度和消息占用过高。
2. 带参数命令仍需复制模板后手工输入，尚未发挥卡片表单能力。
3. 部分命令结果字段多、英文标签多，飞书内阅读成本高。
4. 结果目前以文本回复为主，缺少“摘要优先、详情按需展开”的层级。

## 推荐的下一薄切片

目标：把命令中心改为**一张卡、一次只展示一个层级**。

### 单卡导航

- `/ap menu` 只发送一张首页卡，展示四个分类入口。
- 点击分类后更新原卡，展示该分类的常用操作与命令说明；提供“返回首页”。
- 优先使用卡片回调更新同一消息，不通过连续发送新卡实现分页。
- Workflow Dashboard 保持独立业务卡，不塞进通用菜单卡。

### 参数输入

- 先覆盖高频且字段边界明确的命令，不实现“任意 AP 命令表单引擎”：
  - job 选择与 Workflow 操作；
  - schedule 的 cron；
  - workspace 路径；
  - chat / plan 的文本；
  - 需要用户选择的 agent / member。
- 使用 Card 2.0 `form`、`input`、`select_static` 和提交按钮。
- 表单回调必须映射到服务端白名单和结构化 `ParsedFeishuCommand`，不得直接拼接并执行用户提供的
  完整命令字符串。
- 改变状态的操作保留权限检查和二次确认；输入在服务端继续做现有校验。

### 中文与信息分层

- 先中文化命令中心最常用的 `status`、`sessions`、`jobs`、Workflow 诊断结果。
- 返回卡片先显示中文结论、状态、下一步；长列表或原始诊断放入折叠详情。
- 不对任意输出做脆弱的全局字符串替换；在各命令已有数据边界处生成中文展示模型。
- 保留必要的 ID、路径、commit、错误原文，避免中文化丢失排障证据。
