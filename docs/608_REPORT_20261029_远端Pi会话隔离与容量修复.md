服务重启由用户与 607 跨聊天室并发修复一并执行。本轮不删除历史、不重置生产会话、不升级远端 Pi。

TX-ET-SERVER 的 tpi 在 2026-10-29 10:26:52 创建了新平台 Session，10:27:22 生成新 Pi 原生文件。
旧目录由 taskId 唯一决定，重置后仍共享该目录，采样又把所有 JSONL 累加。
重置前 20,302,250 字节，10:54 的 20,890,618 字节包含新会话 588,368 字节与全部旧历史。
因此 `new-session` 已生效，19.92 MiB 是容量统计范围错误。

## 实现

- `ssh-executor.ts`：无 resumeSessionId 时分配 taskId + UUID 的独立目录；一次执行只分配一次，
  Unix 启动、PowerShell 回退、结果续聊标识及采样均使用同一目录。有续聊标识时原样沿用旧目录。
  比此前讨论的 task/member/platform-session 多字段路径更小：调用方已有目录续聊标识，
  唯一目录本身即可隔离重置及不同成员，无需新数据库字段或修改房间身份。
- 从 Pi JSON 流的 `type: session` 头读取原生 ID；每次执行独立捕获，不跨执行复用猜测值。
- `ssh-session-size.ts`：文件头采样包含原生 ID，只发布与本次 Pi 头唯一匹配的文件大小。
  增量仅比较该文件的前后大小与文件系统身份，其他历史文件增长不计入。
  未知 ID、匹配歧义或采样失败均不发布错误目录总量；不改变 Agent 的正常结果或原始异常。
- 旧目录继续原生续聊，统计自动切换为本轮原生文件；无需搬迁或删除历史。
  上线后下一次完成采样才更新展示，不回写历史运行卡片。新会话含 bootstrap，容量不会严格为零。
- 本次仅 SSH 后端，不改 Remote Runner 协议、Pi 安装、权限或会话重置命令。

## 验证

原实现红灯：`npm run test:session-size-ssh` 在旧目录加入历史文件后，
断言 `current session must exclude old histories` 失败：`20067 !== 37`。
修复后同一断言通过。

通过的测试与检查：

- `npm run test:session-size-ssh`：实际只读 Node 探针、旧目录多文件、准确增量、文件截断、
  大文件、路径引号/符号链接、SSH 失败仍采样、未知/重复 ID 不汇总、采样失败不吞原始异常。
- `npm run test:session-isolation-ssh`：实际执行生成的 Bash 命令，SSH/Pi 模型边界使用 fixture，
  新建、重置目录分离，续聊沿用目录，历史不变，旧目录兼容，同任务并发新会话隔离。
- `tests/remote-ssh-windows-fallback.test.ts`：Unix 缺失时 PowerShell 回退、初始/续聊参数、
  新会话目录不同且返回值与实际生成命令一致。该项为命令和传输 fixture，非 Windows 实机模型执行。
- `tests/remote-ssh-pi-progress.test.ts`：原生进度、回复与供应商错误处理。
- `npm run test:new-session-rotation`、`npm run test:session-size`、`npm run test:session-size-agents`。
- 全量 `npx tsc --noEmit --incremental false`、改动 TS 文件 ESLint、`npm run check:long-files`、`git diff --check`。

使用 platform-ssh 对 TX-ET-SERVER 只读核验：安装的 Pi print mode 确实输出 session header；
新采样代码在实际旧目录读取 37 个文件，目录共 21,241,876 字节，而当前原生 Session
`01a1857b-bf58-78f1-a4f1-87f98ceae0e4` 仅 939,626 字节（约 0.896 MiB），本次采样增量为 0。
没有启动额外模型对话、修改远端文件或中断现有任务。
