# HANDOVER · 飞书长连接静默失活自动恢复交接

## 任务与故障判断

用户报告近期两次向平台发送飞书消息后没有回复，并授权修复和重启服务，随后要求中文交接并提交。2026-10-15 的排查中，平台最后一次处理飞书消息约在 11:21；11:29—11:30 的消息没有进入平台处理链。进程仍在运行，WebSocket 的 TCP 连接仍显示 ESTAB，因而原有进程状态不足以判断飞书事件是否还能到达。重启飞书服务后收发恢复。底层网络或服务端导致这次连接失活的具体触发点没有证据可确定；已确认的设计缺口是 SDK 长连接在未收到 pong 时没有由平台主动判定失活和重连。

## 已完成修复与用户可见行为

- 新增飞书连接监督器：记录最近一次 WebSocket pong，连续 7 分钟未收到 pong 时判定连接失活；每 30 秒检查一次，强制关闭并重启同一 SDK 客户端。重连后收到 pong 才标记为健康。
- 失活与恢复各向 `FEISHU_ADMIN_OPEN_ID` 对应管理员发送一次飞书通知；通知走飞书 REST API，单次请求 10 秒超时，发送失败会记日志。通知原文如下：

  > ⚠️ 飞书连接异常：平台暂时无法确认收到新消息，正在自动重连。未收到回复的消息请在恢复后重发。

  > ✅ 飞书连接已恢复，平台已重新接收消息。异常期间发送但没有回复的消息，请重新发送。

- 连接状态进入运行时状态、连接健康 API、Dashboard 和 `/ap status`。长连接未健康时健康 API 返回 503，避免仅凭进程存活误报正常。
- 将 `@larksuiteoapi/node-sdk` 固定为 1.60.0，保持监督器所依赖的 SDK pong 日志格式稳定。
- 2026-10-15 已在用户授权下重启 `agent-platform-feishu.service`。重启后的运行状态为 `running`、连接状态为 `healthy`，最近一次传输时间为 `2026-10-15T03:59:59.584Z`（北京时间 11:59:59）。

此机制能自动发现并恢复符合“持续无 pong”特征的静默失活，但不能保证所有外部故障永不再发生。故障期间未被平台收到的消息不会自动补发；用户应在恢复通知后重发未获回复的消息。若飞书 REST API 同时不可用，管理员通知可能无法送达。
