## 字段与恢复约定

核对本地官方 SDK 的 `im.message.receive_v1` 和 `im.message.reply` 类型：message/root/parent/thread 是不同字段；reply 支持 `reply_in_thread`，返回 chat/root/thread 信息。官方接口入口：[接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)。网页正文未被抓取，结论以安装的官方 SDK 类型为依据，未冒充真实群实测。

1. 先 `reserveFeishuTaskBinding` 持久化创建意图，以来源消息 ID 去重，并保存标题与已由调用层校验的工作目录。此时没有房间。
2. 用 request.id 作为发送 API 的 uuid；成功发出入口卡片后，以返回的 message_id 调用 `recordFeishuTaskRoot`。失败或结果不明时保留同一意图，先查证原卡片；不能盲目发送新卡片。超出飞书 uuid 去重时限时也必须人工/接口核对原发送结果。
3. 后续经过验证的事件或可信 reply/get 响应同时确认 chat/thread/root 后，调用 `confirmFeishuTaskBinding`。禁止传入客户端自报的归属或由 parent/root 拼出的 thread。
4. 本地事务内嵌套创建 room + binding 并回写 request.bindingId；唯一冲突整体回滚，因此建卡失败、重复创建、映射冲突均不会留下孤立房间。群设置行锁协调并发确认和关闭模式；关闭后拒绝新的最终绑定，已完成请求可幂等返回。

当前接入仅使用单一 `FEISHU_APP_ID`。新任务始终携带明确 appId；旧绑定仅允许当前环境 appId 读取，其他 app 不得继承。群开关函数是内部持久化 API，S03 必须在调用之前完成服务端管理员授权。
