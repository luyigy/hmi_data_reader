# PLAN · 飞书原始Markdown文件选择与发送

本计划记录 2026-10-03 已按任务室指令完成的单 Slice 变更，供交接文档关联；不请求审批或自动启动执行。

## 目标与障碍

在绑定代码仓库的飞书 Live Room 中，让用户找到并收到仓库已提交的原始 Markdown 文件。原有 `/ap doc` 会导入为飞书文档，不能直接发送原始 `.md`；文件较多时，平铺选择或按页翻找也难以定位最近的交接与 PLAN。

## 路线与结果

本计划只有 S01：在现有命令和卡片回调链路中加入 `/ap md`，按 `docs` 交接、`docs` PLAN、`docs` 其他、仓库其他位置切换；默认展示最近的交接，分区内按文件编号倒序排列。选择后从当前 Git HEAD 读取原始内容，以飞书文件回复。用户也可用关键词筛选或完整路径直接发送。

## S01：交付原始 Markdown 文件选择与发送

- **目的与结果**：让用户从同一张飞书卡片选择已提交的 MD，直接收到原始文件；近期交接和 PLAN 可快速找到。
- **实现方法**：复用房间绑定和文档访问检查；用 `git ls-tree` 列文件、`git show` 读指定 HEAD；卡片分区切换在原卡更新，发送时上传飞书文件并回复会话。卡片保存 HEAD，版本变更时要求重新打开。
- **修改边界**：飞书命令解析、入口、帮助、文档读取、文件 API、卡片回调和直接测试构成一条调用链；不改变 `/ap doc` 的导入用途。
- **验收**：文件发送和选择卡测试、命令测试、TypeScript 检查、长文件检查及 `git diff --check` 通过；真实飞书点击留到服务加载新代码后验证。
- **前置与停止条件**：仅从已提交的仓库版本发送；房间未绑定、无访问权、文件不在列表或 HEAD 已变化时停止并提示用户。
- **交付物**：实现、测试、终态 HANDOVER 和提交。当前服务需重启才会加载代码，重启不属于本 Slice 提交动作。
