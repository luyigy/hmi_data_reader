# Kimi 模型切换校验修复

## 问题与实施范围

用户在工程图识图群尝试切换到 `kimi-code/kimi-for-coding`（K2.8 Preview），平台返回 `Invalid Codex model`。本轮修复该命令失败，并按用户已表达的选择设置该房间的 Kimi 模型；不开放 Kimi 思考强度、不更换其他房间默认模型、不触发业务重跑。

基线 `6b208d8`，隔离工作区 `/data1/code/agent-platform-v2-worktrees/kimi-model-selection-20261102`。长文件守卫通过。实施前复现：在 `tests/kimi-code-model-catalog.test.ts` 使用实际命令解析器、处理器和内存持久化，输入用户原文，失败为 `Invalid Codex model`，退出 1。

实施方案：Kimi 模型别名采用已有 provider/model 格式校验，保留 Codex 原规则及 Kimi 禁止显式思考强度的能力边界；回归覆盖真实命令、查询、inherit、非法模型拒绝且配置不变，以及其他 harness 设置。失败则不集成。

## 根因与影响

`normalizeMemberModelSettings` 仅 Pi 走允许 `/` 的分支，Kimi 错误落入 `normalizeCodexMemberSettings`，而该函数禁止 `/`。所有列表中常见的 Kimi 完整别名都会失败，不是 K2.8 无权限。

命令解析器将 `(K2.8 Preview)` 分成额外 args，没有把它拼进 --model；因此此次根因不是括号。`thinking=high` 未带 `--` 时也只是额外 args，不会设置思考强度。推荐只发送模型 ID，避免误以为说明文字或裸参数生效。

GitNexus 定向 impact 列出 Feishu handler、成员 PATCH、Pi 参数构建等调用者。实际源码核对后，复用原 Pi 格式校验且按 harness 保留错误/强度约束，Codex 和 Antigravity 行为不变。本轮不修改公共 API 合同或数据库 schema。
