# WR06：飞书投递超时不拖停业务执行

状态：隔离回归与独立评审已通过，协调器和任务进度卡服务已更新；实际 R01 接续验证中。

远端单据：[IKNBDT](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDT)；父规格：[IKNBDN](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDN)。

## What to build

群话题创建或进度卡更新临时失败时，业务结果继续保存在账本，通知按持久回执补投，不把消息故障当作实施派发失败。

## Acceptance criteria

- [ ] 复用已有持久消息请求和回执，投递重试具有稳定幂等标识，超时先对账而非盲目重复创建话题或卡片。
- [ ] 注入创建话题与更新卡片超时，不改变业务执行状态，不产生业务 dispatch_failed。
- [ ] 恢复投递后消息进入仓库正确绑定群的原子话题，复用现有卡片；私聊仅呈现摘要和入口。
- [ ] 正文保持简短，系统、工具和技术报告折叠，状态区分自动修复、等待依赖、需决定和耗尽。
- [ ] 如果原批准策略明确要求先建立审计通道，启动前如实完成该前提；不通过本票取消已批准约束。

## Blocked by

None（无前置，可先开始）

## 执行方式

本票按 poteto-mode 的 Bug fix 流程实施：先复现真实故障并保留红色测试，再沿已确认架构修复，运行实际行为回归后交独立验收。技能及项目适配在每个新 Session 显式加载。平台负责批准路线、依赖、受控提交和集成；Agent 不自行扩大权限或派发其他票。

会话结束、代码有变化或结果格式可解析均不等于验收通过。保留原审批、历史证据、原仓文件和既有项目环境。超时后先核对现有操作，避免重复执行。
