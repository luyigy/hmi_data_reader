# WR01：自测与平台检查使用一致的报告运行目录

状态：已发布供审阅，尚未批准执行路线或派发。

远端单据：[IKNBDO](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDO)；父规格：[IKNBDN](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDN)。

## What to build

让同一张票在实施自测和只读平台检查中运行相同命令，报告、缓存和临时数据都能写入本次执行目录；原图、真值和源码保持阶段要求的保护。

## Acceptance criteria

- [ ] 用真实临时 Git 仓库、数据库和 Bubblewrap 复现报告写入失败，再证明相同检查命令在统一输出契约下通过。
- [ ] 每次执行具有独立输出目录；项目固定相对输出路径仅经显式声明映射，未跟踪文件不自动获得写权限。
- [ ] 实施、平台检查和独立验收使用已配置的项目解释器与必要输入；不新建项目虚拟环境。
- [ ] 报告、缓存、数据库均不污染原仓；原有输出保留，目录符号链接不能扩大写入权限。
- [ ] 回归证明真实受跟踪输入只读，平台临时输出可写，并记录实际检查命令和结果。

## Blocked by

None（无前置，可先开始）

## 执行方式

本票按 poteto-mode 的 Bug fix 流程实施：先复现真实故障并保留红色测试，再沿已确认架构修复，运行实际行为回归后交独立验收。技能及项目适配在每个新 Session 显式加载。平台负责批准路线、依赖、受控提交和集成；Agent 不自行扩大权限或派发其他票。

会话结束、代码有变化或结果格式可解析均不等于验收通过。保留原审批、历史证据、原仓文件和既有项目环境。超时后先核对现有操作，避免重复执行。


## 实施契约

每个实施 TaskRun、平台检查和独立验收获得独立的 `AP_GRAPH_OUTPUT_DIR`。`TASK_GRAPH_OUTPUT_DIR` 是兼容别名。Python、XDG 和 npm 缓存也指向本次运行目录。已有项目解释器和依赖只读复用。

新检查使用环境变量输出路径。旧脚本必须写固定相对路径时，在项目提交中声明 `.agent-platform/outputs.json`：

```json
{
  "version": 1,
  "paths": ["output/job"],
  "readOnlyPaths": ["output/job/input-materials"]
}
```

平台读取当前提交中的声明。映射只能覆盖被 Git 忽略、没有受跟踪文件的目录，且限于关联的独立 worktree。原始仓库、Git 元数据和共享依赖不在映射范围。目录、声明或内部文件存在符号链接时拒绝映射，保留现场。

旧目录内的原有报告复制到本次运行目录后再挂载，历史报告不被覆盖。声明的只读原图输入直接只读挂载，避免每个阶段重复复制原图。原图仍由现有工作区产物归档保存一次。`readOnlyPaths` 声明的输入在旧路径和运行目录路径都保持只读。复制上限为 10000 个文件、256 MiB；超过上限保留原文件并报告明确错误。

后续阶段不复用前一阶段的可写目录。`AP_GRAPH_PRIOR_OUTPUTS_JSON` 提供同节点的先前只读运行目录，供显式读取夹具和证据。运行记录写入 `output_runtime_prepared` 事件，并由现有节点验证产物归档流程保存。归档验证通过之前不删除这些运行目录。

WR01 仅解决输出运行契约；检查失败后的自动回修及调度器恢复由后续票负责。
