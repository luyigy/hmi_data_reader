# WR03：架构和测试发现缺陷后只回修受影响仓内执行

状态：隔离回归与独立评审已通过，协调器和任务进度卡服务已更新；实际 R01 接续验证中。

远端单据：[IKNBDQ](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDQ)；父规格：[IKNBDN](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDN)。

## What to build

架构复核和独立测试发现原范围内缺陷时自动交回对应执行；已成功的兄弟执行不重新启动，Slice 级验收使用正确的新旧提交组合。

## Acceptance criteria

- [ ] 架构失败、验收失败和集成检查失败使用有命名空间的稳定检查 ID 与统一失败分类；错误 ID 先补收，不模糊匹配为通过。
- [ ] 双执行场景中仅一侧被修复：另一侧 Agent 启动次数为零、成功提交和原始证据保留，不因没有代码变化失败。
- [ ] 受影响跨仓合同、架构边界和联合检查对新组合重新执行；身份不变的旧证据可复用，旧证据不能冒充新组合证据。
- [ ] 替换全量重置 execution 的旧回修路径，预算和目标执行范围明确。
- [ ] 成功后按原批准模式放行后继；需人工批准的节点仍核验真实批准，implement 模式仍不能标独立验收通过。

## 执行方式

本票按 poteto-mode 的 Bug fix 流程实施：先复现真实故障并保留红色测试，再沿已确认架构修复，运行实际行为回归后交独立验收。技能及项目适配在每个新 Session 显式加载。平台负责批准路线、依赖、受控提交和集成；Agent 不自行扩大权限或派发其他票。

会话结束、代码有变化或结果格式可解析均不等于验收通过。保留原审批、历史证据、原仓文件和既有项目环境。超时后先核对现有操作，避免重复执行。


## 实施契约

验收、架构和联合检查使用稳定检查 ID。命名空间分别为 `acceptance:<名称编码>`、`architecture:scope` 和 `integration:<仓库编码>:<名称编码>`。旧验收名称仅按精确匹配兼容，不做模糊匹配。

复核者返回范围内缺陷时，必须给出合法检查 ID 与明确的受影响 `executionIds`。单执行可以使用唯一归属；多执行不得由平台猜测。未知检查 ID、越界执行 ID 或缺失结论仅补收一次。补收次数和原始返回持久保存，重启不会重置同一 claim 的格式预算。仍无有效结论时记录协议耗尽，不能合成通过。

回修只通过统一执行结果接口推进目标执行。未受影响的兄弟保留已集成提交和原证据，不重新启动 Agent，也不因没有代码变化报错。目标回修后重新运行联合合同、架构和独立验收，证据对应本次完整提交组合。

节点进入复核的事件标识由执行提交与 revision 组成；复核结果绑定实际 claim、TaskRun 和候选提交。发布结果在节点锁内再次核验归属。恢复先读取精确绑定的已完成结果，避免重复启动复核者。人工明确重新排期产生新 claim，不复用之前的失败结论。

验证使用真实临时 Git、多仓、独立数据库 schema 和 Bubblewrap，模型调用由测试替身驱动。架构失败、联合检查失败、验收错误 ID 均证明目标执行启动两次、成功兄弟一次、联合合同复验两次，且自动启动后继，人工 resume 次数为零。两次无效复核结论停在明确的协议耗尽状态。
