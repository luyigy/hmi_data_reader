# WR03：架构和测试发现缺陷后只回修受影响仓内执行

状态：已发布供审阅，尚未批准执行路线或派发。

远端单据：[IKNBDQ](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDQ)；父规格：[IKNBDN](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDN)。

## What to build

架构复核和独立测试发现原范围内缺陷时自动交回对应执行；已成功的兄弟执行不重新启动，Slice 级验收使用正确的新旧提交组合。

## Acceptance criteria

- [ ] 架构失败、验收失败和集成检查失败使用有命名空间的稳定检查 ID 与统一失败分类；错误 ID 先补收，不模糊匹配为通过。
- [ ] 双执行场景中仅一侧被修复：另一侧 Agent 启动次数为零、成功提交和原始证据保留，不因没有代码变化失败。
- [ ] 受影响跨仓合同、架构边界和联合检查对新组合重新执行；身份不变的旧证据可复用，旧证据不能冒充新组合证据。
- [ ] 替换全量重置 execution 的旧回修路径，预算和目标执行范围明确。
- [ ] 成功后按原批准模式放行后继；需人工批准的节点仍核验真实批准，implement 模式仍不能标独立验收通过。

## Blocked by

- WR02

## 执行方式

本票按 poteto-mode 的 Bug fix 流程实施：先复现真实故障并保留红色测试，再沿已确认架构修复，运行实际行为回归后交独立验收。技能及项目适配在每个新 Session 显式加载。平台负责批准路线、依赖、受控提交和集成；Agent 不自行扩大权限或派发其他票。

会话结束、代码有变化或结果格式可解析均不等于验收通过。保留原审批、历史证据、原仓文件和既有项目环境。超时后先核对现有操作，避免重复执行。
