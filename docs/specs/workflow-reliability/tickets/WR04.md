# WR04：集成引用变化和合并冲突有明确的恢复出口

状态：已发布供审阅，尚未批准执行路线或派发。

远端单据：[IKNBDR](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDR)；父规格：[IKNBDN](https://gitee.com/luyi1678/agent-platform-v2/issues/IKNBDN)。

## What to build

同仓并行交付遇到集成引用前进时自动重新合流并验证；遇到真实冲突时保留双方现场，在批准范围内修复或提出具体决定。

## Acceptance criteria

- [ ] 注入 integration_stale 后重新读取最新引用，在短锁和比较更新下合并并重跑检查，不覆盖其他交付。
- [ ] 冲突结果保存双方 SHA、路径和 MERGE_HEAD；禁止自动 reset、stash、清理或删除冲突现场。
- [ ] 只有身份、范围和写入归属明确的冲突可进入受控修复；未知来源或超范围冲突等待具体决定。
- [ ] 正常暂停补充与分支归属变化分开处理，不以一个 dirty 错误混淆。
- [ ] 每次验收回修后的新合并结果仍运行 integrationChecks；预算耗尽进入明确终态，不反复要求普通继续。

## 执行方式

本票按 poteto-mode 的 Bug fix 流程实施：先复现真实故障并保留红色测试，再沿已确认架构修复，运行实际行为回归后交独立验收。技能及项目适配在每个新 Session 显式加载。平台负责批准路线、依赖、受控提交和集成；Agent 不自行扩大权限或派发其他票。

会话结束、代码有变化或结果格式可解析均不等于验收通过。保留原审批、历史证据、原仓文件和既有项目环境。超时后先核对现有操作，避免重复执行。
