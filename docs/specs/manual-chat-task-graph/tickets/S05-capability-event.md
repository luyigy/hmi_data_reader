# S05：Agent 用工具申请目录，批准后原会话继续

**What to build：** Agent 在执行时缺少一个目录能力，通过结构化工具申请；用户看到明确用途与范围，
批准后实际应用能力，原 Agent 继续并展示结果。用户或 Agent 讨论申请格式不会触发审批或破坏聊天。
手动聊天与任务图都能完成这个场景，各自保有自己的调度和卡片所有权。

**Blocked by：** [S01](S01-manual-chat.md)、[S02](S02-m06-conversation.md)、[S03](S03-m06-approved-write.md)。
不依赖 S04 业务算法修复。

**Status：** draft，未实施。

**仓库与基线：** `/data1/code/agent-platform-v2` @ `ebbce344249e7c270f6d7f4a2fdc681188c6375e` 加 S01–S03 验证提交。

**默认环境画像：** [spec](../spec.md) 的平台环境，本机 Codex，独立临时目录及隔离审批数据；手动通路测试不启动图服务。

## 验收项及验证命令

- [ ] 真实 harness 暴露资源申请工具/事件；运行时注入身份。请求拥有稳定事件 ID，用途、目录和读写范围可审阅。
- [ ] 重放同一事件不新增审批；批准、拒绝、撤销和应用失败各有正确回执。审批决定与实际应用结果分开显示。
- [ ] 批准后继续同一 Native Session、同一角色和任务；实际访问成功，不把请求文本交给摘要解析器来猜状态。
- [ ] 人或 Agent 在普通文字、代码块、引用中讨论协议不触发申请；普通解释不能导致主对话失败。
- [ ] 手动房间的申请、决定、接续不创建图节点或图 claim；任务图申请仍验证其写占用、角色和候选边界。
- [ ] 旧正文协议仅在显式旧会话兼容入口保留；新会话所选场景无需输出魔法标记，不双发请求。
- [ ] 可见审批卡是实际需要用户决定的交互；执行回复仍复用所属轮次卡，不把审批卡误算成重复执行卡。

把工具入口及原会话实际续接加入以下现有回归入口，并记录真实 harness 证据：

```bash
node scripts/sandbox-postgres-session.mjs run task-resource-access task-resource-runtime task-resource-graph task-resource-concurrency
npm run test:codex-app-server
npm run check:long-files
```

真人演示分别在手动房间与图任务中完成一次“缺目录→工具申请→批准→原会话读写结果”，
再发一条包含协议示例的普通询问，证明没有额外审批。既有审批不为了演示重复创建。

## 保持不变与完成边界

本票只纵向迁移目录能力申请，不借机迁移所有 Harness 或重写所有完成协议。
保留现有批准身份、目录规范化、撤销及读写边界。缺服务或计算资源不伪装为目录申请。
