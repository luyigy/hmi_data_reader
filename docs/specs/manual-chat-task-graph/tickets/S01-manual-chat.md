# S01：任务图未启用时，主对话独立收发和更新卡片

**What to build：** 用户在手动主对话发消息，原 Agent 回复并持续更新同一张卡；
即使任务图调度与展示服务没有启动，正常回复、失败补投、进程恢复后的终态补齐仍可完成。

**Blocked by：** 无。

**Status：** in_progress，代码已验证、可见体验待验收。用户于 2026-10-25 明确授权开始 S01，完成后手动交接。

**仓库与基线：** `/data1/code/agent-platform-v2` @ `ebbce344249e7c270f6d7f4a2fdc681188c6375e`。

**默认环境画像：** [spec](../spec.md) 的平台环境；隔离飞书传输夹具、真实数据库回执，生产主对话仅在获准部署后演示。

## 验收项及验证命令

- [ ] 仅启动聊天通路时，连续两条用户消息各有自己的回复卡，过程和最终答复更新原 message ID。
- [ ] 注入首次发送响应丢失、PATCH 失败及聊天进程退出后重启，补投仍由聊天通路完成，不产生重复卡。
- [ ] 同时启动任务图展示消费者，手动卡片不会被其认领或改终态；启用图的卡片仍由其正确归属者处理。
- [ ] 主对话中讨论 M06、引用申请格式、询问任务状态，不产生任务图派发或业务状态变更。
- [ ] 聊天通路故障与任务图故障分别呈现；任务图停机不使普通聊天等待图状态、检查或重试预算。

在现有回归中加入上述服务缺席/同时存在的行为用例，运行：

```bash
node scripts/sandbox-postgres-session.mjs run feishu-turn-card task-graph-feishu-relay

```

真人演示：在获准的独立运行实例中不启动图服务，主对话发送两条消息，回读各自原卡；
记录消息和卡片 ID。现有生产服务不为此测试停机。

## 保持不变与完成边界

保留统一卡片外观、房间成员、Native Session 接续、权限及历史消息。
通用发送设施可以复用；不能把图后台改个名字就宣称独立，必须证明聊天生命周期不依赖图服务。
只做这条端到端通路所需的整理，不扩展为全平台通知重写。
