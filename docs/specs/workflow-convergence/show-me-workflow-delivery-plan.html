接力评审汇总 · 2026-10-17

让任务真正接得上

前一个任务做完，后一个任务拿到正确版本；缺材料就等材料，补齐后接着做。

实施前方案 · 交互仅演示，不启动任务

01 · 这次到底改什么？

现在容易出现

依赖显示完成，代码却找不到；只写了阻塞报告，也被当作交付；用户说“继续”，平台却恢复了错误的阶段。

改完应该做到

平台先备齐本轮所需输入，再派任务。每次暂停说明原因，继续时回到暂停的位置。工作目录清理后也能恢复。

通用对象只有：任务、依赖、交付物、项目环境、执行尝试。Reader 与 mold 只是一个验收案例，平台不写它们的专用分支。

02 · “等它做完”与“用它的成果”分开

Issues 定关系谁先做、谁等待
→
确认整条路线冻结批准的关系与模式
→
平台准备输入只送本轮真正要用的成果
→
执行并留证据按批准条件放行后继
只等顺序例如等 GPU 使用完。只检查前置完成，不把那个项目的代码、虚拟环境全部搬进来。
要用交付物例如调用另一个仓库的能力。提供固定版本代码、合同和报告，并提供对应项目的运行环境。

Issues 管关系；人确认后，本轮按批准快照执行。关系发生变化需核对，不能静默改变正在运行的任务。关闭 Issue 本身不代表平台验收通过。

04 · 怎么实施：三个单元，逐个交付
由 Codex 顺序实施，每个 Session 完成一个单元，验证、提交、记录后再进入下一单元。


第一单元 · 停得准，接得上
先修正“阻塞”和“交付”的区别
实施者必须明确返回“已交付”或“被阻塞”。阻塞时保存进度，记录卡在哪个阶段，禁止当作完成继续放行。用户补材料说“继续”，沿用现有权限与消息去重链，恢复正确阶段。
验收：只写阻塞报告不会被标完成；同一条继续消息只执行一次；已集成但实施未完的任务，能继续实施而非误入验收。


第二单元 · 成果送到位
统一准备本轮输入，保护版本和恢复点
先审计真实提交和来源，再从批准关系与执行账本选固定版本。只读提供需要消费的上游源码、合同、报告及已有环境。实施、检查、验收、话题问答读取同一份清单。
本单元优先验证同仓门禁：同仓共用集成分支时，前一片未过批准门禁，后一片先等待，避免继承未通过的代码。不同仓库仍可并行。
同一仓内任务的实施与验收复用工作区。前置代码做只读固定副本，不按角色另建一套可写 worktree；默认解释器来自主项目，调用上游用上游的明确解释器。
验收：双仓环境不混用；无关未通过代码不得混入；删除临时目录后仍能重建；旧尝试输入不随上游回修漂移。


第三单元 · 真正跑通联调
需要服务时，临时启动、确认归属、用完回收
由一个执行尝试内的资源模块负责启动、探活、运行检查和回收。使用固定源码、项目现有环境、隔离测试数据与临时回环端口。核对所启动的进程、来源版本及日志，不能随便连一个已有端口。
服务不支持隔离数据等必要能力时，明确阻塞并单独提出业务修改，不暗中扩大平台改造。成功、失败、超时、取消都要回收临时进程。
验收：旧进程占端口不会被误认成新服务；失败后没有遗留进程，不改生产数据。再用 Reader / mold 真实链路做回归。


开始改代码前，先把本轮结论更新到 Spec，并按这三个单元建立或调整 Gitee tickets。复用现有协调器、账本和恢复入口，不再建第二套调度器。

06 · 评审怎么取舍？
三位的共同结论
Antigravity 指出依赖与消费应分开、同仓集成可能夹带未通过代码。Kimi 补齐恢复阶段、保存点和服务回收边界。pi 要求把这些能力放回现有机制，缩小改动，不另造调度系统。
两处分歧，我的最终取舍
恢复靠明确记录阶段。不采用“已 integrated 就只恢复验收”的简化判断；已集成也可能尚未完成实施。保存点写追加事件，不修改首次派发记录。
提交必须真的保得住。pi 所说“任务分支始终保留”与现有清理代码不符，当前会删 job 分支。已集成提交先核对是否由保留的集成分支保护；未集成保存点保留任务分支，活动引用存在就不删。若现有引用无法保证保留期，再增加必要锚点。不能仅凭一个提交号宣称可恢复。
临时目录与磁盘怎么管？
临时源码缓存无活跃使用且满足保留规则后才清理，可以从固定提交重建。报告先归档再清理运行目录。未交付或脏工作区保留并说明原因。项目已有虚拟环境不随任务删除，也不为每个任务重建。清理目录与保留 Git 提交是两件事。
先拿什么证明改造有效？
  • 同仓串行与跨仓并行汇合能正确放行；仅顺序依赖不挂无关代码。
  • 上游回修不会改变正在执行的下游输入，新尝试明确记录版本差异。
  • 缺材料、环境故障、业务实现失败能分清；重复恢复和清理重试不产生重复任务或误删。
  • 使用至少一个非 Reader 命名的通用测试场景，再回归 S06；不把业务例子写成平台规则。
S06 先只读审计、再追加纠正历史分类、核验平台输入与隔离联调，最后列出真实缺失材料。保留原审批与历史，仍按原 implement 模式记录，不擅自提升为验收通过。
