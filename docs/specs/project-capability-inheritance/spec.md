# 项目能力继承与任务资料交互

## Problem Statement

项目已经具有工具、图集和飞书连接，但派生任务、验收及话题会话不能稳定继承。用户反复遇到缺浏览器、缺资料或 CLI 未配置。并行使用 worktree 与 Bubblewrap 应继续保留，不能以开放宿主凭据解决。

## Solution

项目集中管理已批准的能力，任务按用户权限和获批范围自动取得可用配置。用户在任务话题要求查找图片时，执行者能读取获授权资料，并将选定图片展示在原话题。后续任务和验收复用配置，不重复登录或复制整套图集。

## User Stories

1. 作为项目管理员，我希望统一批准工具与资源，让任务无需逐个配置。
2. 作为执行用户，我希望派生工作区直接使用获准工具，保留隔离保护。
3. 作为任务用户，我希望能在话题要求查找资料，执行中也能补充来源。
4. 作为任务用户，我希望收到真正的飞书图片附件，而非服务器路径。
5. 作为验收者，我希望知道实际使用的材料、工具版本与来源。
6. 作为多用户管理员，我希望任务不能借用其他用户的项目或飞书权限。
7. 作为并行任务用户，我希望任务分别写入自己的工作区，共享只读工具与资料。
8. 作为运维人员，我希望缺授权、缺工具和无合适样本分别报告，不笼统报 blocked。
9. 作为授权管理者，我希望撤销权限后新访问立即被拒绝，运行快照不能绕过撤销。

## Implementation Decisions

- 扩展现有项目权限、运行资源解析及快照机制，不另建独立权限系统。项目声明不是授权，管理员批准与用户身份来自受信平台。
- 有效能力由项目授权、当前用户权限、任务获批范围共同限定。派生任务继承能力身份，不继承宿主账号的全部权限。
- 工具和材料版本记录在当前执行快照，实施、验收、续接共享相同来源。外部访问仍核验当前权限；固定快照不冻结已撤销的权限。
- 本地图集按获准目录只读挂载，不全量复制。远端附件按需缓存，缓存键包含租户、来源与内容版本；缓存命中仍核验授权，不能以哈希或文件存在作为访问许可。
- 执行中找到新资料时，保存来源、哈希和追加输入记录，并明确后续轮次使用的新输入版本。不在原快照目录静默替换文件，也不迫使用户重开任务。
- 飞书凭据只在宿主持有。仅支持获准数据源的窄范围资料操作，不开放任意 CLI、URL、群 ID 或飞书 API 透传。表格链接本身不授予访问权。
- 图片展示复用现有回复与附件投递机制，发送目标来自任务话题绑定；上传前校验真实路径、文件类型、大小和本任务读取权限，幂等发送并回读话题归属。
- 卡片正文里的图片语法示例必须按文本呈现；真实本地图片须完成上传后才作为卡片图片，不能因无 image_key 使整段答复丢失。
- Slice 1 实现这条可用路径所需的完整配置与授权，不留下临时全权限兜底。Slice 2 迁移其余启动入口并移除重复解析；过渡期旧入口保持原有隔离，不自动扩大权限。
- 无声明或显式配置失效时给出明确诊断，不静默换浏览器、重登账号或退回 full_access。配置更新产生新快照，未变化能力可复用。

## Testing Decisions

- 优先通过现有任务启动、运行快照、真实 Bubblewrap 与附件投递接口验证行为，不以配置单测代替完整路径。
- Slice 1 验证项目授权、沙箱读取、按需资料补充和绑定话题回图的完整链路。真实飞书读写使用实施时明确批准的测试来源和话题；测试成功不代表业务识读验收通过。
- 本地图集不整份复制，重复下载复用缓存；跨租户、跨用户及符号链接越界均被拒绝，输出无宿主凭据。
- 以旧 ErrCode 11310 和本地图片路径无法展示为反例，检查图片示例可正常回复、真实图片可送达、失败不会吞掉文字。
- Slice 2 在 Reader / Mold 并行及实施、验收、话题续接中验证一致继承、互不串写、版本变化和撤权生效。不能只跑模拟配置读取。
- 当前已完成的原执行会话接续代码是话题交互的已有集成前提，实施时须核对部署版本；不重复创建同范围票，也不提前宣称线上生效。

## Out of Scope

重写 Bubblewrap、任意宿主命令代办、全量图片搬运、实时多架构师协作、改变业务识读真值、绕过独立验收，以及无授权的服务重启与业务续跑。

## Further Notes

只有两个实施 Slice，顺序为 C01 → C02。第一片完成并受控部署即可演示找图与回图，不等待第二片。每片包括实现、测试、演示与证据，不另拆纯框架票。

现有 W2 是沙箱受控交付的基础票，本方案补齐项目能力继承与资料交互，不取代或修改其范围。Issue 发布仅用于计划评阅，不批准自动派发。部署前仍需遵守当前不重启服务的约束。
