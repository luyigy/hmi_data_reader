# HANDOVER · 权限降级显式告警

已完成 S02：消除静默降级（显式告警 + 尊重 full_access）。

**降级检测**（`src/lib/workflow-execution-policy.ts`）：新增 `detectWorkflowPermissionDowngrade`——
仅当 Job 策略为 `workspace` 且成员解析后的 permissionConfig `profile === 'full_access'` 时返回告警
（含涉及成员名单）；`full_access` 策略直接返回 null（尊重成员权限，不降级、不告警）。

**执行卡告警与审计**（`src/lib/feishu-workflow.ts`）：`runWorkflowInBoundLiveRoom` 在绑定房间后对全部
非 user 成员用 `resolveLiveRoomMemberPermission`（成员配置 → 源 Task 继承）解析权限并检测降级；
`buildWorkflowExecutionCard` 新增可选 `downgradeNotice` 参数，告警以加粗 markdown 渲染在
“Workflow permissions” 块之前：“⚠️ 权限降级：成员拥有 full_access，已按 Workflow 策略收敛为
workspace 单目录沙箱（涉及成员：…）”。告警同时写入 dispatch 消息的 metadata
（`workflowPermissionDowngrade: { members, notice, policy }`，与 eventKey、snapshot 并列，可事后审计）。
WorkflowDispatch 模型无 metadata 列，审计落点即该 dispatch 消息 metadata。

**测试**（`tests/feishu-workflow-card.test.ts` 复用扩展）：workspace job + full_access 成员 → 卡片含
降级告警且位于权限块之前、仅列出 full_access 成员；成员非 full_access → 无告警；
full_access job + full_access 成员 → 无告警、snapshot `filesystem: 'full_access'` 不套沙箱。

**验证通过**：`npx tsc --noEmit`、`tests/feishu-workflow-card.test.ts`、
`tests/workflow-execution-policy.test.ts`、`npm run test:workflow-watcher`、
`npm run test:workflow-completion-gate`、`npm run check:long-files`、`git diff --check`。

**遗留事项**：
- 降级检测基于房间成员当前权限配置；rotation 换代不改变 permissionConfig，告警在卡片投递前
  一次性计算（沿用 S01 的 boundRoom 快照），与既有 rotation 流程一致。
- `config/projects.yaml` 引用的三个项目目录（mold-data-webpage-tool / workflow-test /
  hmi_data_reader）再次缺失（S01 建的空目录被清理），已按 S01 同样方式重建空目录使
  `loadProjectsConfig()` 可用；仍需从真实检出补全（既有问题，非本次引入）。
