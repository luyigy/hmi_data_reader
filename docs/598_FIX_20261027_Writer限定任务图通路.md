# Writer 限定任务图通路

用户在 Feishu DM 08a216 明确要求 Writer 只用于 task graph，普通对话和旧 HANDOVER 通路退出该机制。
这是对 588 实施边界的后续裁定，代码在指定 `output/worktrees/thin-room-588` 隔离工作区修改。
源代码服务仍读取主工作区；测试和提交完成前没有把本轮产品代码放入主工作区。

## 已核实问题与范围

- 22:06:54 的 Kimi 投递 `cmvqremew00arf9o1b5ctnwhy` 在模型启动前失败。
  拦截来源是 22:01 已完成的 Codex 运行 `cmvqr74ht000rf9o1fvbin8he`；其 metadata 已有 graphWriterReleased。
- 旧 runner 因本地 Codex/Kimi 配置了 workingDirectory，就为普通运行登记 graphWriter 并扫描历史运行。
  任何 unknown 观察都会拒绝新轮次，实际投递为 failed；本次不把这类失败重放为新用户输入。
- 任务图内 unknown 的具体进程观察故障尚未修复。本次收缩适用范围，不把“普通对话恢复”当作 M06 通过。

## 修改结果

1. runner 以数据库解析的 graphAssociation、自动实施 graphExecution、复核 graphReview 决定是否使用 Writer。
   普通对话/HANDOVER 不获取 graph admission 锁，不扫描 Writer，不登记或释放 nonce。
   任务名、工作目录以及是否出现 PLAN/HANDOVER 文件不用于判断任务图身份。
2. 任务图按目录查找其他运行时，通过真实任务绑定排除非任务图运行，避免无 Writer 的普通运行反过来阻塞任务图。
   当前任务图及同目录其他任务图的运行仍受约束，现有退出观察逻辑没有放宽。
3. 补充资源装配只在图运行使用资源 Writer 互斥；普通运行继续核对授权、目录读写边界和原生 Session。
   普通资源接续/撤销读取 runner 终态，并在事务中复核身份、状态和归属；不会因缺少 graphWriter 永久等待。
   任务图资源接续仍使用原有 OS 退出证明。普通活跃运行不能用终态证明接续，重启/改绑后旧证明无效。
4. 原消息队列、入站幂等、同 Session 活跃运行检查保留。该检查只防止同一个平台 Session 同时启动两轮独立运行，
   与飞书同一条消息重复送达的去重不同，也不扫描整个工作区或已结束的进程历史。

未修改 Schema、历史 Writer 凭据、权限配置、批准图快照、watcher cursor/pending、M06/M07 状态或业务代码。
没有新增工作流、审批、恢复调度器或独立验收角色。
