# 历史会话清理按钮启用修复

## 现场与实施范围

用户在 Feishu DM 08a216 提供截图：固定预览 50 条，已勾选永久删除确认，但按钮仍禁用。

核查发现上次启用单元 `agent-platform-session-history-enable-20261030.service` 因等待任务空闲超过 20 分钟退出，Result 为 exit-code。五个执行服务仍为 10 月 29 日启动的旧进程，不能绕过重载直接写入清理启用标记。页面仅在列表查询时读取启用状态，提示又位于预览上方，勾选框附近没有解释禁用原因。

本次按原功能上线和故障修复授权实施：保留服务重载与执行互斥要求；持续等待安全空闲，公开启用进度；页面独立刷新状态并在按钮旁说明原因。只修启用和交互，不执行用户的真实清理预览。重载或健康检查失败时保持关闭并报告失败，不假报上线。

## 修改

- 启用脚本移除 20 分钟后退出的等待上限，持续记录剩余 TaskRun、Job、Delivery 数量。仍做两次空闲检查，重载五个服务，核对活动状态/PID 与 Web 健康后才启用。
- `activation.json` 记录等待、重载、完成和失败状态；心跳超时提示启用任务可能已退出。
- 新增管理员轻量状态查询 `GET /api/admin/session-history?status=1`，不触发文件盘点。
- 页面每 5 秒更新启用状态和预览有效期，保留已有选择与勾选。网络失败禁用并自动重试；按钮旁显示等待、读取失败、过期、空清单或待勾选原因。
- 启用成功后，有效且已勾选的预览自动允许确认；真正执行仍由服务器重新核验引用、文件和互斥条件。
