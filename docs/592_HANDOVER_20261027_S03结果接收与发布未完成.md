## 已实现的可验证边界

1. `result-protocol.ts` 解析现有三种 TASK_GRAPH 结果格式，区分普通回答、格式错误、正式实施和正式复核。
   拒绝重复结果、混合角色标记和无效缺陷归属；沿用 delivered.ticketVerification，不新增线协议。
2. `task-run-result.ts` 在正常启动事务内记录真实 TaskRun、图归属、执行集合、候选输入、revision、批准快照摘要和角色配置核对结果。
   自动运行和聊天室完成使用同一接收函数；TaskRun ID 幂等、并发重复回调只保留一条事件，重读时拒绝结果被改写。
   多仓旧复核卡的候选逐项保留，不用当前候选覆盖历史版本。exhausted 的次数和失败历史不会因接收结果而清零。
3. 新事件 `task_run_result_recorded` **只是接收记录**，不写交付 commit、不代表证据已绑定最终受测源码。
   自动实施和自动复核已读取同一记录；旧 TaskRun 无新绑定时仍经共享解析器读取既有格式，不为旧记录补造发布权限。
   缺少或歧义的旧复核角色不阻断普通聊天；正式结果会明确拒绝。参与者与批准配置不符也不能发布正式结果。
4. 自动实施在普通回答时不调用 `commitJobWorktree`；只登记实际实施阶段并保留回答和工作区。
   重启恢复遇到已完成的普通回答同样不自动提交、不补派结果收集。显式结构化工作/交付仍沿用旧 checkpoint 合同。
5. `completion-owner.ts` 通过图 Task 关系和 `WorkflowDispatch` 的房间/消息登记解析唯一归属。
   图运行不唤醒 watcher；HANDOVER 只指向登记的 project/job；无登记的普通聊天只保存运行。
   图与 HANDOVER 冲突、多个工作流归属、运行前后归属变化均报配置错误，不按文件、任务名前缀或 graphConversation 猜归属。
