## 核心发现与问题分析

### 1. `alarm` 与 `ambiguous` 判定逻辑不一致

在 `output/holdout_drafts_summary.json` 中，VLM 草稿初判结果为 `alarm: 13, normal: 3, ambiguous: 2`。然而深挖证据后发现：

- **标记为 `ambiguous` 的草稿**（如 `Z017 rank01`、`Z017 rank03`）：
  - **依据**：段号块/温度框呈红色填充，但当前温度（如 295.1 / 310.5）未超过设定值（295.0 / 310.0），且控制输出较高（23.3% / 47.7%）。VLM 疑其为"加热中"而非报警。
- **标记为 `alarm` 的草稿**（如 `Z017 rank05`、`Z051 rank11`、`Z052 rank15`/`rank17`/`rank18`）：
  - **依据**：同样仅为段号块/温度框呈红色背景，且当前温度**未超过甚至低于设定值**（如 `Z052 rank17` 段 5 当前 249.4 < 设定 250.0；`Z052 rank18` 段 5 当前 279.7 < 280.0）。
  - **问题**：与上述 `ambiguous` 样本情况完全一致，却被直接标注为了 `alarm`。

### 2. 佳明 ZizES 屏幕红底的物理语义澄清

根据佳明 ZizES 控制器的 UI 特征与工况特征分析：
- **红底高亮（Heating Indicator）**：段号/当前温度框红色填充 + 控制输出比 `control_percent > 0%`，表示该加热段**正在通电加热/加热输出中**。
- **超温报警（Over-Temp Alarm）**：如 legacy 样本 `rec201`（+11.6°C 显式红色超温框）或 Z051 中段 1 当前温度明显高于设定温度（如 `Z051 rank12` 段 1 当前 319.4°C vs 设定 295.0°C，超温 +24.4°C）。

**结论**：纯段号红底极大概率为**加热状态指示**，若直接认定为报警态，将大幅高估 holdout 的报警样本数。
