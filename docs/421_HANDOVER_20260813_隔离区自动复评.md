# HANDOVER · 隔离区自动复评

已完成 S03：隔离区文档在候选队列为空时自动复评（对应 408 B03）。复评逻辑抽到新模块
`src/lib/scheduled-jobs/workflow-quarantine-review.ts`（72 行），watcher 只接入薄调用层，
`workflow-watcher.ts` 871 → 901 行，仍低于 1000 行阻断线。

**实现**（`src/lib/scheduled-jobs/workflow-quarantine-review.ts`）：`reviewQuarantinedDocument`
以**编号**为复评键而非原路径——隔离记录里的路径可能正是被改名/删除的冲突副本。对目标 head
执行 `git ls-tree -r --name-only <head> -- <隔离文档所在分支空间目录>`，筛出同号文档：
恰好一份且通过完整 `validateWorkflowDocument`（含宽度、front matter、文档规则）→
`resolved`；同号仍多份或内容仍非法 → `still_failing`；同号文档消失 → `missing`。
运行时/git 错误原样上抛，不混入文档校验失败口径。

**watcher 接入**（`src/lib/scheduled-jobs/workflow-watcher.ts`）：候选扫描为空且
`previous.validationFailure?.quarantined` 存在时调用复评。`resolved` → 清掉
`validationFailure`，把该权威文档补入候选队列走正常推进流程（审批卡/执行门禁不变），
无需人工造无意义 commit；非 `resolved` → 返回
`candidate=none quarantine_review=<status>`，保留隔离状态、不重复告警（复评节流，
只写 summary 不发飞书）。新增 `carryQuarantine` 包装候选流程的游标返回
（duplicate / shadow / terminal / plan_review / waiting / session_started），
让隔离状态在无关候选（如改名产生的 040 终态）被处理时不被丢弃，下一轮空扫才能触发复评。

**测试**（`tests/workflow-watcher.test.ts`）：同号 007 双 PLAN 提交 → 首跑 notified、复跑
quarantined；空扫复评仍 `still_failing` 且不发通知、不派发 Session；冲突副本改名为 008
终态提交后，008 正常处理且隔离状态随游标保留；下一轮空扫自动复验 007 权威文档，清隔离并
选出进入 `plan_review` 审批。均基于真实临时仓库 + 真实 watcher handler 跑通。
