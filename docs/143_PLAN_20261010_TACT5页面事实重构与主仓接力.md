# TACT5 页面事实重构与主仓接力计划

## 总体目标

工程师拍摄日精 TACT5「射出·计量」组合页后，系统能按原屏展示和核对每个设定，并把含义已确认的值写进正确的工艺字段；保存、读回和重开仍与原图一致。以后迁移其他页面时复用这条边界，不必让主仓重新猜机台标签的含义。

## 当前障碍与依据

- 现有 [140 页面计划](140_PLAN_20261009_TACT5组合页Reader提取交付.md)和 [141](141_HANDOVER_20261009_TACT5组合页S01交付与剩余证据缺口.md)、[142](142_HANDOVER_20261009_TACT5枚举字段补齐与剩余证据缺口.md)交接已交付 TACT5 模板、候选观测和部分局部补读，但记录了 Z077 印刷证据缺口、VSL/Sp 含义及末段保压有效时间未知、三入口补读不一致。既有计划状态不因本计划自动改变。
- Reader 的 `contracts/page_observations.v1.json` 和 `scripts/extract_families/tact5_process.py` 已输出标签、原值、原屏单位、段号、状态与坐标；仍缺可供主仓稳定消费的逐字段位置和时间语义及其证据来源。`scripts/extract_fields.py` 当前超过 1000 行，后续新增分发职责前须先划出模块边界。
- 主仓已有 `backend/app/integrations/hmi_page_observations.py`、`backend/app/hmi_mapping/reader_observations.py` 和 TACT5 YAML，但仍以别名、灰显及业务规则解释部分原屏事实。主仓的工艺换算、确认写入和页面展示不能移入 Reader。
- 两仓工作树在起草时均有未提交改动。执行片开始前须核对各自 HEAD、工作树、实际运行服务版本和样本哈希，不以本计划写作时的工作树冒充稳定基线。

## 总体路线与责任边界

| 阶段 | 解决的问题 | 交付结果 | 归属 |
| --- | --- | --- | --- |
| A. 固定 TACT5 证据 | 先分清已确认事实、未知项和旧响应 | 同图基线、逐字段证据表、旧 ID 对照 | 本计划 S01 |
| B. 交付页面事实 | Reader 统一报告原屏事实与已证实的物理语义 | 带版本、可追溯、兼容旧响应的 TACT5 观测 | 本计划 S02、S03 |
| C. 收拢执行入口 | 避免 HTTP、命令行和飞书读同一图得到不同事实 | 一条共享提取路径和三入口同图对账 | 本计划 S04、S05 |
| D. 写入业务字段 | 按机台上下文映射、换算、确认与保存 | TACT5 表单候选、API 读回、退出重开 | 主仓 518 的 P01 S02 至 S04，需按本契约协调修订 |
| E. 扩展其他页面 | 验证此边界能处理不同页面语义 | 逐页独立计划与验收 | 后续计划，不在本次 TACT5 片内 |

Reader 负责图像、页面身份、原屏标签和值、印刷单位、物理段序、设定或监控、启用证据、坐标，以及已由原图和控制器资料证实的位置起点或终点、时间单段或累计等页面语义。每项语义须注明依据；证据不足时保留未知。Reader 不派生主仓的业务目标值，不访问主仓数据库，不决定覆盖哪个工艺记录。

主仓负责响应校验、原屏展示、业务字段绑定、单位换算、跨字段推导、人工确认、权限、保存和重开。全局限速不能复制成各段速度；灰显残值不能变成有效设定；缺相邻位置或 V/P 边界时不能补猜段终点；末段保压时间缺同工况来源时保持未知。原屏速度值和单位须留存，换算值另存供计算。`field_catalog.json` 中历史 `web_target` 只作迁移线索，写入去向由主仓裁定。

本计划完成时，调用方能取到可复现的 TACT5 页面事实和三入口差异报告。完整业务效果以主仓同图保存重开验收为准；本计划不能单独宣称整页完成。

## 1. S01：冻结 TACT5 同图基线与语义证据

- **目的**：先锁定可验证输入，防止重构期间把未裁定的页面解释写成事实。
- **完成后结果**：Z078 主图、Z077 两张同布局旁证的原图哈希、真值范围、当前三入口输出、旧 `nissei.tact5` 与新 profile ID 的对应关系，以及逐字段“已确认、冲突、未知”表可供两仓复核。
- **实现方法**：沿用 140 的样本和主仓 `backend/data/hmi-samples/`；分别记录印刷标签、原值、印刷单位、框、物理段号、状态、位置与时间定义的证据。Z077 无完整真值，仅列已确认范围。记录已知 HTTP 局部补读与其他入口的差异，不补造响应。
- **修改边界**：只新增本仓短证据文档或夹具索引；原图和人工真值只读。主仓样本由主仓独立管理。
- **验收**：每个已确认结论能回到原图框、控制器资料或用户裁定；Z078 真值分母和灰显残值另列；旧响应样本及两仓版本可复现。此片先单独冻结证据，避免下一片改契约后失去可比基线。
- **前置与停止条件**：确认当前节点、样本路径和运行版本；缺图、哈希不符或来源不明时停止对应字段的语义确认。
- **交付物**：基线与争议表、测试或回放命令及结果、独立提交和 S01 HANDOVER；HANDOVER 列两仓模板与路由的实际文件清单，主仓未改项标待办。

## 2. S02：约定可版本化的页面事实契约

- **目的**：让 Reader 和主仓对“原屏看见什么”及“页面规则说明什么”采用同一含义，旧消费者仍能读取旧响应。
- **完成后结果**：一个有版本的 TACT5 观测样例和契约检查，逐字段区分印刷值与模板已确认的单位或物理语义，并保留来源。原有 `fields`、`stage_enabled` 和 `page_observations` 旧版本含义不变。
- **实现方法**：以现有 `contracts/page_observations.v1.json` 与 `contracts/field_catalog.json` 为起点，先定义增量字段及版本迁移表，再在 Reader 契约测试中证明旧响应可读、新字段缺省表示未知。位置含义、参考零点、时间定义、全局或分段作用域分别表达；单位保留原屏 OCR 结果，并把模板补全及来源另记，不伪称 OCR 看见字形。
- **修改边界**：Reader 契约、直接合同测试及必要样例；不改图像提取、服务入口、主仓模型。若需要改变现有字段含义，改为显式新版本并列出旧响应处理方式。
- **验收**：旧夹具按旧含义通过；新夹具能表达起点、终点、单段时长、累计时刻和未知，且语义来源可查；禁用、监控、未知不能被契约自身标为可自动写入。此片独立验收可先锁定双方接口，再改图像提取，降低跨仓返工。
- **前置与停止条件**：S01 证据表就绪；语义或版本兼容方式有争议时只记录未知，不改变既有响应。
- **交付物**：契约与样例、兼容测试、主仓接入字段清单、独立提交和 S02 HANDOVER。

## 3. S03：让 TACT5 实图产出页面事实

- **目的**：把契约落实到一张真实组合页，使主仓不必从标签再次猜物理语义。
- **完成后结果**：Z078 同一张图的每项候选均带原屏证据；已确认的位置、时间及单位语义附来源，VSL/Sp 和末段保压有效时间仍可明确为未知；Z077 两图只输出各自可见范围。
- **实现方法**：复用 `templates/tact5.process_settings.injection_holding_metering.json`、`scripts/extract_families/tact5_process.py`、现有状态判读和局部补读。逐字段核对 Reader 模板知识与主仓 TACT5 YAML，若同一标签的单位或段义冲突，生成冲突证据，不以数值凑齐目标字段。
- **修改边界**：TACT5 模板、提取器与直接测试；必要时仅调整相邻契约配置。保留当前候选化输出和旧记录兼容，不改其他控制器、训练数据或主仓代码。
- **验收**：对 Z078 已确认槽位逐项比较标签、值、单位及来源、角色、段号、启用状态和框；17 个灰显残值继续只作禁用观测。Z077 已确认范围单独报告；缺印刷证据的段数和单位仍可为空。此片先验提取结果，再改变分发入口，便于定位差异。
- **前置与停止条件**：S02 契约已定；遇到原图与模板相反的证据、VSL/Sp 未裁定或末段时间缺同工况来源时保留未知，不自动导入。
- **交付物**：同图前后响应及差异、聚焦与相关回归、双仓文件清单、独立提交和 S03 HANDOVER。

## 4. S04：抽出页面分发职责并保持旧入口兼容

- **目的**：让后续页面继续扩展时不增长已超限的 `scripts/extract_fields.py`，同时稳定 TACT5 路由。
- **完成后结果**：页面识别、注册与分发有清楚的模块边界，旧 CLI 调用和现有 profile ID 仍工作；同一 OCR 输入的 TACT5 结果与 S03 基线一致。
- **实现方法**：先核对 `extract_fields.py`、`page_template_registry.py`、`hmi_service.py`、飞书调用方和测试的调用关系，再只把明确的页面分发职责移到短模块。移动时保留原验证、异常处理和拒识行为；测试用 S03 固定响应作前后对照。
- **修改边界**：分发入口、一个新短模块及直接测试；如需调整更多生产文件，拆成下一片。既有超 1000 行文件只能缩短，任何新文件不得达到 1000 行。此片专门验证结构迁移，避免把路由变化与 OCR 算法变化放在同一次提交。
- **验收**：TACT5 与至少一个非 TACT5 profile 的固定输入在重构前后页面身份、字段、拒识和错误行为一致；相关 CLI、服务回归通过；旧导入调用点仍可用。
- **前置与停止条件**：S03 同图基线可回放；无法证明调用方兼容或需要改动无关家族时停止并缩小提取边界。
- **交付物**：路由前后对照、影响范围和回归结果、独立提交和 S04 HANDOVER。

## 5. S05：同图核对 HTTP、CLI 与飞书入口

- **目的**：消除同一张 TACT5 图因入口不同而失去已证实段数或单位的情况。
- **完成后结果**：三入口共用同一页面事实产出和有证据的局部补读；每个入口的响应版本、字段值、来源及拒识结论能对账。无法在真实飞书环境调用时，明确记录模拟入口与真实入口各自结论。
- **实现方法**：把 `hmi_service.py` 当前 TACT5 限定的补读接到共享提取路径或可复用调用边界，保留各入口的传输与鉴权。用 S01 原图和 S03 期望结果对比，聚焦修复差异，不为其他页面建立新框架。
- **修改边界**：Reader 入口接线、共享提取路径与直接测试；不改主仓保存和飞书真实消息流程。超过两个相邻生产文件的修改须先说明原子性，否则拆片。
- **验收**：Z078 三入口对已确认字段的页面事实一致，Z077 未证实的段数或单位不因入口改变而被补猜；服务失败时保留旧错误边界。真实入口未跑时不得写“三入口通过”。
- **前置与停止条件**：S04 路由稳定，测试环境与真实服务版本可确认；真实飞书入口不可用时停止真实入口结论，提交可复现的模拟结果和恢复条件。
- **交付物**：三入口对账、Reader 版本与响应样本、聚焦和回归结果、独立提交及 S05 HANDOVER，供主仓 518 的 P01 接续。

## 主仓如何协调接入

主仓以 [516 架构宪章](/data1/code/mold-data-webpage-tool/docs/dev/516_DECISION_20261008_HMI识别与写入架构宪章.md)和 [518 逐页计划](/data1/code/mold-data-webpage-tool/docs/dev/518_PLAN_20261008_平台Workflow驱动TACT5验收与库存接续.md)为执行边界。Reader S02 冻结契约后，主仓先评审并修订 518 的 P01 S02 至 S04 接入说明，再按原审批流程执行；不得仅凭本仓提交推进主仓 Slice。

| 主仓步骤 | 应做的事 | 验收交接 |
| --- | --- | --- |
| 接收版本 | 在 `contracts/hmi-reader/` 冻结 Reader 契约与字段目录，`backend/app/integrations/hmi_page_observations.py` 校验新旧版本、类型、证据与未知状态；保留原响应。 | 用 Reader S03/S05 同图响应证明接收未丢字段；旧响应和旧 `nissei.tact5` 记录仍能回放。 |
| 映射 TACT5 | 对照 `backend/app/hmi_mapping/profiles/tact5.process_settings.injection_holding_metering.yaml`、`reader_observations.py`、`nissei_tact5.py` 和 `ocr_semantics.py`，按已确认语义绑定统一工艺字段；仅在同图回归通过后退出重复的标签、单位和灰显解释。 | 分列原屏值、模板补全、目标字段、换算依据和待核对项；全局限速、V/P、抽胶与末段保压规则各有直接回放。 |
| 展示与保存 | 前端按 Reader 页面结构与原标签展示原屏候选，用户点选原图证据并确认写入；复用主仓现有工艺计算及保存服务。 | 用同一张 Z078 图记录桌面与 390px 核对、保存、GET 读回、退出重开。Z077 仅验已确认范围；前端显示成功不算持久化通过。 |

主仓每次 HANDOVER 列出 Reader 模板、主仓映射模板、路由入口的实际路径与提交号，分别报告同图 OCR 和字段映射；涉及写入时再报告保存、读回和重开。主仓现有超限测试文件不得增长，新增测试按页放入短文件。运行数据库测试前严格执行主仓 AGENTS.md 的本机回环、`_test` 后缀及实际数据库地址校验。

## 验收与退出

Reader 片各自独立提交并交接，只报告本片已验证范围。Reader 完成的标志是 TACT5 页面事实契约、实图输出、兼容路由和入口对账可复现；主仓完成的标志是同图字段映射与确认保存重开通过。待裁定的物理语义保持未知，不阻塞已确认字段的候选展示，但不得自动写入对应工艺字段。

本计划不做跨品牌批量迁移、训练模型、数据库 schema 变更或生产部署。扩页先重新取得该页的原图、真值、控制器身份和段位语义，再另立逐页计划。执行前还需确认两仓未提交改动的归属；不得覆盖、清理或混入本计划提交。
