# PLAN · 三 Harness 进度流：精准解析 · 脱敏 · 去重 · 完整展示

> **评审中（DRAFT）。** 本文档为只读评审稿。在负责人书面批准前，**任何 Agent 不得将
> `doc_status` 改为 `ready`、不得把 `next_action` 改为 `start_first_slice`、不得实施任何 Slice。**
> 批准后再逐 Slice 落地，并在执行前补齐各 Slice 的最小回归测试。

## 背景与根因（代码取证结论）

直播室里 kimi-code / pi-agent / antigravity 三种 harness 长时间“静默”，不是 ACPX 收不到
stdout，而是事件没有被**精准解析 → 脱敏 → 去重 → 完整展示**地接到飞书进度卡和直播室时间线。
现有代码已经具备部分能力（codex 与 kimi-code 的思考流、`FeishuProgressTracker` 的节流卡片），
但三种 harness 的覆盖不一致，且 `/run` 角色串行流水线完全没接进度回调。具体证据：

1. **Kimi Code** `src/lib/real-agents/kimi-code-agent.ts`
   - 用 `--output-format stream-json`；`processKimiCodeJsonLine` 只转发 `role:'assistant'` 的
     **整段字符串** `content`、`tool_calls`、`tool_use`、`content_block_start.tool_use`。
   - **缺口**：流式文本增量（`content_block_delta` / `delta`）不转发，`thinking` /
     `redacted_thinking` 不转发，`tool_result` 不计数；工具预览直接用原始 `input`，**未脱敏**。
2. **Pi Agent** `src/lib/real-agents/pi-agent.ts`
   - 用 `--print` 文本模式，stdout 原样转发；**从不调用 `onToolEvent`**，也没有结构化事件。
   - **缺口**：`--print` 会把正文积压到结尾才输出。pi 原生支持 `--mode json`（已由
     `scripts/agent-platform-runner.js` 验证可解析 `event.message.content` 文本块）。
3. **Antigravity** `src/lib/real-agents/antigravity-agent.ts`
   - 用 `--output-format stream-json`；stdout 处理**只转发 `step_update.text_delta`**，
     `extractAntigravityResponse` 从最后一条 `event:'result'` 取正文。
   - **缺口**：**从不调用 `onToolEvent`**，工具/函数调用与其他 `step_update` 子类型丢失。
4. **直播室回放路径** `src/lib/live-room-delivery-execution.ts`
   - 已构造 `FeishuProgressTracker` 与 `liveRoomStreamCallbacks`，已有节流
     （思考 8s、工具 3s、心跳 45s；卡片 1.5s）与基础去重（工具签名、连续思考预览）。
   - **缺口**：`shouldRelayLiveRoomStdoutProgress(harnessType)` 只对 `codex`、`kimi-code`
     返回 true → **pi-agent、antigravity 的思考流被完全排除**；且 pi/antigravity 自身不发射
     工具事件，所以卡片里也看不到它们的工具进度。
5. **`/run` 角色串行流水线** `src/lib/live-room-workflows.ts` + `src/lib/feishu-workflow.ts`
   - 经 grep 确认：这两个文件**完全不引用** `streamCallbacks` / `FeishuProgressTracker`。
   - 阶段执行只发“阶段开始/完成”两条系统消息，阶段内部的思考、工具、心跳一律不可见。
6. **脱敏**：当前只有截断（工具预览 50 字、思考 80 字）。绝对路径、文件内容、命令、token /
   密钥 / HMAC 等可能原样进入飞书卡片与直播室时间线。

## 目标（四个硬指标，三者全改）

- **精准解析**：三种 harness 的 stream-json / `--mode json` 事件都被解析成统一事件模型
  （思考 / 助手正文 / 工具调用 / 工具结果 / 系统），不再依赖单一字段。
- **脱敏**：所有进入飞书卡片与直播室时间线的预览都过统一 `sanitize`：绝对路径转相对/基名、
  遮蔽 token/密钥/签名、截断大块参数与文件内容；`stderr` 原始块只入库不再外发。
- **去重**：统一的签名去重 + 最小间隔节流，跨“适配器 → 回放层 → 卡片”一致；突发流量聚合计数。
- **完整展示**：直播室回放路径与 `/run` 角色串行路径**共用**同一套进度桥；卡片显示当前阶段
  （思考 / 工具 / 等待）、步数、最近工具、已用时与心跳，结束用成功/失败摘要 + 工具 tally 收尾。

## 非目标

- 不改 harness 的任务结果判定（success/fail、会话续聊、completion gate 逻辑不变）。
- 不把原始 stdout/stderr 无筛选地全量转发到飞书（按设计仅发脱敏后的进度）。
- 不引入新的 harness、新命令、新房间 mode 或新调度层。
- 不做 Git Worktree、并行子任务、自动重试策略调整。
- 不改远端 runner（`scripts/agent-platform-runner.js` 已用 `--mode json`），仅对齐本地 pi 适配器。

## S01：统一 harness 事件模型 + 脱敏 + 去重组件

**范围**

- 新增 `src/lib/acpx/harness-events.ts`（注意长文件守卫，控制在 800 行预警线内）：
  - `NormalizedHarnessEvent`：`{ kind: 'thinking'|'assistant_text'|'tool_use'|'tool_result'|'system'; text?: string; toolName?: string; preview?: string; emoji?: string }`。
  - `sanitizePreview(value, { workspaceRoot })`：绝对路径转相对/基名；正则遮蔽
    `sk-`、bearer/Authorization、password/token/secret、飞书 `tenant_access_token`/签名/HMAC、
    `.env` 风格 `KEY=VALUE`；工具参数中的 `content`/`command`/`text` 仅保留首段并截断；
    统一截断到既定预览长度。
  - `createProgressDedupe({ toolMinMs, thinkingMinMs })`：按 `kind+签名` 去重，连续相同工具
    折叠为计数，思考按最近签名 + 最小间隔节流；提供 `consume(event)` 与 `flush()`。
- 在 `tests/harness-events.test.ts` 覆盖：路径归一化、token 遮蔽、参数截断、连续工具折叠、
  思考节流与去重、突发聚合。

**完成标准**

- 纯函数模块，无副作用；`tsc --noEmit` 通过；新文件未触 800 行预警线。
- 单测全部通过；现有测试不受影响。

**非目标**：不在本 Slice 接入任何 harness 适配器或回放层。

## S02：Kimi Code 精准解析

**范围**（`src/lib/real-agents/kimi-code-agent.ts`）

- 扩展 `processKimiCodeJsonLine`：
  - 解析流式文本增量（`content_block_delta` / `delta` / Anthropic SSE 风格）→ 经 `sanitizePreview`
    后由 `onStdoutChunk` 转发，确保思考/正文持续可见而不是等整段。
  - 识别 `thinking` / `redacted_thinking` → 发一条“思考中”系统事件（不外泄正文）。
  - 对 `tool_use` / `tool_calls` 经 `sanitizePreview` 处理 `input` 后再 `onToolEvent`；
    `tool_result` 计入步数但不外发内容。
- 在 `tests/kimi-code-agent.test.ts`（新增或复用既有）用真实 stream-json 片段断言：
  增量文本被转发、工具预览已脱敏、`tool_result` 不外发正文。

**完成标准**

- 同一段 kimi 运行，飞书卡片/直播室能看到持续思考与工具进度，且预览不含绝对路径或密钥。
- `tsc --noEmit`、长文件守卫（该文件当前约 270 行，注意不越线）、`git diff --check` 通过。

**完成标准**

- 回退路径保证旧环境不回归；`tsc --noEmit`、长文件守卫、`git diff --check` 通过。

## S05：回放层接线——覆盖三种 harness + `/run` 角色串行路径

**范围**

- `src/lib/live-room-delivery-execution.ts`：
  - 把 `shouldRelayLiveRoomStdoutProgress` 改为按 harness 能力判定（或直接覆盖
    `pi-agent`、`antigravity`、`kimi-code` 三者），使思考流对所有目标 harness 生效。
  - 将“构造 `FeishuProgressTracker` + `liveRoomStreamCallbacks` + 心跳/节流”抽成
    `attachLiveRoomProgress({ room, participant, sourceMessage })`，返回
    `{ streamCallbacks, progressTracker, dispose }`，供两条路径复用。
- `src/lib/live-room-workflows.ts` + `src/lib/feishu-workflow.ts`：
  - 在阶段执行处调用 `attachLiveRoomProgress`，把 `streamCallbacks` 透传给底层 ACPX 执行，
    并在阶段结束/失败时 `dispose`（含 `progressTracker.finalize`）。
  - 阶段间进度卡互不串台：按 participant 维度独立 tracker。
- `tests/live-room-delivery-execution.test.ts` / `tests/live-room-workflows.test.ts` 增补：
  pi/antigravity 触发思考+工具回调；`/run` 阶段执行携带 streamCallbacks。

**完成标准**

- 三种 harness 在直播室回放与 `/run` 角色串行两种路径下都能看到思考/工具/心跳进度。
- 进度卡与直播室时间线内容一致、脱敏一致；阶段切换无残留卡片。
- `tsc --noEmit`、相关回归测试、长文件守卫、`git diff --check` 通过；
  已达阻断阈值（1000 行）的文件不增长，新增职责先在同一提交内拆分模块。

**非目标**：不改 completion gate、不改角色编排顺序、不改续聊/重试策略。
