## 用户行为与范围

在群主聊天区原生 @平台机器人后发送 `/ap broadcast <通知原文>`。仅隔离模式开启时发布；回执包含稳定 ID、序号和发布时目标任务数，明确各成员下一轮可见、不唤醒、不打断、不代表模型已接收或理解。

- 广播正文不经过普通命令 tokenizer，保留内部换行、连续空格、引号、`--option` 和正文中的提及。沿用上游飞书文本解码的首尾 trim；命令与正文之间一个分隔符不属于正文。
- 发布复用 S01 事务、来源消息去重与固定目标快照；不改存储或 S02 消费规则。
- 授权沿用经过签名校验/SDK 入站事件的现有发言准入，不新增“仅群管理员可广播”的权限策略；群消息仍须原生 @当前机器人。显式 blocked 用户拒绝发布，并核验 app、操作者、来源消息及群根位置。平台现有群准入允许群内发言者，不要求私聊配对；此点不同于隔离开关的管理员权限。
- 私聊、任何 thread/root/parent 身份、空正文、关闭模式均拒绝；普通闲聊不进入广播路径。
- 补齐 HTTP webhook 解码及 context 中的 thread/root/parent 传递，避免这个入站路径将话题内广播误判为群根。WS 路径已传递，保持原有逻辑。

修改超过两个生产文件的原因：命令 parser、dispatch、help 是同一入口必需接线；HTTP 消息类型、解码与路由必须共同传递身份，否则话题限制可以被绕过。没有修改 Harness、调度或数据结构。

## 实群剩余验收（由用户发起，Codex 核验）

所有群命令均需原生 @平台机器人。先确认服务重启成功，再在已授权 Agent-swarm 群执行：

1. `/ap isolation on`；复用前置 A/B 任务话题，各成员分别记住不同私有标记。
2. 在群主聊天区 `/ap broadcast 467公共标记-20260923`，回执核对目标数、ID与“下一轮可见”；广播后不应自动启动 Agent。
3. 分别继续 A/B 并要求回复公共标记与自己的私有标记；核对各自话题输出、成员实际输入/消费记录及不出现另一任务私有标记。同房其他成员下一轮也需收到。
4. `/ap isolation off` 后原任务继续隔离且未消费广播仍可读；新广播拒绝。重新开启后发布新广播，验证顺序。
5. 验证发布前归档任务、发布后新任务和另一群不接收；重启后原任务绑定与待消费广播仍恢复。另一群仅在已有明确授权时测试，否则保留该项受阻。
6. 汇集脱敏 message_id、广播 ID、目标与成员消费记录及真人结果，全部通过后追加终止式 HANDOVER（await_acceptance / complete）。不改写历史。
