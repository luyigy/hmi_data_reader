# M06 历史 Writer 与验收路由修复

用户在 Feishu DM 08a216 要求按已讨论的薄平台方案修复。本次沿用 588/S04 的实施、部署和 M06 接续验证授权，
在指定隔离 worktree 编码，不新增任务路线或 watcher 派发。源码提交 `f286d94`。

## 修复边界

- Writer 仍仅用于真实任务图运行。释放回执 nonce 与身份匹配后直接结束占用，已释放阶段 worker 同样直接退出，
  不再扫描历史进程或比对几天前的祖先 PID。未释放的当前 owner 仍区分 alive / exited / unknown。
- 准入只检查关联/目录重叠图任务的活跃运行、待发布结果、执行/复核/对话当前绑定，以及各任务最新的已登记 Writer。
  最新 Writer 覆盖 failed 写库到 finally 清理之间的窗口；已被后续运行取代的终态历史不再参与。
  删除按 workingDirectory 字符串扫全库的路径，不用笼统“终态=退出”放行仍在清理的当前运行。
- 非显式消息按当前阶段选择 tester / reviewer / implementer；currentSpeakerMemberId 和旧 conversation_input
  不再被冒充为用户指定目标。明确回复卡片、明确选角色、已保存消息目标和用户既有 Session reset 仍有效。
  无独立复核会话/角色的自动验收节点继续接回实施者，不制造不存在的 tester。
- 首次启动失败且尚无 native session 时，可在原平台 Session、角色、目录、候选下新建原生线程。
  continuation 和创建运行时的校验一起修复；已知 native 身份漂移仍拒绝。
- 未改 execution-progress.ts，不清零 M06 platformAttempts，不制造新候选，不改业务源码或批准快照。
