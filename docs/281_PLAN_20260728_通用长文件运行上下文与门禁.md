# PLAN · 通用长文件运行上下文与门禁

## 目标

让 Agent Platform 对每个已登记、本机运行的项目，在每次 Agent 启动时即时识别当前超阈值文件，
将约束注入实际 harness prompt，并在本次运行结束时拒绝其继续增长。目标仓库无需 npm、
`package.json`、`AGENTS.md` 或 workflow contract。

## 边界

- 复用 `config/projects.yaml` 中现有 `long_file_detector` 的阈值、扩展名与排除路径；不新建第二套规则、
  数据库模型、DSL 或目标仓库脚本。
- 首版仅支持 `platform_local` 且 `workingDirectory` 可解析到已登记项目根目录的 TaskRun；未匹配、
  gateway 与 `remote_ssh` 均不猜测、不阻断，后续另行设计远端扫描。
- 以本次运行开始时的当前工作树/HEAD 为 baseline，即时扫描；不得使用十分钟定时任务的过期 cursor。
- 提示注入不写入仓库、Room 历史或持久化 prompt；复检是唯一硬门禁。保留 workflow 专用 completion gate
  既有语义，不重复校验或改变其自动纠错流程。

## S01：通用本机项目策略与即时 baseline

从 `workingDirectory` 解析已登记项目根目录和启用的 `long_file_detector` job，复用其规则即时扫描当前
工作树，产出稳定、限长的运行上下文与 baseline。覆盖匹配项目、无 detector、路径不匹配、排除路径与
跨语言扩展名；不接入 prompt 或阻断运行。

## S02：统一 prompt 与 continuation 注入

在 ACPX 的共享 prompt 组装入口将 S01 上下文注入新 session；对 continuation message 注入同一约束，
避免恢复会话遗漏限制。文本须列出项目、HEAD、阈值和历史超限文件，并明确不得增长；空结果不添加噪声。
覆盖本机 Codex/Claude 等共享路径及 continuation，不修改 Live Room 原始用户消息。

## S03：通用完成复检

在本机 TaskRun 完成前按 S01 baseline 复检：历史超限文件增长或新文件达到阈值即使运行失败并提供明确
文件差异；未匹配项目不受影响。多参与者只使用同一个 run baseline，避免参与者之间重复或错误阻断。
覆盖增长、未增长、新跨阈值和既有 workflow completion gate 共存场景。

## S04：验证与交接

运行新增聚焦测试、现有 long-file detector/workflow completion gate、TypeScript、相关 ESLint、
long-file guard、`git diff --check` 与 GitNexus `detect_changes`。创建终态 HANDOVER，列出真人验收：
本机已登记的非 npm 项目收到动态约束、续会话仍有约束、增长被拒绝；不重启服务。
