## 修改内容

### 1. 停掉 gemma-4-31B-it（GPU 0）

**systemd 操作**：
```bash
systemctl --user disable vllm-gemma.service
systemctl --user stop vllm-gemma.service
```

**当前状态**：inactive + disabled（不会开机自启）。
**恢复方法**：`systemctl --user enable vllm-gemma.service && systemctl --user start vllm-gemma.service`

**原因**：gemma-4 占 GPU 0 70GB，PaddleOCR 需要 GPU 调试环境。当前 PaddleOCR 走 CPU，Paddle 3.x 在新 paddle+onednn 上有 PIR 兼容 bug（已知问题），CPU + paddle 2.6 + paddleocr 2.7 是当前最稳定路径。

### 3. PaddleOCR 环境踩坑

| 坑 | 解决 |
|---|---|
| PaddleOCR 3.7 + Paddle 3.3 onednn PIR 转换 bug | 锁回 paddleocr 2.7.3 + paddlepaddle 2.6.2 |
| numpy 2.x 与 paddle 2.x ABI 不兼容 | 锁 numpy<2 (1.26.4) |
| matplotlib 1.x 太老装不上，pandas 1.5 与 numpy 2.x 冲突 | 锁 pandas<2 (1.5.3) + matplotlib (3.11) |
| 网络代理劫持 paddleocr 模型下载（socks5 但没装 socksio） | 手动 `curl --noproxy '*'` 下载到 `~/.paddleocr/whl/{det,rec,cls}/ch_*/` |
| cls 模型 URL 写错路径（应为 `ch/ch_ppocr_mobile_v2.0_cls_infer.tar`） | 修正路径 |

### 4. 三色 triage 阈值

| 指标 | 阈值 | 来源 |
|---|---|---|
| 屏幕宽度 | ≥ 700 px | docs/002 §3.1 |
| 屏幕面积占比 | ≥ 30% | 沙迪克屏占比 21-30% 触发红灯 |
| 模糊度 (Laplacian var) | ≥ 30 | docs/002 §3.1 |
| 反光比例 (>230 像素) | > 15% 拒 / > 5% 警 | 沙迪克 MINOR_GLARE 触发黄灯 |
| 透视畸变 | 1.30（屏幕长宽比偏离 [0.7, 2.5]） | docs/002 §3.1 启发式 |
| 屏幕被图边裁切 | margin > 50px | 边缘严重裁切 |

## 关键发现（决定后续）

### 1. 真实 UI 家族数量 = 4（确认）

经 OCR 验证：
- **TACT** = boletuo Z001（OCR 中未出现 "TACT" 字样，是基于 docs/001 的视觉判断）
- **FANUC** = fanake Z036（OCR "FANUC" 验证，boletuo t1 Tab 命名也是 FANUC 风格，需重新确认）
- **ZizES** = jiaming Z052（OCR "ZES" + "佳明" 验证）
- **TRD6/SPT** = shadike Z020（OCR 未识别具体品牌，但样本视觉已知）

**待复核**：docs/002 把 boletuo 标 TACT，但 OCR 中 boletuo t1 的 Tab 命名是"开模锁模/推顶/射出·计量/温度/监控/主要条件/条件转换" — **这是 FANUC ROBOSHOT 的 Tab 风格**。可能是：
- boletuo Z001 实际是 FANUC 屏但品牌挂错（类似 docs/002 §1 的字段错挂）
- 或者 boletuo 屏本身采用 FANUC 风格 Tab
- **建议下次现场确认 boletuo 屏的物理型号**

### 2. 重复附件的真相比假设更复杂

| 重复组 | 实际 = docs/002 假设 | 实际内容 |
|---|---|---|
| A: boletuo t2 = rijing t2 | TACT/射出·计量 ✅ | boletuo/rijing **共用 TACT 屏**（验证） |
| B: boletuo t3 = rijing t3 | TACT/参数页 ✅ | 同上 |
| C: fanake t1 = fanake t3 | 字段错挂 ✅ | t1 = 储料冷却 Tab 照片被错挂为"炮筒"字段 |

### 3. ZizES 实际段数 = 5 + 油温

docs/001 写"7 段 + 油温"，但 OCR 只看到 5 个数字段 + 油温 = 6 列（含油温）。可能是 docs/001 误识别 — **以 OCR 为准更新**。

### 4. rijing t1 OCR 误识别 FANUC → NUC

已加 `NUC` 关键词兜底（`scripts/classify_ui.py` UI_FAMILY_KEYWORDS）。但这是个**真实工程问题**：OCR 错误率 > 0%，UI 家族识别必须容忍部分漏字。
