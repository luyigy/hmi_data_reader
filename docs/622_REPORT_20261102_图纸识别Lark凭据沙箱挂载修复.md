# 图纸识别群 Lark CLI 凭据不可见修复

## 现场与范围

用户报告图纸识别群无法发送 ZIP，反复要求重新认证。本次核对目标飞书群 `oc_2184f0fb1209d3944a80e2798f57401a`，对应平台房间“工程图识图”、工作目录 `/data1/code/drawings`。最近 Kimi 报缺少 app_secret / 飞书 20140，原生记录显示它使用项目 `.lark-cli` 配置尝试以 bot 发送。

本次只恢复该工作目录普通受限执行中的宿主 Lark CLI 访问，复用已有授权，不重新登录、不改应用或用户凭据、不发送消息或附件。没有切换房间为 Full Access，也没有放开所有项目的凭据访问。任务图隔离 HOME、其他 workspace 及用户身份登录态不是本次修复的验收范围。

## 根因与复现

宿主 hello 用户对同一项目配置执行 `lark-cli auth status --json --verify`，Bot 为 ready / verified。通过平台实际 Bubblewrap 编译器、同一 cwd、workspace-write、网络 enabled 和项目配置执行同一命令，Bot 为 not_configured，原因 missing app secret or bot token。

宿主文件访问追踪表明，配置只记录 appId 等元数据，真正的应用密钥位于 `/home/hello/.local/share/lark-cli/` 的加密存储，由 master.key 解密。原沙箱没有这个目录。仅增加该目录后原探针即变为 ready / verified；故不是凭据被删除，也不是需要用户 OAuth 授权。复制 config.json 并不等于复制凭据。

此外，默认 host `.lark-cli` 不可见，`.local/bin/lark-cli` 的目标 package 也未挂载，可能回退到 NVM 内的另一版 CLI。故一起补齐默认配置和明确的 CLI 安装目录。

## 修改与验证

在 `config/runtime-environments.json` 新增 `/data1/code/drawings` 的三个只读目录：

- `/home/hello/.lark-cli`：已有默认配置。

- `/home/hello/.local/lib/node_modules/@larksuite/cli`：宿主 CLI 的完整安装目录。

复用现有逐工作目录运行环境注册机制，不修改沙箱编译器、认证代码或权限模型。原有 16 个 workspace 条目逐项比较不变，三个新增目录均验证为真实 canonical directory。
