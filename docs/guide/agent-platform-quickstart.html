Agent Platform 新用户入门

直接在飞书与 Agent 协作。私聊适合个人任务；群聊里的独立任务话题适合按项目或目标分开推进。

1 · 第一次使用

  1. 1给 Agent Platform 机器人发一条私聊消息。首次使用可能需要管理员批准准入。
  2. 2管理员批准后，会给你的私聊分配工作目录和可用权限；收到批准通知后，重新发送你的需求。
  3. 3在同一个私聊里持续沟通。描述目标、背景、验收标准和相关文件，Agent 会沿用这个房间的上下文。

工作目录和权限由管理员配置。若路径或访问范围不对，请联系管理员调整，不要用其他人的目录代替。

2 · 日常怎么用

直接提需求

像聊天一样说明要做什么，例如“检查这个页面的错误并修复，完成后说明改动和测试结果”。

先问再改

需要讨论时直接说“先分析原因和方案，暂时不要改代码”。确定方向后再明确要求实施。

查看当前房间

/ap status 查看状态；/ap members 查看成员；/ap help 打开命令帮助。

检查目录与权限

/ap workspace 查看实际工作目录；/ap rights 查看 Agent 当前权限。

3 · 在群聊里开一个独立任务

  1. 请群管理员确认任务隔离已开启：/ap isolation status。
  2. 在群主聊天区发送 /ap task new --title=任务名 --workdir=/绝对/目录，或用 /ap menu 里的“新增独立任务”入口。
  3. 打开生成的任务入口卡片，在它的话题里发送 /ap add --agents=local:codex 添加 Agent，然后只在该话题继续任务讨论。

每个话题绑定一个独立任务和一个主工作目录。独立话题隔离对话与任务状态；如果多个任务写同一目录，文件仍可能互相影响。并行改代码时应安排独立 worktree 或不重叠的文件范围。

4 · 常用控制命令

停止当前运行

/ap stop；要查看运行中的会话，用 /ap sessions。

开始新会话

/ap new-session。适合上下文过长，或要从新的会话重新开始时使用。

查看可选 Agent

/ap agents；在房间中添加成员用 /ap add --agents=<agent-id>。

发现命令

/ap menu 是分类命令卡，/ap help 提供完整文字帮助。

5 · 一个可直接复制的任务描述

请检查当前项目的登录页。目标：修复提交后偶发的空白页。先定位原因，再实施最小修复。完成后告诉我修改了哪些文件、跑了什么验证，以及还需要我确认什么。

如果任务涉及多个仓库、需要联网、安装依赖或访问工作目录以外的文件，请在需求里提前说明；Agent 会按当前房间的实际权限执行。
