# PLAN · 多用户认证与 Web UI 配对接入

## 背景与决策

本计划承接 Live Room 讨论与架构评审，落地“方案 3（Web UI 配对接入流程）”与配套的平台多用户安全体系。

在多用户准入机制上，采纳前期决策：
1. **Phase 1（本计划）**：采用“管理员直接在 Web UI 后台新建并分发账号”模式，打通多用户鉴权、数据归属隔离与 Web 配对接入全链路；暂不开放前台公开注册、验证码、`pending_approval` 及飞书审批卡。
2. **Phase 2（后续演进）**：按需开放自助注册入口并联动审批流。

基于代码库架构评审，当前实施必须优先修复会话身份保真问题，建立服务端真正生效的鉴权中间件与多租户数据隔离，再构建一次性配对票据（Pairing Ticket）与 Runner 安全接入。

## 关键设计与架构规范

### 1. 会话与分级鉴权内核 (`src/lib/auth.ts` / `src/lib/auth-users.ts`)
- **修复 Session 身份丢失**：重构 `createSessionForUser()`，签发包含 `userId`、`role` (`admin` | `user`) 与 `subject` 的 v2 Claims，消除将普通用户还原为系统管理员的漏洞，保持 v1 会话兼容读取。
- **数据库角色实时复核**：`requireCurrentUser(request)` 与 `requireAdmin(request)` 在校验 Session 签名的基础上核验数据库用户状态与角色，防止被禁用或降权的用户凭借旧 Cookie 维持高权限。
- **服务端中间件保护**：接入中央 `middleware.ts`，路由策略划分为 `public`（登录/静态资源/健康检查/自验签入口）、`authenticated`（普通用户与管理员均可访问）与 `admin`（仅管理员可用），默认 fail closed。
- **权限边界收敛**：普通用户仅可访问自身名下的任务、房间和远程节点；平台本地宿主机执行（Platform Local）、全局 Gateway 与全局 Workspace 配置严格限制为管理员专属。

### 2. 多租户数据归属隔离 (`prisma/schema.prisma`)
- 为 `Task`、`LiveRoom`、`RemoteNode` 增加 `ownerUserId` 字段并建立与 `User` 的关联及索引。
- `LiveRoom.createdBy` 保持作为消息发送者标识与审计文本，所有权与访问控制以 `ownerUserId` 为唯一准则。
- 数据查询与操作层统一执行过滤：`admin ? unrestrictedWhere : { ownerUserId: currentUser.id }`。

### 3. 前期管理员极薄用户管理 (`/admin/users`)
- 交付极薄管理端 Web 界面 `/admin/users` 与对应 API（`GET/POST/DELETE /api/admin/users` 及重置密码）。
- 管理员可在页面一键创建新用户（输入用户名、显示名、初始密码）并分发给目标成员，免除直接操作数据库或开发 CLI 的负担。

### 4. 一次性 PairingTicket 与 Runner 安全配对
- **数据模型**：新增 `PairingTicket { id, tokenHash, ownerUserId, expiresAt, consumedAt, createdAt, owner }`。
- **安全生命周期**：
  1. 登录用户在 Web UI 点击“+ 接入我的本地电脑”，触发 `POST /api/pairing-tickets`。
  2. 服务端生成 32 字节高熵随机 Token，仅存储 SHA-256 哈希，TTL 为 10 分钟；单用户仅保留一个有效 Ticket。
  3. 前端展示一键复制命令：`curl -fsSL https://<平台域名>/runner.js | node - --pairing-token=<TOKEN>`。
  4. 新增 `/runner.js` 静态/动态下载路由供本地执行。
  5. Runner 携带 Token 调用公开 `POST /api/runner/claim` 接口，服务端在数据库事务内原子校验与消费（`consumedAt IS NULL && expiresAt > now`），自动生成绑定该用户的 `RemoteNode` 与长期随机 Node Secret。
  6. Runner 将长期凭证保存到本地受限配置文件（`~/.agent-platform/runner.json`），后续 WebSocket 通信改用 `Authorization: Bearer <nodeSecret>` 请求头，杜绝在 URL 查询参数中暴露 Secret。

## 切片规划 (Slices)

### S01：多用户 Session 修复与服务端分级鉴权
- 重构 `src/lib/auth.ts` 与 `src/lib/auth-users.ts`，修复 `createSessionForUser`，升级 Claims v2。
- 实现 `requireCurrentUser` / `requireAdmin` 及数据库角色状态校验。
- 引入 Next.js `middleware.ts`，实现 `public`、`authenticated`、`admin` 路由策略。
- 单元测试覆盖 Session 签发、解密、篡改、过期、降权拦截及页面/API 鉴权行为。

### S02：多租户资源归属隔离与 API 权限约束
- 更新 Prisma Schema：在 `Task`、`LiveRoom`、`RemoteNode` 中增加 `ownerUserId` 外键与关联索引，完成数据库迁移与客户端生成。
- 更新 Task、LiveRoom、RemoteNode 的 Route Handlers，执行 `admin ? all : { ownerUserId: currentUser.id }` 过滤。
- 严格限制宿主机本地执行与全局配置接口仅供管理员调用。
- 编写跨用户越权访问负向测试，验证资源隔离生效。

### S03：管理员用户管理界面与 API 交付
- 实现 `GET /api/admin/users`、`POST /api/admin/users`、`DELETE /api/admin/users/:id` 及密码重置端点。
- 构建 `/admin/users` 极薄管理页面（用户列表、新建表单、重置密码、删除操作），并在管理员导航栏展示入口。
- 完成管理端 API 与页面权限测试，验证非管理员被拦截。

### S04：一次性 PairingTicket 与 Runner 配对接入闭环
- 实现 `PairingTicket` 模型、`POST /api/pairing-tickets` 生成接口与 `/runner.js` 分发路由。
- 实现 `POST /api/runner/claim` 原子兑换接口，生成绑定用户的 `RemoteNode` 与长期 Node Secret。
- 升级 `scripts/agent-platform-runner.js` 支持 `--pairing-token` 配对、配置持久化与 Bearer Header 认证。
- 升级 `src/lib/remote-node-ws.ts` 支持 Header 鉴权；在 Web UI 增加“+ 接入我的本地电脑”配对弹窗。
- 完成端到端配对接入验证、Ticket 重放/过期测试与跨用户设备隔离测试。
