# 082 PLAN 20260825 通用 HMI 结构化候选协议

## 背景与决策

078/170 两个已完成 PLAN 建立了“Reader 白名单标准字段候选 -> Web 确认值 -> 既有 mapper”
闭环，但它只能处理调用方预先知道的字段，不能实现任意 HMI 页面的开放结构发现。

本 PLAN 不新增平行端点：当前 `/api/v1/draft` 只有 Web 这一条受控调用链，直接在跨仓版本
接力中升级合同即可。`/api/v1/recognize` 保持不变，继续提供低延迟 OCR/模板结果；Web
后续在上传识别后自动调用 draft，使产品主链形成 OCR + VLM 双管道。VLM 失败不得抹掉
OCR 结果。

标准字段目录仍可作为 canonical 建议输入，但不再作为输出白名单。无法映射的字段以
`canonical_id: null` 保存候选，由人 review；采集阶段不执行品牌、页面用途或 Profile 的
业务写入门禁。

## 1. S01：通用结构纯函数合同

范围：`scripts/vlm_qwen.py` 与一组最小聚焦测试；不接线 HTTP，不修改 Web。

1. 开工读取 `AGENTS.md`、本 PLAN、081 HANDOVER 并审计当前 6 个未提交文件；将 TACT
   路由/模板工作与 draft 工作分开保留。
2. 修改任何函数前对目标符号运行 GitNexus upstream impact，向用户报告直接调用者、
   受影响流程和风险；HIGH/CRITICAL 先警告再继续。
3. 将 `draft_from_ocr` 的输出收敛为 `sections -> fields -> items` 通用结构；每个字段保留
   `screen_label`、可空 `canonical_id`、`role`、`unit`、`sources`、`evidence` 和
   `needs_confirmation`。
4. 复用已有原图编码、OCR evidence 和 VLM 调用，不新增类层级、字段知识库或依赖。
   调用方可提供 canonical hints，但目录外字段合法。
5. 在 trust boundary 严格限制字符串/数组/section/field/item 数量、有限数、枚举值和
   JSON 形状；不要求 evidence 必须逐字等于 OCR，因为 VLM 可直接读图，但证据不得为空。
6. 最小融合规则：OCR 和 VLM 对同一标签/角色/单位的候选可合并来源；值冲突保留为
   `needs_confirmation`，不得凭模板静默覆盖。若纯函数内无法可靠判同一字段，宁可保留
   两个候选交给 review，不引入模糊匹配框架。

完成标准：聚焦测试至少覆盖目录外字段、可空 canonical ID、动态 item 标签、设定/实际
角色、OCR/VLM 来源、冲突保留、坏 JSON、非有限数、超限输入和无有效候选。运行测试与
`git diff --check`，创建 S01 HANDOVER 并停止。

## 2. S02：HTTP 接线与兼容回归

范围：`hmi_service.py`、S01 纯函数、聚焦服务测试和本 PLAN/HANDOVER；不修改 Web。

1. 将 `/api/v1/draft` 接入 S01 通用合同，继续复用现有 multipart 图片、可选 OCR evidence、
   Bearer 鉴权、图片校验、并发限制和错误映射。
2. 删除“输出必须属于 allowed_fields”的中心限制；如为跨仓过渡保留现有表单字段，只把
   它解释为 canonical hints，不维持两套响应协议或永久兼容层。
3. 验证 `/api/v1/recognize` 请求/响应零变化；draft 不落库、不写文件、不自动确认。
4. 覆盖 OCR 有/无结果、VLM 成功/失败、图片非法、上下文畸形、401/429/502 和响应上限。
5. 提交前运行 GitNexus `detect_changes(scope=compare, base_ref=master)`，确认只影响 draft
   预期符号和流程；执行 workflow preflight，创建终态 HANDOVER 并停止。

完成标准：Reader 有单一、严格、可被 Web 消费的开放结构合同；聚焦及相称回归通过；
不部署、不重启服务、不进入 Web 仓。

## 3. Web 接力出口（不在本 PLAN 实施）

S02 HANDOVER 必须附最终请求/响应示例、限制、错误语义、测试命令和提交 SHA。随后在
`/data1/code/mold-data-webpage-tool/docs/dev/` 新建独立 PLAN，至少拆成：

1. 后端代理与整份结构持久化（优先复用 capture JSON 字段；确认确有查询/迁移需求前不
   新建表）；
2. 上传后自动 draft、通用结构 review 与人工编辑；
3. 已确认结构到既有 canonical mapper 的显式映射，映射不了的仍可保存；
4. mock 全链路与获批测试环境的真实 Reader smoke。

Web 计划必须先审计当前 12 个已跟踪未提交文件，尤其不能直接继承“confirmed 字段绕过
page-purpose/import gate”的临时行为；采集 review 可放宽，最终写入业务表的安全门禁必须
保留。

## 明确不做

- 不把任意 VLM 文本直接转换成数据库路径或业务写入。
- 不自动接受候选，不因 OCR/VLM 一致就跳过人工 review。
- 不为一个调用方新增接口版本路由、通用插件系统、对话会话表或后台任务。
- 不顺手提交当前 TACT 温度路由/模板工作。
