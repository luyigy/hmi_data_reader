## 每个 Session 的规则

只做当前一个可验证单元。理解、修改、测试、HANDOVER 和提交都计入本 Session。
默认控制在一组相邻代码及直接测试。跨越多个职责时先缩小单元，不为了文档表格强行做完。
若当前 Slice 中途需要交接，记录已验证、未验证和具体下一步，不能标为完成，也不能推进后续 Slice。
前置资源确实缺失时允许准备本次所需的局部测试资源；不得改生产数据库、暴露 Docker socket 或全局放开宿主环境变量。

- 结果：独立修复分支、AGENTS 局部例外、PLAN、首份 HANDOVER。
- 实现：复用旧 YAML 格式与校验器，所有自动动作设为 none。
- 边界：只改三份文档，旧 workflow 合同和业务源码不改。
- 验收：两份文档 preflight、Git diff 检查、自动化仍 false。
- 前置与停止：基线和用户修改清楚；本单元提交后停止，不继续编码。
- 交付：文档提交和 `546_HANDOVER_20261023_运行环境修复手动接续.md`。

## S02：数据库回归在实际沙箱可执行

- 目的：先解决后续修复无法运行测试的前置，不把测试能力寄托于尚未实现的服务功能。
- 结果：无宿主 `.env`、无 Docker socket 时，能在实际 sandbox 启动一次性数据库并执行选定回归。
- 实现：先核实现有资源；缺少时准备固定版本 PostgreSQL 工具及必要库、辅助程序与数据文件。用本任务局部入口启动、检查和清理。修测试脚本显式配置的读取顺序，在受控入口内提供配置，不扩大全局变量白名单。
- 边界：测试 runner、一个局部资源准备/运行入口及直接测试；此时不改 GraphService、调度器或旧票快照。局部入口以后复用，不保留两套重复供应逻辑。
- 验收：配置读取缺陷先复现；实际沙箱执行 `task-graph-environment-outcome` 基线套件及一次隔离写入/清理；保存命令、版本、退出码、清理证据。当前套件旧预期通过只证明基线可跑，不证明环境分派正确。
- 前置与停止：先确认可执行资源、依赖和最小授权；禁止用宿主成功替代沙箱成功。需要全局安装、扩大权限或接触生产服务时停止并交接具体原因，不重复失败探针。
- 交付：对应代码/工具提交及新 HANDOVER；明确后续阶段如何复用测试能力。

## S03：阶段服务拥有自己的 PostgreSQL

- 目的：把一次性测试数据库纳入现有阶段生命周期。
- 结果：服务就绪才交给调用者，失去归属或退出有明确失败，结束只回收自身资源。
- 实现：沿 `service-contract.ts`、`attempt-services.ts` 扩展固定资源来源、数据库健康检查和连接回执。必要时提取窄职责 PostgreSQL 模块。TCP loopback 先用现有路径，端口不能只探空闲而不核实实际监听归属。
- 边界：服务合同、阶段服务和直接回归；Node/Python/HTTP 旧入口保持兼容，不新建 Manager。
- 验收：真实启动、并行隔离、端口冲突、启动失败、运行中退出、取消与清理；旧服务测试仍通过。
- 前置与停止：S02 有可重跑环境。固定 binary 不等于固定所有动态依赖，缺项如实交接。
- 交付：固定提交与新 HANDOVER。本 Slice 的函数级真实服务验收独立于后续 Graph 接线。

## S04：相同资源接入实施与验收

- 目的：消除两个入口对数据库能力的遗漏和重复装配。
- 结果：实施与独立验收消费相同固定资源定义，每阶段使用各自干净数据。
- 实现：扩现有 `RuntimeDeclaration` 与 pin/复验，复用 S03 生命周期，接入 `runner-harness.ts` 和 `check-environment.ts`。只收敛共同准备逻辑，保留写权限、模型访问和输出差异。
- 边界：既有运行声明、准备交接和两个入口。这个原子接线超过常规两文件预警线，因为两个入口必须采用同一个已固定合同；若一个 Session 无法验证完整链路，先记录子单元与剩余内容，不提前宣告完成。
- 验收：实施/验收各跑真实 PostgreSQL 回归、资源版本一致、数据独立；未授权根/未知字段/资源变动仍拒绝；browser/OCR/skills 和旧 HTTP 服务回归。
- 前置与停止：S03 生命周期已验证。禁止同一能力另建平行配置或万能镜像，禁止自动升级旧任务授权。
- 交付：完整接线提交、删减的重复装配说明及新 HANDOVER。

## S05：环境失败按事实处理

- 目的：阻止缺能力被重复派发，保留工程问题由原 Agent 修复的原则。
- 结果：环境报告和候选保留，经已有准备边界核实；暂时故障有界；误报仍回工程闭环。
- 实现：修 `implementation-result.ts` 的过宽条件和必要的既有准备交接，替换 MISSING=4/lastFailure 消失的错误测试。不能只排除一个 if 就宣称全链修好。
- 边界：environment_failed 路径及直接回归。其他 blockerKind 未证实的风险先记录，不一起重写。
- 验收：实际协调/账本回归覆盖首次缺失不空转、误报、暂时故障、条件未变、条件恢复与原候选接续；旧普通工程问题和权限问题保持原行为。
- 前置与停止：已有真实测试环境和准备核实证据。只修改文本回执或 mock 调用次数不算完成。
- 交付：对应修复提交与新 HANDOVER。

## S06：独立审查与收口

- 目的：独立检查固定代码与真实证据，防止实施者自查代替验收。
- 结果：审查结论、修复闭环或未完成清单，精确到提交与实际命令。
- 实现：独立 reviewer 审查范围、误报反例、并发和清理；不因先前 kimi/pi 讨论过方案就视为代码已审。
- 边界：本修复分支。发现缺陷交回实施者局部修复并重新核验，不擅自部署。
- 验收：必要套件、workflow/长文件/diff 检查与独立结论齐全。重跑范围由变化决定。
- 前置与停止：前述单元真实验证完成；缺证据则保持未完成。
- 交付：最终 HANDOVER。此时仍需单独处理合入、部署与原 S02 接续，不自动恢复任何业务票。
