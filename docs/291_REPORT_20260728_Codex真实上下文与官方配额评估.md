# REPORT · Codex 真实上下文与官方配额评估

## 文档定位

本文是供后续会话继续讨论的技术交接记录，不是 PLAN 或 HANDOVER；不含 workflow Prompt 标记，不能作为
workflow watcher 的输入，也不授权启动实现工作。

## 当前结论

平台当前的 `contextWatermark` 是策略估算值：可见消息数、运行事件数与拼接 transcript 字符数三者取最大比率。
它不代表 Harness 实际向模型提交或保留的 token 数。

Codex 可提供两类官方 telemetry：

- App Server 的 `thread/tokenUsage/updated`：每个 Codex thread 的实际 token 使用情况；可用于替代 Codex
  成员的估算水位。
- App Server 的 `account/rateLimits/read` 与 `account/rateLimits/updated`：ChatGPT/Codex 账户当前限额桶的
  `usedPercent`、窗口时长与重置时间；只适用于服务账户认证，不等同于 OpenAI API key 的账单用量。

OpenAI API key 场景可另用 Usage / Costs API 与响应 rate-limit headers，但那是组织/API 项目用量，不能冒充
ChatGPT 或 Codex 套餐额度。

## 现状与缺口

- `src/lib/real-agents/codex-agent.ts`：只有 `approvalPolicy === 'on-request'` 时走
  `runCodexAppServer`；普通执行与 resume 仍走 `codex exec --json`，只能拿 thread id 与文本事件。
- `src/lib/real-agents/codex-app-server.ts`：已负责 thread start/resume、turn、工具事件与审批，但尚未处理
  token usage 或 account/rate-limit 通知。
- `src/lib/acpx/runner.ts`：已把 Codex thread id 写入 `TaskRun` / `TaskRunParticipant.controlMetadata`，可复用
  该 JSON metadata 保存 telemetry，首版不需要 Prisma migration。
- `src/lib/live-room.ts`：已计算并输出成员水位；`src/lib/feishu.ts` 与 Web 成员面板已经消费该 payload。

## 推荐的最小实现边界

只实现 `platform_local`、Codex、非受限 workspace：

1. 让 Codex App Server 将 token usage 与官方 quota 回调给 Harness。
2. 由 ACPX runner 将最新值与采集时间写入该 participant 的现有 `controlMetadata`。
3. Live Room 序列化时，Codex 有 provider telemetry 则显示真实 token 水位；没有时仍显示现有估算，并标明
   `provider` 或 `estimated` 来源。
4. UI/飞书复用现有水位展示入口；quota 首版仅显示已用百分比和下次 reset，不创建账户报表、历史趋势或
   多厂商抽象层。

## 必须先解决的风险

1. **隔离语义不能倒退。** 普通 `codex exec --json` 经 `bubblewrap` 执行；现有 App Server 路径没有。
   同时 ACPX 已明确拒绝受限 workspace 的 Codex App Server 模式。切换默认路径前，必须让 App Server 接入
   等价的 workspace/network 隔离，或严格保持该范围禁用。
2. **账户可见性。** quota 属于 `CODEX_HOME` / ChatGPT 登录账户，不天然属于 Live Room 成员；共享机器或
   多账户场景必须按账户边界展示，不能向无权用户泄露其他账户的用量。
3. **长文件守卫。** `src/lib/acpx/runner.ts`、`src/lib/live-room.ts`、
   `src/components/live-room/LiveRoomWorkspace.tsx` 和 `src/lib/feishu.ts` 均已超过阻断线，不得增长。实现时
   应新建小型 telemetry 模块/组件，原文件仅替换或提取调用。
4. **会话语义回归。** 必须覆盖新 thread、resume、审批请求、超时/中断、进程 PID 持久化与 Live Room
   continuation；不要仅因拿到 telemetry 而改变完成、权限或中断行为。

## 预计改动面

中等偏重，约 6--8 个业务文件加聚焦测试；风险集中在本地执行、续接、审批与隔离边界，而不是数据库或
API schema。GitNexus MCP 在本次调查中索引刷新后连接关闭，未能输出正式 graph impact；实施前必须恢复该
连接，并对将修改的共享 symbol 做 upstream impact。

可能涉及：

- `src/lib/real-agents/codex-app-server.ts`
- `src/lib/real-agents/codex-agent.ts`
- `src/lib/harness/types.ts`
- `src/lib/harness/adapters/codex.ts`
- 新建 Codex telemetry / persistence 小模块
- `src/lib/acpx/runner.ts`（仅委托调用，不能增长）
- `src/lib/live-room.ts`、`src/types/index.ts` 与现有展示入口（以提取替代增长）

## 后续启动条件

只有在用户明确授权实现后，才建立独立 PLAN / workflow slice。开工时先确认 App Server 当前版本支持的
`thread/tokenUsage/updated` payload，恢复 GitNexus impact 分析，并优先处理 App Server 的 sandbox / network
隔离等价性；未完成该前置条件，不得把普通 Codex 路径切换为 App Server。

本文仅记录评估，没有查询真实账户、存储任何凭证、修改业务代码、数据库、API 或运行中 workflow 状态。
