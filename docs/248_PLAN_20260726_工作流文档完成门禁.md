# PLAN · 工作流文档完成门禁

## 目标

把 PLAN/HANDOVER 合同校验从 watcher 的事后检查前移到 Session 完成边界：

- `workflow-contract.yaml` 继续作为唯一规则源；
- Agent 负责按规则写文档，但不能绕过平台校验；
- 涉及 PLAN/HANDOVER 的 Session 只有在文档已提交、且目标 Git ref 上的提交版本通过
  validator 后，才能标记完成；
- 校验失败直接返回具体文件和错误，不启动 watcher 或下一 Session。

同时修复当前两个已知问题：

1. `247_PLAN_20260726_FeishuJob系统命令补齐验收.md` 的终止动作携带 Prompt；
2. `/ap job run` 把执行失败、重复和锁冲突合并为“未执行”。

## 原则

- 不复制合同规则；复用现有 `validateDocument`。
- 不以 Git hook 作为保证；hook 可选，平台完成门禁才是强制入口。
- 只校验目标 Git ref 中已提交的 PLAN/HANDOVER，不读取工作区版本。
- 无工作流文档变更的普通 Session 不增加门禁。
- 不修改 CRITICAL 的 `executeScheduledJob` 返回类型。

## 实施计划

### S01：抽取独立 validator

1. 对所有拟修改 symbol 执行 GitNexus upstream impact；HIGH/CRITICAL 先告警。
2. 从 `src/lib/scheduled-jobs/workflow-watcher.ts` 抽取最小可复用的合同加载、候选文档选择
   和 `validateDocument` 能力，watcher 改为调用它。
3. 提供一个仓库内可直接运行的校验命令，输入 Git ref 和候选文件；输出逐文件结果并以
   非零退出码表示失败。
4. validator 只通过 `git show <ref>:<path>` 等读取提交版本，继续使用
   `docs/workflow/workflow-contract.yaml`，不增加第二份 schema。
5. 补一个现有测试文件或一个最小测试文件，覆盖：
   - 终止 action 携带 Prompt 失败；
   - 可执行 action 缺 Prompt 失败；
   - 合法 PLAN/HANDOVER 通过；
   - 工作区合法但目标 ref 非法时仍失败。

验收：watcher 原有测试全部通过，独立命令能在 `03deaaf` 上准确指出 247 的合同冲突。

### S02：接入 Session 完成门禁

1. 先用 GitNexus 查清 ACPX Runner、Live Room delivery 和 API execute 的共同完成边界，
   只在能够覆盖 Platform Local Session 的最小公共入口接入。
2. 完成前检查本次 Session 相对起始 ref 新增或修改的已提交 PLAN/HANDOVER：
   - 没有候选文档：原流程完成；
   - 有候选文档且全部通过：原流程完成；
   - 未提交或校验失败：TaskRun/Participant 不得标记 completed，状态进入可见失败或
     `needs_review`，错误包含文件名和 validator 原因。
3. 保留 Agent 的最终回复和运行日志，便于修正文档后重试；不得自动提交、自动改文档或
   自动启动 watcher。
4. 在根 `AGENTS.md` 只补操作义务：提交 PLAN/HANDOVER 前运行独立 validator。规则内容
   仍只引用 contract，不复制枚举或字段。

验收：用隔离仓库/任务证明非法提交不能完成、合法提交可完成、无文档变更不受影响。

### S03：修复真实失败回显并验收

1. 在 scheduled-job 命令层查询本次 manual run 记录，区分：
   - 已有运行或幂等未启动；
   - 已启动并成功；
   - 已启动但 failed/timed_out，并显示持久化错误摘要。
2. 不修改 `executeScheduledJob` 返回类型；只复用已有运行记录。
3. 修正 247 的合同冲突后，运行独立 validator 验证当前 HEAD。
4. 运行 TypeScript、workflow-watcher、scheduled-jobs、Feishu job command 聚焦测试、
   `git diff --check` 和 GitNexus `detect_changes()`。
5. 提交后按实际改动重启 Platform Local 服务，在 Feishu DM 验证：
   - `/ap job run workflow-watcher` 显示准确失败原因；
   - 非法工作流文档被完成门禁拒绝；
   - 合法文档完成后 watcher 正常处理。

## 停止条件

- 共同完成边界不存在，必须在三个以上入口重复门禁逻辑：先报告再决定是否重构。
- 任一拟修改 symbol 为 HIGH/CRITICAL：先报告 blast radius。
- 测试可能发送真实飞书消息、启动 Session 或改变真实 watcher 状态：改用隔离数据。
- 工作区既有 `AGENTS.md`、`CLAUDE.md` 修改先确认归属，不能覆盖。

## 完成定义

- Agent 写错合同文档时，Session 在完成前收到具体错误。
- validator 与 watcher 使用同一实现、同一 contract、同一目标 Git ref。
- 247 合同冲突已修复。
- `/ap job run` 不再用“未执行”掩盖真实失败。
- 所有聚焦回归、类型检查和 GitNexus 变更范围核对通过。
