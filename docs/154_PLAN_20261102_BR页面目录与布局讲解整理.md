# B&R 页面目录与布局讲解整理

## 目标和现状

用户要求重新审视 B&R 整页的文件层级和职责，整理成后续页面可参考的样板；布局源码本身必须用易懂中文说明。当前完整 profile 三段直接映射目录造成多余嵌套；layout/holding_layout 拆分与宽泛命名不直观；raw_observations 混合定位、读取、结果组装和版本包管理。

## 路线与边界

本片只整理 Reader 的 B&R 射胶保压页，保留稳定 profile ID 和识读阈值，不修改 mold、数据或部署。依次固定 6dee04d 基线及 v1/v2 输出，把目录压平为控制器/页面，按身份、布局、字段、观测、包、回放归位，补源码中文讲解，再验证输出与旧包不变。文件移动、拆并、导入迁移和新包哈希必须同片完成，避免留下一半生效的模块路径。

## S01：建立易懂的页面文件边界

- 目的：从目录和源码即可顺着理解页面的识别流程。
- 完成后结果：`b_and_r/injection_holding/` 直接放本页实现；一个 layout.py 管理射胶/保压布局；README 明确每个文件的职责、版本兼容限制和阅读顺序。
- 实现方法：合并布局文件和标题身份辅助；拆开原屏版式定位、字段读取、输出封装和包管理；AST 更新导入，冻结数值与状态行为；给布局增加中文变量、分步算法、门禁及教学例子。完整 profile 三段保留为注册身份，不强制与目录段数一致。
- 修改边界：本页实现、公共注册和直接调用方、该页 README/测试、包元数据。旧冻结包不改，新源码身份用新版本；不改 OCR、标准字段、真值或模型。
- 验收：B&R v1 完整冻结回放一致；v2 原屏字段/状态/问题与两份冻结输入一致，仅包版本/哈希变化；完整测试、源码 AST 与分层依赖检查、成功/拒绝教学示例实际运行、旧包字节校验、git diff --check、提交前 detect_changes。
- 前置与停止条件：工作区干净，基线 6dee04d44764e3b80a96bdd2353f59a71260e828；先做 impact。若需要改变识读算法或外部业务行为才能组织文件，应停下说明，不以目录整理掩盖算法变更。
- 交付物：独立可 revert 的提交、源码内讲解、分层 README 和 155 HANDOVER。完成即停止，不扩其他页面。
