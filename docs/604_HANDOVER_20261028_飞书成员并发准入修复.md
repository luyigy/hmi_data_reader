## 本次行为

1. 派发入口用 pending 状态条件更新原子领取 delivery，并传递 deliveryId。Runner 在已有 workspace advisory lock、Task/TaskSession 行锁保护下，从数据库重读 delivery、room、member、member session、source task。参与方的 backend、gateway、agentId、role、harness 和 continuationKey 必须匹配可信成员绑定。
2. 新普通房间运行将 `roomAdmission` 写入 TaskRun.controlMetadata。不同成员可并行；同一成员在不同平台 Session 中也不能重入。同一 message/member 的重复 delivery 及跨进程重复请求只准入一次。合法 fresh retry 必须引用自身已失败的前一 Run，重复 retry 仍被拒绝。
3. Resume 必须引用该成员同一任务/平台 Session 的持久化 participant 来源，原生 ID 必须匹配记录。活动运行中的同 host/harness/native Session 互斥，不能用另一个成员绕过。批准的资源接续保留自身授权检查，并用审批 revision 和前次失败运行区分接续/重试。
4. 没有可信 roomDelivery 的旧调用保留原 Session 防重入；Graph execution/review 继续走原准入、Writer、候选和绑定流程，不迁移旧记录。
5. 同 host 的可写目录按规范路径及祖先/子目录关系检查，包含权限 writableRoots 和已挂载补充可写资源。不同成员不会绕过同目录写冲突；新普通房间本地 writer 也检查现有 Graph claim/未退出 Writer。补充资源继续使用现有资源写入预留与退出证明。
6. 本地与远端是不同写入域。远端目录映射在后续执行阶段才解析，因此本次保守地对同一已登记远端 host 的写入串行化；没有声称支持同一远端 host 上不同目录的写入并行。danger-full-access 按主机根目录范围保守处理。
7. TaskRun 是多活动运行事实来源。`activeRunId` 恰好一个活动运行时指向它，多于一个或没有时为 null。创建、正常完成、启动异常、liveness 回收、Feishu 启动清理、资源恢复及交互状态统一重算，结束一个成员不会清掉另一个。仍有活动 Run 时 Task 保持 running，等待输入的注意状态来自活动集合。
8. 控制 API 在没有显式 runId 且存在多个活动运行时返回 409，防止按单值指针/最近运行猜测控制对象。Feishu 启动清理对新的 roomAdmission 必须有退出证明；缺少本地 PID 不能把远端 WPI 判作已结束。

没有数据库 schema 迁移，没有放宽沙箱或生产目录授权。历史活动运行缺少成员绑定时继续保守互斥，不能在上线时伪造绑定解除它。
