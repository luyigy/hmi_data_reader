# HANDOVER · 飞书交互审批卡片实现

## 已完成

- workflow watcher 的飞书发送改为复用平台 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，
  不再通过 `lark-cli` 默认机器人发送。
- PLAN_REVIEW 已改为包含批准、拒绝、修改的 interactive 卡片，并保存
  `reviewMessageId` 与审批截止时间。
- 文字回复和卡片按钮共用审批转换入口；卡片回调在数据库 advisory lock 内校验审批
  人、pending key、message ID、时限和当前状态。
- 批准与拒绝更新原卡片；修改按钮只提示回复
  `revise: <具体反馈>`，实际回复后再进入 revision。
- runner 在同一 advisory-lock 事务内读取并保存 cursor，避免 watcher 覆盖卡片回调
  已写入的审批决定。
