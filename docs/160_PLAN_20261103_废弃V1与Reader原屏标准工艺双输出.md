# 废弃 V1 与 Reader 原屏标准工艺双输出

## 1. 总体目标和用户已经确定的决定

上传一张受支持的机台照片，Reader 独立返回原始屏幕数据、按标准工艺字段组织的局部候选，以及不能确认或转换的原因。调用方不需要再次解释品牌、页面行列或原屏字段含义。

2026-11-03 用户明确要求：

1. 彻底废弃旧 V1，不维护旧调用、旧响应、兼容适配器或回退路径。
2. 新系统只有一条页面识别、布局和读值链路；从同一份页面事实生成原屏和标准候选。
3. 没有机台数据输入来源时，不执行依赖机台参数的物理换算。能确定的转换先在 Reader 完成。
4. 其余物理补全以后由 mold 执行，或在 Reader 将来接入真实机台数据来源后执行。本计划不建设该来源。
5. 本轮只写计划，用户重开 session 后实施。

以上决定取代此前方案中的“保留 V1 兼容输出”“兼容优先”和旧消费者兼容验收要求。架构规范中的观测与解释分离、先建布局后验值、证据可追溯和安全待核原则继续适用。

本文的 draft 表示实施尚未启动，不表示上述产品决定需要重复讨论。用户在新 session 要求按本计划开始时，即为启动指令；按仓库规范更新为 ready / start_first_slice，仅执行 S01。本 session 不启动任何代码 Slice。

## 3. 目标数据流与职责

```text
照片
  → 公共质量检查、矫正、OCR、视觉观测
  → 页面身份路由
  → 页面插件的一套布局与字段读取
  → 页面事实：字段身份、原值、原单位、角色、物理段位、状态和证据
      ├─ 原屏输出
      └─ 标准工艺转换：语义映射、确定性单位转换、逐字段核验
           ├─ 可提供的标准工艺候选
           └─ 待核、无法映射和缺少机台上下文的说明
  → 一个新响应，同时携带原屏、标准候选、关联和转换依据
```

| 位置 | 本计划后的职责 |
| --- | --- |
| Reader 页面插件 | 页面判断、布局、读值、段位和页面物理语义；不访问 mold 数据库 |
| Reader 标准转换层 | 将页面事实解释成标准字段，执行不依赖机台的确定性转换，保留缺失条件 |
| Reader HTTP 和 CLI | 调用同一个识读及转换入口，只提供一种新结果格式 |
| mold | 通用消费与合并、人工修订保护、原图和证据保存、权限、业务提交，以及机台相关物理补全 |

Reader 不导入 mold 的 Python 模型、ORM、页面包接纳逻辑或数据库配置。mold 现有 3.2 字段作为首期目标字典，以版本化合同及固定样例约束两边。不能在两个仓库分别随意扩充一套同名标准。

未来机台来源可作为明确输入接入。当前不预建机台查询服务、默认机台、空适配器或伪造参考值。

## 4. 原屏与标准候选的约束

### 4.1 同源双输出

原屏对象优先复用 `page_observations.v2` 的事实表达。这里的 v2 是原屏合同名，不是继续保留历史 v2 定位算法的理由。修改不兼容的原屏语义时须发布新合同身份，不能暗中改写冻结定义。

新信封的字段名和版本在 S01 冻结，至少表达：

- 新结果合同版本、目标标准模型版本，二者独立。
- 页面身份及 matched / unknown / ambiguous / unsupported 的明确结果。
- 原图 SHA-256、尺寸、坐标空间、OCR 和页面规则版本、源码或包身份、标准映射规则身份。
- 原屏事实和未被映射的屏幕内容。
- 以 `parameter_data` 3.2 字段路径组织的局部标准候选。
- 标准字段到原屏字段的一对多、多对一关联；数组元素使用稳定实体 ID，不使用数组下标冒充段 ID。
- 转换输入、输出、单位、规则版本和必要的计算依据。
- 逐字段的缺读、冲突、禁用、状态未知、语义不明、单位不支持和机台上下文缺失。

原屏值不可被标准转换覆盖。预测框与实测边框、设定与实际、空间映射验证与读数可信度、段位身份与启用状态分别保存。

### 4.2 标准候选是局部输入

- 不要求一张图凑齐完整工艺。不得用完整草稿模型的默认值补温区、段数、单位、压力侧、位置含义或启用状态。
- 缺失字段、空对象或空数组不是删除既有工艺的命令。合并和覆盖由消费端管理。
- 不能把候选直接宣称为完整 `normalized_parameter_data` 或现有保存 API 请求体。
- 标准路径明确但物理补全缺少机台资料时，仍可保留该标准字段的原单位输入。例如射速保留 `40 percent`，绝对射速暂缺。
- 标准语义本身不确定时，只保留原屏及原因，不把值强塞到相似标准字段。
- 原屏所有字段都要有处置记录：已映射、仅作观测、禁用、待核或不支持，不允许静默丢失。

### 4.3 当前可转换和必须延后的项目

| 输入或情况 | 当前 Reader 行为 |
| --- | --- |
| `%`、`sec` 等已确认单位别名 | 转为合同精确枚举，如 `percent`、`s`；原屏单位原样保留 |
| 语义明确的 °F、inch、ms | 可换算到对应 °C、mm、s，保存原值、结果和公式；目标字段必须支持该单位及含义 |
| 已确认塑料侧压力的 bar → MPa | 可使用 ×0.1；不得用单位本身判断压力侧 |
| 压力侧未知 | 可保留标准路径明确的原压力输入，压力侧保持未知；不生成塑料侧物理结果 |
| 40% 射速，无 100% 对应速度 | 标准候选保留 `40 percent`，绝对速度缺省；记录缺少速度参考值，不能生成 80 mm/s |
| 液压侧压力，无增压比 | 保留液压侧原值及已知语义，塑料侧结果缺省；列明需要增压比 |
| 螺杆速度百分比或周向线速度，缺最大转速或直径 | 保留可确定的输入；不得生成 rpm，不将轴向退回速度套用旋转公式 |
| 保压时间为每段时长还是累计时间不明 | 不猜时间定义、不直接求和；保留原屏和待解释原因 |
| 有 V/P 位置、时间数值，勾选或条件逻辑不明 | 数值可作为原屏事实；不因此生成已确认切换模式或默认 position_or_time |
| 段启用状态未知、位置物理原点不明、压力设定/上限不明 | 不生成依赖这些语义的自动确认值；保留读数和具体缺口 |

同一换算不能在两个仓库重复执行。已换算的标准候选必须标明当前值的单位和依据；mold 应以收到的单位及未完成项继续处理，不能再按屏幕原单位重算一次。

## 5. 总体路线和本计划完成后的结果

本计划只实施 Reader 侧的伯乐单页纵向链路；mold 的通用合并保存接口和机台数据源另行规划。

| Slice | 消除的障碍 | 可验证的结果 |
| --- | --- | --- |
| S01 | 输出边界和未知语义未冻结 | 正式合同、字段处置表、带预期结果的固定样例 |
| S02 | v1/v2 两套布局读值 | 一份可离线核验的伯乐页面事实 |
| S03 | 标准字段解释散落在 mold | Reader 独立完成伯乐标准映射和确定性转换 |
| S04 | 新结果未接到唯一服务入口、旧路径仍活跃 | HTTP/CLI 只输出同源双结果，旧 V1 明确不可用 |
| S05 | 缺少真实上传和独立人工核验材料 | 原图到双输出的实测报告、新版本发布身份和消费说明 |

## 6. 分片实施

### S01：冻结新结果合同和伯乐字段处置样例

- 目的：确定 Reader 交付的原屏、标准候选、转换和未知项到底是什么，避免边写算法边猜 mold 的模型要求。
- 完成后结果：无需启动 mold，即可校验一份新结果 JSON；每个伯乐字段都能查到标准去向或不映射原因。
- 实现方法：只读核查 mold 3.2 实际枚举和字段含义，冻结所需标准字段子集及来源版本；在 `contracts/` 定义新信封和局部候选校验规则，在专属 fixtures 保存手工核对过的正负样例。确定稳定段 ID、工艺顺序、目标引用格式和原因码。区分机台依赖缺失与标准字段自身无法确认。
- 修改边界：新合同、固定 JSON 样例、对应合同测试和说明；不改 OCR、布局、HTTP、数据库或运行服务。合同与样例文件可能超过两个，它们构成同一份可独立校验的交付，不是新增多个生产功能。
- 验收：正常候选和原屏独立校验通过；拒绝 NaN、Infinity、字符串数值、错误单位枚举和重复段 ID；低可信或未知启用不能伪装成已确认值；`40 percent` 无机台数据时不出现绝对速度；字段关联引用均存在；部分候选不会被解释成完整草稿或删除命令。
- 前置与停止条件：先检查两仓状态和最新代码；本文确定的弃用 V1、无机台时不换算方向无需再问。遇到确实无法裁定的物理语义，记录 unresolved 并继续已有确定部分；若出现必须扩充 mold 标准模型才能表达的新物理量，则单列接口问题，不跨仓改模型。
- 交付物：S01 独立提交、HANDOVER、合同及通过/拒绝样例。本片完成后停止。新 session 的首片就是此片。

本片不含线上识别，因为先固定两个输出如何关联、未知怎样表示，可以独立阻止后续把默认值伪装成观测事实。

### S02：建立唯一伯乐页面事实

- 目的：取消同图经两套布局和读值而产生不同状态的根因，为两个输出提供唯一事实来源。
- 完成后结果：离线输入图片/OCR 后得到统一字段身份、段轴、读值、单位、状态和来源；没有标准工艺层自行找框或重读 OCR。
- 实现方法：在现有页面目录复用最可靠的布局和读值能力，形成唯一页面事实结果。代码过去服务过 V1 不等于算法必须抛弃；删除的是旧输出路径和重复解释。核实物理段序，保留不确定状态；切换选择框不能可靠识别时继续 unsupported。页面结果只包装事实。固定样例比较原文、段位和原图回投。
- 修改边界：伯乐 `layout.py`、`extractor.py`、`page_result.py` 及直接测试；必要的页面源码清单和新版本身份更新。此片预计超过两个生产文件，因为布局、读值和结果的接口必须原子迁移；不同时修改 HTTP、UI、mold 或扩展其他品牌。若预估无法单 session 收口，先在 PLAN 拆分可独立验收的子片，不留下断裂导入或假发布身份。
- 验收：同一 OCR 只经过一次布局/读取；所有字段有原文和来源或明确缺失原因；预测格不冒充实测框；单格缺读保留其他事实；段号、错列和标签冲突不能自动导入；真实原图的 bbox 正确回投；灰显、零值或数值存在不单独决定启用；不将 5.0→6.0 等 OCR 错误用规则改回“正确值”。
- 前置与停止条件：依赖 S01 合同。必要信息缺失时交付待核事实，不能伪造 enabled、位置含义或勾选态以提高通过率。不要继续按漏一格、漏一行分别新增补丁分支。
- 交付物：统一页面事实、布局/段位证据图、字段状态 JSON、测试结果、独立提交与 HANDOVER；不部署中间态。

### S03：实现独立标准工艺转换

- 目的：让 mold 无须再次理解伯乐原屏字段和页面布局。
- 完成后结果：纯页面事实输入即可生成标准工艺局部候选、字段关联、转换记录和未解决项；不依赖图片重读或 mold 运行环境。
- 实现方法：在页面目录放页面语义映射，公共纯转换仅处理确有复用价值的量值规则。映射先检查角色、段位、读数和启用状态，再按标准字段语义解释；单位转换保留前后量值及规则身份。原屏事实作为只读输入。未来机台依赖用清晰原因表达，不实现假输入来源。
- 修改边界：首期通常是一份伯乐标准映射模块、一份确定性量值转换模块及直接测试。具体文件名依据 S01 的合同和现有目录确定，不预建所有品牌和工艺分区空模块；不导入 mold 业务模型或访问网络、数据库。
- 验收：已确认的转换数值正确且有证据链接；未显示不填零；物理顺序不照搬屏幕 order；压力设定/上限、设定/实际、逐段/全局速度不能混用；单字段不支持不抹掉其他候选；40% 无绝对射速；未知压力侧无塑料侧值；未知时间含义无默认累计或求和；标准结果转换前后原屏对象内容不变。
- 前置与停止条件：依赖 S02 页面事实。允许部分输出和空候选加明确 unresolved。不能为了凑齐字段再加一条 OCR/布局路径，不能通过导入完整草稿模型的默认值补齐缺口。
- 交付物：字段转换和单位转换测试、双结果固定样例、覆盖/待核明细、独立提交与 HANDOVER。

### S04：切换唯一 HTTP/CLI 输出并删除 V1

- 目的：让真实调用方只调用一条新链路，结束格式选择和旧算法并存。
- 完成后结果：HTTP 上传和 CLI 都得到同一个新信封，包含原屏与标准候选；旧 V1 调用明确失败，无静默兼容或回退。
- 实现方法：在现有编排入口串联 S02、S03；由页面事实分别生成原屏和标准候选。按 S01 冻结的新入口和版本处理请求；删除 `observations_version=v1`、旧字段数组响应、仅为旧调用保留的分支、废弃适配器和引用，迁移当前调用方及测试。未知/歧义/不支持时保留 OCR 和身份原因，不强行进入伯乐转换。
- 修改边界：`hmi_service.py`、共用编排、CLI/受控集成入口及相邻测试。删除旧路径和调用方必须同片完成，预计超过两个生产文件；本片只做入口切换、旧代码删除和版本清单收口，不再改变布局算法或新增前端业务。提交前列明删除清单，禁止顺带删除原图、真值、模型、历史业务数据或其他人的修改。
- 验收：同一输入 HTTP/CLI 的内容哈希、页面、段位、候选和关联一致；没有一次请求跑两次页面解释；默认只有新输出；旧 URL/格式选择请求按合同明确不可用；运行入口无 V1 回退；用 AST/导入和实际调用验证遗留消费者已迁移或明确移除。旧测试转为新事实/候选断言，不以旧 JSON 格式保持一致作为验收目标。
- 前置与停止条件：S01 至 S03 已验收。旧消费者会中断是用户接受的破坏性变更，不能以兼容要求阻塞本片。若某外部消费者暂未迁移，记录影响，不在本仓重新加 V1 兼容层，也不跨仓自动修改。
- 交付物：唯一新入口、删除清单、HTTP/CLI 合同测试、新识读和映射版本身份、独立提交与 HANDOVER。

V1 废弃针对旧输出合同、运行逻辑和消费者。`/api/v1` 这样的 URL 字样、架构规范标题中的 v1 或其他独立版本号不等于旧输出路径；按真实调用链处理，不以字符串搜索结果直接批量删除。无用途的旧包导出兼容代码退出运行链，历史源码和冻结内容可通过 Git 历史查看。

### S05：真实图片双输出验收与交付

- 目的：证明新链路能独立交付标准数据，而不只是在固定 JSON 上通过测试。
- 完成后结果：在 Reader 侧打开一份报告，即可对照原图、逻辑格、原屏读值、标准候选、转换前后值及待核原因。
- 实现方法：用实际图片经新 HTTP 上传入口重新 OCR；报告工具放 `scripts/evaluation/` 或 `scripts/diagnostics/`，不平铺新的一次性顶层脚本。覆盖现有伯乐真实样本及有充分局部结构的裁剪，冻结回放和故障注入分开标记。用同一新结果走 CLI/保存 JSON 再读回，确认事实、ID、单位和来源不变。
- 修改边界：Reader 验收工具、专属测试与报告、发布清单和使用说明；不建设完整业务 Web、不操作 mold 数据库、不自动接纳 mold 页面包、不修改用户人工记录。本片的 JSON 保存读回是 Reader 产物验证，不能冒充 mold 业务保存验收。
- 验收：全部强制矩阵通过或有明确安全待核结果；代码与新发布身份一致；旧包不冒充新源码；实际原图哈希与回投框可信；逐字段统计原屏覆盖、标准映射、拒绝和未解决项，检查错误段位和语义误映射；记录整链路耗时但不以测试次数宣称未知照片准确率。
- 前置与停止条件：依赖 S04。不能靠降低门槛、默认启用或补造物理值通过验收。没有真实独立样本时明确样本范围；未知语义留待核，不扩大到其他品牌补样本数。新运行版本的部署按用户在实施 session 的授权执行；未部署时明确写出，不凭本计划修改当前服务。
- 交付物：新版本与源码身份、实图 HTML/JSON 证据、原屏和标准候选示例、独立提交、最终 HANDOVER，以及给 mold 的通用消费说明。

## 7. 强制验收矩阵

| 场景 | 必须得到的结果 |
| --- | --- |
| 完整伯乐页和充分局部裁剪 | 页面身份正确；原屏和标准候选同源，字段可回溯 |
| 只有数字、未知页面、两页互斥证据 | 明确 unknown/unsupported/ambiguous，不强套伯乐标准映射 |
| 首格、中间格或整行边框漏检 | 用联合证据恢复或待核，不把剩余最右格改编号为第一段 |
| 打印段号、标签或几何证据冲突 | 具体字段带冲突，不自动赋予错误段位 |
| OCR 漏读、重复、低置信或误读 | 原屏及其他字段保留；不凭工艺常识修正读数 |
| 已启用、已禁用和未知状态 | 分别表达；禁用/未知不冒充可导入启用段，原屏仍可保留数值 |
| 第 1 段的屏幕 order 为 5 | 标准顺序按真实工艺段轴核实，不复制展示排序 |
| 40% 射速且无机台输入 | 原屏仍为原单位；标准候选可为 40 percent；没有 mm/s 物理值 |
| 单位别名、°F/inch/ms 的确定性转换 | 数值、目标单位和公式正确，原屏未被覆盖，无双重换算 |
| bar 且压力侧未知 | 不宣称为塑料侧压力；保留可确认原压力输入和缺口 |
| 液压侧压力缺增压比 | 无塑料侧补全值，不能默认增压比为 1 |
| 每段时间/累计时间或 V/P 勾选未知 | 不默认相加、不默认切换模式；原屏和原因完整 |
| 不能映射到标准字段的屏幕内容 | 原屏仍输出，明确未映射原因，不因目标字典缺槽位丢失 |
| 标准候选为部分结构 | 无模型默认填充，无删除指令，不覆盖其他页面字段或人工修订 |
| 无 mold 运行环境 | Reader 可单独运行、出双结果和验收报告 |
| HTTP、CLI、JSON 保存读回 | 同图同身份、同字段及来源，只有一种新结果格式 |

## 8. 不属于本计划的工作

## 9. 新 session 恢复与交付要求

恢复时读取本仓当前 AGENTS、本文、页面 README、架构规范和 mold 标准字段说明，检查两仓最新 git 状态及 HEAD。159 HANDOVER 只作历史导航；其中保留 V1、等待文件结构整理等旧方向，以本计划和最新用户指令为准。

开始实施前对拟编辑的既有函数运行 GitNexus upstream impact 并说明直接调用方、流程和风险；HIGH/CRITICAL 先警示。新 session 不默认重做目录整理，也不根据旧部署路径猜测当前服务版本。

用户启动本计划后只执行 S01。后续每片按最新 HANDOVER 选择，不一次自动做完整个计划。每片完成对应验收、提交前 detect_changes、只暂存本片改动，创建含下一片信息的 HANDOVER，然后停止。需要改计划的文件预算或接口细节时先记录具体调整，用户已经确定的弃用和换算边界不重新议价。
