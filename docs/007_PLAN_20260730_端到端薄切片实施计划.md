# 实施计划：HMI 工艺参数抽取 · 端到端薄切片

> 本版为 Live Room 第三轮讨论（kimi-code 修订版 + codex / antigravity / claude 三轮成员建议）后的定稿。
> 相对初版的关键修订：front matter 契约化；trigger 拆为 T1/T2；样本口径修正为 102 张原图（唯一规范输入 `*.ocr.postprocessed.json`）；删除 `machine_priors.json` 与 `rectify_screen.py`；`machine_id` 命名收紧为 `品牌_机台号_控制器家族`；错误自动入库率统一为严格 `= 0` 并补全指标公式；各切片补独立停止条件；明确 PoC 门槛不等于生产准入。

## 1. 范围

**做（scope_in）**：S1 机器级人工标注；S2 record 级控制器识别（离线聚合）；S3 ZizES 温度页字段级真值集；S4 端到端薄切片（裁切→OCR→路由→提取→校验→真值比对）。

**不做（scope_out）**：换 PaddleOCR-VL / 云 GPU / 训练；其余家族模板（达标后再复制到 KEBA/弘讯/EST/B&R）；飞书自动回填；`ui_family` 大规模重命名（新增字段、保留兼容）；重拍 SOP；**生产环境真实自动入库**（本 PLAN 全部切片仅到"允许进入扩样验证"为止）。

## 2. 方案

### 切片总览与依赖

```
T1（PLAN 获批即触发）:
  S2 开发 + 离线试跑（不依赖 S1，102 张规范 OCR JSON 即可跑通）

T2（S1 标签 + S3 真值到位后触发）:
```

S2 与 S3 的准备工作可并行；S4 依赖 S1 的标注表与 S3 的真值集。

### S1 机器级人工标注

**新增文件**：`ground_truth/machine_labels.json`（唯一机器先验事实源，全流程只读此文件，不再派生第二份先验表）。

由熟悉设备的人按机台标注一次，不按文件名猜控制器：

```json
{
  "version": "1.0",
  "annotated_by": "",
  "annotated_at": "",
  "machines": {
    "伯乐_A01_KEBA": {
      "machine_brand": "BOLE",
      "controller_family": "KEBA | HONGXUN | EST | B_AND_R | ...",
      "hmi_variant": "v1",
      "location": "",
      "notes": ""
    }
  }
}
```

- **`machine_id` 唯一键规则**：`品牌_机台号_控制器家族`（如 `伯乐_A01_KEBA`）。同一机台可能更换控制器，仅 `品牌_机台号` 不足以唯一标识设备。
- 覆盖 `docs/samples_v2/` 全部 22 条记录所属机台。

**停止条件**：`machine_labels.json` 通过 JSON Schema 校验；键符合唯一键规则且无重复；22 条记录 100% 能映射到有 `controller_family` 的机台。

### S2 record 级控制器识别

**新增文件**：
- `scripts/aggregate_record.py` — record 级聚合识别。

**不新增**：`machine_priors.json`（先验直接读 S1 的 `machine_labels.json`，避免双事实源）。

**输入口径（关键约束）**：
- `output/json/` 为 **102 张原图** 的派生 OCR 结果，每张含 `.ocr.json` 与 `.ocr.postprocessed.json`（部分含 `.rectified.ocr.json`），共 204+ 文件，**不能视为 204 个独立样本**。
- 唯一规范输入：**`*.ocr.postprocessed.json`**；其余变体不参与聚合（加入 `.gitignore`）。
- SHA-256 重复组（沿用 `dedup` 报告）：**每组保留 1 个代表文件**参与统计；不得直接采用 `unique` 列表（否则重复组整体漏掉），也不得让重复样本拉高/拉低覆盖率。

**聚合规则（v1，刻意收敛）**：
1. 按文件名前缀 `..._recNN` 分组。
2. 每张图复用 `classify_ui.find_ui_family` 打分；record 级得分 = 各图得分累加。**v1 仅做置信度投票**：现函数签名 `find_ui_family(lines) -> tuple[str, float]`（`scripts/classify_ui.py:52`）不返回各家族完整得分，"标题区 10% 加权 ×2"在现状下无法直接实现，延后到基线跑通且确有收益时再叠加（届时新增 `score_all_families(lines) -> dict[str, float]`，不改旧签名）。
3. 多数决得 record 级 `controller_family`；若与 S1 标签冲突 → 标记 `conflict` 进人工复核队列，不以先验覆盖图片证据。
4. 回填：record 级结果写回该 record 所有页的 `controller_family` 字段；单页保留原 `ui_family` 兼容旧结果。

**离线验证（不重跑 OCR）**：

```bash
python scripts/aggregate_record.py output/json --labels ground_truth/machine_labels.json \
  --output output/record_classify_report.json
```

- 报告中**固化 OCR 快照**：记录所用 OCR 产物对应的 git commit SHA 与 `postprocess.py` 版本号（防上游升级导致结论过期）。
- 输出含每 record 的 `family_scores` 全向量与 unknown 列表。

**停止条件**：脚本在全部 102 个规范输入上无报错跑通，输出格式符合上述约定。准确率验收（Record 分类准确率 ≥ 95%、Unknown 比例 ≤ 5%、与 S1 冲突率报告）属 T2。

## 3. 验证与验收门槛

**6 项验收指标**（`accuracy_report.json`）：
1. 控制器分类准确率
2. 页面分类准确率
3. 字段完整率
4. 数值准确率 ≥ 95%
5. 可自动入库比例
6. 错误自动入库率（核心，**严格 = 0**）

**指标公式（统一定义，删除"显著下降""接近 0"等模糊表述）**：

| 指标 | 公式 | 门槛 |
|---|---|---|
| 数值准确率 | \|匹配真值（允许误差 ±0.5）的数值字段\| / \|真值非空数值字段\|（缺失真值不计入分母） | ≥ 95% |
| 错误自动入库率 | \|误识别但仍 status=ok 的字段\| / \|status=ok 的字段\| | **严格 = 0** |
| Unknown 比例 | \|unknown 图片\| / \|参与聚合图片\| | ≤ 5% |
| Record 分类准确率 | \|与 S1 标签一致的 record\| / \|全部 record\| | ≥ 95% |

**门槛语义**：5–10 张真值 × ≥95% 意味着 n=10 时最多允许 0 张错，统计上只能证明"端到端管道可跑通（PoC）"。**达标 = 允许进入扩样验证；不代表许可生产环境真实自动入库。**

## 4. 风险

| 风险 | 等级 | 缓解 |
