# PLAN · LiveRoom网页与飞书监控及房间管理

## 总体目标与当前障碍

管理员在网页和飞书里都能查看房间总量、绑定、正在执行的工作、异常及用户归属，并能安全地取消绑定、归档或删除房间；普通用户只看到确定属于自己的房间。

现在网页 `/api/live-rooms` 主要列房间，飞书 `/ap status` 主要列平台运行指标，均不能按房间和用户给出上述视图。已有 `LiveRoom`、`FeishuConversationBinding`、`LiveRoomDelivery` 和 Session 数据；`online` Session 只表示会话可复用，不能算“正在执行”。网页房间 API 已有归档和“先归档后永久删除”，但没有单独解绑入口，删除时也未针对运行中的投递或飞书任务入口做完整保护。网页用户 `ownerUserId` 与飞书用户 `openId` 尚无可靠统一映射；群、话题也没有可靠的单一所有者。

## 路线、本 PLAN 的结果与范围

本 PLAN 是 Phase PLAN，覆盖监控读模型、两个查看入口和房间管理。飞书端查看是优先交付，管理动作依赖准确的绑定和执行状态后再开放。

| 阶段 | 解决的问题 | 完成后可验证的结果 | 本 PLAN |
| --- | --- | --- | --- |
| A：统一口径 | 各端统计不一致，Session 在线被误算为工作中 | 同一房间清单与异常判定 | S01 |
| B：飞书查看 | 管理员离开网页无法查看 | 飞书私聊中的概览、房间和用户视图 | S02 |
| C：网页查看 | 缺少可筛选的全局管理页面 | 管理员网页概览和明细 | S03–S04 |
| D：安全管理 | 解绑、归档、删除的边界不清 | 两端共用的动作规则及界面 | S05–S08 |

全部完成后，管理员在两端看到相同口径的房间数、飞书绑定数、执行中房间数、排队/失败/疑似卡住数；能按网页用户、飞书私聊用户、群/话题、归属待核实分别查看房间及最近工作。每条异常显示判定原因和时间。房间详情明确显示绑定及可用操作。网页和飞书均可执行受权限约束的解绑、归档和永久删除。

首版不自动合并网页用户和飞书用户，也不将群/话题归给某个发言人；只显示有证据的归属。首版不自动清理历史异常、不发送主动告警、不引入定时任务。历史排队记录只标记异常，不能擅自按时间取消。

## 共同口径与操作规则

- **已绑定房间**按有至少一条有效 `FeishuConversationBinding` 的不同 `liveRoomId` 计数，同时单列绑定条数；房间列表显示私聊、群根或话题及 app/chat 范围。归档房间仍可显示其绑定，并单列归档数。
- **正在执行**以 `LiveRoomDelivery.deliveryStatus=running` 的不同房间计数；`pending` 单列排队。Session `online` 不计入执行中。最近进度、Session 心跳和本机进程可用性分别展示；无法验证进程存活时显示“未知”，不声称正常运行。疑似卡住阈值复用现有房间进度口径，失败按明确时间窗统计，页面标明刷新时间。
- **归属**：网页房间按 `ownerUserId`；飞书私聊按绑定的 `senderOpenId`，显示访问状态；群/话题单列。一个房间若有多种来源或无确定归属，应在管理员视图显示“多来源/待核实”，不能用创建者或最近发言人冒充所有者。普通网页用户按现有所有权规则查询；普通飞书用户只可在已批准身份和可验证的私聊绑定范围内查看，群中只看当前绑定，不开放全局名单。
- **解绑**只解除指定飞书绑定，保留房间、消息和其他绑定；需要说明解绑后原飞书会话不再路由到该房间。**归档**保留历史与绑定，但拒绝新的执行。**永久删除**沿用“先归档”规则，删除房间及其级联历史前需二次确认。三者都由服务端重新鉴权和检查目标状态；有运行中或排队的投递时拒绝并提示先处理执行，不由界面静默中断。话题绑定还需处理 `FeishuTaskBindingRequest.bindingId` 和任务入口卡片，保证旧话题不会凭旧标识重新绑定或误路由。外部卡片更新失败时记录可恢复状态，不向用户假报全部成功。
- 网页全局管理仅管理员；飞书全局管理仅配置的 `FEISHU_ADMIN_OPEN_ID`，且入口限管理员私聊。飞书卡片操作不能信任客户端传来的房间、绑定或操作者 ID；用回调身份、作用域、短期操作令牌和服务端状态复核。普通用户的管理权限在实现前必须明确可验证的身份映射；首版可仅开放管理员管理。

## Slice 路线

### S01：统一监控读模型

- **目的/结果**：产出可复用的分页房间清单、汇总、用户分组和带原因的异常状态，让飞书和网页读同一口径。
- **实现方法/边界**：在独立的 Live Room 管理读模型模块查询现有房间、绑定、投递、Session 与用户表，按房间聚合并返回明确的 `running/queued/failed/stalled/unknown`、来源及时间字段；复用 `live-room-read-model.ts` 的进度含义。预计只新增读模型和直接测试，不迁移数据库、不改现有执行状态。
- **验收**：覆盖多绑定去重、私聊与群归属、归档房间、陈旧排队、无心跳、失败时间窗和 Session 在线但无运行投递；分页汇总与列表一致。运行相关测试、TypeScript 和长文件检查。
- **前置/停止**：无前置；若现有数据无法可靠区分某状态，以“未知”交付并记录差距，停止推断真实进程健康。
- **交付物**：独立提交、直接测试和 S01 HANDOVER；完成后停止。

### S02：飞书管理员查看

- **目的/结果**：先让管理员在飞书私聊发送管理命令，看到概览，并用卡片分页查看房间、异常、用户和房间详情。
- **实现方法/边界**：扩展飞书命令解析/帮助及卡片回调路由，新增专用监控卡片模块调用 S01 读模型；回调按 `openId` 重新鉴权、分页和过滤，显示刷新时间和异常原因。普通用户只按上述确定范围读；不在群里发全局名单。预计涉及命令入口、卡片路由、专用模块和直接测试；这些是同一飞书入口链路，必要时进一步拆成命令与卡片两个提交。
- **验收**：管理员与非管理员、私聊与群、翻页/刷新、过期卡片、无绑定和异常详情均有测试；真实飞书私聊点击验证卡片身份及分页。
- **前置/停止**：依赖 S01；如回调不能可靠取得操作者身份，停用卡片全局详情并在 HANDOVER 说明。
- **交付物**：独立提交、测试/点击记录和 S02 HANDOVER；完成后停止。

### S03：网页管理员监控接口

- **目的/结果**：网页能从有权限控制的 HTTP 接口取到与飞书相同的概览和明细。
- **实现方法/边界**：新增管理员管理 API，调用 S01 读模型；支持分页、状态与归属筛选，服务端限定范围，返回明确错误码。只改 API 和直接测试，不改 UI 或执行链路。
- **验收**：未登录、普通用户、管理员、过滤和分页的接口测试；同一固定数据下与 S01 结果一致。
- **前置/停止**：依赖 S01；若网页与飞书身份无法映射，不暴露跨来源普通用户查询。
- **交付物**：独立提交、接口测试和 S03 HANDOVER；完成后停止。

### S04：网页监控页

- **目的/结果**：管理员可在网页查看可点击的概览、房间列表、用户分组和异常原因。
- **实现方法/边界**：新增管理页及导航入口，调用 S03 API；显示绑定类型、最近工作、刷新时间、状态及归属待核实项。只改页面/导航和直接 UI 验证，不添加管理写操作。
- **验收**：浏览器核对管理员和普通用户可见性、空状态、分页及与飞书相同的样例房间计数；构建/类型检查。
- **前置/停止**：依赖 S03；若列表过大导致加载困难，优先调整分页，不扩大到数据库迁移。
- **交付物**：独立提交、页面验证和 S04 HANDOVER；完成后停止。

### S05：房间管理动作的服务端规则

- **目的/结果**：获得一个供两端复用的解绑、归档、永久删除执行入口，避免绕过运行状态检查。
- **实现方法/边界**：在独立管理模块封装权限、绑定作用域、运行/排队守卫、原子解绑与归档/删除规则；处理话题请求引用和入口卡片后续修复记录。审视已有 `/api/live-rooms/[id]` 的归档/删除路径，使所有入口共享规则。预计触及管理模块和现有路由及直接测试；若卡片修复需额外持久化，先单独提出迁移计划，不在本 Slice 隐式扩范围。
- **验收**：并发状态变化、重复点击、其他房间绑定、运行/排队保护、话题旧入口、归档后删除以及权限边界的测试；验证解绑保留房间历史，删除后旧路由不能复活。
- **前置/停止**：依赖 S01；若无法保证“检查状态到执行动作”的原子性或外部卡片修复可追踪，停止开放删除并在 HANDOVER 给出补救设计。
- **交付物**：独立提交、事务/路由测试和 S05 HANDOVER；完成后停止。

### S06：网页管理 API

- **目的/结果**：网页取得对指定绑定解绑、归档及删除的受控接口，并返回可供 UI 展示的影响与拒绝原因。
- **实现方法/边界**：把现有归档/删除路由统一接到 S05 的管理规则，新增指定绑定解绑路由；服务端重新确认管理员、目标状态和幂等结果。只改 HTTP 入口及直接测试，不改 UI。
- **验收**：未登录/非管理员、重复请求、运行中拒绝、解绑后房间仍在、归档后才可删除及跨房间绑定 ID 均有接口测试。
- **前置/停止**：依赖 S05；若旧路由仍能绕过 S05，停止开放新接口。
- **交付物**：独立提交、接口测试和 S06 HANDOVER；完成后停止。

### S07：网页管理操作界面

- **目的/结果**：管理员在网页房间详情选择指定绑定解绑、归档或永久删除，提交前能看清影响，执行后看到更新结果。
- **实现方法/边界**：在 S04 管理页调用 S06 API，按可用状态展示按钮、二次确认和拒绝原因；删除后刷新列表与计数。只改页面及直接 UI 验证。
- **验收**：浏览器核对取消确认、重复点击、运行中拒绝、解绑后历史保留、归档后删除和普通用户不可操作。
- **前置/停止**：依赖 S04、S06；若 S06 未覆盖旧入口的安全检查，停止开放按钮。
- **交付物**：独立提交、页面验证和 S07 HANDOVER；完成后停止。

### S08：飞书管理卡片操作

- **目的/结果**：管理员也可在飞书房间详情卡片中解绑、归档或删除，不必返回网页。
- **实现方法/边界**：扩展 S02 卡片回调，先展示影响和确认步骤，再调用 S05 规则；回调重新读取房间状态、绑定及操作者身份，确认令牌短期有效且单次使用，成功/失败均刷新卡片。只改飞书入口及直接测试。
- **验收**：真实飞书私聊验证确认、取消、过期、重复点击、非管理员转发卡片、运行中拒绝和话题绑定；与网页动作结果一致。
- **前置/停止**：依赖 S02、S05；如果飞书回调不能可靠校验身份或确认令牌，不开放破坏性按钮，保留 S02 的只读视图。
- **交付物**：独立提交、真实点击记录和 S08 HANDOVER；完成后停止。

## 验收与退出

每个 Slice 单独完成测试、`npm run check:long-files`、文档 preflight 和提交后交接，不混入工作区的其他改动。整体验收以真实飞书私聊和网页管理员账号对照同一时刻快照；分别试私聊、群根、话题、无绑定、归档、排队、运行中和失败房间。操作验收需保留测试房间的可核查结果，生产房间不得为测试执行永久删除。若 S08 完成，两端的查看及管理都具备且权限边界验证通过，再将 PLAN 标为完成并等待用户验收。
