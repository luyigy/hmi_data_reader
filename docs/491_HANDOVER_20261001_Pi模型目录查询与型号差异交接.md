## `glm-5.3` 为何不在 list 中

- Pi 的 `cli/list-models.ts` 调用 `modelRegistry.getAvailable()`：只列本地已注册且有认证配置的模型，不查询当前会话，也不向供应商实时请求模型列表。`--offline` 禁止启动阶段网络操作。
- 本机执行 `pi-test.sh --list-models glm-5.3 --offline` 返回 `No models matching "glm-5.3"`。本机 `~/.pi/agent/models.json` 的自定义条目只有 `vllm-local/Qwen3.8-27B-FP8`；本机 Pi 内置目录中有 `zai/glm-5.1`、`glm-5-turbo` 等，没有 `glm-5.3`。
- 既有 `docs/evidence/481-s01-native-probe.jsonl` 曾记录：Pi RPC 的 `get_state.model.id` 是 `glm-4.7`，同轮响应 `responseModel` 是 `glm-5.3-flash`。这说明 CLI 选择型号与上游返回型号可能不同；该旧探针不能证明用户当前终端正使用哪个型号，也不能将 `glm-5.3` 自动加入可选目录。
- 用户报告当前终端显示 `glm-5.3`。下次核对该终端的当前会话 `get_state.model`、本轮消息的 `model` / `responseModel` 及终端显示字段，确认是 CLI 可选型号、别名，还是供应商实际响应型号。若确需选择 `glm-5.3`，先确认 Pi/供应商是否支持，再更新 Pi 模型注册；不要只在平台 list 中硬编码一行。
