## 3. 自动接力协议（2026-08-01 用户授权开启）

**用户原意**：每轮 Plan 下去后按切片自动做，做完自动找下一张 PLAN 或 inbox，不再逐项等人点。

### 3.1 已预授权（可直接执行，不再逐项请示）

1. `docs/026_PLAN_20260801_FANUC与DEMAG温度页模板细分执行.md` 全部 9 切片，含 30 条附件下载、飞书核验表创建/预填、VLM 预标注成本。
2. 真值确认环节降级为**自动整批接受**：VLM 草稿零修改转真值，每份真值备注保留 `visual_skim_acceptance` 降级说明（同 015 先例）；用户保留**事后否决权**——发现错误随时推翻，按 020 S1 先例更正真值并重跑。
3. 只读类操作（大表盘点、OCR、提取、验证、报告落盘、checkpoint）在任何阶段均自动进行。
4. 切片间接力：完成即 checkpoint 到对应 `output/s*_progress.json`，立即开始下一切片，不等用户。

### 3.2 自动裁决与全局停止条件（2026-08-01 039 S1 修订）

**普通指标 FAIL 不再等待用户逐项裁决**：

1. 验收 FAIL 时先定位根因；根因明确且影响范围可验证时，允许**最多一轮**定向整改（禁止开放式调参）。
2. 整改复验仍未达 PASS，或当轮无法定位明确根因时：能保证 `error_auto_import_rate = 0` 的，将风险字段或整页置 null/review 降为 `SAFE_REJECT`，记录后继续全局队列；无法安全归零的记 `BLOCKED_EXTERNAL` 并写明恢复条件，不阻塞独立单元。
3. `SAFE_REJECT` 造成的低完整率/低 numeric 必须如实报告，不得伪装成 PASS；DEMAG 射保段表（038）即按本条收口。

**仍是全局停止条件（碰到即停并报告）**：

- 生产真实自动入库、飞书回填（核验表除外）、服务重启、删除/覆盖用户数据。
- 无法隔离的工作区写冲突；权威输入未提交却被当作自动化输入。
- 修改既有家族（ZizES/TACT/KEBA/B_AND_R）行为且无法做到零 diff 时。

### 3.3 接力顺序

1. 当前活跃 PLAN 的下一个切片（以 `output/*_progress.json` checkpoint 为准）。
2. 活跃 PLAN 全部完成 → HANDOVER 落盘 → 回到父 PLAN（013）衔接下一切片。
3. 无活跃 PLAN → 本文件 §4 Backlog 自上而下取第一项可执行的，先立 PLAN 再执行。
4. 全部清空 → 停止并报告。
