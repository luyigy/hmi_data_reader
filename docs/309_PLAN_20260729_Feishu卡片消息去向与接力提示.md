# PLAN · Feishu 卡片消息去向与接力提示

## 目标

让 Live Room 的 Feishu assistant 卡片准确区分三种语义：

- Broadcast：标题只显示发送者；
- Direct：仅结构化 `deliveryIntent: directed_visible` 且目标有效时显示
  `发送者 → 目标`；
- Handoff：标题仍只显示发送者，并在 footer 以弱化文案显示 `下一位：目标`。

消息发送去向与下一轮流程接力必须解耦；不得再因 `$member` 同时被 mention 检测命中而把 handoff
误画成 Direct 箭头。

## 已确认现状

- `LiveRoomMessageMetadata` 已有 `deliveryIntent`、`visibilityMode` 与
  `handoffToMemberId`，无需新建消息 schema 或第二套状态机。
- `resolveLiveRoomMessageMetadata` 已优先把有效 `$member` 记录为 `deliveryIntent: handoff`。
- `buildAssistantRelayCard` 当前同时依据 `message.visibility` 与 `deliveryIntent` 判断 Direct，
  因而 handoff 消息即使结构化 intent 正确，仍可能显示箭头。
- relay payload 对 handoff 已有目标 ID，但目标名称快照只覆盖 Direct 场景；任意位置的 `$member`
  不能保证获得稳定的 footer 文案。
- GitNexus 对 `buildAssistantRelayCard` 的 upstream impact 为 LOW：1 个直接测试依赖、0 条受影响流程。
  `processLiveRoomDelivery` 为 HIGH：1 个直接调用方、4 类受影响流程，覆盖 Web API、飞书命令和
  Live Room 触发路径。

## 边界与决策

- 复用现有 `deliveryIntent` 作为唯一判定依据，不从正文、`@`/`$` 位置或接力目标反推卡片语义。
- 仅补充 relay 展示所缺的 handoff 目标名称快照；不修改 handoff claim、预算、锁、调度、Session
  continuation、权限或消息可见性。
- Direct 目标缺失、intent 缺失或非法时降级为 Broadcast，不显示猜测箭头。
- Handoff 目标缺失时保持普通标题且不显示错误 footer，不从正文猜名称。
- footer 复用 Feishu 卡片现有 `note` + `plain_text` 原生元素，不新增组件或依赖。
- Web 卡片、命令语义、数据库 schema、workflow contract 与既有历史消息不在本次范围。
- 不重启服务、不发送真实飞书消息；真人验收需要用户另行明确授权。

## S01：修正结构化语义映射并完成回归

先对实际准备修改的每个 symbol 运行 GitNexus upstream impact；若
`processLiveRoomDelivery` 仍为 HIGH，先确认改动只增加 handoff 目标显示名称快照，不触碰执行控制流。
在 assistant message metadata 中复用 `handoffToMemberId` 并补齐对应显示名称；随后让
`buildAssistantRelayCard` 严格按结构化 `deliveryIntent` 渲染：

1. `broadcast` 或缺失/非法 intent：标题为发送者，无 footer；
2. `directed_visible` 且目标名称有效：标题为 `发送者 → 目标`，无 handoff footer；
3. `handoff` 且目标名称有效：标题为发送者，正文不变，末尾增加
   `note` 元素 `下一位：目标`；
4. handoff 与 Direct 字段同时存在时，以 `deliveryIntent` 为准，不同时展示箭头和“下一位”。

在现有 `tests/feishu-live-room-relay.test.ts` 增加最小断言，覆盖 Broadcast、Direct、Handoff、
字段缺失/非法降级，以及正文中普通 `@member` 不改变结构化 intent 的场景。运行该聚焦测试、
相关 handoff/metadata 测试、TypeScript、相关 ESLint、`npm run check:long-files`、
`git diff --check` 与 GitNexus `detect_changes({scope: "compare", base_ref: "master"})`。

完成标准：

- 三类卡片与上述视觉语法一致，Handoff 不再显示 Direct 箭头；
- metadata 缺失、非法或目标缺失时安全降级，不从文本猜测；
- handoff 调度、预算、终态、锁释放、Session 与权限行为没有变化；
- 所有实际验证通过并保留事实结果；
- 提交实现后创建 `plan_progress: complete`、`next_action: none` 的 S01 终态 HANDOVER，并停止。

## 风险与控制

- `processLiveRoomDelivery` 是 HIGH 风险共享路径：只允许增加展示 metadata；若需要改分支、返回值、
  调度或持久化控制字段，立即停止并另行评估，不把范围扩进本 Slice。
- `deliveryIntent` 是唯一语义源；保留 `visibility` 只作可见性字段，不作为 Feishu 标题判定兜底，
  防止再次把 Handoff 与 Direct 混合。
- 测试直接断言 card object 的标题、正文与 note 元素，避免引入快照框架或新依赖。
- 开工前已有的 `AGENTS.md`、`CLAUDE.md` 和 `.codex-tmp/` 改动属于用户，不修改、清理或提交。
