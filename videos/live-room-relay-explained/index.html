拟议流程 · 尚未上线

一张任务卡，
怎样安全走完？

把复杂的接力，变成看得懂的六步。

实施 → 验收 → 通过 / 返修约 50 秒
LIVE ROOM · 机制讲解02 / 06
1
先发任务卡

一次只推进一项

卡上写清：要做什么、谁来做、怎样算通过。

目标这一项交付什么
负责人一位成员认领
验收条件事先写清检查办法
每项任务有独立记录拟议流程
LIVE ROOM · 机制讲解03 / 06
2
实施成员动手

做完，交出真实提交

平台核对代码提交、修改文件和检查结果。

认领任务
→
修改代码
→
提交记录
同一项任务只允许一人同时实施。
避免重复唤醒导致两份冲突结果拟议流程
LIVE ROOM · 机制讲解04 / 06
3
另一位成员验收

不是说“通过”就算通过

平台实际运行检查，保存结果；验收人不能是实施人。

检查提交确认代码确实存在
运行验证看命令退出结果
留下证据以后能追查原因
机器证据和人工判断一起看拟议流程
LIVE ROOM · 机制讲解05 / 06
4
分叉点

通过就继续；没过就返修

✓ 验收通过完成这一项，给下一项发新任务卡。
↩ 验收失败带着具体问题返修；两次仍不行就暂停，请人判断。
不让整串任务一直消耗同一条消息的预算。
失败有出口，链条不会无限重试拟议流程

服务重启怎么办？

从保存的任务状态接着走

重启后找回未完成任务，确认没有人正在做，再恢复接力。

保存进度
→
检查是否重复
→
继续 / 暂停
你能看到：谁做了、验了什么、卡在哪里。
这是准备建设的机制，不代表目前已经自动运行完
